LiveHD Passes:
Order, Intent and Options

From source to LNAST upasses, LGraph optimization, legalization, and the simulation, synthesis and equivalence back ends

1Overview

LiveHD [1] compiles hardware through two intermediate representations. LNAST is a language-neutral abstract syntax tree: front ends for Pyrope [2] and SystemVerilog produce it, and the upasses elaborate, check and simplify it while it still has names, scopes and statements. LGraph is a hierarchical, word-level netlist (an hhds::Graph per definition, nodes typed as logic, arithmetic, muxes, state and instances): every downstream pass — optimization, legalization, code generation, simulation, synthesis and equivalence — operates on it. lnast.tolg is the single bridge between the two.

Every lhd command starts with the same compile pipeline (Figure 1) and then adds its own back end (Figure 2). The kernel runs each pass as one recorded step (its name and labels appear in the result JSON recipe, e.g. pass.upass constprop:1 dce:mark inline:true unroll:false verifier:true). Options are set with --set <scope>.<pass>.<knob>=value; inside a command a bare --set cprop.x resolves to the command's scope (compile.cprop.x). lhd list options prints every knob with its default and help; the tables below list the ones that change what a pass does.

The LGraph order is fixed by one rule: only passes that work inside one definition may run before pass.legalize; anything hierarchical runs after it. Legalize is the one owner of combinational loops, so every hierarchical pass already sees an acyclic design:

lnast.tolg → cprop (no hoist) → bitwidth → legalize → enableopt → cprop (+ loop hoist) → bitwidth → [satopt] → latch check → formal → seal

2Front Ends

inou.prpPyrope → LNAST

Parses Pyrope sources with the tree-sitter grammar and builds one LNAST per file, discovering imports so the referenced modules are parsed as well. With lhd.incremental and a user --workdir, unchanged parses are restored from the compile cache instead.

inou.slangSystemVerilog → LNASTdefault Verilog reader

Elaborates SystemVerilog with slang [3] and translates the elaborated design to LNAST, so Verilog goes through the same upasses and lowering as Pyrope. Packed structs stay bundles by default, procedural for loops can be handed over rolled, and unknown modules can be kept as blackboxes.

Options: compile.slang.struct_port_bundles, compile.slang.roll_loops, compile.slang.unroll_limit (4000), compile.slang.flat_top_io, compile.slang.timecheck, compile.slang.preserve_param_provenance

inou.yosys.tolgVerilog → LGraphdebug

Reads Verilog through Yosys (and yosys-slang) and imports the netlist straight into LGraphs, bypassing LNAST. It exists to cross-check the importer and to compare against Yosys, not as a production path.

Options: compile.yosys.memory_mode, compile.yosys.setundef, compile.yosys.blackbox, compile.yosys.script

pass.lnastfmtoptional

A compiler self-check of the parsed LNAST: validates the tree's structural invariants (reference spellings, node shapes) and reports a malformed tree as an internal producer bug, located by its LNAST position. On by default in debug builds, off in optimized builds.

Options: compile.lnast_fmt

3LNAST Stage: pass.upass

pass.upass is a framework, not a single transformation: a set of small upass plugins that elaborate, check and simplify the LNAST together. The kernel re-runs it until every import resolves, then hands the result to lnast.tolg.

Common characteristics of the upasses

  • Streaming, not multipass. All plugins run interleaved in one walk of each function tree: for every node the runner calls each active plugin's process_<op> hook in the resolved order. There is no iterate-to-fixpoint loop; the source is traversed once (semacheck's one-shot pre-walk, the post-walk dead-code sweep and the ssa/timecheck/pipe tree walks are the bounded exceptions).
  • Operate on LNAST. Input is the front end's LNAST; output (toln) is a rewritten LNAST that replaces the body. When nothing downstream reads the LNAST (dce:mark), dead statements are marked instead of rebuilding the tree, and lnast.tolg skips them.
  • One shared symbol table. A single Symbol_table (function / block / always / conditional scopes) is owned by the runner and shared by every plugin, so a value constprop folds is immediately what typecheck, bitwidth and the coalescer see. A fresh table per function tree.
  • Vote, don't rewrite. Each hook returns a keep/drop vote for the statement; the runner owns the rewrite, tuple flattening (detuple), inlining, wrap/saturate lowering and dead-code removal.
  • Comptime evaluation. Constants, attributes and comptime casserts are resolved during the walk; a comptime-false assertion is a compile error.
  • Per function unit. Each comb/pipe/mod body is split into its own unit and specializations are queued as new units; units run serially, each with its own runner.
  • Linear cost. Every plugin must be O(N) in its tree; a super-linear upass is treated as a bug (inlining is bounded by a depth of 256 and a splice budget).
  • Dependency-ordered. Plugins declare what they depend on; the order is a topological sort, and disabling a plugin disables its dependents with an option-forced warning.
  • Incremental. Units the compile cache marks converged or pre-elaborated are skipped, and the cold-compile order is replayed.

3.1 Steps around the walk

lambda splitbefore the walk

Splits each comb, pipe and mod body into its own LNAST unit, so every later step works one function at a time.

ssabefore the walk

Harvests port metadata into io_meta, expands IO tuples and renames multiply-assigned variables into single-assignment form, so the walk sees one definition per name.

Options: compile.upass.ssa (true)

timecheckafter the walk

Discharges the pipeline-timing checks decidable on LNAST: derives the cycle of each value through stage declarations and pipe/mod calls, reports a misaligned read as a located error and removes the checked obligation; what it cannot decide is left for the LGraph checker. Always runs (the LSP needs its diagnostics).

pipeafter the walktoln

Inserts the output flops of pipelined (pipe) functions in the rewritten LNAST.

3.2 Runner plugins (one walk, in this order)

verifierfirst

Checks every comptime cassert: known-false is an error; test builds compare the pass/fail tallies against expected counts. Stripped from function bodies unless asked for.

Options: compile.upass.verifier (true), compile.upass.verifier_pass, compile.upass.verifier_fail, compile.upass.verifier_include_funcs

semacheck

Semantic legality the language defines: writes to read-only attributes, declare-once, shadowing. The user-facing checks that used to live in several passes.

Options: compile.upass.semacheck (true)

attributes

Pyrope attribute semantics: set/get, sticky propagation, comptime attribute checks and conflicts.

Options: compile.upass.attributes (true)

typecheckneeds attributes

Compile-time kind and type legality: operator/operand kinds, nil use.

Options: compile.upass.typecheck (true)

constpropneeds typecheck

Folds values through the shared table, votes redundant statements away and resolves imports (an unresolved import is deferred to the next kernel round instead of failing).

Options: compile.upass.constprop (true)

bitwidthneeds constpropread-only

The last optimization plugin: derives each value's max/min range into bw_meta for lnast.tolg and reports a provable overflow.

Options: compile.upass.bitwidth (true)

coalescerneeds bitwidth

Deferred emission and dead-store elimination: a variable overwritten before it is read is never emitted. Off when nothing consumes the LNAST, and self-disabled on Verilog-origin units.

Options: compile.upass.coalescer (auto)

assertneeds constprop

Reports a statically false cassert call.

Options: compile.upass.assert (true)

Framework-wide knobs: compile.upass.order replaces the whole plugin list (e.g. verifier,constprop,verifier); compile.upass.inline inlines fully defined comb calls (the compile kernel turns it on); compile.unroll requests per-iteration expansion instead of keeping a loop rolled (default false: an eligible loop stays one compact u_loop instance); compile.upass.reset_style (sync|async) wires implicit resets; compile.upass.toln materializes the rewritten LNAST.

lnast.tolgLNAST → LGraphseparate step

Lowers each post-upass function tree into an hhds::Graph: ports from io_meta, widths from bw_meta, if to muxes, pipeline registers to flops, and pipe/mod calls to Sub instances. Callees are lowered before their callers. It runs only when some output needs graphs, and is skipped for graphs restored from the cache.

4LGraph Stage

Common characteristics of the LGraph passes

  • Operate on LGraph. One hhds::Graph per module definition in a GraphLibrary; an instance is a Sub node pointing at its callee's definition (rolled loops are Subs with a loop descriptor).
  • Per definition, hierarchical. A pass transforms one definition at a time and treats an instance through its declared interface; flattening is local to the passes that need it (formal preflight, sim, STA), never in place.
  • Fixed recipe. cprop → bitwidth → legalize → enableopt → cprop → bitwidth: legalize runs as soon as packed fields are canonical and widths are known; the second round folds what legalization, width inference and enable optimization exposed. No pass re-runs the others privately.
  • Parallel inside a pass. cprop and enableopt process independent definitions on worker threads; passes themselves run in sequence.
  • Intra-module before legalize, hierarchical after. Only passes that work inside one definition (bitfuzz, cprop's per-body transform, bitwidth — which reads a callee only through its declared interface) run before pass.legalize; anything that crosses definitions (cprop's loop-invariant hoist, formal's hierarchical preflight, satopt's design-level use) runs after it.
  • Legalize early, seal last. Every pass after pass.legalize — enableopt, the second cprop/bitwidth, satopt and pass.formal — sees an acyclic design and must keep it acyclic. The seal at the end checks one driver per sink and freezes the structure every consumer reads (compile.verify_frozen re-checks it, and in debug builds re-scans for a re-created loop).
  • Registered EPRP methods. Each pass registers a method (pass.cprop, …) with its labels; the kernel runs it as a step with its own log, timer and diagnostics (halting errors stop the pipeline at that step).

pass.bitfuzztest only

Strips derived width/sign annotations right after lowering, to prove that cprop keeps integer semantics without them and that bitwidth recovers them.

Options: compile.bitfuzz.mode (wires; off removes the step), compile.bitfuzz.reg_pct, compile.bitfuzz.seed

pass.cpropmutatesruns twice

Constant and copy propagation, common-subexpression elimination, mux sharing, packed-field canonicalization and dead-node deletion, one definition at a time. In its second run (after legalize) it also hoists iteration-invariant work out of rolled loop bodies into their hosts, the one cross-definition rewrite.

Options: compile.cprop.loop_hoist (true), compile.cprop.low_lanes (true)

pass.bitwidthmutates annotationsruns twice

Range-based width and sign inference in the spirit of Stephenson et al. [4]: propagates value ranges and annotates every driver pin with bits and signedness, plus the rewrites a range enables. An instance's widths come from its declared interface.

Options: compile.bitwidth.max_iterations (3)

pass.legalizemutatesearlyone owner of loops

The one sanctioned structural transform, run right after the first cprop+bitwidth so enableopt, satopt and pass.formal (and its hierarchy views) already see a legal design. (1) Acyclic repair, the only place combinational loops are handled: afterwards every definition is acyclic at arc level (an instance output depends on the inputs its port summary lists). Instances on a real cycle through ports and state-free instances on a false one are inlined; a rolled loop on a false ring is split by its carries, never unrolled; packed slices are rewired; a genuine loop is a comb-loop error. (2) Loop split of rolled loops into parallel and induction halves. It is not an optimizer. Every path that produces graphs runs it (Pyrope, slang, the Yosys reader, lhd compile lg:); a consumer never repairs loops itself.

pass.enableoptmutatesalways onstructural

State-context optimization: removes flop and latch hold loops (a mux feeding q back becomes the enable), recognizes reset and hold structure, simplifies data that only matters under an enable, and shares stateful muxes. It decides with structural facts and Boolean identities, never a solver. It preserves initialization, reset priority, clocking and pipeline depth; the second cprop/bitwidth round cleans up after it.

pass.satoptopt-inmutatesproof-backed

Solver-backed simplification (cvc5, plus ABC &fraig for mux-arm facts): every rewrite is nominated, proven and only then committed, within a per-cone budget. Where enableopt matches enable structure syntactically, satopt proves facts about controls: an enable or select that is always 0/1 (constants), an enable/select re-derived from up to three existing one-bit signals (simp_ctrl), a memory write enable that is never active or ports to merge/narrow (memory); its other stages (equiv, complement, odc, muxtree, share, hotmux, resub) simplify general logic. Off by default: proofs cost solver time and mapped QoR effects are mixed.

Options: pass.satopt (false), pass.satopt.stages, pass.satopt.budget_k, pass.satopt.cone_max

pass.formalannotates

Proves Pyrope assert/assume properties and Hotmux one-hotness with cvc5 [5], marking each proven or runtime_check; a refutation at the top boundary fails the build. The hierarchical preflight virtually flattens from the top. lhd compile runs it in fast mode (induction); lhd sim turns it off.

Options: compile.formal.mode (none|fast|normal), compile.formal.timeout (10 s total), compile.formal.on_refute (error|warn), compile.formal.bmc_bound, compile.formal.cone_max, compile.formal.warn_*

sealend of compile

After the last pass that may reshape the graph: re-checks one driver per sink pin on the settled design and freezes every definition. From here only attributes may change; a consumer that must reshape (sim, synthesis) works on a private copy.

Options: compile.verify_frozen (debug builds: freeze, re-verify after the emits, and re-scan that no pass re-created a combinational loop)

Emits

lg: saves the graph library; inou.cgen.verilog writes one .v per module (read-only, with an optional source map, compile.cgen.srcmap); inou.cgen.sim builds the simulator (Section 5.1); pass.prp_writer writes Pyrope from the LNAST with a recompile self-check; ln: dumps the LNAST. Isabelle and Lean emits export the design to proof assistants.

5Back Ends

Common characteristics of the back ends

  • Read the frozen design. Each back end starts from the sealed graphs and never reshapes the shared library: sim and synthesis work on a private copy.
  • Specialize after partitioning. Once the partitions are decided (sim colors, synthesis regions), pass.specialize pushes constants across instance boundaries in the private copy. LEC compares the original modules, so it does not specialize (a per-color LEC would).
  • Partition into regions. Simulation (colors) and synthesis (regions) both cut the hierarchy into pieces that can be processed independently and in parallel.
  • Incremental by construction. Stable structural ids and per-region caches let an edit recompile only what changed (lhd.incremental is the one switch for every reuse tier).

5.1 lhd sim

inou.cgen.simprivate copy

Generates a cycle-based C++ simulator over hlop Slop<N> values. On a private copy it runs pass.specialize (skipped when observing signals or writing a VCD), prepares the graph (clock gates folded into enables) and fuses parallel loops. Color_plan then groups the flattened design into colors — kernels with bounded live state — schedules them, and assigns stable structural ids so the layout and kernels can be reused across runs. sim.drvgen writes the testbench driver; the host compiler builds it in parallel (with precompiled headers on large designs) and runs it.

Options: sim.jobs, sim.ninja, sim.vcd, sim.tune.backend (slop|llvm), sim.tune.live_words, sim.tune.fence, sim.tune.dirty, sim.tune.profile, sim.init_zero, sim.unknown_zero, sim.checkpoint*

5.2 lhd synth

pass.colorannotates

Colors every definition into regions: alg=synth bounds each region by gate-equivalents and keeps named boundaries stable; alg=reduce (behind synth.reduce) extracts repeated subgraphs as shared definitions. Other algorithms (acyclic, mincut, path, …) serve lhd pass color.

Options: pass.color.alg, pass.color.synth.max_ge (5000), pass.color.hier, synth.reduce (false)

pass.specializeprivate copyafter partitioninghierarchicalsim and synth

The hierarchical cprop/bitwidth round (pass/specialize): information that crosses an instance boundary. Into a child: an input every instance ties to the same constant, or drives narrower than declared (the widest instance wins; the copy reads it through a mask/sign-extend, its interface unchanged). Out of a child: a constant output, or an output narrower than declared (the parent reads it through a fit of that width). Per definition only the specialization all its instances share is applied, as ONE copy <name>__k<hash> (named by that context) that every instance is re-pointed at; the original is never edited and stays available (a testbench may drive it directly). Instances that disagree keep the shared definition: double synthesis or simulation code is worse than a missed specialization. Runs to a fixpoint on a private copy once partitions are decided: sim before Color_plan, synthesis on the mapper's copy after pass.color (state-free callees only; created nodes inherit a neighbor's color). LEC will specialize both sides alike (a definition only where ref and impl agree), so the hierarchies stay pairable. Next: boundary cones (a parent Sum collapsing with a child Sum) through the same copy/re-point machinery.

Options: max_versions (0: no hierarchical traversal; 1: the shared specialization only, the default; N: up to N per-binding clones), synth.specialize (true)

pass/synth → pass.abc | pass.usynprivate copy

Shared region infrastructure builds each region as a module on a private copy, then the mapper optimizes and technology-maps it: ABC [6] (pass.abc) or the native unate synthesizer (pass.usyn). Region results are cached for incremental resynthesis [7]. Details in synthesis.html and synth_usyn.html.

Options: synth.mapper (abc|usyn), synth.liberty, synth.threads, pass.abc.memory, pass.abc.flow, pass.abc.boundary, and the pass.usyn.* family

pass.opentimerread-only

Static timing analysis of the mapped netlist with OpenTimer [8]; by default it flattens the hierarchy into a scratch definition and reports the critical path into timing.json.

Options: synth.opentimer (true), pass.opentimer.hier, synth.sdc, synth.spef

5.3 lhd lec and lhd formal verify

pass.semdiffannotates

Structural matching of the two designs: stamps a match attribute on corresponding nodes and definitions, so the solver only reasons about what actually differs.

Options: formal.lec.semdiff (structural)

pass.lecread-only

Relational equivalence of the two designs: hierarchical (proves children first and collapses proven ones into boxes, top-down by default), with state pairing, induction and BMC over cvc5, and a flat confirmation before any refutation is reported. lhd formal verify uses the same engine to check assert/assume with BMC or induction.

Options: formal.engine, formal.solver (cvc5), formal.timeout, formal.lec.hier, formal.lec.hier_order, formal.lec.collapse, formal.lec.trust, formal.bound

5.4 Standalone passes

lhd pass <name> runs one LGraph pass on an lg: input: color (with --emit-dir lg: also partition, which builds a new library with one module per definition and color), partition, single_edge, satopt, abc, usyn, opentimer, formal, liberty gensim, semdiff and analyze (a read-only survey of loops, clocks and colors, pass.analyze.checks).
