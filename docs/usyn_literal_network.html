USYN literal-network experiment (statistics only)

Question: if a small mux network (the literal network), settled in the first half of the cycle by early control signals, chose the input literals of each selected DOMINO gate, how much simpler would the gate be? For every selected cell with at most 8 inputs and each depth n = 1..3, the cell function is Shannon-cofactored over n eligible controls (all subsets tried). Lower bound: the largest re-synthesized cofactor gate (any shared gate must implement every cofactor). Template: one cofactor's own gate that realizes every cofactor by substituting its inputs with remaining inputs, complements or constants (exact bounded search, every hit re-verified over all input assignments). The literal network is reported separately as 2:1 mux count; it is not charged to the DOMINO gate, because it settles in the otherwise idle first half. Selection and netlists are unchanged.

Setup: lhdsuite Pyrope sources, lhd synth --set synth.mapper=usyn, asap7 at 1000 ps, pass.satopt=false, pass.usyn.tmap_trials=1, pass.usyn.literal_stats=FILE. DOMINO cost is usyn's proxy: formula transistors + 5 per Domino / 8 per DominoLatch.

Findings

  • The opportunity is real on the DOMINO side. Restricting the controls to registered signals (scenario reg), a literal network of depth 1 already removes 7–14% of the DOMINO transistors and 15–37% of the series stack of the cells it applies to; depth 3 removes 15–31% of the transistors and 20–67% of the stack. Allowing static logic over registered signals (stat) makes almost every cell eligible and reaches 30–37% fewer transistors and 58–69% shorter stacks at depth 3. Stack depth, i.e. evaluation delay of the DOMINO gate, is where the idea pays most.
  • Exact templates are usually found. When the lower bound (largest re-synthesized cofactor) shows a gain, a single shared template that realizes every cofactor by literal substitution is found for most cells, and its cost is within a few percent of the lower bound (the gap is largest at depth 2 on dino/picorv32, where many cofactors are not literal-substitutable from one another). Every template was re-verified over all input assignments: 0 mismatches.
  • The literal network fits the first half easily. Mapped alone with the usyn tmap (asap7, 1000 ps target), the literal network of every core settles in 29–120 ps — under a quarter of the 500 ps first half — so depth 1–3 is electrically and timing-wise comfortable at this frequency.
  • Its area is the cost. As static asap7 cells the network is 1.0–3.0× the CMOS area of the cells it serves (matched_filter depth 1 is the cheapest, the deep xs_div trees the dearest). tmap cannot price the DOMINO gate itself, so whether the smaller DOMINO gate pays for the network needs a DOMINO area model or custom mux/DOMINO cells; in static-CMOS terms alone (network + template mapped as CMOS) the variant is larger and slower than mapping the original function directly, as expected (it serialises the network in front of the gate).
  • Mux count per improved cell grows quickly with depth (about 1–3 at depth 1, 3–8 at depth 2, 7–18 at depth 3): depth 1–2 with registered controls is the sweet spot to try first with custom cells.

Coverage and caveats

  • xs_alu (Alu) is purely combinational: it has no state, hence no DOMINO endpoints to analyse.
  • xs_renametable (RenameTableWrapper) does not compile from Pyrope: upass.tolg rejects a field/index read of an unresolved value (t261379). It is pre-existing (lhdtrack's older frozen lhd fails the same way) and is a front-end bug to fix separately; it is excluded here. xs_rob is excluded by request.
  • minion from Pyrope needs larger usyn admission limits: pass.usyn.work=40000000000, max_nodes=200000000, memory_budget_mb=98304 (1h14m, 11 GB). Memories stay native black boxes in every run (minion: 167 Memory nodes, none lowered).
  • Remaining unclassified (in:other) inputs are mostly black-box outputs (memories, instances), memory reads and wide-bus selects: not provably registered from the region's view, so never counted as controls.
  • Only cells with at most 8 inputs are analysed (the gate limit is 8, so this is nearly all of them); controls are the cell's own native inputs (a phase-1 producer is never a control).
  • The (b) numbers are cone-local: each region's improved cells are mapped as standalone networks, so logic shared with the rest of the region is not credited, and the network-only mapping counts each slot as an output (no sharing with the template), which inflates its area slightly.
  • Latches are out of scope by construction. In minion most latches implement clock gating: the ICG enable latch and its clk & latch gate are clock-control paths that stay ordinary CMOS (usyn keeps them as native barriers), never DOMINO gates or literal networks, and their outputs are not data controls. The few two-phase latch pairs (prim_phase_pair_*) are native boundaries too, so they produce no DOMINO endpoints. Only ~100 of minion's ~80k cell inputs come from a latch at all, and none is first-half-stable, so the latch scenarios are omitted from the tables.
  • Inputs driven by logic in a neighbouring region are traced back through the source design: when that logic depends only on registered signals it counts as static-from-registered (stat).

in:* counts native (non-producer) cell inputs by class; stat = interior signal whose whole support is registered.
