Cone-Based Synthesis Partitioning and
Region-Based Technology Mapping

Methodology of the LiveHD pass.color synth (cones mode) and pass.abc passes

1Problem Formulation and Flow

The input is a hierarchical word-level netlist graph (LGraph) produced by the LiveHD front end. Each definition d is a directed graph Gd = (V, E) whose nodes are typed operations: bitwise and reduction operators, arithmetic (sum, multiply, divide), comparisons, shifts, multiplexers (a two-arm Mux, an n-arm Mux, and a Hotmux of (control, value) pairs), bit-level wiring (mask, concatenation, sign extension), state elements (flops, latches, memories), and instances of other definitions. Edges connect a driver pin to a sink pin and carry a bit width and a signedness.

Definition 1 (Coloring, region). Let Vp ⊆ V be the partitionable nodes, i.e. all nodes except graph IO and constants. A coloring c : Vp → ℕ assigns a color to every partitionable node. The region of color k in definition d is Rk = { v ∈ Vp(d) : c(v) = k }. Every region is emitted as its own module <d>__c<k> and is optimized and technology-mapped independently.

The partitioning problem is to find a coloring such that (i) each region can be optimized and mapped within bounded time and memory, (ii) logic that benefits from joint optimization, in particular shared sub-cones, lands in the same region, (iii) region boundaries fall at state elements or where combinational cones share little logic, and (iv) the coloring is deterministic and stable under local design edits, so that mapped regions can be reused incrementally. The mapping problem is then to translate each region into a Liberty-cell netlist with ABC, reassemble the hierarchy, and correct the timing distortions that the partition boundaries introduce.

Fig. 1 shows the flow. The coloring (Section 2) runs on the compiled library. The mapping pass (Sections 3–4) works on a private copy of the library: it prepares compact loops, removes dead logic, applies SAT-proven simplifications, extracts arithmetic and memory modules, cuts the colored design into regions, maps every region, refines the partition-boundary timing environment, and finally runs post-mapping architecture trials. 2Cone-Based Synthesis Partitioning

A forward partitioning that propagates a region id along combinational fan-out fixes the region shape by connectivity alone and needs a separate size window to split and merge the result afterwards. Two failure modes follow directly: inheriting an id from every fan-in welds a register's data cone to the cone of its enable (stall) signal, and propagating to the fan-out re-merges downstream cones where they reconverge; on a flattened processor either rule placed more than 99% of the nodes in a single region. The cones algorithm instead grows one backward cone per state input, decides size while it decides shape, and merges cones by the amount of logic they share. Region boundaries therefore fall where two register cones share little logic. Algorithm 1 lists the phases.

  2. Mark dead nodes: Vp minus the backward closure of outputs and state ▷ §2.2
  3. Form control groups over select and enable closures; mint colors 1..K ▷ §2.3
  4. Collect data roots: arithmetic cuts, register data inputs, memory ports, stateful instances, outputs
  5. for each data root r in order do WALK(r) ▷ Algorithm 2
  6. Place registers into their data-input color; sweep uncolored sinks; totality fallback ▷ §2.5
  7. if Γ > 0 then overlap merge (Algorithm 3), then forward merge across registers ▷ §2.6–2.7
  8. if Nmin > 0 and Γ > 0 then absorb small colors ▷ §2.8
  9. Renumber colors deterministically; isolate every arithmetic boundary operator that no control group claims ▷ §2.9
  10. Attach dead nodes to the color of a colored fan-in

2.1Cost Model: Predicted AIG Size

Every size decision uses one unit, the predicted number of two-input AIG nodes that the mapping pass's bit-blaster creates for a node, π(v). It is derived from the structure of the blaster (Section 4.2) and calibrated per operator against a reference library. The unit replaces synthesis gate equivalents (GE) for three reasons. First, GE mispredicts the number of mapped cells by a median factor of 1.8 and a 90th percentile of 5.6, in both directions: runtime shifts are over-counted by up to 24×, adders are under-counted about 5×, and register-file arrays by 8–11×. Second, the predicted AIG size over-counts mapped cells by a stable factor, which is what a single shared threshold needs. Third, ABC runtime tracks the mapped size, not GE.

Sums and products saturate at the largest integer; otherwise a 1024-bit multiplier would wrap to a small score and license a monster region. An unknown width counts as one bit, so a live operation is never free.

2.2Liveness

The compiler keeps some logic that no output observes. The typical case is a one-hot multiplexer of a unique if whose value is unused: its exclusivity is an obligation that simulation and formal verification still check. Synthesis may ignore such obligations. Let S be the drivers of primary outputs together with every node that is not combinational, not partitionable, or a clock cell. The live set L is the backward closure of S over the fan-in arrays. Every node in Vp ∖ L is dead: it is never a root, never walked, and never shapes a color. At the end it takes the color of its first colored fan-in, so it adds no color. The mapping pass deletes it (Section 3.2).

2.3Control Cones

The control pins are the select of a Mux, the controls of a Hotmux, the enable of a flop or latch, and the port enables of a memory. Control logic is kept out of data colors because merging a stage's data cone with the cone that gates it is precisely what collapses a forward partitioning into one region. Two closure families are grown with union-find over components:

  • Select closures (when multiplexers act as boundaries): every live multiplexer seeds a component. The walk from a multiplexer follows its control pins and only those data arms that are themselves multiplexers, so multiplexer chains stay together while ordinary data arms remain region inputs. Two multiplexers that read the same select driver pin are joined.
  • Enable closures: every distinct driver of a control pin seeds a component (the control pins of non-multiplexer sinks when multiplexers are grouped with control; of every sink, multiplexer selects included, when multiplexers belong to data colors), and its walk follows all fan-ins.

Reaching a node already owned by another component joins the two components, and so does reading the same primary-input pin. Overlapping select and enable closures therefore form one control group, while groups with distinct primary-input selects stay apart. Walls inside a closure are state elements, large arithmetic (multipliers, dividers, adders over 8 bits) when arithmetic boundaries are enabled, and, when multiplexers belong to data colors, the multiplexers themselves. Wide comparisons and runtime shifts are not walls: a closure that reaches one claims it.

Two refinements follow. Wiring admission (only when multiplexers are grouped with control) adds a node to a group when it only rewires, ties or inverts bits (a bitwise operator with a single variable input, or zero-cost wiring), all its variable inputs come from that group, and one of its fan-outs leads back into the same group; this keeps mux(s, x, x|k) from exposing x and x|k as independent region inputs. Budget splitting partitions a component whose size exceeds min(Γ, Γctrl): its internal edges are sorted by the size of their producer, largest first, and joined Kruskal-style while the union fits. Because weights only grow, one sorted pass leaves no fitting contact between different parts. A group smaller than a floor (fewer than Nmin nodes and at most Γ/64 predicted nodes, or below an optional control floor) is not emitted; its nodes are left for the data walks. Emitted groups receive colors 1..K before any data cone is grown, and data walks never enter a control-owned node.

2.4Data Cones: Roots and Budgeted Backward Walk

Roots are collected in one pass and walked in a second, in a deterministic node order. The root kinds are:

  • Arithmetic cut: a boundary operator (Section 2.9) that no control group claimed is owned by its own color before any walk, seeds its operands, and starts its budget at its own size.
  • Register data input: one root per flop or latch, seeded by its din driver. Clock, reset and initial-value pins never seed a root; enables are control closures (a separate enable root is created only when control cones are disabled).
  • Memory: one anchor color owns the memory node, and one root per port index seeds that port's address, data and enable drivers.
  • Stateful instance: an anchor color owns the instance and one root seeds all its input drivers.
  • Primary output: one root per output port, so output-only glue forms cones instead of singletons.
Algorithm 2 WALK(r): budgeted backward walk of root r
  1. t ← initial budget of r; Q ← seeds of r ▷ explicit stack, epoch-stamped visits
  2. while Q ≠ ∅ do
  3. n ← pop(Q); skip if dead, seeded, visited, control-owned, or a state element
  4. if n is an arithmetic cut then ω(own(n), r) += π(n); continue ▷ contact, never claimed
  5. if t + π(n) > Γ and t > 0 then record overlap with own(n); stop ▷ n is left for another cone
  6. if own(n) = ⊥ then own(n) ← r else ω(own(n), r) += π(n) ▷ first wins; walk through
  7. t ← t + π(n); if t > Γ then stop ▷ a single indivisible node
  8. for each fan-in driver d of n do
  9. if d is a primary-input pin then add zero-weight contacts to the first and last cones that read it
  10. push(Q, d)

Three properties of the walk matter. Ownership is first-wins and disjoint: a cone that reaches a node owned by an earlier cone keeps walking through it and records the shared size as overlap, so ω(a, b) is the predicted size of the logic both cones need. The budget is soft but never grown by a crossing: a walk stops at the first node that would push it over Γ and leaves that node for another cone; only a single indivisible node can exceed Γ by itself. Primary inputs are shared zero-cost leaves: every cone that reads an input pin records a zero-weight contact with the first and with the previous reader (a star plus a chain), which lets cones that share only inputs merge later without materializing a quadratic clique on a high-fan-out input. Zero-cost wiring consumes no budget, since cutting in front of it cannot make it cheaper. When a cone claims a runtime right shift it also claims that shift's constant-mask output slices, so the mapper can demand-narrow the barrel.

2.5Register Placement and Totality

A register joins the color of its data-input driver when that driver is owned, is data (not control), and is neither an arithmetic cut nor a state element: a pipeline stage is the logic plus the register it writes. A register fed by a primary input, another register, a memory, a stateful instance or an arithmetic cut stays a one-node color, because joining it would weld two pipeline stages through the very boundary the algorithm places. The join is also budget-checked against Γ. The remaining unowned nodes are then rooted at the sinks of the uncolored subgraph (reset and clock glue, unreached output glue) and walked, which keeps leftovers in cones rather than singletons. A final fallback roots any node of an isolated combinational cycle. After this phase every live partitionable node has exactly one owner.

2.6Overlap-Driven Merging

The colors and their overlaps form a region graph H: a vertex per color with weight π(C), and an edge per recorded pair with weight ω. The merge repeatedly unites the pair of largest overlap whose union fits the target:

(a*, b*) = arg max(a,b) ∈ E(H) ω(a, b)   subject to   π(a) + π(b) ≤ Γ(1)

Proposition 1 (Single-pass fixpoint). Because ownership is disjoint, π(A ∪ B) = π(A) + π(B) and ω(A ∪ B, C) = ω(A, C) + ω(B, C). Weights only grow under merging, so a pair refused once can never fit later. One pass over a priority queue with lazy invalidation therefore computes the greedy fixpoint of (1), not an approximation of it.

Algorithm 3 Overlap merge with lazy invalidation
  1. push every recorded pair (ω, a, b, version 0) into a max-heap ordered by (ω↓, a↑, b↑)
  2. while heap ≠ ∅ do
  3. (ω, a, b, v) ← pop; skip if a or b is no longer a representative, or v is stale
  4. if π(a) + π(b) > Γ then discard ▷ refused forever (Prop. 1)
  5. s ← merge(a, b) ▷ survivor = larger adjacency; fold the smaller map
  6. for each neighbor n of the dissolved side do bump version(s, n); push (ω(s, n), s, n)

The size test happens at pop time, so a survivor's untouched pairs stay valid although its size grew. Folding the smaller adjacency map into the larger one keeps merges into high-degree hubs, such as a reset cone that touches thousands of colors, from becoming quadratic; the overall cost is O(P log P) for P recorded pairs. The heap order is total, so the result never depends on hash iteration. Zero-weight contacts sort last: shared logic merges before shared wiring or inputs.

2.7Forward Merging Across Registers

The backward merge only unites colors that touch. A register fed by an input or by another register owns no logic and has no recorded pair, and would remain a one-node color. A second phase therefore merges a register's color with the colors that consume its output, using only the budget the backward merge left over: the backward cones are what the mapper optimizes, so they get first claim on Γ. A consumer register qualifies only through its data input; enable, clock, reset and other control pins never qualify, so the phase cannot re-weld data and control cones. Candidates are ordered by the smallest combined size, the dual of the backward phase, and are re-keyed lazily at pop time. In pair mode each (register, consumer color) is one candidate; in all mode (the default) the whole qualifying fan-out is one all-or-nothing candidate. A merged register is re-queued with its new targets, so pipeline chains pack until Γ stops them.

2.8Small-Color Absorption

Γ is a soft target. The walk budget and the merge strand a tail of tiny colors: the remainder of a truncated cone, input-fed registers, output glue. A color is small when

|C| < Nmin  ∧  π(C) ≤ Γ / 64(2)

The second clause keeps a few-node color that holds one heavy operation, such as a wide multiplier a truncated walk left behind; folding several of those together would build an oversized region. Small data colors are processed smallest first. Each is merged into the neighbor that maximizes the lexicographic pair (overlap, number of connecting edges), regardless of the resulting size; a data neighbor is preferred, and a control color is used only when no data neighbor exists (for example a register between two control multiplexers). A survivor that is still small is re-queued. Arithmetic-cut nodes are neither counted nor used as contacts, since the next phase isolates them anyway.

2.9Arithmetic Boundaries and Boundary Profiles

An operator is an arithmetic boundary when it is a multiplier or divider, an adder wider than 8 bits, a magnitude comparison with an operand wider than 8 bits (it lowers to a subtraction), or a runtime shift wider than 8 bits whose value and amount are both non-constant. Constant shifts are wiring and never cut. Three independent switches (arithmetic, comparisons, shifts) decide which operators are boundaries, and a fourth (multiplexers) decides whether multiplexers are grouped with control through select closures (Section 2.3) or left in data colors. The default profile enables all four, which keeps ABC's regions small. A register-to-register profile disables all four, so colors are no longer cut at combinational operators and run register to register; they remain bounded by Γ, and select and enable logic still forms separate control groups unless control cones are disabled. An explicit setting always overrides the profile. The boundary predicate itself does not depend on the control-cone option, but the multiplexer switch acts only when control cones are enabled, and a comparison or shift that a control group claims is not isolated; with control grouping disabled such operators become isolated boundaries.

After merging, every arithmetic boundary operator that is not a member of a control group is moved into a fresh color of its own, together with its constant-mask output slices so the mapper still sees the demanded width; a wide comparison or runtime shift claimed by a select or enable closure stays in that control color. The merge phases therefore fuse the operator's operand cone with its consumers, and the operator itself becomes a separate region that the mapping pass specializes per width (Section 3.4). Before isolation, control colors keep ids 1..K and data colors are renumbered in first-encounter order along a deterministic topological node order; each isolated boundary operator then receives a fresh id above that range, in node order.

2.10Hierarchical Designs

Coloring each definition separately makes every module boundary a region boundary and hides a leaf module's register fan-out behind its output ports. The hierarchy is therefore colored as a virtual flat view (Algorithm 4). A per-occurrence color store lets two instances of the same definition carry different colors. Compact loop bodies stay opaque instances in the flat view and are colored as a single unit, because one implementation serves every iteration. Source-specified regions (block attributes) are walls: their nodes are never walked or merged, keep their colors, and algorithm colors are numbered above them.

Algorithm 4 Virtual flat coloring
  1. if the hierarchy is non-recursive then
  2. F ← flatten(top) into a scratch definition, keeping loop bodies and body-less cells opaque; record an origin (definition, node, instance path) for every cloned node
  3. color F with Algorithm 1; build the coloring descriptor from F
  4. clear old colors; for each colored node f ∈ F: write c(f) to origin(f) ▷ per instance path
  5. delete F
  6. else color each unique definition separately

The descriptor records that the colors were computed on the flat view, so the partitioner flattens again before cutting (Section 3.7) and a color that spans modules becomes one region. Because first-wins ownership can split a later cone into disconnected pieces, the descriptor also states that a color may be disconnected; the partitioner then emits one module per color instead of one per connected component.

Complexity. Preparation and liveness are linear in |V| + |E|; control grouping is too, except for the budget split, which sorts the internal edges of oversized components. No per-cone phase (walks, register placement, merges, absorption) reads the graph's edge lists, which would rescan the out-edges of high-fan-out reset and enable drivers from every cone; only the final isolation step reads the pins of arithmetic-boundary operators, once each. A walk costs one step per visit using epoch stamps; zero-cost wiring may be re-walked once per root, which bounds visits by the number of roots times the wiring size rather than by Γ. The merges cost O(P log P).

3Region Construction

The mapping pass never modifies the input library. It copies the full callee closure of the design, including the interface declarations of body-less cells, into a private library and transforms only that copy. Compact loops are prepared first (Section 3.6); then come dead-logic deletion, selector and memory proofs, arithmetic and memory extraction, and finally the per-bit multiplexer facts, which are applied as each source is cut. Each step prepares the next: dead logic disappears before it costs proofs; constant selectors are resolved before memory proofs so those see simplified enables; arithmetic and memory modules are extracted before partitioning so they remain named instances even in a flattened parent; per-bit multiplexer facts are applied on the final colored source right before it is cut, where they are visible to the mapper of every region.

3.1Soundness Model

All SAT-based steps are combinational: primary inputs, flop outputs and memory read data are free symbols. The per-bit multiplexer proof also cuts latch and instance outputs to free symbols; the solver-based proofs (selectors and memories) instead return no fact when a latch sits in the cone, and for instances the selector proofs descend into bodied callees while a body-less instance (or, for memory proofs, any instance) returns no fact. A proven fact therefore holds for every state, reachable or not, which is conservative and makes each fact safe for the whole design. A proof that is unsupported or runs out of budget yields no fact. Candidates are first filtered by simulating eight deterministic word-level input vectors; the filter can only reject a candidate, never prove one.

3.2Dead-Logic Deletion

Every combinational node without consumers (excluding clock cells) seeds a worklist; deleting it releases its drivers, which are deleted in turn once they lose their last consumer. This removes the unread one-hot multiplexers the compiler keeps for their verification obligations (Section 2.2), together with the cones that only fed them, before any proof or partitioning work is spent on them.

3.3SAT-Based Simplification

Constant selectors.

The candidates are the select of every two-arm multiplexer, every explicit control of a one-hot multiplexer, and the enable of every one-bit-enabled flop. A selector fact states

∀x : ( c(x) ≠ 0 ) = v(3)

Survivors of the simulation filter are decided by an SMT solver (cvc5) at word level, through the same encoder that whole-design equivalence checking uses, descending into called submodules. The resource limit is 256 steps per driver pin in the cone, and a cone over 50,000 pins is left alone, so the budget is deterministic and machine independent. A proven selector is tied to its constant and a never-selected arm is tied to zero; for a one-hot multiplexer the first control proven always-on wins, and later arms and the fallback are zeroed, which is the reference priority semantics. Both rewrites are exact: a pin is tied to the value it always carries, and an arm is zeroed only when no input selects it. Logic that loses its last consumer is swept.

Memory port simplification.

For memories that match the single-clock model the memory cell can represent, four oracles are proven with the same solver: a dead enable, two exclusive enables, an address relation (always equal, or never colliding, when both ports are enabled), and a constant address bit. The transformations, in order, are:

  • removing an address bit proven constant on every port, which halves the depth and re-packs the initial contents;
  • clearing forwarding and undefined-collision entries for read/write pairs that can never collide;
  • removing ports with a dead enable;
  • merging adjacent write ports that have equal addresses and constant lane enables (on overlapping lanes the later port wins), or that have exclusive enables; only adjacent ports merge, since moving a lower-priority write past an intervening conflicting write would change last-writer-wins;
  • merging read ports whose addresses are equal whenever both are enabled, or whose enables are exclusive.

Pair worklists are capped per phase, so a pathological multi-port memory cannot monopolize synthesis; a budget-out keeps the original behavior.

Per-bit multiplexer facts.

Partitioning hides correlations from a region: when a multiplexer's select logic and its arm logic land in different colors, the region that contains the multiplexer sees them as unrelated inputs. For a multiplexer m with arms a0, …, an and selection predicates seli, a fact states that bit b of arm i is constant or equal to another arm's bit whenever arm i is selected:

∀x : seli(x) ⇒ ai[b](x) = κ(x),    κ ∈ { 0, 1, aj[b], ¬aj[b] }(4)

Candidates are generated only for multiplexers whose arm or control logic comes from another color; inside one region a fact does not change the region's function and is left to the mapper. Survivors of the simulation filter become the outputs of one miter per definition, r = seli ∧ (ai[b] ⊕ κ), blasted with the mapper's own operator lowering, except that a one-hot multiplexer is modeled with priority semantics (never assuming exclusivity), and swept by bounded SAT sweeping (&fraig); a fact is proven when its output is swept to constant zero. A fact holds only while its arm is selected, so the rewrite changes only that arm's input of m, never the arm's driver (which has other consumers) and never the multiplexer output. Each arm is rebuilt from maximal runs of bits with the same choice: one run is a single pin (a constant, the other arm's driver, or its complement), and mixed runs become a concatenation of slices of the original arms, constants and complements. The first fact per (arm, bit) wins; a bit that reads another arm's bit is dropped if that bit is itself rewritten, since the rewrite reads the original drivers; and a fact that the arm already satisfies structurally inside the multiplexer's region is skipped, which makes re-application idempotent. New nodes take the multiplexer's color.

Proofs are cached per definition under an exact source descriptor, i.e. node identities, operators, colors and edges, not a hash: a harmless renumbering misses rather than attaching a theorem to a different node. Selector caches additionally record every descended callee, since editing a callee can change a caller's facts. Cache files are written atomically.

3.4Width-Specialized Arithmetic Modules

Every operator of an arithmetic-boundary family (the predicate of Section 2.9) is enclosed in its own definition, whether or not the coloring isolated it; extraction is gated by separate per-family permissions (on by default), not by the boundary switches. The definition is keyed by a descriptor of the operator kind, the width and signedness of every port, the constant operands, its color and the options of its source section; constants are specialized into the body and every other input becomes a port, so equal realizations share one definition. Output widths are narrowed to the width actually demanded by consumers. A shift amount of the form index · stride + bias is recognized and only the index crosses the module boundary, with the affine term rebuilt inside, because an opaque amount would hide the constant-zero low bits that retire most of the barrel shifter. The regions that hold these modules are among the units that post-mapping architecture trials re-map (Section 4.10).

3.5Memory Folding

A memory is either kept as a native instance (implemented by a memory macro) or lowered into flops and decode logic. In the default mode a memory is lowered when its storage is at most 1024 bits or when it has more than three ports, since no macro exists for such an array; larger memories stay native. A lowered memory is generated as RTL, flattened and mapped to flops in isolation, so no parent logic enters the operation; per-lane partial flops are folded back into word flops so that equivalence checking can relate the storage banks. In every mode a memory keeps a named instance boundary.

3.6Compact Loops

A compact loop instance stands for several iterations of one body. Before mapping, the data-parallel part of a body (logic that depends on data inputs but not on the carried values) is extracted into its own definition, mapped once and replicated per iteration. Loops without carried state are mapped once and their occurrences materialized after mapping, so the mapper never bit-blasts N copies of the same logic; loops with carried state are expanded. A preserved loop body is a single synthesis unit.

3.7Cutting the Design into Regions

When the colors were computed on the virtual flat view, the design is flattened again into a scratch definition, keeping extracted arithmetic modules, memory modules and loop bodies as instances; those are decomposed separately. Otherwise each definition is cut in post-order. The per-bit multiplexer facts of Section 3.3 are applied to the source immediately before it is cut.

Definition 2 (Region formation). In flatten mode, or when colors may be disconnected, there is one region per color, Rk = { v : c(v) = k }. Otherwise a region is a connected component of the subgraph induced by one color.

Every driver feeding a sink of region R is classified as a constant, a primary input, an internal edge of R, or a crossing edge, which becomes an output port of the driver's region and an input port of R, deduplicated per driver. Region ports are named reproducibly from structural signatures computed with a Kahn traversal, without recursion or depth cut-offs. The producer signature σp of a pin is anchored at constants, primary inputs and named signals and otherwise mixes the operator shape with the signatures of its operands grouped by operand role, so a+b and b+a agree while no operand changes role. The forward signature σf is the multiset of the pin's uses. An input port is keyed by (σp, σf) and an output port by σp; ports are sorted by key, which fixes the order of ABC's inputs and outputs and makes cold and warm runs produce the same netlist. A region is reuse-eligible only if no port signature is coarse (a cycle) and no two input keys tie: a tie is a genuine automorphism under which a cached body could be stitched onto permuted ports.

A definition with a single region is emitted under its own name and interface. Otherwise it becomes a wrapper holding one unnamed instance per region module <d>__c<k>, so hierarchical names stay transparent to name-based equivalence checking, timing and waveforms. 4Region Technology Mapping

Every region is mapped independently (Algorithm 5). The region is translated to a bit-level network whose inputs and outputs are the region ports, the crossing registers and the native boundaries; ABC optimizes and maps that network; the result is read back as a netlist of library-cell instances. All graph accesses happen under one lock; only the ABC phase, which touches private data, runs concurrently across regions.

Algorithm 5 MAPREGION(R)
  1. compute GE(R), π(R) and the crossing register bits; pick the flow tier and per-region overrides
  2. B ← region budget (Eq. 6); recipe ← resolved flow, options and budget as text
  3. if R is reuse-eligible and the cache holds a structurally identical body with an identical recipe then reuse it; return ▷ §4.8
  4. choose crossing registers; demote registers with an asynchronous reset or a derived clock ▷ §4.3
  5. detect native boundaries: wide wiring, disjoint shift/OR packs, combinational cycles ▷ §4.4
  6. schedule the remaining operators topologically; blast each onto the tape, creating inputs on demand ▷ §4.2
  7. fold enable and synchronous reset into each latch's next state; create outputs for region ports and boundary inputs
  8. replay the tape as an ABC network; install the static boundary environment ▷ §4.6
  9. run the flow with the budget ladder and the area candidate ▷ §4.5
  10. read the mapped network back into cell instances, registers and native boundaries ▷ §4.7

4.2Bit-Level Translation

The region is recorded on a blast tape, a backend-neutral bit-level representation with the node kinds constant, inverter, two-input AND, OR and XOR, primary input, latch and primary output, where every fan-in precedes its node. The gate constructors fold only locally (constants, x ∧ x, x ⊕ x, and so on). The tape is replayed object by object into an ABC netlist in creation order, so the ABC network is identical to one built directly while blasting, and its size is known before any ABC object is allocated.

Demand-driven inputs. A bit of a region input port or of a native boundary output becomes an ABC input only when some operator reads it. A region that reads a small slice of a wide packed port therefore does not create tens of thousands of unused inputs. Bit insertion (set-mask) and concatenations are resolved per demanded bit; bit extraction and sign extension are rewiring expanded over their full output width. The creation order of inputs and outputs is recorded and the read-back pairs ABC's inputs and outputs by position, which ABC preserves through its flows. A driver that cannot be materialized refuses the region; it is never read as a silent constant.

Scheduling. The region's node list is only mostly topological, so operators are blasted from a dependency queue that visits every dependency once, avoiding repeated fixpoint passes on large regions. An adder is built once at the widest width any of its outputs needs, and left shifts and inversions are trimmed to the width their in-region consumers demand.

4.3Sequential Elements

By default flops cross into ABC as latches so the mapper sees the true next-state function. Three kinds of flops stay native boundaries instead. A flop with an asynchronous reset stays native, because the reset is an event: folding it into the data input would let it act only on a clock edge. A flop with a derived clock, i.e. a clock that, traced through single-bit identities, is not a region input or a constant, stays native, and its clock cone is still mapped and reconnected. Level-sensitive latches never cross, because ABC's latch is an edge-triggered register. For every crossing flop the next state is folded as

D = rst′ ? rval : ( en′ ? din : Q ),    en′ = ∨i en[i],   rst′ = ∨i rst[i] ⊕ neg(5)

so a synchronous reset has priority over the enable, matching the generated RTL and the equivalence checker's model, and the result maps to a plain D flip-flop. Multi-stage pipeline registers cross as a chain of latches named like the generated RTL, so equivalence checking can pair the hidden stages. Only a true power-on value (an initial value without a reset) is given to ABC as a latch initial state; a reset-backed register powers on unknown, like the cell it maps to. When the chosen flip-flop cell only provides an inverted output and the bit has no power-on value, the latch stores ¬D under the built-in delay and area flows (not the large-region tier or a user flow), so the mapper absorbs the inversion in its own phase assignment; this encoding is exact only under combinational transformations.

4.4Native Boundaries

Some nodes are cut out of the ABC network and reconnected natively: instances, memories, clock cells, demoted flops, all latches, and native wiring. Native wiring comprises wiring cells of at least 4096 bits (and any concatenation with an over-wide lane), wide disjoint packs of constant shifts combined by OR, exported constant-amount shifts and wide exported packs, and the unpeeled remainder of Kahn peeling over the combinational nodes: every node on a combinational cycle plus all in-region combinational logic downstream of one, up to the next state element or instance. This is a boundary cut rather than an approximation, but that downstream cone is left unmapped. Property markers have no hardware and are dropped. A boundary output enters ABC as inputs only for the bits that an in-region operator reads. A boundary input driven directly by a region input or by a native-wiring node is reconnected natively, which also keeps region-input clocks, resets and enables out of the AIG. Any other boundary input, including one driven by another instance, memory or native register, becomes one ABC output per distinct (driver, bit), shared by every consuming boundary; a pure feed-through buffer is removed on read-back. A region whose outputs are all native receives one unobserved constant output, since ABC cannot process an empty network.

4.5Mapping Flows and the Per-Region Objective

The delay and area flows (Table IV) end in technology mapping with &nf and an output conversion (&put -o) that shares a gate driving several outputs through output-only buffers instead of duplicating it; the read-back removes those buffers again. The large-region flow ends in a plain &put and keeps ABC's duplication. No flow contains retiming, because moving registers would break the register-name correspondence that equivalence checking relies on, lose the attribution of logic to registers, and could change observable latency. Technology mapping uses a unit-delay gate library, so &nf minimizes depth on the smallest cells, and every physical decision is made by gate sizing with the Liberty timing model. A fanout-buffering and down-sizing tail follows every built-in and large-tier flow when fanout buffering is enabled; it is removed when the library has no two-dimensional delay tables, on which the timer cannot run. The timed area candidate ends in a buffering, up-sizing and down-sizing tail instead, and a user-supplied flow gets no tail.

4.6Partition-Boundary Timing Environment

Inside ABC a region's outputs drive no load, its inputs come from ideal drivers, and fanout buffering never builds trees for input fanout. Mapped in isolation, regions therefore report paths that are far shorter than the paths a whole-design timer later finds. Following hierarchical-flow practice, every region is given a boundary environment: an output load and a virtual downstream delay per output, and a driving cell and an arrival time per input. The environment is established in two phases.

Phase A (before mapping) is a pure function of the source graph and the library and does not depend on how other regions were mapped. It is not part of the incremental cache key, so a reused region keeps the netlist mapped under the environment of the run that stored it. With C̄ the mean input capacitance of the library's small single-output cells, an output port p receives

load(p) = ext(p) · C̄ + [ p drives a primary output ] · Cio(8)

where ext(p) counts the sinks outside the region. Every input bit is driven by a stand-in cell: the smallest single-input non-inverting cell whose delay at a load of 4C̄ is within twice the fastest such cell, which excludes delay cells; the inverter is the fallback. The same cell drives the fanout-tree construction for inputs.

Phase B (after all regions are mapped) runs only when a delay target is set, globally or for some region, and the library has delay tables; without a target, which is the default, the Phase A estimates are final. It replaces the estimates with exact values. The mapped regions are imported, and the exact load of every input is computed as the sum of the cell pin capacitances it drives, followed across instance ports and parents; output loads and the real driving cells are resolved the same way. Each region is then re-sized in place under its exact environment within its budget B. With more than one round, output arrivals and input departures are propagated between parent and child regions after every round, since a path through k regions needs k rounds to settle; a single round (the default) makes the loads and drivers exact.

4.7Read-Back

The mapped network is converted back into the region body. Inputs and outputs are paired with the recorded creation order. Every mapped gate becomes an instance of its library cell, and an unreadable gate is a hard error rather than a silent constant. An identity buffer whose output feeds only combinational outputs of the ABC network (region outputs or register data inputs), such as the decoupling buffers the output conversion inserts, is removed by aliasing its output to its input; buffers built for fanout always feed a gate and are kept. For a flip-flop cell with only an inverted output, an inverter at the root of a data input that feeds only that register is dropped, or the root gate is replaced by its cheapest inverting twin (same pins, complemented function) when that costs less than an inverter. Each crossing latch becomes a flip-flop instance whose drive strength is chosen from the register's output fanout, because fanout buffering never buffers a register output; a bit with a power-on value stays a native flop. Register instances carry attributes that let equivalence checking reassemble multi-bit registers. Finally, every mapped gate is attributed to the source location of the first region output whose cone reaches it, in one linear pass.

4.8Incremental Region Reuse

Each region stores its pre-mapping body and its mapped body. A mapped body is reused in place when (i) the new pre-mapping body is structurally identical to the stored one, established by an exact node bijection, and (ii) the resolved recipe, which already contains the substituted per-region budget, is byte-identical. Hashes serve only to discover candidates across renamed regions; the cache is a speedup, never an oracle, so a hash collision cannot become a miscompile. A salt covering the tool sources, the library contents, the register and memory options and the chosen flip-flop cell invalidates all rows when any of them changes. On a hit ABC is not started, and a run in which every region hits also skips the boundary refinement. Stored mapped bodies are written after refinement, so the cache holds the refined netlists.

4.9Parallel Mapping and Memory Admission

Regions are mapped in batches by parallel lanes, each with a private ABC session; results are published in partition order, which keeps the output deterministic. A lane is admitted only if its projected memory fits:

P(R) = 256 MiB + 8 · |library| + 4 KiB · π(R),    admit ⇔ M < L ∧ P(R) < L − M(9)

where M is the larger of the measured footprint and the baseline plus all reservations, and L is the smaller of half the physical memory and the configured process budget. A region that cannot be admitted while no lane is running maps serially. Within a region, the footprint growth is sampled during blasting (counting the ABC objects the tape will create), after the replay, and around every flow step; a region whose growth exceeds the budget is refused rather than allowed to exhaust the host.

4.10Post-Mapping Architecture Trials

For regions below the large tier that contain adders or comparisons, multipliers, or shifts (constant-amount shifts included) whose architecture is automatic, alternative lowerings are evaluated after the whole design is mapped: adder in {ripple-carry, carry-lookahead, carry-skip}, multiplier in {array, tree}, and the two stage orders of the barrel shifter, at most eleven trials per region. Each trial restores the pre-mapping body, re-maps it with the candidate, and re-scores the design: area is summed over every instance of every module, and, under a delay target, a temporary network stitched across combinational region boundaries (registers cut the paths) is timed with the library model. Regions are visited in name order. With a target T, a region is tried only if the longest stitched path through it reaches min(T, current worst delay): any region on a path violating T, or, once T is met, the regions on the current critical path; eligibility is re-checked after every kept candidate. A candidate is kept if its descending-sorted endpoint delays are lexicographically better (0.001 ps tolerance), or, when they tie or the region has no target, if its area is smaller and its sorted endpoint-delay vector is not lexicographically worse; otherwise the previous body is restored.
