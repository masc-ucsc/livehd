Shared Synthesis Flow:
Partition, Optimize and Technology Map

Common region infrastructure and the optimization-to-mapping handoff for ABC and uSyn

1Flow and Organization

The input is a hierarchical word-level netlist graph (LGraph) of LiveHD [1]. Each definition d is a directed graph Gd = (V, E) of typed operations — logic, arithmetic, comparisons, shifts, multiplexers (Mux, and the one-hot Hotmux), wiring, state and instances — whose edges carry a width and a signedness.

Definition 1 (Coloring, region). Let Vp ⊆ V be the partitionable nodes (all but graph IO and constants). A coloring c : Vp → ℕ assigns a color to every partitionable node; the region of color k is Rk = { v : c(v) = k }. Every region becomes a module <d>__c<k> that is optimized and technology-mapped on its own.

A good coloring bounds region time and memory, keeps useful shared logic together, cuts where cones share little, and stays deterministic under edits so synthesis results can be reused. pass.color computes it (Section 2). Backend-independent infrastructure in pass/synth (Section 3) supplies the private design copy, preparation, module and memory handling, region construction, logical translation and cell-netlist read-back. lhd synth selects logical optimization with synth.mapper=abc|usyn (Section 4), then technology-maps the result (Section 5). The ABC optimizer [2] and the native uSyn optimizer share these seams but use different search algorithms; their details live in synth_abc.html and synth_usyn.html. Region results are compiled incrementally in the spirit of LiveSynth and SMatch [3, 4] (Section 3.5).

2Cone Partitioning

A forward partitioning that propagates a region id along fan-out fixes the region shape by connectivity alone: inheriting an id from every fan-in welds a register's data cone to the cone of its enable, and following fan-out re-merges cones where they reconverge. These rules can transitively join otherwise distinct state cones and create a region whose size is governed by reconvergence rather than a chosen resource bound. The cones algorithm grows one backward cone per state input, decides size while it decides shape, and merges cones by the amount of logic they share (Algorithm 1), so boundaries fall where register cones share little logic.

2.1Cost Model

Every size decision uses one unit: π(v), the predicted number of two-input AIG nodes the bit-blaster (Section 3.3) creates for a node, calibrated per operator (Table I); π(S) sums over a set and saturates. The predictor counts the bit-level construction induced by each operator, so region sizing uses a common structural estimate before a backend creates its working network. A color's soft size target is Γ = 30,000 predicted nodes (pass.color.max_gate; 0 yields raw cones without merging). Unlike min-cut hypergraph partitioning [5], the partition is driven by register cones and shared logic, not by cut size.

2.2Control and Data Cones

Logic no output or state reads is dead; it never roots or shapes a cone and finally joins the color of a colored fan-in. The control pins — a multiplexer select or Hotmux control, a register enable, a memory port enable — are grown first into control groups by union-find over their closures, split Kruskal-style when larger than Γ, and given colors 1..K. Data walks never enter them, because merging a stage's data cone with the cone that gates it is what collapses a forward partitioning.

Data roots are register data inputs, memory ports, stateful instances, primary outputs and arithmetic cuts. Each walks backward within a budget (Algorithm 1, line 5): the first cone to reach a node owns it, a later cone walks through it and records the shared size as overlap ω(a, b), and a walk stops before exceeding Γ. Primary inputs are zero-weight shared leaves, so cones sharing only inputs can still merge. A register joins its data-input color unless another boundary feeds it.

2.3Overlap Merging

The colors and their overlaps form a region graph whose vertices weigh π(C) and whose edges weigh ω. The merge repeatedly unites the pair of largest overlap whose union fits:

(a*, b*) = arg max(a,b) ω(a, b)   subject to   π(a) + π(b) ≤ Γ(1)

Proposition 1. Because ownership is disjoint, π(A∪B) = π(A) + π(B) and ω(A∪B, C) = ω(A, C) + ω(B, C). Weights only grow, so a pair refused once never fits later, and one pass over a priority queue with lazy invalidation computes the greedy fixpoint of (1) exactly.

Algorithm 2 Overlap merge with lazy invalidation
  1. push every recorded pair (ω, a, b, version 0) into a max-heap ordered by (ω↓, a↑, b↑)
  2. while heap ≠ ∅ do
  3. (ω, a, b, v) ← pop; skip if a or b is merged away or v is stale
  4. if π(a) + π(b) > Γ then discard ▷ refused forever (Prop. 1)
  5. s ← merge(a, b), folding the smaller adjacency into the larger
  6. for each neighbor n of the dissolved side do bump version(s, n); push (ω(s, n), s, n)

The heap order is total, so the result never depends on hash iteration, and folding the smaller adjacency keeps merges into hubs such as a reset cone from turning quadratic (O(P log P) for P pairs). A second, forward phase merges a register's color with the colors that read its output through their data inputs, smallest union first, using only the budget the backward merge left. Under the flop-to-flop profile the Γ test of line 4 is skipped.

2.4Boundary Profiles: ABC Regions and Flop-to-Flop Regions

An arithmetic boundary is a multiplier, divider, adder with a result over 8 bits, magnitude comparison with an operand over 8 bits, or runtime shift of a non-constant value with a result over 8 bits. Two default profiles (pass.color.mapper=abc|usyn, set from synth.mapper) differ in how they treat boundaries and control. The ABC profile (stop_mux, stop_arith, stop_cmp, stop_shift, ctrl_cones and ware_* on) keeps ABC's regions small: every boundary operator is isolated into its own color (the merges fuse its operand cone with its consumers, and the operator becomes a width-specialized module, Section 3.2), multiplexers group with control, and control groups stay separate. The flop-to-flop profile (the unate mapper's: all of the above off, flop_to_flop on) turns boundaries, control groups and arithmetic modules off and walks every cone to the register boundary, merging all overlapping cones whatever Γ says, so every combinational path lies inside one color and Γ only bounds the forward merge. Any explicit setting overrides either profile.

A non-recursive hierarchy is colored as a virtual flat view, so module boundaries are not forced region boundaries: the design is flattened into a scratch definition, colored, and the colors are written back per instance path; the partitioner flattens again before cutting. An optional synth.reduce step first extracts repeated subgraphs into shared definitions. Every phase except the control split is linear in |V| + |E|.

3The Shared Region Pipeline

pass/synth never modifies the input library: it copies the design's callee closure into a private library and transforms only the copy. The steps are ordered so each prepares the next.

3.1Preparation

Loop bodies are prepared for reuse, and every plain clock cell (division 1, not inverted) is rewritten on the copy into the latch-based clock gate it denotes,

gclk = clk ∧ Latch(din = en, enable = clk, transparent while clk = 0)(2)

so that it maps onto an integrated clock-gate (ICG) cell (Section 3.3); divided or inverted clock cells stay native. Combinational nodes without consumers are then deleted transitively. The pipeline itself proves nothing: proof-backed simplification (pass/satopt: constant selectors, equivalences, observability, per-bit multiplexer facts swept by &fraig [6] with cvc5 [7] for the rest) is an opt-in compile step (pass.satopt=true, off by default) that, when enabled, has already rewritten the graph the mapper receives; see pass/satopt/README.md.

3.2Modules, Memories and the Cut

Under the ABC profile (ware_arith, ware_cmp, ware_shift) every arithmetic-boundary operator is enclosed in its own ware definition keyed by its kind, port widths, signedness, constants and color, so equal realizations share one module; a dynamic word select keeps its affine amount inside the module and only the narrow index on the port. With pass.abc.memory=auto (default) a memory is lowered to flops in isolation when it has at most memory_max_bits (1024) bits or more than three ports; memory=true|false forces either, and a memory written from more than one clock always stays native. The native uSyn path retains memories as barriers, separating storage semantics from combinational optimization. Under ABC, loop bodies without carried state are mapped once and replicated; carry-dependent loops can be unrolled (pass.abc.unroll_carry) after carry-independent logic is lifted into a shared body. Native uSyn keeps compact loops rolled. The shared preparation and reconstruction honor the selected path's loop policy.

The colored source is then cut: one region per color (or per connected component of a color when the colors are local). Every crossing driver becomes an output port of its region and an input port of each reader, deduplicated per driver. Ports are named and ordered by structural signatures from a Kahn traversal (the producer shape with operands grouped by role, and the multiset of uses), so cold and warm runs produce the same network; a region whose input keys tie is not reusable, since a genuine automorphism could stitch a cached body onto permuted ports. A multi-region definition becomes a wrapper of unnamed region instances, which keeps hierarchical names transparent to equivalence checking and timing.

3.3Translation to the Lnet

Each region is translated into an Lnet: a flat network of k-input LUTs numbered densely in topological order, node 0 the constant, with no complemented edges (inversion lives in the tables) and boundary tables of inputs, latches and outputs. The blaster writes a RAW Lnet exactly as it creates logic — lazily created constants, explicit inverters and 2-input AND, OR and XOR, folding only constants and x op x — and records where every output was created, so a backend can replay it object for object. A STRASH rebuild hashes it structurally, folds complemented edges into the tables and drops logic no output reaches.

Inputs are created on demand: a bit of a region port or of a native boundary becomes an input only when an operator reads it, so a region reading a slice of a wide packed port does not create thousands of unused inputs. Operators are blasted from a dependency queue; n-ary operators use balanced trees, adders are ripple-carry, carry-skip or carry-lookahead and multipliers arrays or trees (the architecture only seeds the logic). A register crosses as a latch with its next state folded as

D = rst′ ? rval : ( en′ ? din : Q ),    en′ = ∨i en[i],   rst′ = ∨i rst[i] ⊕ neg(3)

so a synchronous reset has priority over the enable and the result maps to a plain D flip-flop. State that does not fold into D is still mapped onto Liberty cells, but outside the AIG:

  • Asynchronous reset. The register crosses with D = en′ ? din : Q; its reset is traced to a region input (or exported as an extra output) and wired to a clear or preset flop chosen per bit by its reset value.
  • Clock gate. clk ∧ Q of a one-bit latch transparent while clk is low, as in (2), is absorbed into an ICG cell; its enable is exported and the gated clock is read back as an input, so the registers it clocks map to flops clocked by the ICG.
  • Data latch. A level-sensitive latch maps onto a Liberty latch cell per enable polarity, with clear/preset or a folded reset.

Each falls back to a native boundary with a named reason (reset-native, icg-native, latch-native) when the library has no suitable cell or the flow is a user command list. Instances, memories, divided or inverted clocks and other derived clocks, cyclic logic and pure wiring of at least 4096 bits always stay native, reconnected around the mapped logic; a region that is a single constant shift is rebuilt as wiring without a mapper. Only a true power-on value becomes a latch initial state. A logical_state mode, used by pass.usyn, translates every register bit independently of the Liberty file.

3.4The Driver and Backend Seam

The region driver, used by the full ABC path and by the mapping-only provider after native uSyn optimization, owns everything around a mapping (Algorithm 3, Fig. 3): per-region options, the region cache, the translation, the optional region hook, parallel lanes, the read-back and the architecture trials. A backend implements one interface: start and stop a session per lane, contribute its recipe to the cache key, map an Lnet (or the hook's rewrite of it) into a cell netlist — library cells in topological order over the Lnet's boundary, one signal per output, latches with their initial values — and refine and score the stitched design. The region writer turns the cell netlist into the region body, keeping every name equivalence checking relies on (register roots, pipeline stages, aggregate attributes); an identity buffer that only feeds outputs is aliased away, and every gate is attributed to the source location of the first output whose cone reaches it.

Algorithm 3 MAPREGION(R) in the region driver
  1. resolve per-region options; recipe ← backend.plan(R) (+ the hook's recipe)
  2. if R is reusable and the cache holds a structurally identical body with an identical recipe then reuse it; return
  3. L ← blast(R) as a RAW Lnet, with native boundaries ▷ §3.3, memory-admitted
  4. rewrite ← hook(L) if a hook is set else none ▷ e.g. mapping-only (tmap), or refused
  5. cells ← backend.map(L, rewrite) ▷ §4–5
  6. write cells into the region body; store pre- and post-mapping bodies in the cache

3.5Reuse and Parallel Lanes

A mapped body is reusable when the new pre-mapping body is structurally identical to the stored one, by an exact node bijection, and the resolved recipe agrees. Hashes index candidate artifacts; structural matching and recipe checks authorize reuse. Producer versions and relevant library contents invalidate artifacts when their assumptions change. Independent regions use private backend sessions and are published in deterministic partition order. Admission accounts for projected worker storage, outstanding reservations and process memory before concurrent work starts; a region exceeding its time or memory allowance is refused.

4Optimize Before Technology Mapping

Choose the logical optimizer first. Selecting ABC or uSyn determines both the coloring profile and the logical optimization path. Both paths use the preparation, partitioning and logical translation of Sections 2–3, then realize their selected logic with a technology mapper. ABC being used for the final cell mapping does not imply that ABC did the preceding Boolean optimization.

The detailed algorithms follow parallel descriptions in ABC synthesis and uSyn synthesis. Shared here means the surrounding region infrastructure and the optimization-to-mapping contract; each optimizer retains its own algorithms and acceptance objective.

Algorithmic choices at the optimization boundary

The optimizer choice determines the region profile, the network representation and the selection objective. ABC uses combinational rewriting and covering, with an area-oriented or delay-oriented recipe. uSyn uses exact bounded endpoint realization followed by residual optimization and complete CMOS topology extraction. Native preselection cleanup, post-expansion cleanup and multi-representation exploration are independently selectable stages; mapped profile selection compares complete combinations of these stages.

Technology mapping is a separate choice. A native logical CMOS network may be retained directly, or passed to a provider for cell covering, buffering and sizing. Compile-time proof-backed simplification precedes either optimizer and does not change the distinction between native search and technology mapping. The public selector is synth.mapper=abc|usyn; command syntax and implementation settings belong to the ABC and uSyn references.

5Technology Mapping and Physical Budgets

Technology mapping covers the selected Boolean network with legal library cells. Buffering and sizing then repair fanout and spend or recover physical slack; partition-boundary refinement replaces isolated-region estimates with the loads and drivers of the stitched design. The shared driver and writer own the handoff and reconstruction (Section 3.4). The ABC provider implements the cell covering and physical algorithms described in ABC §4–6.

In the full ABC path, the backend's built-in recipe performs logic optimization before &nf. In the uSyn path, pass/synth/tmap.hpp accepts a complete native CMOS design and selects a mapping-only region hook: strash; &get -n; &nf; &put -o, with applicable buffering, sizing and mapping-only slack recovery. It runs neither FRAIG/don't-care synthesis nor ABC's alternate area or arithmetic recipes. Native topology choices have already been extracted; no choice classes cross this seam.

Both mapped paths use the same kinds of physical constraints: a delay target, launch/capture register overhead, a fanout limit, slack-to-area recovery and a partition-boundary environment. Logic levels and native cost proxies guide logical search; library cell area and timing guide covering and physical refinement. The handoff preserves source-state correspondence so the reconstructed netlist can be checked independently.

ABC mapped regions and uSyn logical selections/mapped realizations have separate reuse identities. A reusable artifact must agree with the current input structure, effective transformation recipe, producer version and all library or timing assumptions that affect it. Separate identities allow physical remapping without repeating a library-independent native search.
