Cone Partitioning and
Region-Based Technology Mapping

Methodology of LiveHD synthesis: pass.color synth, the shared region pipeline of pass/synth, and the ABC backend of pass.abc

1Flow and Organization

The input is a hierarchical word-level netlist graph (LGraph). Each definition d is a directed graph Gd = (V, E) of typed operations — logic, arithmetic, comparisons, shifts, multiplexers (Mux, and the one-hot Hotmux), wiring, state and instances — whose edges carry a width and a signedness.

Definition 1 (Coloring, region). Let Vp ⊆ V be the partitionable nodes (all but graph IO and constants). A coloring c : Vp → ℕ assigns a color to every partitionable node; the region of color k is Rk = { v : c(v) = k }. Every region becomes a module <d>__c<k> that is optimized and technology-mapped on its own.

A good coloring bounds every region's time and memory, keeps logic that benefits from joint optimization together, cuts where cones share little, and is deterministic and stable under edits so mapped regions can be reused. pass.color computes it (Section 2). Everything between the colored graph and a mapped region is shared, backend-independent infrastructure in pass/synth (Section 3): a private copy of the design, simplification, extraction of arithmetic and memory modules, the cut into regions, the translation of each region into a flat LUT network (the Lnet), and the read-back of a mapped cell netlist. A backend maps one Lnet to cells and owns whatever whole-design sizing it offers; pass/abc is the ABC backend (Section 4) and is the only code that calls ABC. Unate synthesis (pass.usyn) is a region hook on the same pipeline that covers each region with domino gates before handing it to the ABC backend.

2Cone Partitioning

A forward partitioning that propagates a region id along fan-out fixes the region shape by connectivity alone: inheriting an id from every fan-in welds a register's data cone to the cone of its enable, and following fan-out re-merges cones where they reconverge. On a flattened processor either rule put more than 99% of the nodes into one region. The cones algorithm grows one backward cone per state input, decides size while it decides shape, and merges cones by the amount of logic they share (Algorithm 1), so boundaries fall where register cones share little logic.

2.1Cost Model

Every size decision uses one unit: π(v), the predicted number of two-input AIG nodes the bit-blaster (Section 3.3) creates for a node, calibrated per operator (Table I); π(S) sums over a set and saturates. Gate equivalents mispredict mapped cells by a median factor of 1.8 in both directions; π over-counts by a stable factor and tracks ABC's runtime. A color's soft size target is Γ = 30,000 predicted nodes.

2.2Control and Data Cones

Logic no output or state reads is dead; it never roots or shapes a cone and finally joins the color of a colored fan-in. The control pins — a multiplexer select or Hotmux control, a register enable, a memory port enable — are grown first into control groups by union-find over their closures, split Kruskal-style when larger than Γ, and given colors 1..K. Data walks never enter them, because merging a stage's data cone with the cone that gates it is what collapses a forward partitioning.

Data roots are register data inputs, memory ports, stateful instances, primary outputs and arithmetic cuts. Each walks backward within a budget (Algorithm 1, line 5): the first cone to reach a node owns it, a later cone walks through it and records the shared size as overlap ω(a, b), and a walk stops before exceeding Γ. Primary inputs are zero-weight shared leaves, so cones sharing only inputs can still merge. A register joins its data-input color unless another boundary feeds it.

  2. Mark dead nodes: Vp minus the backward closure of outputs and state
  3. Grow control groups over select and enable closures; colors 1..K

  5. walk back from r: claim unowned nodes, add shared ones to ω(own(n), r), stop past Γ
  6. Place registers into their data-input color; root and walk leftovers ▷ totality
  7. Overlap merge (Algorithm 2); forward merge across registers with the budget left
  8. Absorb colors with |C| < Nmin and π(C) ≤ Γ/64 into their largest-overlap neighbor
  9. Renumber deterministically; isolate every arithmetic boundary no control group claims ▷ σ

2.3Overlap Merging

The colors and their overlaps form a region graph whose vertices weigh π(C) and whose edges weigh ω. The merge repeatedly unites the pair of largest overlap whose union fits:

(a*, b*) = arg max(a,b) ω(a, b)   subject to   π(a) + π(b) ≤ Γ(1)

Proposition 1. Because ownership is disjoint, π(A∪B) = π(A) + π(B) and ω(A∪B, C) = ω(A, C) + ω(B, C). Weights only grow, so a pair refused once never fits later, and one pass over a priority queue with lazy invalidation computes the greedy fixpoint of (1) exactly.

Algorithm 2 Overlap merge with lazy invalidation
  1. push every recorded pair (ω, a, b, version 0) into a max-heap ordered by (ω↓, a↑, b↑)
  2. while heap ≠ ∅ do
  3. (ω, a, b, v) ← pop; skip if a or b is merged away or v is stale
  4. if π(a) + π(b) > Γ then discard ▷ refused forever (Prop. 1)
  5. s ← merge(a, b), folding the smaller adjacency into the larger
  6. for each neighbor n of the dissolved side do bump version(s, n); push (ω(s, n), s, n)

The heap order is total, so the result never depends on hash iteration, and folding the smaller adjacency keeps merges into hubs such as a reset cone from turning quadratic (O(P log P) for P pairs). A second, forward phase merges a register's color with the colors that read its output through their data inputs, smallest union first, using only the budget the backward merge left.

2.4Boundary Profiles: ABC Regions and Flop-to-Flop Regions

An arithmetic boundary is a multiplier, divider, adder over 8 bits, magnitude comparison over 8 bits or runtime shift over 8 bits. Two default profiles, chosen by the mapper, differ in how they treat boundaries and control. The ABC profile keeps ABC's regions small: every boundary operator is isolated into its own color (the merges fuse its operand cone with its consumers, and the operator becomes a width-specialized module, Section 3.2), multiplexers group with control, and control groups stay separate. The flop-to-flop profile (the unate mapper's) turns boundaries, control groups and arithmetic modules off and walks every cone to the register boundary, merging all overlapping cones whatever Γ says, so every combinational path lies inside one color and Γ only bounds the forward merge. Any explicit setting overrides either profile.

A non-recursive hierarchy is colored as a virtual flat view, so module boundaries are not forced region boundaries: the design is flattened into a scratch definition, colored, and the colors are written back per instance path; the partitioner flattens again before cutting. Every phase except the control split is linear in |V| + |E|.

3The Shared Region Pipeline

pass/synth never modifies the input library: it copies the design's callee closure into a private library and transforms only the copy. The steps are ordered so each prepares the next.

3.1Simplification

Combinational nodes without consumers are deleted transitively, then the satopt engine (pass/satopt) runs its synthesis profile. Every proof is combinational: inputs, register outputs and memory read data are free symbols, so a proven fact holds in every state; an unsupported or out-of-budget proof yields no fact. Word-level simulation (corner and seeded random patterns, plus every solver counterexample) only nominates candidates. cvc5 decides constant selectors (a Mux select, a Hotmux control, a one-bit flop enable), constant values and memory port relations, each rewritten exactly. Per-bit multiplexer facts recover correlations a partition hides when a select and its arms land in different colors:

∀x : seli(x) ⇒ ai[b](x) = κ(x),    κ ∈ { 0, 1, aj[b], ¬aj[b] }(2)

Each candidate becomes one output seli ∧ (ai[b] ⊕ κ) of a single proof Lnet, which the backend sweeps (ABC: &fraig); a proven fact rewrites only that arm's input. Proofs are cached per definition under an exact source descriptor, the code identity and the proof options, and one deterministic budget bounds the whole engine. Its optional stages (equivalence, complement, observability, resubstitution) and the compile-time profile are described in pass/satopt/README.md.

3.2Modules, Memories and the Cut

Under the ABC profile every arithmetic-boundary operator is enclosed in its own definition keyed by its kind, port widths, signedness, constants and color, so equal realizations share one module. A memory stays a native instance unless it has at most 1024 bits or more than three ports, in which case it is lowered to flops in isolation. Loop bodies without carried state are mapped once and replicated.

The colored source is then cut: one region per color (or per connected component of a color when the colors are local). Every crossing driver becomes an output port of its region and an input port of each reader, deduplicated per driver. Ports are named and ordered by structural signatures from a Kahn traversal (the producer shape with operands grouped by role, and the multiset of uses), so cold and warm runs produce the same network; a region whose input keys tie is not reusable, since a genuine automorphism could stitch a cached body onto permuted ports. A multi-region definition becomes a wrapper of unnamed region instances, which keeps hierarchical names transparent to equivalence checking and timing.

3.3Translation to the Lnet

Each region is translated into an Lnet: a flat network of k-input LUTs numbered densely in topological order, node 0 the constant, with no complemented edges (inversion lives in the tables) and boundary tables of inputs, latches and outputs. The blaster writes a RAW Lnet exactly as it creates logic — lazily created constants, explicit inverters and 2-input AND, OR and XOR, folding only constants and x op x — and records where every output was created, so a backend can replay it object for object. A STRASH rebuild hashes it structurally, folds complemented edges into the tables and drops logic no output reaches.

Inputs are created on demand: a bit of a region port or of a native boundary becomes an input only when an operator reads it, so a region reading a slice of a wide packed port does not create thousands of unused inputs. Operators are blasted from a dependency queue; n-ary operators use balanced trees, adders are ripple-carry, carry-skip or carry-lookahead and multipliers arrays or trees (the architecture only seeds the logic). A register crosses as a latch with its next state folded as

D = rst′ ? rval : ( en′ ? din : Q ),    en′ = ∨i en[i],   rst′ = ∨i rst[i] ⊕ neg(3)

so a synchronous reset has priority over the enable and the result maps to a plain D flip-flop. A flop with an asynchronous reset or a derived clock, every level-sensitive latch, every instance and memory, and wide or cyclic wiring stay native boundaries, reconnected around the mapped logic. Only a true power-on value becomes a latch initial state.

3.4The Driver and Backend Seam

The region driver owns everything around a mapping (Algorithm 3, Fig. 3): per-region options, the region cache, the translation, the optional region hook, parallel lanes, the read-back and the architecture trials. A backend implements one interface: start and stop a session per lane, contribute its recipe to the cache key, map an Lnet (or the hook's rewrite of it) into a cell netlist — library cells in topological order over the Lnet's boundary, one signal per output, latches with their initial values — and refine and score the stitched design. The region writer turns the cell netlist into the region body, keeping every name equivalence checking relies on (register roots, pipeline stages, aggregate attributes); an identity buffer that only feeds outputs is aliased away, and every gate is attributed to the source location of the first output whose cone reaches it.

Algorithm 3 MAPREGION(R) in the region driver
  1. resolve per-region options; recipe ← backend.plan(R) (+ the hook's recipe)
  2. if R is reusable and the cache holds a structurally identical body with an identical recipe then reuse it; return
  3. L ← blast(R) as a RAW Lnet, with native boundaries ▷ §3.3, memory-admitted
  4. rewrite ← hook(L) if a hook is set else none ▷ unate synthesis
  5. cells ← backend.map(L, rewrite) ▷ §4
  6. write cells into the region body; store pre- and post-mapping bodies in the cache

3.5Reuse and Parallel Lanes

A mapped body is reused in place when the new pre-mapping body is structurally identical to the stored one, by an exact node bijection, and the resolved recipe (flow, options, per-region budget and hook settings) is byte-identical. Hashes only find candidates; the cache is never an oracle. Code salts in three layers — pass/synth with the passes it builds on, then each backend, then the hook — invalidate rows when the code that produced them changes. Regions are mapped by parallel lanes, each with its own backend session, and published in partition order, so the output does not depend on the number of lanes. A lane is admitted only if its projected memory fits below half of physical memory, and a region whose measured growth would exhaust the host is refused.

4ABC as the Mapping and Sizing Backend

The ABC backend replays the RAW Lnet into an ABC netlist in creation order, so the network is object-for-object the one the blaster would have built directly and its size is known before any ABC object exists. Region inputs and outputs are paired with the Lnet's creation order, which ABC preserves through its flows.

4.1Flows

The delay and area flows (Table II) end in &nf on a unit-delay gate library, so the mapper minimizes depth on the smallest cells and every physical decision is left to gate sizing with the Liberty timing model. No flow retimes: moving registers would break the register-name correspondence of equivalence checking and could change latency. &put -o shares a gate that drives several outputs through output-only buffers, which the read-back removes again.

4.2Per-Region Budget

With a delay target T, a region with registers must also absorb the launch clock-to-output delay and the capture setup time, which ABC's combinational timer does not see. The region budget is

B = ⌊T − m⌋ if R has registers,   ⌊T⌋ otherwise,    m = tclk→Q + tsetup of the flip-flop cell(4)

A budget is not "as fast as possible": after the flow, a budget ladder spends measured slack on area (Algorithm 4), with an area-recovery remap only when the slack s = 100(B/d − 1) is at least 25% (relaxation min(s, 200)). Every flow option can be overridden per color from source annotations or the command line; an unknown key is an error.

Algorithm 4 Budget ladder and area candidate; d(N), a(N) = timed delay and area
  1. if the area candidate applies then N0 ← copy of the unmapped network
  2. N ← flow(network); if no budget then return N
  3. if d(N) > B then size up and down within B; if still late, size without a bound
  4. else if the flow is remappable and s ≥ 25 then undo the map; remap with relaxation; buffer; size down within B
  5. if N0 exists and d(N) ≤ B then NA ← area flow(N0); keep it iff d(NA) ≤ B and a(NA) < a(N)

4.3Partition-Boundary Environment

Mapped in isolation, a region's outputs drive no load and its inputs come from ideal drivers, so regions report paths far shorter than a whole-design timer finds. Every region therefore gets a boundary environment in two phases. Phase A, before mapping, is a pure function of the source graph and the library: an output port p sees

load(p) = ext(p) · C + [p drives a primary output] · Cio(5)

where ext(p) counts sinks outside the region and C is the mean input capacitance of small cells, and every input is driven by a stand-in small buffer that also drives the fanout trees built for inputs. Phase B runs once every region is mapped, when a delay target exists and the library has NLDM tables: the exact load of every crossing net (the sum of the pin capacitances it drives, followed across instance ports) and its real driving cell replace the estimates, and each region is re-sized in place within its budget. Further rounds propagate arrivals across the hierarchy; one round makes the loads and drivers exact.

4.4Read-Back

ABC's mapped network is converted into the backend-neutral cell netlist: every gate is a cell instance with its fanins in pin order, an unreadable gate is a hard error, and a flop cell with only an inverted output absorbs the inversion (the latch stores ¬D under the built-in flows, or the root gate is swapped for its inverting twin). Each crossing latch becomes a flip-flop sized from its output fanout, because fanout buffering never buffers a register output. The region writer (Section 3.4) does the rest.

4.5Architecture Trials

After the whole design is mapped, regions with automatic adders, multipliers or shifters re-map their pre-mapping body under the alternative lowerings (at most eleven trials) and re-score the design: area over every instance and, under a delay target, the endpoint delays of a network stitched across region boundaries. A candidate is kept if its sorted endpoint delays are lexicographically better, or if they tie and its area is smaller.
