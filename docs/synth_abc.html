AIG rewriting, LUT and SOP restructuring, structural choices and physical sizing

1Motivation and Contribution

ABC [1] optimizes each synthesis region as a shared Boolean network, then covers the selected network with standard cells. Different factorizations of the same function expose different mapping cuts: a small AIG can map poorly, while a larger but shallower alternative can meet a delay target. LiveHD combines ABC's established rewriting, structural-choice and LUT/SOP algorithms with bounded regions, stable source-state correspondence, incremental reuse and a partition-boundary timing environment.

This page follows the same progression as the uSyn description: network construction, logical optimization, candidate selection, realization, mapping trials and resource control. Coloring, preparation, the Lnet interface and read-back ownership belong to the shared synthesis flow (cited as [S §n]). The ABC reference documents implementation options.

2Regions and the Logical Network

The ABC coloring profile builds Γ-bounded regions and separate arithmetic modules [S §2.4]. The shared blaster translates a region into a RAW Lnet [S §3.3]; the backend replays it into an ABC netlist object-for-object in creation order. ABC preserves the input/output order used to reconnect packed ports and named register bits. Memories retained by the memory policy and unsupported state/control structures stay behind native boundaries [S §3.2–3.3].

The working representation is an AIG, a directed acyclic graph of two-input AND nodes and complemented edges. Structural hashing merges identical nodes. XORs, muxes and arithmetic are represented by their Boolean expansions; the imported structure is a starting point for synthesis, not a prescribed cell topology. Built-in flows preserve register boundaries and do not retime or merge registers, keeping the state correspondence used by independent LEC.

3Logic Optimization and Network Topologies

The delay and area flows (Table I) combine AIG rewriting and choice computation [2, 3], don't-care resynthesis [4] and SOP balancing [5], and end in &nf on a unit-delay gate library, so the mapper minimizes depth on the smallest cells and every physical decision is left to gate sizing with the Liberty timing model. No built-in flow retimes: moving registers would break the register-name correspondence of equivalence checking and could change latency. &put -o shares a gate that drives several outputs through output-only buffers, which the read-back removes again.

AIG, LUT, SOP and structural choices

The area recipe uses bounded FRAIG reduction, dc2 resynthesis and &dch structural choices before covering. The delay recipe alternates AIG restructuring with 6-input LUT mapping (&if) and local don't-care resynthesis (&mfs), saves competing networks, and uses &load to recover the selected result. &sopb exposes a balanced SOP topology between the two rounds. LUTs here are temporary logic-optimization units; the final output is a standard-cell network.

Structural choices retain equivalent AIG implementations so mapping can explore cuts beyond one factoring [3]. This differs from uSyn's native extraction: uSyn picks a complete XAG before requesting mapping, whereas ABC's choice-aware flow carries alternatives into its covering stage. Neither method guarantees a globally optimal mapped network.

Algorithm 1 Optimize and map one ABC region
  1. replay the RAW Lnet; resolve the region recipe, physical budget and boundary environment
  2. preserve the unmapped network if a timed area candidate is eligible
  3. choose area, delay, large-region or explicit user flow (Table I)
  4. run its logical restructuring; retain/select equivalent alternatives within that recipe
  5. cover with &nf; buffer and size under the applicable physical budget
  6. compare the timed area candidate when eligible; return a complete cell netlist

Recipe selection. The requested objective selects an area-oriented or delay-oriented recipe. A timed area candidate may compete with the delay realization when both can be compared under the same physical budget. The mapping-only provider uses the covering and physical stages after native uSyn synthesis, without selecting an additional ABC Boolean-optimization recipe.

4Candidate Selection and Per-Region Budget

With a delay target T, a region with registers must also absorb the launch clock-to-output delay and the capture setup time, which ABC's combinational timer does not see. The region budget is

B = ⌊T − m⌋ if R has registers,   ⌊T⌋ otherwise,    m = tclk→Q + tsetup of the flip-flop cell (reg_margin=auto)(1)

The ladder needs a tool-owned flow, an NLDM library and B > 0; the area candidate additionally needs the built-in flow, a region below large_ge and area_flow ≠ none. A budget is not "as fast as possible": after the flow, a budget ladder spends measured slack on area (Algorithm 2), with an area-recovery remap only when the slack s = 100(B/d − 1) is at least 25% (relaxation min(s, 200)). Each region resolves its objective and resource limits before candidate construction, so competing recipes share a consistent comparison context.

Algorithm 2 Budget ladder and area candidate; d(N), a(N) = timed delay and area
  1. if the area candidate applies then N0 ← copy of the unmapped network
  2. N ← flow(network); if no budget then return N
  3. if d(N) > B then size up and down within B; if still late, size without a bound
  4. else if the flow is remappable and s ≥ 25 then undo the map; remap with relaxation; buffer; size down within B; repair by up/down sizing if late
  5. if N0 exists and d(N) ≤ B then NA ← area flow(N0); keep it iff d(NA) ≤ B and a(NA) < a(N)

5Mapped Realization and Read-Back

ABC's mapped network is converted into the backend-neutral cell netlist: every gate is a cell instance with its fanins in pin order, an unreadable gate is a hard error, and a flop cell with only an inverted output absorbs the inversion (the latch stores ¬D under the built-in flows, or the root gate is swapped for its inverting twin). Each crossing latch becomes a flip-flop sized from its output fanout, because fanout buffering never buffers a register output; the clear/preset flops, ICGs and latch cells of [S §3.3] are emitted from the library's state-cell ladders, and per-bit cells keep the names reg[i] that equivalence checking matches. The region writer ([S §3.4]) does the rest.

Standard-cell covering and physical sizing have different objectives: the unit-delay gate library guides logic depth, while Liberty NLDM surfaces guide buffering, drive strength and the physical budget. Output-only identity buffers are aliased by the shared writer; functional cells and source register roots remain explicit. The same mapping/read-back machinery serves the uSyn provider with Boolean synthesis and ABC's second area recipe disabled [S §5].

6Partition-Boundary Environment

Isolated-region mapping omits crossing-net loads and input drive constraints. To account for these dependencies without requiring simultaneous mapping of all regions, the method supplies a boundary environment in two phases. Phase A, before mapping, derives estimates from the source graph and library: an output port p sees

load(p) = ext(p) · C + [p drives a primary output] · Cio(2)

where ext(p) counts sinks outside the region and C is the mean input capacitance of small cells, and every input is driven by a stand-in small buffer that also drives the fanout trees built for inputs. Phase B runs once every region is mapped, when a delay target exists and the library has NLDM tables: the exact load of every crossing net (the sum of the pin capacitances it drives, followed across instance ports) and its real driving cell replace the estimates, and each region is re-sized in place within its budget. Further rounds propagate arrivals across the hierarchy; one round makes the loads and drivers exact. Phase B is skipped when every region was reused.

7Technology Mapping and Architecture Trials

After the whole design is mapped, regions with automatic adders, multipliers or shifters (and wide comparisons) re-map their pre-mapping body under the alternative lowerings (at most eleven trials: 3 adders × 2 multipliers × 2 barrels, minus the baseline) and re-score the design: area over every instance and, under a delay target, the endpoint delays of a network stitched across region boundaries. Under a target only regions on the worst stitched path are tried. A candidate is kept if its sorted endpoint delays are lexicographically better (differences below 0.1% tie), or if they tie and its area is smaller. Because every trial re-scores the whole design, the step is skipped when the design exceeds ware_max_cells (200,000 mapped cells) and stops at the first time or memory refusal; regions above large_ge are not tried. Trials reuse retained pre-mapping snapshots (bounded per region and in total) and their own cache rows, never the baseline's. The tmap provider turns trials off.

8Budgets, Reuse and Determinism

The shared driver [S §3.5] reuses mapped regions only when both the input structure and effective recipe agree. Library contents, producer salts, state-cell selection, boundary settings and physical budgets participate in identity. Parallel lanes use private ABC sessions; translation, cache access and graph publication remain serialized, with results published in partition order.

Memory admission and configured time limits bound region execution and whole-design trials. Large regions take the shorter flow of Table I and do not receive architecture trials or the second area candidate. A refusal or unsupported read-back is a failed mapping, not a successful partial netlist. Built-in synthesis uses bounded ABC proof work; the reconstructed netlist retains state correspondence for independent whole-design equivalence checking.

9Positioning Relative to Prior Work

DAG-aware rewriting [2], structural choices [3], don't-care resynthesis [4] and SOP balancing [5] supply the logic algorithms. LiveHD's organization puts them behind a backend-neutral region interface and adds stable partitioning, reuse, boundary refinement and whole-design architecture evaluation. The native uSyn alternative shares that infrastructure but optimizes register-rooted endpoint functions and residual CMOS logic before invoking mapping only. Their search units, costs and candidate-selection points differ [S §4].
