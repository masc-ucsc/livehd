How to read this page — what the three columns mean, and the four verdict states

The verdict column has four states, not two. better / worse is a move past the epsilon in the direction this page knows the metric runs; noise is inside it; and unclassified means this page has no direction rule for that metric — the delta is shown and deliberately NOT judged, because a guessed direction paints a regression green. Add the name to LOWER_IS_BETTER / HIGHER_IS_BETTER in bench/ledger.py to give it a verdict.

What the three columns mean

full
— Every cache is off (the one switch lhd.incremental=false covers the compile, pass.abc and formal caches), every output directory fresh. This is what the flow costs with no incremental machinery at all: the honest denominator.
cold
— Caches on, every directory still fresh: the same work as full plus the cost of populating the caches. The difference is the price of admission for incrementality, charged on every clean build.
incremental
— The identical command again over that workdir, after a comment-only touch to the source. Nothing semantic changed, so every content-keyed cache must hit. This is the number the loop exists to move.

Where a phase has no cache off-switch today, full and cold run the same command and are expected to match within noise — that is a measurement, not redundancy.

1. Wall clock — full vs cold vs incremental

incr speedup = cold / incremental: what the machinery buys on a rebuild. cache cost = (cold − full) / full: what it charges on a first run — flagged past +5%. A cell reading "-" is a mode that was not run; it is never a zero. A mode that did not pass is shown but never used: its wall clock is the time to a crash, not the time to an answer, so both derived columns read "-".

load is the 1-minute run queue while the three modes ran, highest of the three. It is not a result — it is how much to trust the row. The control probe is single-threaded and cannot see this: one desktop app pinning one core leaves the control at 36 ms while tripling a parallel host C++ build, which is exactly what happened during the first sitting of this page. A load well above the core count means the absolute milliseconds are inflated; the ratio columns, measured back to back, survive it better than the raw cells do.
