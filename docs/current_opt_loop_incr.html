How to read this page — full, cold, no-change, edit, and the speedup denominator

What the four timing columns mean

full
— Every cache is off (the one switch lhd.incremental=false covers the compile, pass.abc, pass.opentimer, and formal caches), every output directory fresh. This is what the flow costs with no incremental machinery at all: the honest denominator.
cold
— Caches on, every directory still fresh: the same work as full plus the cost of populating the caches. The difference is the price of admission for incrementality, charged on every clean build.
no-change incremental
— The identical command again over that workdir, with identical source or after a comment-only touch. Nothing semantic changed, so every content-keyed cache must hit. This is the number the loop exists to move.
one-file edit
— One small semantic edit, built over the same warm workdir. Only work affected by that file should be redone.

Both speedups use full as their denominator: full / no-change and full / edit. The cold incremental sample is shown to expose cache-population cost, but it is never the denominator of a displayed speedup.

The Compile only table is the dedicated lhd compile incremental benchmark. Synthesis − STA is compile + color + ABC and excludes OpenTimer. In the edit-only colors changed column, simulation uses the number of rewritten simulator units and synthesis uses ABC cache misses (the colors resynthesized).

Where a phase has no cache off-switch today, full and cold run the same command and are expected to match within noise — that is a measurement, not redundancy.
