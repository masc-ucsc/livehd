Compile iteration and runtime diagnosis

The initial LLVM implementation emitted one native object and one C++ wrapper per color. Removing the wrappers was insufficient: matched-filter still retired 38.31 billion instructions versus Slop's 23.41 billion. A direct scalar ABI reduced that to 30.55 billion, identifying the remaining per-color call boundary. Full LTO proved the opportunity (about 4.0 seconds), but system LLVM 19 cannot read lhd's LLVM 22 bitcode. The embedded-version helper now performs only the necessary per-module bitcode link, always-inline pass, bounded scalar cleanup, and native lowering.

Likely/unlikely annotations are not the missing lever. The slow all-LLVM DINO binary missed only 0.38% of branches; forcing short-circuit wide comparisons removed 4.6 billion instructions but did not improve wall time. Wide arbitrary-width colors remained slower, so LLVM mode now selects only scalar single-output regions with demonstrated amortization and falls back to Slop elsewhere. For the inverse direction, rebuilding matched-filter's hot Slop TU at -O3 measured 4.70 / 4.72 / 4.71 seconds versus -O2's 4.68 / 4.67 / 4.79—no retained gain. Slop already carries [[likely]] on its hot equality/update paths.

How to read this page — what the three columns mean, and the four verdict states

The verdict column has four states, not two. better / worse is a move past the epsilon in the direction this page knows the metric runs; noise is inside it; and unclassified means this page has no direction rule for that metric — the delta is shown and deliberately NOT judged, because a guessed direction paints a regression green. Add the name to LOWER_IS_BETTER / HIGHER_IS_BETTER in bench/ledger.py to give it a verdict.

What the three columns mean

full
— Every cache is off (the one switch lhd.incremental=false covers the compile, pass.abc, pass.opentimer, and formal caches), every output directory fresh. This is what the flow costs with no incremental machinery at all: the honest denominator.
cold
— Caches on, every directory still fresh: the same work as full plus the cost of populating the caches. The difference is the price of admission for incrementality, charged on every clean build.
incremental
— The identical command again over that workdir, after a comment-only touch to the source. Nothing semantic changed, so every content-keyed cache must hit. This is the number the loop exists to move.

Where a phase has no cache off-switch today, full and cold run the same command and are expected to match within noise — that is a measurement, not redundancy.
