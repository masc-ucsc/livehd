How to read the defaults. “On” means that the feature runs when placement is enabled, the phase runs and all its conditions are true. “Off” means that you can enable the feature at that point in the flow. “Inactive”, “not scheduled” and “skipped” show a gate in the current code. These words do not mean that the algorithm cannot be useful at that point. All phases share many controls. Because of this, you cannot set these controls for one phase only. A weight with a zero default stays zero in this reference. To enable it, you must select a positive value, because this page does not give a recommended value.

All short option names on this page start with synth.place.. The only exception is place, which is synth.place itself. For example, to set local_density_weight, use --set synth.place.local_density_weight=0.1. The value 0.1 is only an example. It is not a new default. This document does not change runtime defaults.

Be careful with timing and final recovery. The FP phase supports timing feedback, and this feedback is on by default when FP runs. The final phase also uses macro.timing_interval, and final timing starts after final.timing_start=200 GP iterations. When resize=true, in-GP buffer repair starts at the second timing checkpoint. To stop it, set resize.gp=false. Enabled timing recovery and sizing finish before the mandatory terminal legalization. The old switch for terminal legalization is removed.

Scope: These defaults are the registered lhd synth options. Other diagnostic drivers can use different defaults. For example, the tools/physical_repair JSON replay driver enables resizing only when you request it, and its timing_rounds default is 0. The CLI defaults are resize=true and timing_rounds=3.

Some replay experiments are not registered synth.place.* options: cell_jump, vanished_memory, macro transparency and the adaptive GP A/B controls. Refer to the implementation guide for these experiments. The removed terminal_legalize / legalize.terminal switches and the virtual-buffer timing switches are not supported options.

Enabled-feature tuning and complete option list

The tables show the registered defaults. They also show the parameters that have no effect while their feature is off. The panel text explains forced overrides, inherited values and execution gates. An empty value shows as (empty). Each of the 292 placement options shows one time only.

Placement stages and budgets · 9 options

To enable placement, set place=true (default false). To request centroid floorplanning, set fp=true. The macro refinement and the final cell phase then follow. FP GP runs only when it has centroid candidates or adjustable IOs. A design without macros uses only one final solve.

final=false and mode=gp are diagnostic alternatives. They do not give the normal final-cell flow with fixed macros. threads=1 applies to all phases. io_iterations=500 is the limit for the first IO placement solve.

Floorplan, macro clearance and technology · 14 options

The generated frame uses utilization=0.30 and aspect=1, unless die/core or an imported floorplan gives the frame. The final cell_halo can decrease the cell-to-macro clearance. It does not decrease the macro-to-macro clearance. When the RC overrides are empty, the placer uses the technology characterization. These options are inputs and policies. They are not algorithms with their own schedule.

Clock and reset distribution is not part of the physical optimization of data nets. Imported placement masks do not block the estimated routing. Soft SRAM-halo masks guide GP, but they release sites for buffer repair and legalization. Hard row-cut masks stay as placement obstacles.

Global density and adaptive penalty · 8 options

The global density objective is part of GP. adaptive_density=false stops the penalty adjustment from overflow feedback. density_upper_bound=true selects the experimental penalty that ignores underfull bins (default false). The other defaults are initial_density_weight=0.01, stop_overflow=0.1 and schedule_iterations=500. Macro charge scaling and exact macro footprints are true by default. A legal result and GP convergence are two different results.

Virtual density fillers · 5 options

Virtual fillers are internal density particles. They are not netlist cells, and they do not use legal sites. To disable them, set virtual_fillers=false. When they are on, the defaults are fraction=1, cell_scale=1, bin_fraction=0.25 and max_count=0 (no count limit). The target area changes with the phase geometry and density. Because of this, the particle count can change between phases, also with the same options.

Convergence continuation · 3 options

post_density_factor=0 disables the bounded continuation after density and geometry are stable. For other values, the weighted wirelength and the inflation must also become stable. Routing and the measured FP timing (if available) are also part of the check. The iteration limit of the phase continues to apply. A factor of 4 allows up to four times the first eligible iteration count as more work.

Timing feedback and net weighting · 11 options

timing_driven=true for normal full placement, and OpenTimer is necessary. FP supports timing feedback. To disable the FP checkpoints, set fp.timing_interval=0. macro.timing_interval=0 disables the periodic checkpoints of macro GP and final GP.

The shared weighting defaults are fraction=0.2, max_weight=5, smoothing=0.5 and exponent=1. The FP schedule defaults are timing_after_density=false, timing_movement=0 (fixed interval) and timing_max_updates=10 (movement mode only). Macro GP and final GP use these schedule controls too. final.independent_timing=false uses the macro weights. When it is true, final starts with synthesis weights and updates only after density is stable. There is no separate timing-interval option for final.

A positive fraction (up to 1) decreases the added routing and local-density forces, in proportion to the current timing net weights. This is a soft force policy. It does not set a displacement limit. It does not decrease the usual physical density force or the filler response.

Timing recovery: sizing and buffering · 9 options

resize=true controls FP sizing, buffer removal and Steiner repair at the active FP timing checkpoints. Macro GP timing updates the weights, but it does not resize. Final GP starts timing after final.timing_start=200 iterations. With resize.gp=true, the placer can insert and remove real buffers from the second final checkpoint. resize.gp_margin=0.01 sets a slack dead band relative to the shortest clock period. If there is no clock, it uses the estimated path delay.

Post-placement sizing and repair then run before the mandatory final legalization. The enabled defaults are resize.engine=legacy, vt_swap=false and dont_use=empty. The new sizing engine is opt-in.

Examples

Use the normal mapped synthesis flow with your Liberty, LEF and SDC files. The workdir W keeps the placement and timing caches.

./bazel-bin/lhd/lhd synth design.v --top top --workdir W \
  --set synth.liberty=cells.lib --set synth.lef=tech.lef,cells.lef,macros.lef \
  --set synth.sdc=design.sdc --set synth.place=true

Add the switches that you want to the end of that command:

# Request the optional FP phase. The macro and final phases follow.
--set synth.place.fp=true

# Keep congestion spreading in macro and final. Disable it in FP only.
--set synth.place.fp.route.model=off

# Enable local spreading in all GP phases (example strength).
--set synth.place.local_density_weight=0.1

# Disable virtual fillers in all GP phases.
--set synth.place.virtual_fillers=false

# Do not run macro-stage cell detail. Keep cell legalization.
--set synth.place.macro.detailed=false

# Enable in-GP buffer repair and post-placement resizing before final legalization.
--set synth.place.resize=true

# Start final-GP timing after a warm-up of 200 iterations.
--set synth.place.final.timing_start=200

# Disable periodic FP timing. The macro and final intervals do not change.
--set synth.place.fp.timing_interval=0

The periodic checkpoint switches do not disable all timing analyses. Initial timing, stage-boundary resynthesis feedback and final STA have different purposes. For a run that examines only geometry, also examine timing_driven, resize, io_resynth and resynth. Do not change only an interval.

Use a different workdir for each major placement configuration. Reuse follows lhd.incremental. After a rebuild, measure the second warm invocation.

Technology-independent halo and override precedence

The default synth.place.halo=auto uses ten placement-row heights on each side. An explicit micron value overrides it, also zero and X,Y pairs. The Eyeriss designs in HighTide select different halos for different technologies. The table below uses their checked-in settings and the standard-cell LEFs from the pinned ORFS revision of HighTide, fb65d5b487d2afd443fc1892330f622c776a57ac. The local Eyeriss placement input also confirms the ASAP7 geometry.

All dimensions are in microns. Each halo is for one side. Two facing macro halos add together to make the macro-to-macro channel.

ASAP7: 5 × 50.054 × 0.2700.162 × 0.27018.522.702.70 × 2.70
Nangate45: 15 × 150.190 × 1.4000.380 × 1.4003.5714.0014.06 × 14.00

On ASAP7, the old fixed 5 µm halo keeps approximately ten times more rows than on Sky130HD. The smallest signal cell width has a different number of sites in each library. Also, the smallest LEF CORE object can be a filler or a tap. For these libraries, the base row height is a more consistent scale than the minimum width or a minimum-area cell.

The automatic fallback is a square H = 10 × base row height. The placer then rounds it outward to the active X site pitch and to the Y row pitch, as the halo code did before. This value is a start heuristic. This page does not claim that ten rows is optimal.

Override precedence: explicit user micron value (also zero or an X,Y pair) → explicit technology/design configuration → automatic row-height fallback. An unset final cell_halo uses the resolved macro halo. An explicit final cell halo keeps the per-axis upper limit. The scale comes from the selected placement site, or from the row site of the active imported or previous frame. The placer resolves the physical halo before frame sizing, cache admission and legality checks. It keeps the halo through the fixed-macro handoff.

Generated cores keep density capacity for the padded macro footprints and for the standard cells. Explicit die/core dimensions always have priority. QoR records both the micron value and the rounded DBU exclusion.

The HighTide MACRO_PLACE_HALO is an ORFS design argument. Here, LiveHD reads only its own synth.place.halo value. A flow integration must translate the resolved design/technology setting explicitly, because the LEF data does not contain it. For example, the Nangate45 Eyeriss configuration documents a 15 µm minimum for PDN clearance. Because of this, its explicit value must have priority over the 14 µm fallback. When the flow forwards these design settings, all three Eyeriss halos stay the same.
