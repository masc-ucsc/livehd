Placer features and phase defaults

Start with the algorithm you want to control, then compare fp_plan, macro_plan, and final. The matrix shows what actually runs in the normal full-placement flow. Expand a feature to see every associated option and its registered default.

1 · fp_planOptional centroid floorplanning

synth.place.fp=false
When requested and eligible: FP GP → optional target warp → centroid snap.

2 · macro_planMacro placement / refinement

Runs when the staged flow needs a macro frame. Macros and cells move; selected macros and IOs are fixed for final.

3 · finalFull-flow cell placement and legality

synth.place.final=true
Fresh cell solve with fixed macros/IOs → final legalization. A cell-only design goes straight here.

How to read the defaults. “On” assumes placement is enabled, the phase runs, and its prerequisites are met. “Off” means a feature can be enabled at that execution point. “Inactive”, “not scheduled”, or “skipped” identifies an execution gate in the current implementation; it does not claim the algorithm could never be useful there. Many controls are shared across phases, so they cannot be independently toggled per phase today. Zero-valued enabling weights stay zero in this reference: enabling them requires choosing a positive strength, not an invented enabled preset.

All short option names below have the prefix synth.place., except place, which means synth.place itself. For example, local_density_weight is set with --set synth.place.local_density_weight=0.1. The number here is illustrative, not a new default. No runtime defaults are changed by this document.

Timing and final recovery need special care: FP currently supports timing feedback, enabled by default when that phase runs. Final uses macro.timing_interval too, after final.timing_start=200 GP iterations. With resize=true, in-GP buffer repair starts from the second timing checkpoint unless resize.gp=false. Enabled timing recovery and sizing complete before mandatory terminal legalization; the former terminal-enable switch has been removed.

Scope: These are registered lhd synth options, not defaults for every diagnostic driver. The tools/physical_repair JSON replay driver enables resizing only when explicitly requested and defaults timing_rounds to 0; the CLI defaults are resize=true and timing_rounds=3. Replay experiments such as cell_jump, vanished_memory, macro transparency and adaptive GP A/B controls are not registered synth.place.* options. See the implementation guide for those experiments. The removed terminal_legalize / legalize.terminal and virtual-buffer timing switches are not supported options.

Examples

Use the normal mapped synthesis flow with your Liberty, LEFs and SDC. W owns the placement and timing caches.

./bazel-bin/lhd/lhd synth design.v --top top --workdir W \
  --set synth.liberty=cells.lib --set synth.lef=tech.lef,cells.lef,macros.lef \
  --set synth.sdc=design.sdc --set synth.place=true

Append the desired switches to that command:

# Request the optional FP phase; normal macro/final stages follow.
--set synth.place.fp=true

# Keep congestion spreading in macro/final, disable it only in FP.
--set synth.place.fp.route.model=off

# Enable local spreading everywhere GP runs (illustrative strength).
--set synth.place.local_density_weight=0.1

# Disable virtual fillers in all GP phases.
--set synth.place.virtual_fillers=false

# Skip macro-stage cell detail while retaining cell legalization.
--set synth.place.macro.detailed=false

# Enable in-GP buffer repair and post-placement resizing before final legalization.
--set synth.place.resize=true

# Begin final-GP timing after an initial placement warm-up.
--set synth.place.final.timing_start=200

# Disable periodic FP timing; macro/final cadence remains unchanged.
--set synth.place.fp.timing_interval=0

Periodic checkpoint switches do not disable all timing analyses: initial timing, stage-boundary resynthesis feedback and final STA have separate purposes. For a geometry-focused run, also review timing_driven, resize, io_resynth and resynth rather than changing only a cadence. Use separate workdirs for major placement configurations. Reuse follows lhd.incremental; after a rebuild, measure the second warm invocation.

Technology-independent halo and override precedence

The default synth.place.halo=auto uses ten placement-row heights per side. Explicit micron values, including zero and X,Y pairs, override it. The Eyeriss designs in HighTide explicitly select different halos across technologies. The comparison below uses their checked-in settings and the standard-cell LEFs from HighTide’s pinned ORFS revision fb65d5b487d2afd443fc1892330f622c776a57ac. ASAP7 geometry was also checked in the local Eyeriss placement input.

All dimensions are microns. Halos are per side; two facing macro halos add to the macro-to-macro channel.

ASAP7: 5 × 50.054 × 0.2700.162 × 0.27018.522.702.70 × 2.70

Sky130HD: 30 × 300.460 × 2.7201.380 × 2.7201.8427.2027.60 × 27.20

The former fixed 5 µm halo reserves about ten times as many rows on ASAP7 as on Sky130HD. The smallest signal-cell width spans different numbers of sites, and the smallest LEF CORE object may instead be a filler or tap. For these libraries, the base row height is a more consistent scale than either the minimum width or a minimum-area cell. The automatic fallback is a square H = 10 × base row height, then rounded outward independently to the active X site pitch and Y row pitch, as the existing halo implementation already does. It is a starting heuristic; ten rows is not claimed to be optimal.

Override precedence: explicit user micron value (including zero or an X,Y pair) → explicit technology/design configuration → automatic row-height fallback. An unset final cell_halo continues to inherit the resolved macro halo; an explicit final cell halo retains the existing per-axis upper bound. The scale comes from the selected placement site, or the active imported/previous frame’s row site. The physical halo is resolved before frame sizing, cache admission and legality checks, and is carried through the fixed-macro handoff. Generated cores reserve density capacity for padded macro footprints plus standard cells; explicit die/core dimensions stay authoritative. QoR records both the micron value and the rounded DBU exclusion.

HighTide’s MACRO_PLACE_HALO is an ORFS design argument; LiveHD currently parses only its own synth.place.halo value here. A flow integration must translate the resolved design/technology setting explicitly; reading LEF alone does not recover it. In particular, Nangate45’s Eyeriss configuration documents a 15 µm minimum related to PDN clearance. Its explicit value must therefore win over the 14 µm fallback. Explicitly forwarding these design settings leaves all three Eyeriss halos unchanged.

Geometry sources at the pinned revision: ASAP7 cell/site LEF, Nangate45 site LEF, Nangate45 cell LEF, Sky130HD site LEF, and Sky130HD cell LEF.

This investigation checks configuration and geometry only. It does not establish routed congestion, PDN feasibility or timing quality for the fallback. The row-height fallback and default FP/macro IO adjustment were explicitly approved on 2026-10-23.
