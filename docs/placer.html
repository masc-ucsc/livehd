How fp_plan, macro_plan and final are different

Two floorplan solvers. fp=auto runs the chunk plan of the diagram. The centroid rows of the two tables below, and the fp.* timing, snap and pin options, belong to the experimental centroid solver. It replaces the chunk plan with fp=centroid, or when any fp.* option is set without fp=chunks or an explicit lhd.ram_budget_mb.

The three phases use the same GP engine. They are different in three items: the objects that can move, the forces in GP, and the steps after GP. Each phase fixes more objects than the phase before it. The table shows only the differences. The shared settings are in the first row.

How to read the defaults. “On” means that the feature runs when placement is enabled, the phase runs and all its conditions are true. “Off” means that you can enable the feature at that point in the flow. “Inactive”, “not scheduled” and “skipped” show a gate in the current code. These words do not mean that the algorithm cannot be useful at that point. All phases share many controls. Because of this, you cannot set these controls for one phase only. A weight with a zero default stays zero in this reference. To enable it, you must select a positive value, because this page does not give a recommended value.

All short option names on this page start with synth.place.. The only exception is place, which is synth.place itself. For example, to set local_density_weight, use --set synth.place.local_density_weight=0.1. The value 0.1 is only an example. It is not a new default. This document does not change runtime defaults.

Be careful with timing and final recovery. The FP phase supports timing feedback, and this feedback is on by default when FP runs. The final phase also uses macro.timing_interval, and final timing starts after final.timing_start=200 GP iterations. With resize=true, buffering and sizing run after legal GP; GP itself never edits the netlist. Enabled timing recovery and sizing finish before the mandatory terminal legalization. The old switch for terminal legalization is removed.

Registered default and effective default. resize, resynth and wl_resynth are registered as true. The driver turns them on only in a full placement with synth.timing on; without timing they are off, and setting one to true there is a usage error. policy.fast=true turns off resynthesis, sizing and buffer edits together.

Scope: These defaults are the registered lhd synth options. Other diagnostic drivers can use different defaults. For example, the tools/physical_repair JSON replay driver enables resizing only when you request it, and its timing_rounds default is 0. The CLI defaults are resize=true, timing_rounds=3 and repair.iterations=3.

Some replay experiments are not registered synth.place.* options: cell_jump, vanished_memory, macro transparency and the adaptive GP A/B controls. Refer to the implementation guide for these experiments. The removed terminal_legalize / legalize.terminal switches are not supported options. Sources and maintenance lists the options removed since the last edition and what replaces each.

Partition roles: grid, region, bin

Placement divides the core in three roles, named by what they do in the flow, not by the algorithm that first needed them. Each role has one option prefix. A grid (grid.*) is a set of uniform tiles over the core for the global-placement force fields in FP, macro and final GP. Cells put area and routing demand into the tiles and read forces back; a grid has no cell membership and never stops a cell from moving. A region (region.*) is an irregular rectangle of the detail-final phase, after final GP converges and before legalization. Region edges follow fixed macro edges and IO bus spans, each region holds at most region.max_cells movable cells, and its membership is explicit. Bus order, boundary pins and pin alignment work on region edges, and the mesh stays fixed for the whole phase. A bin is a uniform legalization tile with usable capacity, before/after occupancy and a hard density cap. The bin role has two prefixes and, for now, two capacity models. Terminal bins (legalize.bin.*) count row sites without macro halos and fixed tap/spacer cells, and count fixed logic cells as occupancy. SAT bins (satlegalize.bin.*) measure exact row area without every non-movable cell, fixed logic included. One shared model would change SAT results, so that is a separate decision.

There is one placement-wide routing grid, grid.route. RUDY/RSMT, the macro channel pressure, native legalization and detailed placement, terminal bins and SAT route-grid bins all read it. Only an explicit legalize.bin.grid gives the terminal legalizer a different count. Stage-scoped grids keep their names (preroute.bins). The older spellings (bins, seed, dynamic_bins, auto_bins, bin_max, local_density_bins, busorder*, boundarypins*, pinalign, legalize.max_density, satlegalize.region_size, satlegalize.route_grid) are retired: lhd refuses each one and names its replacement.

Grids: density, routing and local · 4 options

The density grid is fixed at grid.density=64 bins per axis by default. grid.density_mode=macro picks the count from the macro geometry. grid.density_mode=dynamic sizes it from the movable area, with a limit of grid.density_max=512. Routability step at the end of placement (legroute) · on by default

Goal: end placement with a placement a global router can route, on the given die and core. synth.place.legroute=true is the default: the plan rounds are the first step of final legalization. It is a routability estimate on tiles, not the detailed router of stage 5. The plan is todo/livehd/2r-route.html. What exists today is the minimal core left after the SAT-based stages (cell boxes, regional SAT placement, in-box routing, the probe) were removed: a tile grid with per-layer track capacity, a clock charge, a negotiated global router and the rounds below. The check that the cells of each grid cell can really be legalized there is the next step of that plan and is not built yet.

  1. Measure. On the converged global placement (cells may still overlap), route every signal net between its physical pins on a tile grid: a tile is two placement rows tall and twice the widest flop wide. Each routing layer above the pin-escape layer keeps its usable tracks per tile after power metal, hard blockages and macros; clock nets are not routed, a spine-tree estimate is charged instead. The router is a 2D negotiated router (rip-up and reroute with a rising congestion cost); legroute.global_pattern=true (the default) tries FastRoute-derived L/Z patterns before the maze. legroute.route_escape=true also routes on the pin-escape layer (ASAP7 M2). legroute.capacity_share=auto is 1 − route.layer_adjustment, so the two track derates agree.
  2. Feed back. While the route does not fit, widen the cells of the nets under routing pressure (x only, up to plan.max_inflate; the most timing-critical cells keep their size) and resume global placement from the converged pose, then restore the widths. With plan.route_model=coarse the router's H/V utilization maps drive the placer's routability force during that slice instead.
  3. Select. Every round is routed again before it can replace the incumbent; a round that routes worse ends the rounds, and plan.max_degradation_ps can add an estimated-slack guard. The best measured round is installed.
  4. Legalize. The regular terminal legalizer legalizes the selected placement. legroute itself legalizes no cell.

What a passing round establishes. The router's demand fits its own capacity model on every tile edge. That model is not calibrated against OpenROAD's derated per-layer capacity, has no routing profile for nangate45 yet, and says nothing about whether the cells of a tile can be legalized inside it. Demand is kept per direction, not per layer.

When the route does not fit. With a die, core or floorplan given, the run never stops for it: the best measured round is kept, the remaining overflow is reported and placement continues to legalization. A generated core with synth.place.allow_increase_area=true restarts the whole command at a lower utilization instead (area_step; routing may ask for at most legroute.area_restarts=1 of the area_restarts); utilization=0 bisects the utilization on the same signal. See core sizing.

Inspect. Under the placement output directory, final/legroute_planN/plan.json holds each measured round (signals, unresolved nets, overflow edges and tracks in total and per direction, per-layer capacity), plan_failures.tsv the unresolved nets, feedback.json the placement change of the round, final/legroute_plan_timing.json every candidate's score and accept/reject reason, and final/legroute_plan_selection.json the selected round with its outcome (fits, continued_with_overflow or area_restart). qor.json repeats the selected round's numbers under legroute. With snapshots=true each round also saves the exact DEF it measured.

The registered controls below are conditional on enabling legroute. Defaults were checked against the CLI option registry on 2026-11-26. One round measures the converged placement; up to legroute.plan.rounds=2 feedback rounds follow.

Routing with LiveHD

This section applies only when the flow stays in LiveHD after placement. lhd route is a separate command: it reads the placed DEF bundle that lhd synth --emit-dir def:DIR wrote, routes every signal net that has no wires yet, and writes the DEF back with ROUTED wiring and the cells it moved. It calls no external tool. A flow that hands the placed DEF to another router skips this stage, and nothing on this page describes that router.

./bazel-bin/lhd/lhd synth design.v --top top --workdir W \
  --set synth.liberty=cells.lib --set synth.lef=tech.lef,cells.lef,macros.lef \
  --set synth.sdc=design.sdc --set synth.place=true --emit-dir def:placed

./bazel-bin/lhd/lhd route def:placed --workdir R                      # one process, the whole frame
./bazel-bin/lhd/lhd route chunk def:placed plan:fp_chunks.json --set lhd.jobs=4 --workdir R   # parallel homes
./bazel-bin/lhd/lhd route repair def:placed route:R/route --workdir R --emit-dir def:routed   # reopen around failures
./bazel-bin/lhd/lhd route verify def:routed                            # check existing wires only

The bundle records the order of its technology, cell and macro LEFs. A frame from another source is passed as def:design.def lef:tech.lef lef:cells.lef, technology LEF first. Routing options are --set route.NAME=VALUE; they do not start with synth.place..

The model: tracks, intervals and one via per crossing

Every signal wire is a default-width piece on a track of the DEF, on a layer that runs in one direction. Every via is the technology's default single-cut via where two tracks cross. A track is a sorted list of intervals, each owned by a net, by fixed metal or by a cell. Routing a net means finding free intervals and crossings, and a wire is legal when it satisfies five rules against the intervals around it:

RuleWhat it keepsRead from the technology LEF
R1 end to endTwo pieces on one track keep a gap between their ends. Pieces of one net merge.largest of SPACING, end-of-line spacing, LEF58_SPACING … ENDTOEND and the reach of LEF58_EOLKEEPOUT
R2 facing endsEnds that face each other on neighbouring tracks keep a gap along the track. The new wire is lengthened until the ends overlap.LEF58_CORNERSPACING, or the part of the spacing that the track pitch does not already give
R3 minimum lengthA piece is at least as long as the minimum area needs. It grows toward the side with room, never out of the die. A via pad on the piece counts as area.AREA, MINSIZE, via pad rectangles
R4 cut spacingTwo cuts of one cut layer keep their spacing, also two cuts of one path.cut SPACING or LEF58_SPACINGTABLE DEFAULT, cut size from the via
R5 via padsWhere the via pad is wider than the wire, the pad keeps the spacing from other nets, from fixed metal, and from pads of its own net that it does not touch (a notch).via pad rectangles, SPACING, width spacing table

No rule number is stored in the source. The router reads the layer and via statements of the LEF and the tracks, rows and units of the DEF. The pin layer is the lowest routing layer; the routed layers are the ones above it that have tracks. A registered technology profile can narrow that range: ASAP7 routes M2 to M7 with pins on M1. A top layer whose via pad does not fit between the tracks below it is left out and reported (Sky130HD met5). Search costs and windows that were measured on ASAP7 scale with the pitch of the first routed layer.

The first routed layer must run along the rows, and neighbouring routed layers must cross. Metal across the direction of a layer appears in two places only: a pin jog and a port jog, each one track long (see pin access).

What a flat lhd route does, in order

  1. Read the technology and the frame. Tracks become interval lists. Power and ground wires, blockages, nets that already have wires, cell obstructions and macro bodies enter as fixed intervals. Rows give the legal sites and which sites are taken.
  2. Settle the cells. By default every placed cell keeps its site. With route.prelegal=true (route-first) movable cells float at their input position and take the nearest free legal site when the first net needs them, so the input can be the placement before legalization. Clock sinks, macros and cells with wired upper-layer pins do not float.
  3. Find pin access. A standard-cell pin gets candidates: positions on the tracks that cross its pin metal where the landing pad of the pin via stays inside the pin. A pin with its own strap on a routed layer is reached on the strap. A macro pin is a bar at the macro edge; it is extended out of the macro and reached from the layer above or below. A port is reached on its bar.
  4. Order the nets. Clock nets first. With a timing: file of pin slacks from the placer, the nets go worst slack first (crit_frac=1). Without it, shortest pin box first (order=short).
  5. Route each net. Pins join the tree in Prim–Dijkstra order from the driver (pd_alpha=0.3, nets of four pins or more). Each pin runs an A* search over (layer, track, crossing) states toward the tree, inside a window around the connection. The path is then committed piece by piece under R1 to R5. A rejected commit bans that piece and searches again.
  6. Repair a failed net, in this order: more landing positions for the blocked pin; slide the cell of the blocked pin along its row (shift=3 tries, shift_reach=6 sites, pushing up to chain=4 neighbours; a flop at most flop_reach=2 sites); move the cell to a free site of a nearby tile (tile_move); rip up the nets in the way and route this one first (ripup=3 per net, rip_width=6 nets per failure).
  7. Final passes (final_passes=6) go over the nets still open with a larger search budget. Here reserve gives all pins of a blocked cell their landings together and holds them while the nets around come back.
  8. Protect timing (only with timing:). The cells of the worst tenth of the nets by slack become fixed once those nets are routed (anchor_frac=0.1), so later repairs do not move them.
  9. Verify and write. The router reads its own DEF back and checks shorts, R1 to R4, wide-metal spacing, opens, cells off site and cell overlaps. It does not check R5 yet; the search enforces R5, the verifier does not confirm it. It writes routed.def, feedback.tsv (one row per net: routed, or the pin and the reason it failed), findings.tsv (one row per rule finding with its rectangle) and stats.json under R/route. The result is complete only with zero open nets and zero findings.

Pin access where via pads are wider than the wire. In Sky130HD the pins of one cell sit a pad and a spacing apart on a single met1 track, so two neighbours cannot both go up from that track. A pin there has a second kind of candidate, the jog: the pin via stays on the pin's track and a met1 piece one track long, across the layer's direction, takes the net to the track above or below. A reserved pin holds only its landing pad. Technologies whose pads are as wide as the wire (ASAP7) get neither; there a reserved pin holds a corridor from the pin to the third routed layer.

A port walled in by fixed metal. A port bar can sit so close to power-grid metal that no via pad fits on it and its own track is blocked. Such a port gets a jog from its bar to the next track, written with the net.

What it does not do

  • No clock tree. The router routes the clock nets it finds, first. If placement did not build a clock tree (synth.place.pcrs.clock=false, the default), the clock is one net with every flop on it; the router will try to route it as one net.
  • One via per cut layer, the default single-cut via with the narrowest pads. No via doubling, no rotated or off-track vias.
  • No antenna repair, no metal fill, no power routing. Power and ground come from the frame.
  • Timing enters through order and protection only: which nets route first, whose cells are fixed, and (off by default) extra spacing for the worst nets. There is no timing-driven layer choice and no extraction inside the router.
  • Macro pins must be bars of the default wire width at the macro edge.
  • A flat run is single-threaded. Parallelism is the chunk mode.

Examples

Use hints.json for experimental advisory macro-placement metadata. The hierarchical placement-hint guide includes the typed JSON format, coordinate seeds, regression commands, and limitations. No hints are enabled by default.

Use the normal mapped synthesis flow with your Liberty, LEF and SDC files. The workdir W keeps the placement and timing caches.

./bazel-bin/lhd/lhd synth design.v --top top --workdir W \
  --set synth.liberty=cells.lib --set synth.lef=tech.lef,cells.lef,macros.lef \
  --set synth.sdc=design.sdc --set synth.place=true

Add the switches that you want to the end of that command:

# Plan color/macro chunks under a 1 GB worker budget and open the FP gate in a GUI run.
--set synth.place.fp=chunks --set lhd.ram_budget_mb=1024

# Legacy default: never run the FP phase.
--set synth.place.fp=false

# Keep congestion spreading in macro and final. Disable it in FP only.
--set synth.place.fp.route.model=off

# Enable local spreading in all GP phases (example strength).
--set synth.place.local_density_weight=0.1

# Disable virtual fillers in all GP phases.
--set synth.place.virtual_fillers=false

# Do not run macro-stage cell detail. Keep cell legalization.
--set synth.place.macro.detailed=false

# Keep the netlist as mapped: no resynthesis, sizing or buffer edits during placement.
--set synth.place.policy.fast=true

# Skip the routability rounds before terminal legalization.
--set synth.place.legroute=false

# Build the native clock tree (also turns on the power grid and taps on a supported technology).
--set synth.place.pcrs.clock=true

# Ask the terminal legalizer for room around pin-dense cells (example values).
--set synth.place.legalize.pin_footprint=20 --set synth.place.legalize.pin_padding_critical=true

# Start final-GP timing after a warm-up of 200 iterations.
--set synth.place.final.timing_start=200

# Disable periodic FP timing. The macro and final intervals do not change.
--set synth.place.fp.timing_interval=0

The periodic checkpoint switches do not disable all timing analyses. Initial timing, stage-boundary resynthesis feedback and final STA have different purposes. For a run that examines only geometry, also examine timing_driven, resize, io_resynth and resynth. Do not change only an interval.

To route in LiveHD, add --emit-dir def:placed to the synthesis command and continue with the commands in Routing with LiveHD.

Use a different workdir for each major placement configuration. Reuse follows lhd.incremental. After a rebuild, measure the second warm invocation.

Technology-independent halo and override precedence

The default synth.place.halo=auto uses ten placement-row heights on each side. An explicit micron value overrides it, also zero and X,Y pairs. The Eyeriss designs in HighTide select different halos for different technologies. The local Eyeriss placement input also confirms the ASAP7 geometry.

On ASAP7, the old fixed 5 µm halo keeps approximately ten times more rows than on Sky130HD. The smallest signal cell width has a different number of sites in each library. Also, the smallest LEF CORE object can be a filler or a tap. For these libraries, the base row height is a more consistent scale than the minimum width or a minimum-area cell.

The automatic fallback is a square H = 10 × base row height. The placer then rounds it outward to the active X site pitch and to the Y row pitch, as the halo code did before. This value is a start heuristic. This page does not claim that ten rows is optimal.

Override precedence: explicit user micron value (also zero or an X,Y pair) → explicit technology/design configuration → automatic row-height fallback. An unset final cell_halo uses the resolved macro halo. An explicit final cell halo keeps the per-axis upper limit. The scale comes from the selected placement site, or from the row site of the active imported or previous frame. The placer resolves the physical halo before frame sizing, cache admission and legality checks. It keeps the halo through the fixed-macro handoff.

Generated cores keep density capacity for the padded macro footprints and for the standard cells. Explicit die/core dimensions always have priority. QoR records both the micron value and the rounded DBU exclusion.

The HighTide MACRO_PLACE_HALO is an ORFS design argument. Here, LiveHD reads only its own synth.place.halo value. A flow integration must translate the resolved design/technology setting explicitly, because the LEF data does not contain it. For example, the Nangate45 Eyeriss configuration documents a 15 µm minimum for PDN clearance. Because of this, its explicit value must have priority over the 14 µm fallback. When the flow forwards these design settings, all three Eyeriss halos stay the same.

This investigation examines only configuration and geometry. It does not show routed congestion, PDN feasibility or timing quality for the fallback. The project approved the row-height fallback and the default FP/macro IO adjustment on 2026-10-23.
