LLVM versus Slop: eight Pyrope simulation outliers

2026-10-06 · Satsuma · retained compiler fe201d40b · original sweep 20261006T110636

Two distinct code-generation problems explain the reproduced 2× regressions. Memory callback boundaries prevent direct array-access optimization; extra colored-runtime bookkeeping dominates small combinational loop bodies. Controlled changes remove those regressions with identical simulation checksums and unchanged LLVM arithmetic kernels. The other six original 2× classifications do not reproduce at that magnitude; smaller residual gaps remain in four cases.

Every number here measures simulation execution only. Setup, object generation, compilation and linking are excluded. Ratio = Slop execution time / LLVM execution time: below 0.5 means LLVM takes over twice as long.

Why the memory path loses

The deserializer stores seven 8-bit entries in std::array<Slop_u<8>, 7>, plus staged-write records. The representation preserves defined/undefined values and write ordering. It is contiguous fixed-size storage, although its cells are richer than plain bytes.

LLVM kernels call __lhd_llvm_mem_*_read_* and __lhd_llvm_mem_*_stage_*. The ABI passes addresses/data as pointers to packed words; callbacks reconstruct Slop values, call the array model, and pack results. Host C++ receives its O2 pass before the kernels are linked. The final linker runs AlwaysInliner plus SROA, EarlyCSE, InstCombine, SimplifyCFG and ADCE. Kernels have the always-inline attribute; these callbacks do not. Consequently the later constant addresses and enables cannot simplify the callback internals.

The deserializer experiment adds only alwaysinline to the 22 callback definitions in retained host bitcode, then uses the frozen linker and unchanged kernel bitcode. All 44 static callback callsites disappear. The ~2.1× execution loss disappears with them. There is no replacement of the memory model, partition, or arithmetic.

The CDC FIFO also requires visibility across generated files: callback definitions are outside the two evaluator shards. The experiment extracts the 34 unchanged callback bodies, compiles them to bitcode, gives them linkonce_odr and alwaysinline, and includes them in each shard link. All 68 static callback callsites disappear. An attribute alone on a definition unavailable to the shard is insufficient.

Implementation direction: emit small typed/inline memory accessors into every module that needs them, or lower array address/load/store operations directly into kernel IR with a well-defined layout. Preserve unknown-value handling, bounds behavior, staged writes, read ordering, write priority, and change reporting. The measured result shows that exposing the existing array accesses is sufficient to remove these major losses; changing to bare integer storage is not required for this result.

Why identical partitions still produce different loop overhead

Every shared .color-plan.txt report is byte-identical between Slop and LLVM. However, inou_cgen.cpp additionally creates colored roots for compact bodies only when LLVM is selected. The arbiters acquire one or two extra plans. Slop emits compact generation-cached phase functions. LLVM surrounds tiny pure combinational kernels with owner checks, input-history comparisons, dirty bits and quiescence tracking; publishing also invokes a reset-settle path.

Software sampling locates ~55% of br_arb_rr samples in its LLVM loop body, and ~87% of br_flow_arb_rr samples in its two LLVM loop bodies. The diagnostic replacement unconditionally evaluates the same two LLVM phase kernels in __color_run(), and evaluates the same publish kernel in __color_reset_settle(). It keeps the object layout and arithmetic bitcode unchanged. Both tested bodies have empty state-commit functions. This eliminates the repeated scheduling protocol and makes LLVM faster than Slop in both cases.

Implementation direction: generate a compact execution path for proven stateless combinational bodies, retaining the LLVM kernels. The diagnostic rewrite is deliberately limited to these fixtures. It must not be generalized to stateful, multi-clock, observed or checkpoint-sensitive bodies without semantic tests.

Remaining instruction-quality differences

The AMBA and credit-sender cases have no memory callback bottleneck. Samples concentrate in the root evaluator. Static disassembly shows extra stack traffic in AXI and credit sender, but static instruction counts alone do not prove the dynamic cause. The push-credit FIFO improves with callback inlining but still has a ~27% gap in that experiment.

As a separate test, the existing LLVM 22.1.8 tools link the retained host and kernel bitcode, run default<O2> with loop unrolling disabled, and hand the result to the frozen native code generator. Partitions, LLVM arithmetic inputs and final code generator are retained. This only helps modestly and slightly regresses AXI-Lite; replacing the bounded pass pipeline with generic O2 is not a demonstrated general fix.

Profiling and scope

perf record was attempted but perf_event_open is denied on this host (perf_event_paranoid=3). GNU gprofng software PC sampling was used for all 16 executables on CPU 50, at five times the original cycle counts. Paired checksums also match for those longer runs. Samples identify hot functions; the profiler's reported absolute CPU-time totals undercount wall duration on this host, so no absolute timing claims use them. Timings come from independent unprofiled runs and child rusage.

These are diagnostic transformations of retained generated artifacts, not production compiler fixes. No production source, benchmark source, ledger, or published report was changed. Existing user edits were preserved. The complete causal explanation is established for both reproduced 2× regressions and for the smaller arbiter/CDC gaps. The residual instruction-level causes in AMBA, credit sender and push-credit FIFO are explicitly narrower follow-up work.

br_arb_rr

A pure combinational rolled-loop body is a separate colored runtime only on LLVM. Software samples put ~55% in that body. Bypassing input-history comparisons, dirty-bit handling, quiescence and owner checks, while retaining both original LLVM phase kernels, lowers 3.560 s to 1.961 s; Slop is 2.099 s. This explains the reproducible gap.
