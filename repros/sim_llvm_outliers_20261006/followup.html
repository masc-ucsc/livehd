The missed optimization

The loop selects one 16-bit lane from an 80-bit value. LLVM packs that value into two words inside a five-word argument buffer. Cgen_llvm::dynamic_extract selects a word address dynamically and loads through it. That dynamic index prevents scalar replacement from eliminating the packed buffer after kernel inlining.

// Existing shape: selected address keeps the packed array alive.
word = load(inputs + select(condition, 3, 4));

// Experimental shape: both slots are fixed and valid.
lo = load(inputs + 3);
hi = load(inputs + 4);
word = select(condition, lo, hi);

Both slots are initialized, nonvolatile input-buffer words. The transformation preserves the selected word exactly; bounds handling, funnel shift, lane selection, output conversion and changed-value reporting remain unchanged. It only exposes fixed addresses to LLVM's existing scalar replacement and simplification passes.

The machine-code evidence is direct: the hot LLVM loop's __color_run() goes from six stack references to zero. Before, it copies the two input words through the stack; afterwards it loads them directly from the simulator object into registers. The function has 54 versus 53 static instructions, illustrating that avoiding the stack traffic matters more here than the instruction count alone.

Before: hot loop assembly · After: hot loop assembly · Original kernel IR · Modified kernel IR

Production direction: specialize the small-word-count path in Cgen_llvm::dynamic_extract to select scalar word values from fixed slots. Start with the two-word case proved here. Keep indexed loads for large packed values, where loading every word would be wasteful. This is a diagnostic IR experiment, not an applied production compiler patch.

Other hypotheses checked

  • Lazy mux evaluation: a separate experiment skips extraction for an unselected lane, preserving the original LLVM kernel for selected lanes. It gave a small gain by itself (2.839 → 2.755 s in its batch), but adds no meaningful gain once fixed-slot loads eliminate the buffer overhead.
  • Equivalent-phase reuse: both phase kernels have byte-identical normalized IR bodies and empty state commits. Replacing the second evaluation with a whole-output copy nevertheless regressed execution (2.839 → 3.713 s). Combining that copy with fixed-slot loads also remained slower. Fewer arithmetic evaluations or static instructions alone do not establish a faster machine-code path; this copy transformation is rejected.
  • Conditional staging stores: avoiding stores of unchanged next-state values regressed AXI, AXI-Lite and push-credit FIFO in these tests. It is not a demonstrated opportunity.
  • Additional optimization passes: GVN and SLP did not close the push-credit FIFO gap; full O2 after inlining provided only a small further gain. Credit sender also gained only about 3% with full O2.
  • Host instruction selection: native-CPU compilation of the relevant harness translation units was slower on both backends for credit sender, and did not help the FIFO. This is exploratory evidence, not a claim about all CPU targets.

Remaining limits

The push-credit FIFO remains about 29% slower with the callback-inlining change in its latest matched baseline (1.217 s versus 0.939 s), and credit sender remains about 14% slower (1.570 s versus 1.382 s). These follow-up experiments do not establish their remaining instruction-level cause. The confirmed new opportunity is the structured mux's small packed-buffer extraction; no all-design speedup or complete closure of the LLVM/Slop gap is claimed.
