Cause and fix

The previous LLVM path rebound the lane's inputs, updated generations, entered the scheduler, packed its inputs, and called a native color on every ordinal. AddMop's arithmetic body was only 56 bytes. The new entry transports inputs once, retains carries and activation values in SSA, and explicitly inlines one body copy into the native loop. Count, first and step remain runtime arguments. LLVM loop metadata disables unrolling. Proven nonnegative loop-index ranges remove impossible sign and bounds guards, while count remains dynamic. Object emission still uses the shared bounded workers and rejects external symbols.

Eligibility is based on a complete stateless native computation rather than the separate Slop expression-emitter check, which rejected compiler bookkeeping nodes in the arbiters. Slop now ignores those same proof-only nodes, matching the ordinary emitter and enabling its own inlined body. Whole declared port widths must match the ABI. Stateful, nested, multi-color, resource-backed and observed loops retain the existing compact scheduler; migrating those remains work.

Wide-loop follow-up

The full sweep exposed a missed LLVM SROA promotion: alloca i64, count is treated as an array allocation even for constant count. Commit 7ea7ce546 expresses the extent in an LLVM array type instead. Native regression tests verify that fixed packed carry buffers disappear after optimization, while retaining the loop and its inline body. The paired rerun improves br_arb_lru LLVM from 38.462 to 34.039 s; Slop is 10.797 s, so its larger gap remains. The distributor uses the compact scheduler, not these native loop adapters, and needs a separate diagnosis.

Remaining gaps

AddMop retains a smaller transport/call-boundary gap. FIFO sampling places 42 of 70 samples in C++ scheduling and transport, and 18 in native kernels. Its main adapter transports 28 input words and 30 output words. AXI places 29 samples in C++ scheduling/transport and 38 in native kernels. These measurements locate remaining costs; they do not establish that arithmetic optimization alone will remove them. Hardware perf is disabled on this host, so these are staggered GDB interruption samples.
