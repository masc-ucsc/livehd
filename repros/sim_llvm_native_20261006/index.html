Independent LLVM simulator objects

LLVM colors now emit native PIC objects with no external dependencies. The final audit checked 5,284 objects, including 4,981 from whole-core Minion: zero named undefined symbols, zero unused Slop pure includes. Minion native LLVM takes 2.681 s per 100,000 cycles versus 2.831 s for old LLVM and 2.273 s for Slop. Its setup + compilation takes 280.08 s versus 345.47 s for old LLVM.

This architectural step is not a uniform execution-speed improvement: 16/18 small-design LLVM cases are slower than the old cross-language-inlining path. Removing that inlining creates a real call and packing boundary. The measurements below retain these regressions rather than hiding them in an aggregate.

Follow-up: controlled slowdown diagnosis and remaining C++ inventory

What changed

  • Memory uses contiguous packed words. Color IR implements addressing, bounds checks, write staging, forwarding, lane masks, undefined collision draws, and combinational commits.
  • Wide division and bulk-memory operations lower within the object; native symbol validation rejects libc or compiler-runtime dependencies.
  • LLVM object creation uses bounded workers. sim.jobs sets the object and host-build limit; the default samples available CPUs and load and always permits one job.
  • C++ compiles normally and links native objects through response files. Both the normal simulator and standalone Bazel export include those objects. Unused .pure.inc evaluators are removed.

The driver, scheduling, hierarchy, state commits, input/output packing, dirty propagation, reset and observation remain C++ in this first step. The packed-memory support template is shared standard code. This does not yet remove all design-specific C++.

Whole-core Minion

The unmodified ../lhdsuite/minion/pyrope/minion_top.prp and minion_prog_tb.prp execute the sustained program workload for 100,000 cycles. Every measured run passes its retirement and PC assertions and reports 41,321 retired instructions, PC 1032. This is the whole Pyrope core, not the tensor register-file microbenchmark.

Execution numbers are medians of five runs after one excluded warmup, alternating variant order, pinned to CPU 34. Setup and compilation use fresh workdirs, eight jobs, the same Clang host compiler, tuning off and VCD off. Construction timings are single wall-clock samples; the shared machine also had other builds running. Independent front-end compilations can produce slightly different color plans, so Minion is an end-to-end comparison, not a fixed-partition microbenchmark.

Correctness and integration

The selected Bazel targets pass: 11 code-generator unit tests, the 19-block Slop/LLVM smoke batch with backend switching and shards, and a dedicated native-memory test. Further checks cover 10 memory fixtures with both unsigned and signed Slop carriers, checkpoint creation, bit-exact deterministic restart with VCD, warm object reuse, missing-object regeneration, standalone export contents, and response-file paths containing spaces.

The dedicated memory test caught an existing LLVM bug: pre-rise reads failed to replay the write prefix. The frozen old backend returned old stored values where Slop produced seeded unknown collision values. Native LLVM now stages that prefix in IR; equal seeds reproduce a trace and different seeds change it. Undefined collision values use a seeded packed-memory stream and need not match Slop's particular random values. As in the existing simulator, checkpoint restart does not restore PRNG stream positions.

Minion also caught the shell argument-limit failure from thousands of objects. Both host build paths now use response files; the final Minion run uses the normal built-in build path, without a manual link workaround.
