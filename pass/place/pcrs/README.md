# pass.pcrs — power, clock, reset and scan-chain networks

Full placement can build a physical clock tree with `--set synth.place.pcrs.clock=true`.
Reset distribution has its own switch, `synth.place.pcrs`, which defaults to on.
On a supported technology, full native CTS also builds the technology’s default VDD/VSS
grid and inserts handoff taps. `synth.place.pg=off` selects an external grid. Without native
CTS, `synth.place.pg=auto` enables the same grid independently. A positional JSON file
can tune the grid for a design. The DEF export includes `power_grid.json` with the
effective dimensions and supply pin names. HighTide checks the imported VDD/VSS
connections and reuses this grid. Placements without a native grid use ORFS tapcell and PDN.
See the [placement settings](../README.md#native-power-grid).

For the HighTide routing handoff, use `postroute.py --campaign DIR --out OUT run DESIGN VARIANT --clock-tree pcrs`.
Use a platform-qualified design such as `sky130hd/lfsr` for SKY130. An unqualified `lfsr` selects ASAP7. Provide the placement and scoring SDC from that platform's campaign. The report converts each stage's timing measurements to picoseconds.
Both clock-tree owners run the platform CTS legalization, timing repair and reporting sequence. Use `--cts-repair on` (default) or `--cts-repair off` on both sides of a comparison. The harness checks the actual CTS repair command in the stage log and estimates clock parasitics again at the legalized positions. To make a specific excluded master available during CTS timing repair, pass the repeatable option `--cts-allow-cell MASTER` to both arms. The harness checks the Liberty and physical master, records the effective list, and stores that experiment in its own run directory. Use `--cts-max-buffer-percent PERCENT` to override OpenROAD’s hold-buffer budget during CTS repair. HighTide records the limit seen on the actual repair command. Global-route repair is a separate setting. Use `--grt-repair on|off` on both arms to control incremental design and timing repair. Use `--grt-congestion strict|allow` for the initial global route and its incremental reroutes. Omitting either option uses the design’s setting. HighTide records the effective settings in global-route metrics and stores explicit policies in separate run directories. Use `--trial 1` and `--trial 2` to keep repeats in separate directories. Earlier runs appear as `legacy` because their CTS repair policy differed by clock-tree owner.
The HighTide comparison report gives final setup and hold slack, TNS and skew in ps. For imported placements the result also records the SHA256 of each LEF in read order and an aggregate digest. The report keeps runs with different physical views in separate rows. Its final parasitics column identifies SPEF extraction or the platform’s global-route estimate. A power-grid failure after extraction preserves the timing measurements and the failed stage. It counts native clock buffers from the placement manifest and checks their connectivity after detailed routing. It compares OpenDB instance names across handoff, CTS and global route to count newly added hold buffers, then counts the survivors at final extraction. The stage report gives the physical area of each set in µm², using the master present at that stage. It excludes `hold<number>` names present at handoff. The report identifies archived stage counts taken from the resizer, whose internal counter can restart within one repair command.
LiveHD records each clock net by its driver pin so final DEF export preserves `USE CLOCK` through net renaming.
After a source edit, running `lhd synth` again in the same workdir can retain clock-buffer names from the previous
physical generation. PCRS matches the clock source pin, then matches branch members from leaves to root. It
recomputes connectivity, placement and electrical sizing for the edited graph. The cache checks the technology,
options and saved handoff before supplying the previous identities.
A distribution with `root_buffer: null` drives its `retained_sinks` or `gate_leaf_sinks` directly. The manifest records their predicted wire delay from the source pin in `estimated_direct_sink_arrivals_ps` when the fitted topology survives gate cloning.
HighTide checks these loads and the buffered branches at DEF import, protects their clock cells and nets,
and writes propagated clocks at the CTS stage. After routing it reopens the final ODB and checks the drivers,
loads, protection, clock wires and nondefault routing-rule widths and spacings. A successful check sets `routed_clock_topology_verified` in the run record.

With `synth.place.pcrs.source_fork=true`, a characterized clock source can drive several top-level buffer inputs directly. PCRS compares the modeled source delay at the combined pin and wire load with the fastest legal two-stage path through a shared root. It prices each root driver together with its input load on the existing source. A branched root inside a placement home uses the same comparison as a chunk entry. Direct drive must meet source fanout, capacitance and receiver slew limits. The report names all directly driven buffer instances in `root_buffers` when there are several. HighTide verifies each input against the same source net after routing.

### Chunk clock entries

With an accepted multi-chunk floorplan, each clock leaf belongs to one home. PCRS uses the floorplan's color or macro assignment even when sink positions overlap. Ports and cells added after planning can use the nearest accepted region. The clock tree connects one entry per receiving home of each buffered distribution. A clock generated and consumed in the same home can use its existing output pin as the entry. The clock and latch pins of a discrete gate assigned to different homes keep their original common clock connection.

`lhd synth chunk clocks --workdir W` lists the entries in the saved tree. Add a chunk ID such as `0:1` to inspect its pins and estimated arrival from each physical clock source in ps. `--report DIR/pcrs_clock.json` selects an exported snapshot. To inspect extracted timing, pass `--routed PATH/6_clock_chunk_arrivals.tsv` from HighTide's final design results. HighTide checks membership and connectivity, reads the final SPEF, and measures early and late rising and falling propagated clock arrivals at each entry. Data paths through a gate enable are excluded. Those absolute times include the clock waveform edge. An unavailable edge has a null value. The CLI verifies the clock report digest before combining the two measurements.

For a primary clock port without an SDC driving cell, `source_fork=true` can connect chunk entries directly when the modeled load fits within the original clock net's pin and wire capacitance. For a buffered entry going into one remote home, PCRS evaluates the source and entry delays together when choosing its drive strength.

Add `--extracted-hold` to the HighTide `postroute.py run` command to try hold repair after detailed routing on either CTS method. The pass extracts the routed checkpoint with the platform's OpenRCX rules and runs hold repair only if hold fails. OpenROAD legalizes the new cells around the original placements and reroutes the trial. A fresh OpenROAD process reopens the candidate, re-extracts it and checks timing, annotation, placement, DRC, antenna and electrical limits. On native trees it also checks the protected clock connectivity and routing rules. Acceptance requires lower hold violation magnitude in total and preserves setup and hold at individually failing endpoints within 0.001 ps. If the ordinary trial reaches extraction and fails its acceptance checks, the command retries from the original routed database. This retry targets negative hold slack with a zero repair margin and fixes existing routed clock paths during detailed routing. It checks their rules and metal geometry before restoring their original wire objects. Both trials use the same extracted timing and physical checks. An accepted retry records `fixed_clock` in `selected_attempt` and keeps the first trial under `initial_trial`. The selected ODB goes through the normal fill and signoff stages. The run record includes the decision and measured slacks under `extracted_hold`. For each scored trial, `trial_wire_delta_um` gives the change in detailed-route clock and data wirelength relative to the input, including rerouted nets whose terminals stayed the same. Accepted trials retain `extracted_hold/before.odb` next to the post-route checkpoint.

With native clock synthesis enabled, `synth.place.pcrs.cluster_strength=0.25` adds placement-only two-pin anchors during final cell GP. The default is zero. Each checkpoint groups movable flops by clock driver, requested arrival and accepted chunk using the hard clock planner's electrical limits, fanout and radius. Every pair within a leaf gets an anchor. A movable integrated gate, or a discrete gate whose stored enable matches its clock phase, also gets an anchor to each member. A gate that serves multiple leaves divides its total anchor strength equally among them. Each leaf distributes its share over its member flops before the data-criticality adjustment. The checkpoint reports the number of gate-to-flop pairs as `gate_anchors`. At each checkpoint, `previous_anchors` counts the pairs present in that placement and `retained_anchors` counts those whose endpoints remain connected by an anchor after regrouping, regardless of weight. Provisional grouping fits and refines the hard planner’s leaves before trunk construction. Each GP step weights these forces by placement overflow and each checkpoint accounts for data criticality and group size. The anchors stay out of the physical netlist, HPWL, routing, and timing. `pcrs_clock_clusters.jsonl` records the groups, pair count, infeasible domains and leaf star wirelength in micrometres. Timing rounds that already have a physical tree trace through PCRS distribution buffers to find each original gate or source. This lets a timing round regroup members across its previous leaves. After the last tree build, final legalization can run further GP steps to relieve routing congestion. These steps use the installed leaf memberships. The iteration-zero record in the final stage has `installed_leaves=true` and includes the gate anchors. The clock manifest records final member distances at the exported pin positions under `final_placement` for each leaf.

HighTide's `postroute.py run --cts-clock-rc routing-layers` uses the configured clock routing layers for placement-based timing estimates after clock-tree construction. Both tree owners use the platform's per-layer resistance and capacitance from `MIN_CLK_ROUTING_LAYER` through `MAX_ROUTING_LAYER`, averaged by direction for each timing scene. The resulting estimate guides CTS timing repair. The route report records the layer names. The default is `--cts-clock-rc platform`. Use final extracted slack to compare the policies.

Run `postroute.py clock-wires DESIGN WORK` in the HighTide comparison tools to measure a completed route. `WORK` is the deployed directory containing the ORFS make wrapper. The command reports extracted clock-net capacitance in fF and detailed clock and data wirelength in µm, using final OpenDB clock roles. Run `postroute.py clock-paths WORK` for extracted setup and hold skew on register-to-register paths. It samples up to 100 endpoints per timing path group and sense. Use `--include-pairs` to compare matching register clock pins and waveform edges across trees. Each pair reports its worst sampled slack, the data startpoint and endpoint, the last launch and capture clock drivers when present, and the clock insertion delays measured from the respective waveform edges. To trace specific data endpoints, repeat `--to-pin` with their exact OpenSTA names, for example `--to-pin 'register_file._mem[42][29]/D'`. Targeted reports include paths from input ports and to output ports. With `--include-pairs`, the `unpaired_paths` list gives the available launch or capture clock insertion for I/O and cross-clock paths. Only pairs with both propagated paths on the same clock enter the skew distribution. Detailed path rows report elapsed data-path delay. When the handoff hold-cell inventory is available they also count inserted hold buffers on each data path and sum their cell delays. Interconnect delay is excluded from that sum.
Use `postroute.py clock-wires DESIGN WORK --per-net` to inspect the final pin membership, detailed wirelength and extracted wire capacitance of each routed clock net. The report gives the sum and maximum of the Manhattan distances from sink pins to the center of their bounding box, in µm. When a net has one located driver, `driver_star_um` sums the distances from that driver to the same sinks. Positions come from OpenDB after legalization. A missing sink location is listed on its net.
Use `--stage grt` to measure the same pins after global routing. This reads the global-route database and estimates parasitics from its guides. The totals include reported values, and the output lists clock nets missing a wirelength or capacitance estimate. With `--per-net`, a missing value is JSON `null`. The default stage uses final detailed wirelengths and extracted SPEF.


Run `postroute.py hold-chains DESIGN WORK --stage grt` to trace the physical hold buffers left by repair. The JSON report counts buffers by upstream driver, ranks the largest sources, and measures stage depth to each load outside the tree and Manhattan distance between consecutive buffers. The stage can be `cts`, `grt` or `final` (default). The comparison uses the saved handoff names or the original placement database to exclude pre-existing instances.

For a matched CTS or global-route placement failure, `postroute.py run --repair-displacement-um 120` retries the standard legalizer after a placement failure (DPL-0036) or a failed placement check (DPL-0033) on either clock method and stores the run separately.

With physical clock synthesis enabled, `synth.place.pcrs.gate_merge_trials=2` times both survivor choices for the first
nearby pair of identical integrated clock gates. Candidates come from the four closest eligible neighbours in the placement plane. Larger budgets consider more choices. Each pair must share the same
clock, enable and test-enable nets and drive private flop clocks. The default trial budget is zero.
PCRS compares both survivor choices for each pair in distance order. Each accepted merge becomes the starting layout for the next pair.
It compares complete buffered layouts using estimated RC, checks the
removed gate's timing obligations at the survivor, and rejects a new setup or hold failure or any worsening of an existing violation.
Supply a JSON object mapping physical clock-net names to activity fractions in [0, 1] with `synth.place.pcrs.gate_activity=FILE`. With activity, PCRS ranks survivors by the normalized gain in area, switched clock capacitance and gating-check slack. Unspecified gated nets use activity 0.5 and ungated nets use 1. Without measured activity, PCRS still checks the cost and breaks ties in favour of saved area. Clock-arrival limits are measured from the original tree across all merges.
`pcrs_clock.json` records the baseline, each survivor, saved area, timing and decision.

With `synth.place.pcrs.gate_leaf_trials=1`, PCRS also tries using an integrated gate as the leaf driver for a group
of 6–30 flops. The existing gate drives the clock pins directly when its characterized fanout, capacitance and
slew permit the load and propagated timing passes the same endpoint and arrival checks. Trials run after gate merging.
`gate_leaf_trials` in the report shows the decision and area saved by each trial, and `gate_leaf_sinks` lists the
flop pins driven by each accepted gate. The default trial budget is zero.

With `synth.place.pcrs.gate_raise_trials=N`, PCRS considers connecting a shared gate directly to the source when it is the only consumer of its parent distribution tree. It replans the downstream tree and verifies the gate and all sink timings. The report records the decision under `gate_leaf_trials` with operation `raise_gate`. The default trial budget is zero.

With `synth.place.pcrs.gate_clone_trials=N`, PCRS times up to N local gate copies after leaf scheduling and before hold repair. The default is zero. A copy shares the original enable and test nets and directly drives one existing leaf of 6–30 flops. PCRS first connects each copy to the original gate's clock net. If a timed copy fails the hold, arrival or electrical checks and budget remains, it can try the input of the PCRS identity buffer driving that gate. The report records that input as `clock_tap`. The other flop groups keep their buffer assignments. PCRS checks the original gate master first. If its drive or legal site is insufficient, it tries pin-compatible gate masters in increasing physical area. Substitution requires matching Liberty latch or state-table behavior, output functions and gate style. The no-sizing policy restricts a copy to its original master. PCRS checks propagated timing at the old and new gate controls, endpoint slack and electrical limits. The clock-arrival bound applies to the new gate input as well as the flop clocks. The `gate_clone_trials` report records the tested leaf, decision, site, area change and timing. An arrival or hold rejection also records the limiting pin, its measured value and its bound.

## Clock

When a local gate copy meets electrical limits but fails propagated timing, the remaining clone trial budget can try other pin- and function-equivalent drive strengths at that site. Each size is legalized and timed with its actual input loading. A setup rejection records the endpoint with the greatest loss beyond its allowed slack.

Run `lhd synth design.v --top TOP --workdir W --set synth.liberty=LIB --set synth.pcrs.clock_report=true` to inspect the mapped clock structure before placement. The report is `W/synth/pcrs_clock_structure.json`. It also follows `--emit-dir report:DIR`. Timing and placement can both be disabled.

The report traces each Liberty state clock pin through buffers, inversions and integrated gates to its structural root. A primary input or the output of unrecognized clock logic starts a domain, so one SDC clock can have several structural roots. For a logic root, the report gives the driver master and the signal connected to each input. A domain lists flop, latch and memory clock pin counts, both flop edges and maximum gate depth. Functions group gate clones by their parent function, clock polarity, gate style, enable and test control. Enables driven by the same positive conjunction of up to six signals can share a group. A flop is counted in the function of its last gate. The below-six and above-thirty fractions use all mapped flop clock pins as their denominator. Constant clock sources, incomplete bindings and native memories are counted separately.

The gate census traces discrete gates through clock buffers and inverters. It distinguishes a transparent enable latch from a flip-flop that samples on the edge entering the inactive clock phase. The gate and its storage clock must trace to the same source. The `_edge_enable` style records a sampled enable, and `_low_enable` records active-low data. Physical planning preserves the actual clock pins and the native timer retains flip-flop data timing. An opposite-edge enable flop launches a half-cycle data path. Its clock arm and the gate’s clock arm can each receive repeaters to meet electrical limits. A transparent latch and its gate retain the phase links from their common fork.

Feedback in `items` is ordered by the affected pins' Liberty capacitance in fF. For mixed edges the cost covers the less common edge. The report lists the integrated gate masters allowed by the mapper and counts library entries marked `dont_use`. A gating recommendation gives the gate output, and a pair differing by one positive AND term in the same module occurrence also gives the related gate. Each item includes the source location if the mapped gate or an affected sink carries one. Missing capacitance and missing source records are explicit. Capacitance is the sum of the available pin loads at the synthesis corner. Switching activity and interconnect are outside this estimate.

After placement optimization and before final legalization, PCRS groups the clock sinks by position, pin load and slew limit. A hard macro has its own leaf. PCRS selects identity buffers from the physical cell library and checks the source wire as well as the inserted stages. A primary clock port uses its SDC input transition or driving cell when supplied. Clock gates and inverters keep their functions and drive separate subtrees. A source wire that exceeds the modeled limits can receive repeaters. The planner and propagated placement timing use the platform’s clock wire resistance and capacitance when provided. An explicit resistance and capacitance override applies to both clock and signal wires.

PCRS recognizes discrete clock gates when a latch and an AND or OR gate share the clock phase required for gating. It follows existing inverters and buffers to the last common clock net. Both pins at that fork stay on one clock-tree leaf. The connections from the fork through the existing phase logic to the gate and latch are preserved. PCRS can move a placed buffer or inverter on a private, unrouted phase path to a free compatible row site closer to the latch or gate it drives. Shared phase drivers keep their placement. This also applies when one gated clock feeds another gate. In `pcrs_clock.json`, `discrete_clock_gates` lists the matched gate, latch, and fork pins. `relocated_phase_cells` names the instances that moved. A network’s `retained_sinks` lists pins still driven directly by its source. A network serving only retained sinks has an empty `branches` array and a null `root_buffer`.

When a private phase cell moves, PCRS first groups sinks at their original positions. It moves the fork pins into the region of a stationary member, then checks loads, slew and wire lengths at the new positions. This keeps a small gate edit from splitting otherwise unrelated launch and capture flops. If the resulting tree is electrically infeasible, PCRS repartitions the domain. The network report records which tree used the original regions in `used_previous_leaf_regions`.

A long source wire feeding or leaving a clock gate may require a series of repeaters shared by all downstream branches. Among legal chains of the same minimum depth, PCRS compares delay at the actual wire lengths, including the new load on the existing source. Equal-delay candidates use the smaller area. On independently buffered inputs to a discrete gate, the balance trial evaluates the faster feeder chain against the nominal tree. The report identifies the selected networks with `minimize_source_latency`.

With `synth.place.pcrs.balance=true`, PCRS also tests the drive strength of the first two stages when a source repeater feeds a common trunk. It evaluates their combined delay at the actual wire lengths, including the extra load on the source. Each stage can use an equal-area driver or the next larger footprint. If full balancing fails its timing guards and a primary clock has a shared pair, PCRS keeps the nominal topology and tries sizing both stages, then the first stage alone if needed. Each trial must improve a setup or hold violation and preserve endpoint floors and electrical limits. The clock offset budget for all subsequent edits starts at the original nominal tree. The clock manifest records each attempted stage count, timing and limiting pin under `useful_skew.source_drive_trials`.

For a drive-strength comparison, set `synth.place.pcrs.leaf_drive_steps=1` with the clock tree enabled. At each leaf, PCRS tries the next buffer with lower estimated stage delay and equal or better slew at the actual load. Higher values try further steps. Parent loads and source-wire limits are recomputed. If the source or trunk cannot support the trial, PCRS retries with fewer steps. The default is zero. The JSON records the requested count and the achieved count at each leaf.

To schedule individual leaves, pass `--set synth.place.pcrs.leaf_schedule=FILE`. The JSON object maps a physical sink pin from a leaf's `children` list to an absolute drive step. For example, `{"launch_reg:CK": 2, "capture_reg:CK": 0}` strengthens the launch leaf and slows the capture leaf relative to a default step of one. PCRS applies the schedule after grouping and rebuilds the trunk using the resulting loads. With balancing enabled, different requests on one physical leaf split its members by drive. The nominal reference honors the same requests. With balancing disabled, conflicting requests on one leaf fail. Unknown pins, incompatible requests within one discrete gate fork, and unavailable drive steps fail before clock cells are inserted. Evaluate setup and hold across the whole design when selecting a schedule.

Set `synth.place.pcrs.skew_rounds=N` to select leaf sizes using propagated setup and hold timing. For a failing setup path, the search tries earlier launch and later capture. For a failing hold or removal check, it tries later launch and earlier capture. Each round tests the proposed leaf changes individually and together using placement Steiner RC. If speeding up the worst hold path’s capture leaf improves hold but pushes sibling capture endpoints below their floors, the scheduler retries those leaves together. They must share the same immediate clock driver. Each affected leaf moves one drive step and the entire trial is timed again. When a hold improvement costs setup, the search also evaluates adjacent drive sizes on the limiting setup path together with that hold edit. A hold repair can spend positive setup slack while keeping every endpoint that already fails setup from getting worse. The search preserves endpoint coverage, hold bounds, setup TNS and electrical violation counts. It prefers a reduction in hold violations when both kinds of check fail. Manually scheduled leaves stay fixed. Zero rounds (the default) skips the search. The `useful_skew` report records which endpoint and check motivated each trial and the timing of the accepted layout.

Automatic scheduling limits each sink’s change in propagated arrival to `synth.place.pcrs.skew_period_fraction` times its own clock period (default 0.05). It compares early and late rise and fall arrivals at every timed corner with the tree at the start of the search, including any user-supplied leaf sizes. Set `synth.place.pcrs.skew_hold_margin_ps` to protect a positive hold reserve at every endpoint (default `auto`, 29 ps for the measured ASAP7 RVT library and 0 ps elsewhere). A pin already below that reserve must retain its previous slack or improve. The report names the pin with the largest rejected arrival shift or hold shortfall and gives the measured values in ps. Its trial list records the launch and endpoint, leaf edits, timing, and selection or rejection reason for each alternative.

Set `synth.place.pcrs.hold_area_um2` to a positive buffer area budget to repair residual hold after leaf scheduling. PCRS ranks each signal net and eligible identity buffer by estimated hold TNS recovered per square micron. It sums the recoverable slack of failing loads sharing that net, caps the credit at each load’s deficit, and uses the faster characterized rise/fall delay at the combined pin load. It retains two masters per net and shortlists six candidates overall. It first times up to four distinct nets together at free compatible sites. Each edited net must recover hold slack at its own endpoints. If the combined edit fails, PCRS retries the shortlisted candidates individually and spaces out further batch trials while rejections persist. An area budget can therefore fund shared reset-removal repairs and dedicated delay cells on individual data paths. It reconnects only failing loads on that net, including asynchronous reset checks, and retimes the entire layout before accepting each insertion. Acceptance preserves existing setup violations, passing setup checks, endpoint hold margins, clock-arrival bounds, and electrical violation counts. The default budget is zero. The `hold_repair` object under `useful_skew` records the selected timing, added area, each buffer’s site and loads, and why repair stopped. All area values are square microns.

After clock construction, timing uses the design’s SDC exceptions and includes data and reset recovery/removal checks on the physical tree. The temporary control-net cuts used for pre-CTS placement end at that handoff.

The graph and the DEF passed to final legalization contain the same clock connections. The exported DEF marks these nets with `USE CLOCK`. The adjacent `pcrs_clock.json` records the root, branch membership, source wire length, load, estimated slew and repeater count. These estimates use the planned buffer positions. Use the emitted `pcrs_clock.sdc` for propagated timing on the physical result.

Balancing (`synth.place.pcrs.balance`, on by default) inserts physical clock buffers on early arms. The planner propagates downstream insertion through integrated and recognized discrete clock gates and characterized clock buffers and inverters. A retained phase pin contributes its downstream delay even when it remains on the existing clock source. A `synth.place.pcrs.arrival_targets` JSON object can assign a pin an internal `insertion_ps` and a relative `wanted_ps`. Setting only `wanted_ps` preserves the internal delay from Liberty. Set `insertion_ps` to zero to override it explicitly. Within each chunk the balanced planner groups ordinary pins by downstream plus internal delay minus the requested arrival. The requested range within an ordinary group is at most half the shortest characterized buffer stage. When multiple arrival bands compete in a chunk, ordinary pins can share a leaf only when their modeled pin-to-pin wire-delay spread also fits that window. A coupled phase fork retains one leaf. Leaf fitting still enforces electrical and geometric limits. Explicitly isolated sinks keep dedicated leaves. Different explicit drive requests on a shared balanced leaf split only that leaf. Pins in the same discrete gate fork must request compatible drives. The provisional placement anchors use the same arrival groups. The reported target skew measures the spread of effective arrivals across buffered and retained pins, including downstream and internal insertion and each pin’s requested arrival offset. The scheduler checks a balanced candidate against the nominal tree and keeps the nominal tree when an endpoint, electrical or offset bound fails. If the nominal timing check is unsupported, the scheduler skips the balanced trial. The clock manifest lists the SDC, clock-phase or gate-check reason under `useful_skew.unsupported_checks`.

Set `synth.place.pcrs.leaf_fanout` (default 24, range 2–30) and `synth.place.pcrs.leaf_radius_um` (default 0, unlimited) to bound grouping. The fanout limit applies to the stages PCRS plans. Pins that stay on the existing source count against that source's own Liberty limits.

Set `synth.place.pcrs.max_slew_ps` to bound the estimated transition each planned stage delivers to its loads. At the default of 0 the only bound is the library's `max_transition`, and the planner picks the smallest buffer that meets it, so long trunk stages can run at that limit. A target makes the planner use a stronger buffer or split the group. The existing clock source keeps its library limit. A target that no buffer can meet on a single load fails the build with the usual "no legal clock driver" message.

### Wire model, drive and balance defaults

These defaults come from the coralnpu tree-swap experiments and the A1 sweeps (see the PCRS review page of the todo hub).

- **Clock wire RC.** `synth.place.pcrs.clock_layers` (default `auto`) replaces the platform's `set_wire_rc -clock` by the layer RC of the layers the clock is routed on, averaged by direction. `auto` takes the two highest layers the wire RC file characterizes with `set_layer_rc` (M6 and M7 on ASAP7); give `M4-M7` or `M4,M6` for another set, or an empty value for the platform wire. On ASAP7 the platform clock wire is about 3.5 times the resistance of M6 and M7, which carry 75 to 95% of every clock net longer than 50 µm after global routing. The layer capacitance is taken 10% below the layer tables, because the hand-off routes trunks with twice the spacing. Against the global-route estimate of the 10,105 sinks of the coralnpu tree, the mean error of the latest arrival is 428 ps with the platform clock RC, 135 ps with the M4 to M7 average, 62 ps with the M6 and M7 average at table capacitance and 9 ps (median +0.8 ps) with the 10% lower capacitance. Planner, placement timer and `tools/clock_timing_report --clock-layers` use the same value. Calibrated on one platform and one design: sky130hd and nangate45 are unchecked.
- **Trunk drivers.** `synth.place.pcrs.trunk_drive_steps` (default `all`) gives each stage above the leaves the fastest legal driver at its load, as `leaf_drive_steps` does for leaves. A trunk stage is few cells and every sink below it shares its delay. Upsizing the 56 trunk buffers of the coralnpu tree by three drive steps took the latest capture clock from 1,179 to 869 ps after global routing.
- **Leaf fill.** A group above the fanout limit is cut into whole groups' worth, so leaves fill to `leaf_fanout` (coralnpu: 643 leaves of 15.7 pins became 425 of 23.8, and 691 clock buffers became 450).
- **Balance.** Subtrees whose sinks arrive at different times are kept apart until each band is one root. The band roots are joined last and the early ones are padded once with a chain of stages. Gaps below half of `skew_period_fraction` times the clock period are left alone. The value of `synth.place.pcrs.balance` is `true` (a balanced tree is kept when timing accepts it, or when no timing check can score it: a gate without a gating check, a register behind a clock inverter; `useful_skew.balance_decision` says `accepted_unverified`), `verified` (only when timing accepts it) or `false`.
- **Gate intervals.** A gate passes the earliest as well as the latest arrival of its own subtree to the domain above.
- **Sites.** A group that cannot be legal at the middle of its bounding box tries the coordinate medians, the load-weighted centre and, for a group of up to six, each pin's site.

### Viewing the tree

Under `lhd synth --gui`, the page's **clock tree** layer draws the built tree on the placement: stages coloured by depth, endpoints by estimated arrival or leaf slew, or a grid of local skew. The agent socket's `clock` command reports the same data and `clock_edit` stages leaf drives, wanted arrivals and the scalar options above before restarting the flow with them. `screenshot layers=...,clock` draws the tree without a browser. See the [agent socket guide](../../../.agents/skills/livehd/agent_socket.md#the-clock-tree).

 To measure technology-specific clock RC, use the routed DEF, SPEF and manifest from the same run:

```sh
bazel run //tools:clock_rc_fit -- --profile fit.json routed.def routed.spef pcrs_clock.json cells.lib setRC.tcl tech.lef cells.lef
```

The tool emits the predicted and extracted wire-only capacitance and summed resistance of every native branch as TSV. The profile scales the platform RC by the ratio of extracted to predicted totals, separately for leaves and trunks. Pass the profile as `synth.place.pcrs.clock_rc_fit=fit.json` to size the tree and evaluate scheduling trials. The existing source uses the platform RC.

Each buffered leaf reports its planned star wirelength in µm when its membership is unchanged by gate edits. After final legalization, the handoff records `final_placement` on each leaf and on gates that directly serve a leaf. Its center is the midpoint of the final member-pin bounding box. `star_wire_um` sums the Manhattan distances to that center and `max_member_distance_um` gives the farthest member.

Each leaf lists a nominal arrival time for each child pin in the same order as `children`. Times start at the source output pin. The planner uses the placement timer’s driver-rooted Steiner network with horizontal and vertical clock-layer RC, distributed wire and pin capacitance, and per-pin Elmore delay. Each buffer sees its own output net’s total capacitance. The network's `estimated_insertion` reports the earliest and latest arrival, their difference, and the largest arrival difference between children of one leaf.

In the HighTide PCRS handoff, OpenROAD routes the exported trunks using its clock nondefault routing strategy. The selected trunks retain the nominal routing width and get twice the nominal track spacing. Existing net-specific rules take precedence.

## Reset

A reset network is one reset signal and everything it reaches through identity buffers and inverters. Its roots are the
drivers carrying the synthesis reset role and the drivers of asynchronous clear/preset pins; each root is walked up to the
top of its chain (graph input, design flop, any other driver). The pass **rebuilds the distribution from its sinks every
call**: the previous buffers, inverters and pass flops are stripped, the loads are grouped, and a new tree is minted.

* **One balanced tree per (reset root, clock domain).** A sink's domain is the root clock of the flop it is (an async reset
  pin) or of the flops its reset logic feeds (the D pins within four cells, majority). The root clock is found through
  integrated clock gates and identity buffers, so a gated flop uses the ungated clock and the reset still arrives while
  the clock is stopped. Reset crossing domains is a clock-domain-crossing problem and is not synchronised here.
* **N flop levels, same N for every sink of a domain** (`synth.place.pcrs.reset_pipeline`, default true; false = 0 levels). The domain's reset is delayed exactly N cycles everywhere, so the
  design behaves as before after a longer reset. N is a timing choice (0 is a plain buffer tree). Both polarities of a
  domain share N; an inverter in front of the tree (or the parity of an inverting-Q flop family) keeps each sink's
  polarity. Asynchronous reset pins are served the same way: the reset is registered to the clock edge.
* **Fanout.** No driver of the tree carries more than `synth.max_fanout` loads (default 16): a reset tree is ordinary logic. Level sizes follow
  from the sink count: `ceil(sinks/f)` leaf flops, `ceil(that/f)` above, and a buffer tree in front of level 1 if needed.
  Sinks cluster by placement when positions are known (recursive bisection), else by instance name (source hierarchy):
  the placer passes the positions of the placement a call starts from, and the first such call rebuilds every tree
  once (`Options::regroup`) so a tree made before placement does not keep its name-order groups. The root serves
  every clock domain of its network; when the domains together put more than the cap on it (many small gated-clock
  domains), its loads go behind one buffer tree. A graph output behind a buffer returns to the root undelayed.
* **Cells.** The plain posedge flop, identity buffer and inverter families of the Liberty that the LEF can place. A
  cell is the smallest of its family that the pins and the wire it drives leave at half its capacitance limit
  (`Options::wire_ff_per_unit` and the positions give the wire; before a placement only the pins count), and the
  root gets one sized buffer when its load is more than the smallest buffer would carry. Names are
  `<hierarchy>.__pcrs_rst{f<level>|b<level>|i<level>|r0}_<id>`, where `<id>` is derived from what the cell drives:
  every placement stage derives the trees again and finds a cell's place from the stage before by its name, so
  the same loads must give the same name and other loads another (the master may differ by a size; the netlist's
  wins). Generated cells use the load's logical hierarchy. The hash includes the physical sink names, so loads
  in different anonymous placement regions stay distinct when the clock pins pass through legalization.
  Flops carry the node attribute `pcrs_stage` (low 16 bits the level,
  bit 16 = inverted Q).

### Depth

`Depth_state` holds the wanted depth per domain (`root@clock`), shared by every placement call of a flow
(`Options::pcrs_depth`). The default policy keeps the depth already in the graph and starts a new domain flat when one
driver can serve it, with one flop level otherwise. A network whose domains all keep their depth is not touched, so its
cells keep their names and placement.

* `retarget_for_wns`: when a cell of a domain is on the worst setup path, add one level to that domain (one domain per
  call). TNS is never consulted: the clock goal may be unreachable.
* `retarget_shrink`: at the last timing round, take one level from a domain whose flop D/Q pins have slack beyond their
  longest hop arrival (merging two hops costs about one more hop).

`timing_place` applies both before each warm round; the round's placement then rebuilds from the new depth.

### Placement and timing

With pcrs on (`Prects_library::reset_is_data`) a reset is ordinary data: it is placed, timed and repaired like any net,
and only clock networks stay excluded. pcrs decides the structure (flop levels, groups) and sizes each cell for its
load; repair then works on the tree like on any data net, splitting the long nets and resizing on real RC and slack
(a sized buffer on 32 loads spread over the die is still a slow wire: NVDLA partition_c went from -2.2 ns to -0.23 ns
when repair was let in). A pcrs rebuild of a network strips whatever repair added to it. `qor.place.pcrs` reports `networks`, `sinks`, `flops_added`/`buffers_added`/`removed` (this call), `flops` (in the
placed netlist), `max_depth` and per-domain `depth`/`sinks`/`flops`/`buffers`/`kept`. Post-placement simulation must hold
reset for at least `max_depth + 1` cycles.

### Formal

`bypass_stages()` replaces every tagged flop by a wire (a `Not` for an inverting Q) when `lhd lec` loads an `lg:` side, so
LEC compares the design as if the tree had no stages whatever depth timing chose. The `lg:` directory on disk is not
changed. A placed netlist written as Verilog loses the tag and is not bypassed.

### Not handled (yet)

Domino storage reset pins (`synth.place.reset_pins`) keep the legacy tree. Loads that are not placeable library cells
(graph outputs, macros) keep their direct connection to the root. Depth changes happen between timing rounds, not inside a
GP checkpoint.
