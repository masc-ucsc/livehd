#       \buffer_pc          WIDTH 49  SIZE 2  RD_PORTS 5  WR_PORTS 2

#       \u_inst_data.rf_q   WIDTH 256 SIZE 2  RD_PORTS 2  WR_PORTS 1
#                           RD_CLK_ENABLE 2'00     RD_TRANSPARENCY_MASK 2'00
#   * the shortest cycle through each memory LEAVES on a read-data driver pin
#     and RE-ENTERS on a WRITE-port pin, never on a read port's `addr`:
#       memory_18584.p1 (read data) ... or_83816.p0 -> memory_18584.p3   = port 0 `din`
#       memory_18576.p5 (read data) ... mux_89964.p0 -> memory_18576.p20 = port 1 `enable`
#     (Memory sink pid = port * Ntype::Memory_port_stride + offset; offset
#      0 addr, 3 din, 4 enable -- graph/cell.cpp.)

# CLASSIFICATION: a LOWERING/TRAVERSAL DEFECT, and specifically a dependency-
# GRANULARITY one.  Not a genuine RTL loop, not a packed aggregate
# self-reference, not a latch artifact.
#
#   `reachable_topo_order` (pass_lean.cpp) models a Memory cell as ONE atomic
#   node, so any path from ANY read output back to ANY write-port pin is a back
#   edge.  The real dependency is per port, and the certificate builder this
#   walk feeds ALREADY knows it: `cert_memory_expand` composes a read's base
#   image from `build_chain(fwd_ords)` -- the FORWARDED write ports only -- and
#   gives a SYNCHRONOUS read port a register SOURCE (`s.<reg_field>`, source
#   kind 2) rather than any function of this cycle's inputs.
#
#   For \u_inst_data.rf_q the forwarding matrix is 2'00: no read port sees that
#   write port's data in the same cycle, so the measured read->din path is not
#   a dependency the certificate has.  For \buffer_pc the cycle leaves on
#   driver pid 5, which with WR_PORTS 2 is read ordinal 3 -- one of the two
#   ports RD_CLK_ENABLE 5'11000 marks SYNCHRONOUS, i.e. a registered output.
#
#   The IR agrees: `Ntype_op::Memory = 41` is an ODD slot, and bit 0 IS
#   `is_loop_last` (graph/cell.hpp, with a static_assert).  hhds documents its
#   topological traversals as breaking the combinational cycle at exactly those
#   nodes.  pass.lean's walk is the one consumer that bypasses `forward_class`
#   for a hand-rolled DFS (its own comment says so), and it is the one that
#   treats a Memory as combinational.
#
# WHAT IS STILL OPEN.  This part identifies the mechanism; it does not yet fix
# it.  The fix must be generic (a per-port dependency model, not a special
# case), must keep refusing a cycle that closes through a FORWARDED write port
# -- which is a real combinational path -- and needs a minimized RTL fixture
# plus a mutation-sensitive differential or LEC gate before the other three
# Class-A modules are re-run.


###############################################################################
# PART 4.  The fix: per-port memory dependencies, ordered over the certificate
###############################################################################
#
# `reachable_topo_order` modelled a Memory CELL as one atomic node.  The
# certificate's dependencies are per PORT, and `cert_memory_expand` already
# knew that -- a read's base image is the chain of the write ports FORWARDED to
# it and of no others, and a SYNCHRONOUS read's output is a register source.
# Only the ordering pre-pass over-approximated, and it did so at cell
# granularity, where read-output -> logic -> write-input is a self-dependency.
#
# WHAT CHANGED.  Four phases, the order of the first three forced:
#   1. every Memory's externally visible read ids are RESERVED (a memory's port
#      pin may be driven by ANOTHER memory's read output, so no memory's
#      dependencies can be built until all of them have ids; the memories are
#      taken in nid order so nothing depends on graph iteration order, and
#      cert_memory_fill refuses to run before the count is complete);
#   2. each Memory is FILLED -- write chains, operand resizes, per-port deps;
#   3. the ordinary combinational nodes are built;
#   4. ONE topological order is taken over the COMBINED certificate DAG
#      (`cert_dag_order`, lean_common.cpp), not over the LGraph node vector.
# A Memory is now a traversal boundary like a flop, and its port cones were
# already explicit roots.  The sort is STABLE, so a design with no memory is
# ordered exactly as before.
#
# A cycle that survives phase 4 is a cycle in the MODEL -- a read forwarded
# from the write whose data it feeds -- and is still refused, now naming the
# memory, the port and the whole path.
#
# EVIDENCE.
#
# No regression, over the 105 accepted CORE-ET certificates (re-emitted from
# each one's stored lgdb_norm with scripts/cert_reemit_diff.sh, so only
# pass.lean re-ran and any difference is attributable):
#     identical=76 changed=29 emit-failed=0 missing=0 of 105
#     memory designs=29  non-memory designs=76  unexpected changes=0
# The split is exact: every design that moved has a memory, every design
# without one is byte-identical, and there is no crossover.  All 29 changed
# certificates are still ACCEPTED by checkDesign and ran 4 cycles (29/29).
# Two of them got SMALLER -- intpipe_csr_msgs by 2 nodes, txfma_f1 by 16 -- and
# every node dropped was UNREFERENCED in the old certificate (the memory clock
# cones the old walk pulled in and nothing ever read).  Both now have zero
# unreferenced nodes.
#
# The four Class-A modules, re-run end to end.  THREE ARE UNBLOCKED, and all
# three reach checkDesign ACCEPTED with the requested 4 cycles executed -- not
# merely "it emitted something":
#
#   module                         gen   verdict    nodes   wall_s   rss_kb  cycles
#   minion_frontend_thread_buffer  0000  ACCEPTED   18840    372.9        -       -
#   minion_dcache_top              0000  ACCEPTED   56878   4261.6        -       -
#   minion_frontend                0000  ACCEPTED   76871   7412.0 12193620       4
#   intpipe_csr_file               emit 7 -- still refused, see below
#
# `gen` is compile/single_edge/emit/static_gates, all zero.  minion_frontend's
# full row (run 34fac25b5_20261001-154122_2876382_29371):
#     sources=68189 nodes=76871 outputs=13 flops=281 mems=7 inputs=23
#     check_ms=1293 step1_ms=11494 run_ms=42867 cycles=4
#     wall_s=7412.0 rss_kb=12193620 (~11.6 GiB)
#   reason is EMPTY: a harness timeout would say "harness limit, not a model
#   refusal", and a refusal would carry its tag.  `.partial` and `.tmp` are both
#   absent beside a present direct_sweep.tsv, which is what says the run
#   finished rather than was interrupted.
#   `rtl_evidence = not-measured`: a census stops after emit, so the LEC gate
#   did not run for it.
#
# The other two ACCEPTED verdicts come from their sweeps' PROGRESS LOGS, not

# intpipe_csr_file is NOT a memory cycle: it refuses with
