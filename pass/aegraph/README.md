# pass/aegraph: acyclic e-graph constant propagation

`pass.aegraph` is a second constant-propagation engine for LGraph, an
alternative to `pass/cprop` behind one knob. It is a Cranelift-style acyclic
e-graph ("aegraph"): hash-consing, eager rewrites at insertion, no rebuild,
extraction, then elaboration back into the graph. The design and the plan are
`todo/livehd/2a-aegraph.html`; this file says what exists today.

**Status: milestone I (cost profiles, profile-driven extraction, the `:expect` tests) on top of H (mux, lane-write and packed-read rules, the latch-hold root, gate G2), G (analyses, mask/lane and Div/Rem rules,
the LEC preflight switch), F (the full CSE policy and the G1 measurements), E (the rulegen DSL), D (rule runtime), C (the A/B harness) and B (the
skeleton engine).** The engine hash-conses, folds fully known
cones and runs 77 rewrite rules through the rule runtime (`runtime/match.hpp`):
the pattern-shaped ones are written in `rules/*.rules` and generated by `rulegen`
(`tools/aegraph.bzl`), the rest are hand-written C++ (`rules/*.cpp`, native).
The e-graph engine is the default (since 2026-10-22); classic cprop stays as the reference and is not removed. Adding a rule is one entry in
a `.rules` file (see "Adding a rule").

## Selecting the engine

```
lhd compile foo.prp                                              # aegraph (the default)
lhd compile foo.prp --set compile.cprop.engine=classic           # the reference engine
lhd compile foo.prp --set compile.cprop.engine=aegraph
lhd compile foo.prp --set compile.cprop.engine=aegraph+classic  # aegraph, then classic, in each slot
lhd compile foo.prp --set compile.cprop.engine=aegraph --set compile.cprop.engine_slots=first
lhd sim foo.prp --set compile.cprop.engine=aegraph --set compile.aegraph.cost=sim           # price the LLVM simulator (auto = sim under lhd sim)
```

* `compile.cprop.engine` accepts only `classic|aegraph|aegraph+classic`. There
  is no `none`: at least one engine always runs. A bad value is rejected when
  the options are read, not when the pass runs.
* `compile.cprop.engine_slots=both|first|second` swaps only one of the two
  compile cprop slots (`first` runs before `pass.legalize`, `second` after
  `enableopt`); the other slot stays classic. Default `both`.
* The kernel does the dispatch (`compile_graph_passes`, `lhd/lhd_kernel_common.cpp`):
  the set name stays `compile.cprop` for every engine, and the driver merges the
  `compile.aegraph` set into a `pass.aegraph` step. `Pass_cprop::optimize`
  refuses any non-classic `engine` that reaches it.
* `low_lanes`, `loop_hoist` and `engine` are registered on `pass.aegraph` as
  INTERNAL labels (hidden from `lhd list options`): each knob has ONE
  spelling, `compile.cprop.*`, and `--set compile.aegraph.low_lanes` (or
  `loop_hoist`, `engine`, `engine_slots`) is rejected with that hint.
* The compile-cache descriptor names the resolved engine
  (`pipeline=cprop[aegraph:both],bitwidth`), so an engine switch never replays
  the other engine's graphs. `//pass/aegraph:pass_aegraph` is in
  `//lhd:compile_salt`.

## What one run does (`aegraph.cpp`)

1. **Pre-pass.** Tarjan SCC over the combinational structure (state and IO break
   cycles). A non-trivial SCC, or a self edge, is a combinational cycle that may
   be false at word level (a packed struct written field by field). The classic
   scalar rewrites (`Cprop::do_scalar`: packed-slice resolution, `Get_mask(Concat)`,
   `Set_mask` lane reads) run on the SCC members FIRST, in the pre-pass, and the
   body is re-examined: a ready/valid network of packed vectors (the shape of
   `br_amba_axi_demux`) leaves no opaque member (`PackedFalseCycleIsResolvedInThePrePass`).
   What stays cyclic is OPAQUE: never hash-consed, never folded.
2. **Build.** One forward walk. IO, state, `Sub`, `AttrSet`, `Clock_cell`, `LUT`,
   `runtime_check` nodes and non-exclusive `Hotmux` cells are skeleton leaves:
   their driver pins are leaf classes (a state output is also marked, `Egraph::is_state`).
   Before the walk three cheap scans run (`aegraph.cpp`): `mark_dead` (a pure node nothing live
   reads is dead on arrival and counts as no reader), `precount_twins` (nodes that will hash-cons to
   one class share one reader total, so `x + y` read by the output and, later, by `(x + y) + z` is
   not "single use" when the second reader is built before the twin: the flatten rule would
   otherwise absorb it and leave two `x + y`) and `pin_latch_holds` (a Mux that feeds a latch's din
   and takes the latch's own Q as a direct arm is a root: no rule rewrites it, latch contract rule B). A pure node is normalized (commutative
   banks sorted by class id, multiplicity kept: `Sum(a,a)` is `2a`, `Xor(a,a)`
   is `0`) and hash-consed on `op + operand classes + color + synth_policy +
   proven`. The `proven` code is in the key so a proven `Hotmux` never merges
   with an unproven twin. Names are not in the key.
3. **Constant analysis.** Every class carries a three-valued `Dlop` (or no
   value). A node whose operands all have values is evaluated with the same
   Dlop semantics classic folds with. The result becomes a constant ONLY when it
   is fully known (the P7 contract): a result with `?` bits stays a node, and a
   `?` literal is one const node that is never merged by value and never
   re-minted. Fully known constants are interned by value: a Boolean and an
   Integer of the same value are ONE class (the first spelling seen is the one
   realized); String, Bitwidth and Nil keep their own tag. A fold that is exactly an operand (constant-selector `Mux`, a
   shift by zero, a window covering a whole literal) forwards that operand's
   class. An out-of-range or disconnected `Mux` selection stays a `Mux` (Q1).
4. **Rewrite rules** (milestone D, see below). A node that is NEW in the e-graph
   is offered to the rules of its root op in priority order. A `simplify` result
   replaces the node's class (subsume); an `alt` result is unioned with it.
5. **Extract.** A class without unions is its first member (the original node).
   A union keeps its original side unless the alternative is STRICTLY cheaper under the
   cost profile (`compile.aegraph.cost`, "Cost profiles" below: width-aware and
   sharing-aware; `extractor_fuel` saturates the cost), so a tie never changes the graph.
6. **Elaborate (diff).** Original nodes that are class representatives are
   reused untouched: nids, names and srcids survive. An original node whose class
   a rule replaced is REBUILT IN PLACE as the rule's e-node (same cell, name,
   output pin and consumers; only its op and operands change, like the classic
   in-place rewrites); e-nodes no original node realizes become new cells. A duplicate is retired by
   reconnecting each consumer sink to the representative (snapshot the edges,
   `connect_sink`, then `del_node`). Guards: a ring that closes over a compact
   loop keeps the node (`closes_loop_self_edge`); a parallel edge that hhds
   would dedup keeps it; two named twins both stay (a named twin absorbs an
   unnamed one and moves its name). The retired root's width stamp is copied to
   the representative when that has none. Dead pure nodes are then deleted.

After elaboration `Cprop::do_post` runs the classic region passes (pack
canonicalization, vector-mux narrowing, muxctx, mux/op sharing, flop-enable
folding, dead-code sweep) and, with `low_lanes`, low-lane narrowing; then the
library-wide `loop_hoist`. Low-lane narrowing runs only in the slot BEFORE
`pass.bitwidth`: the kernel hands the second slot the INTERNAL label
`after_bitwidth=true`, which turns `low_lanes` off. After bitwidth a slice of a pack
that low-lane narrowing re-spells becomes a Concat declaring its full window, while
bitwidth has already dropped the `#[0..<n]` masks that only the unpacked spelling's
tighter range justified, so a lane driver can come out wider than its window (an
internal "Concat lane" error on XiangShan `fpsqrt_r16_block`; fixture
`inou/prp/tests/equiv/aeg_pack_slice_lanes`). Classic avoids it because its first
sweep already folded those slices. These are classic *sub-routines*, shared with
`Cprop::do_trans` through `Cprop::region_passes`; the engine never runs the full
classic forward sweep (that is what `aegraph+classic` does).

With every rule off (`rules_only=` naming no rule, or `rules_disable` listing
them all) the result is the input graph except for shared and folded nodes. The
engine is deterministic: class ids follow forward-walk order, the rule table is
sorted by (priority, group, name), and no decision iterates an unordered container.

## The rule runtime (milestone D)

```
runtime/match.hpp, match.cpp   Ctx, Results, PatternMatch-style combinators, the registry
rules/arith.cpp                bank algebra, booleans, comparisons               (group arith, native)
rules/shift.cpp                mixed shift composition                           (group shift, native)
rules/mux.cpp                  constant-arm Mux logic                            (group mux, native)
rules/*.rules, analyses.decl   the pattern rules, in the DSL                     (generated, see below)
```

A rule is a function over the e-graph; it never touches an LGraph handle.

```cpp
AEG_RULE_GROUP(arith);
AEG_RULE(not_not, simplify, 30, Ntype_op::Not) {         // name, tag, priority, root ops
  Class_id x = kNoClass;
  if (match_root(ctx, root, Ntype_op::Not, m_op(Ntype_op::Not, m_bind{&x}))) {
    out.subsume(x);                                      // Not(Not x) = x
  }
}
```

* **`Ctx`** reads classes (`known`, `is_int`, `small_int`, `bool01`, `eq_against`,
  `each_member`: fuel-limited iteration over the members of a union; a rule that scans every
  operand of an n-ary root calls `grant_fuel(arity * k)` first, or only the first few operands
  are ever read) and builds
  e-nodes (`make`, `make_bank`, `konst`). `make` folds, normalizes, hash-conses and
  runs the rules of the new e-node, `rewrite_depth` levels deep. Pointers and
  spans obtained from `node_of`/`operands_of`/`known` are invalidated by `make`.
* **`Results`**: `subsume(c)` (tag `simplify`: the first match in priority order
  replaces the class), `add(c)` (tag `alt`: unioned with the class, up to
  `matches_limit` per e-node and `eclass_limit` members), `choice(...)` (tag
  `choice`, skipped while `choices=off`; no choice rule exists yet).
* **Combinators**: `m_any`, `m_bind`, `m_same`, `m_int`, `m_k`, `m_op(op, pats...)`
  (positional, exact arity), `match_root`, `match_root_each`. A pattern calls its
  continuation per matching member, so a later failure backtracks into the next
  member of a union.
* **`AEG_NATIVE_RULE`** is the same registration for rules no pattern can express
  (loops over a bank, region walks); `native` is recorded in the table: rulegen
  generates no proof obligation for them, so a native rule needs an equiv fixture.
  `Ctx::admits(literal, v)` / `admits_nonzero(literal)` are the `(admits ?q C)`
  guard of generated `choice` arms.
* **Registry**: `Rule_id` (1-based, in the order of the sorted table) and the
  dispatch table per root op. A rule registered after the first use is a bug.
* **Union nodes.** `Egraph::add_union(a, b)` makes a new class `uni(a, b)`; an
  aegraph never rebuilds, so neither side changes. A rewritten class leaves an
  `alias` to its replacement: a later hash-cons hit reads the replacement.
  `eclass_limit` is at most 32.
* **Soundness rules the hand rules obey.** Every rule is exact in cprop's
  unlimited-integer algebra. No rule creates a `?` spelling (P7): constants are
  combined only from FULLY KNOWN classes and a `?` literal is an opaque operand.
  A rule that flattens a cell requires the inner cell to have no other reader and
  equal attrs (color, `synth_policy`). A chain link whose only reader is a same-op,
  same-attrs cell leaves the work to that reader and the chain top absorbs every
  single-use link in one firing (an e-node is never freed, so flattening link by link
  would leave O(k^2) dead operands behind): a wide chain ends as one banked cell, as
  in classic, with no width cap.
* **Memory layout.** An `Eclass` is 20 bytes (the analysis value lives in a side
  table shared by index), an `Enode` 20 bytes (attrs are an index into a table of the
  few distinct color/`synth_policy`/`proven` combinations), operands 8 bytes in one
  pool, and the hash-cons table is a flat open-addressing array of `Enode_id`
  (no stored hash, no chains).

### The analyses (milestone G)

Guards may ask the facts of `rules/analyses.decl`; each is implemented with `AEG_ANALYSIS(name, n_class,
n_const)` in `runtime/analyses.cpp` and called by generated code as `an::NAME(ctx, classes, constants)`.
rulegen refuses a guard on a declared analysis without an implementation. A parameter is a class (a bare
name) or a constant `(k n)` in the declaration. The facts are lazy and memoized per class in the e-graph
(`Egraph::analysis_cache`), computed from the class's own e-nodes:

| analysis | meaning |
| --- | --- |
| `bool01 x` | 0 or 1 (structural, plus the interval [0, 1]) |
| `range x lo hi`, `nonneg`, `fits x n`, `sfits x n` | an interval per class (int128, saturating, rounded in the direction of each bound) |
| `known_zero x m`, `known_one x m`, `low_zero x n` | known bits of the low 64 (low-lane facts: shifts, multiples, packed words) |
| `exclusive x y`, `opposite x y` | disjoint bits; the (base, polarity) of a boolean and its `EQ(.,0)` |
| `has_lane x lo hi` | the persistent lane layout (Concat, Set_mask chains of any length, SHL, SRA, Or/Sum of disjoint shifted fields): the window lies in one lane of another class or of zero. A field wider than the 99-bit interval facts (a 10400-bit input bundle) still has a width (`unsigned_bits`: wide unsigned inputs, windows, Concats, Or/And/Xor, shifts), so a packed Or of wide fields keeps its layout; lane offsets and window constants go up to `kMaxLaneBit` (2^24) |
| `lt_always`, `ge_always`, `distinct`, `nonzero`, `zero` | relations decided by the intervals and bits |

Declared widths are facts: a graph input (its IO declaration) and a Flop/Fflop/Latch output with a stamp are
leaf classes bounded by their physical width (`seed_leaf`), so `a:U8 / 4` is a shift. Mux facts require
every connected arm and, for an n-ary Mux, a selector provably in range (Q1).

`bazel test //pass/aegraph:aeg_analyses_smoke` is the soundness fuzz: random e-graphs with concrete leaf
values; whenever the runtime says an analysis holds, its `:spec` from the declaration must hold on the
values, the lane layout is checked window by window against `Get_mask`, and the polarity against the
values; it also fails when `analyses.decl` and the `AEG_ANALYSIS` registry disagree
(`LHD_AEG_FUZZ_SEED`, `LHD_AEG_ANALYSES_GRAPHS`, `LHD_AEG_ANALYSES_VERBOSE=1` for per-analysis counts).

### Every fold site follows the engine (`livehd::fold_body`)

`compile.cprop.engine` is not only the two compile cprop slots. Every other place that folds a graph body
goes through `livehd::fold_body` (`fold_body.hpp`): `classic` runs `Cprop::do_trans` (byte for byte what the
site ran before), `aegraph` runs `optimize_body` (the engine plus the classic post steps), `aegraph+classic`
runs both. The kernel sets the engine ONCE per command (`apply_lhd_settings` -> `set_fold_engine`, the
`fold_engine` library, no dependency on cprop or the engine); the cost profile is `synth` at the synthesis
sites, `sim` at the sim-time fold, and the resolved `compile.aegraph.cost` elsewhere.

| site (`LHD_FOLD_BODY_LOG` name) | where | cost | low_lanes | bitwidth after |
| --- | --- | --- | --- | --- |
| `specialize.constants`, `specialize.refold` | `pass/specialize` (sim and synth private copies) | compile | no | yes |
| `cgen.sim.refold` | `inou/cgen/cgen_sim.cpp`, after a small loop is spliced flat (`sim.unroll_sites`) | sim | no | yes |
| `synth.state_sweep` | `pass/synth/state_sweep.cpp` (refold after constant registers go) | synth | no | yes |
| `synth.loop_cleanup` | `pass/synth/loop_cleanup.cpp` (guard scope: the cells the expansion minted; classic cutter only, the engine's guard rule is whole-body) | synth | yes | yes |
| `synth.memory_module` | `pass/synth/memory_module.cpp` (method level: `fold_graphs` runs pass.cprop / pass.aegraph) | synth | yes | yes |
| `satopt.cleanup` | `pass/satopt/pass_satopt.cpp` | synth | yes | yes |
| `formal.lec.preflight`, `formal.semdiff` | `lhd/lhd_kernel_formal.cpp` (the re-simplify after hierarchy inlining, the mixed-loop identity) | synth | no | NO: `Options::preflight` |
| compile.sweep | the per-round fold of `compile.sweep` runs the engine's pass methods like the schedule slots | compile | yes | yes |

Not folding sites, and so left alone: `Bitwidth_rewrite`, `enableopt` and `satopt` use `Cprop` as a helper
class (`Inp_pins`, `share_mux_regions`, the low-lane helpers); `legalize` and `semdiff` only mention it.

Caches never mix engines: the compile-cache descriptor names the engine (as before); every synthesis and
formal salt that a fold site can influence goes through `fold_salt_mix` (identity for `classic`, so classic
keys are unchanged) -- the ABC region/tmap caches, the usyn logical cache and provenance, and the formal
verdict cache -- and `//pass/synth:synth_salt` and `//lhd:formal_salt` hash `pass_aegraph`.

Observability: with `LHD_FOLD_BODY_LOG=1` each call prints `fold_body engine=<engine> site=<site>` on
stderr; `fold_count(site, engine)` reads the counters in-process. Tests: `fold_body_test` (dispatch,
counters, salt, `fold_graphs`), `SpecializeRefold.FollowsTheProcessWideFoldEngine`,
`//lhd/tests:lhd_fold_sites_test` (one command per site family under each engine, results PROVEN, region
cache keyed by engine), the `prp-sim-loop_*_{aeg,aegc,unroll}` fixtures and `equiv/loop_carry_kinds_4`.

### The LEC preflight engine

`--set formal.lec.preflight_engine=classic|aegraph|aegraph+classic` (INTERNAL) picks the engine of the
re-simplify after hierarchy inlining; UNSET it follows `compile.cprop.engine` (default `aegraph`; the e-graph archive is in `//lhd:formal_salt`). No `pass.bitwidth`
follows it, so under `Options::preflight` every cell the elaborator creates is stamped (a member's top
class takes the member's stamp, an interior cell the range-analysis bound) and an engine that would create
a cell it cannot stamp REFUSES the graph (`Stats::refused`) and classic does it. `optimize_body` then runs
`Cprop::do_trans`. Tests: `PreflightEngineOnTheDemuxShapeIsStampedAndEquivalent`,
`PreflightStampsBoundedNewCellsAndRefusesUnboundedOnes`.

### The 77 rules

`RULES.md` is the generated table (name, tag, priority, root, proof tier, source
line, what it does); it is the list. In short:

| group | pattern rules (`.rules`) | native rules (`.cpp`) |
| --- | --- | --- |
| arith | `mult_pow2_shl`, `not_not`, `xor_bool_one` (30), `not_xor_alt` (5, an `alt` that ties) | `const_fold_bank` (100), `annihilate` (90), `ident_drop` (80), `single_operand` (70), `idempotent`, `xor_pair_cancel`, `sum_cancel` (60), `flatten` (50), `or_absorb`, `and_absorb`, `bool_complement` (40), `cmp_same`, `eq_bool_chain` (30), `and_mask_get_mask` (20) |
| shift | `shl_shl`, `sra_sra`, `sext_sext`, `sext_getmask` (30) | `shift_zero` (40), `shift_compose` (30, the mixed SHL/SRA cases) |
| mux | `mux_sel_arm`, `mux_sel_not` (30), the alt `mux_lane_vector` (20) | `mux_bool_const_arms`, `mux_const_arm_logic` (30), `mux_setmask_pair` (35), `mux_setmask_arm` (34), `mux_guard_accumulation` (25, loop bodies only), the alt `mux_oob_sel` (20) |

Milestone G adds groups `mask` (window algebra: `getmask_getmask`, `getmask_shl_*`, `getmask_sra`,
`getmask_fits/above`, `getmask_setmask_*`, `setmask_*`, `concat_*`, `lt_always`..., `ror_bool`, `sext_fits`,
`mux_*_sel`, and the native `getmask_lane` / `concat_lanes`) and `div` (`div_one`, `div_self`, `div_pow2`,
`rem_pow2`, `div_shl_pow2`; the alts `div_pow2_trunc`, `div_mulshift8/16/31`, `rem_via_div`). A `Set_mask`
whose value is a `Get_mask` of at least the window is deliberately NOT simplified: cgen and the LEC encoder
read the value operand as already fitting the window. Div and Rem are pure and CSE'd in classic too
(`is_computed_comb_op`, `cprop_opshare.cpp`).

Milestone H adds the classic `scalar_mux` / `scalar_eq` / `scalar_bool` equivalents that were still missing and the packed-read rules:

* `mux_setmask_pair`, `mux_setmask_arm` (native; `simplify` in H, `alt` since I, see "Cost profiles"): the lane factoring of `scalar_mux`
  (`Mux(s, b, Set_mask(b, w, v))` becomes `Set_mask(b, w, Mux(s, Get_mask(b, w), v))`, and two rival writes of one lane share one lane Mux),
  so a conditional write to one bit of a packed register keeps a one-bit Mux. A latch hold Mux is a root and is never factored.
* `mux_guard_accumulation` (native): the rolled-loop accumulation guard, `Mux(s, a, a OP x)` = `a OP Mux(s, id, x)`. It needs
  `Options::guard_scope` (the graph is a lifted loop body) and `Options::unstamped_ok` (the pre-bitwidth slot), exactly the
  classic conditions (`set_guard_scope`, `may_emit_unstamped`); a held state output keeps its Mux (`Egraph::is_state`).
* `mux_oob_sel` (native `alt`): the Q1 out-of-range or disconnected selection of an n-ary Mux is a `?` owned by the Mux; 0 is one legal
  resolution, offered as an alternative the extraction may take (classic folds exactly this to 0). Out-of-range is never a `simplify`.
* `sra_lane`, `getmask_concat_straddle`, `setmask_to_concat` (native), `getmask_not_getmask` (DSL): a packed array element read is `SRA(word, k)`
  of a non-negative word, read through the lane layout (now also through `SRA`, and through write chains of any length); a window across
  two lanes of a private Concat is the narrower Concat; a chain of constant disjoint lane writes over zero (or a Concat) is one Concat
  (classic's pack canonicalization); the low window of a complement does not need the mask under the Not.
* `getmask_fits` is native: `Get_mask(y, 0, n) = y` when `y` fits, except for a leaf (an input or a register output; the mask is where the
  width fact is written for the region passes that follow) and for a Sum (a mask between two additions keeps the chain unmerged for the
  low-lane narrowing). Bitwidth deletes the redundant masks afterwards, as in classic.
* `mux_lane_vector` (DSL `alt`) and `bit_run_reduction` (native `alt`): the per-lane forms of `vectorize_bit_muxes` (one lane of a bit-sliced mux is a
  bit of the 64-bit-aligned word Mux, shared by hash-consing among the lanes of a run) and of `vectorize_bit_reductions` (four or more adjacent
  single bits of one word under an And/Or are a window test). The classic region passes still do the real vectorizing on the extracted
  graph; these record the equivalence for the cost profiles of milestone I (a lane alone is cheaper as the scalar mux, so `mux_lane_vector`
  is never extracted before then; `bit_run_reduction` is a smaller tree and is). Milestone I prices them: see "Cost profiles".

Milestone I prices the alts ("Cost profiles" below). What changed in the rule set: the Set_mask lane factoring is an `alt`; `div_mulshift8/16/31` and
`rem_via_div` (never extractable before) are taken under `sim` and not under `synth` (a divide by a constant is a multiply-high in the LLVM kernel and a
specialized array in hardware: 24 against 16 kernel instructions on a four-divide microbench; `aeg_div_rem` area 4182 against 4637 if forced); a collapsed
Mux alt (`s1 ? a : (s2 ? a : f)` = `(s1 | s2) ? a : f`) was built, proved, measured identical in ABC and WORSE in the simulator (+4 to +28 kernel
instructions in four of the six `tests/sim` fixtures it fires in: the post steps see a stack differently from a merged selector) and withdrawn. A
Mux-chain-to-Hotmux alt is not written: it needs the `{proven}` attribute and its obligation, and `mux_share` already forms Hotmuxes on the extracted graph.
`Cprop::indexed_get_mask` now reads only the stamped bits of a Get_mask whose pin bitwidth stamped narrower than its window (a Concat of the whole window
overflowed its consumer's lane under `lhd sim` on minion).

What the e-graph engine does NOT redo, because the classic post steps already run on its output with the same code: the vector-mux window
narrowing (`vectorize_bit_muxes` in `region_passes`), muxctx (`muxctx::prune`), mux and operator sharing, flop-enable folding
(`fold_constant_flop_enables`), pack canonicalization and the dead-code sweep. The muxctx order change was measured: with `muxctx::prune` off
the corpus grows by 7 nodes under classic and by 6 under aegraph (pred_aig +12 under both), so running it after the extraction instead of
after the classic forward sweep changes nothing measurable.

### QoR pass on the lhdsuite cores (2026-10-22)

Measured on `../lhdsuite` dino and picorv32 (`lhd synth` / `lhd sim`, sky130, `-c opt`) and the lhdtrack corpus:

* `getmask_sum_chain` merges a windowed Sum into its consumer only when the window has no other reader. A shared window
  (`t = (v + inc) mod 32` read by two subtractions and a compare, bedrock's `br_credit_counter`) used to be re-added in every
  consumer: three adders over the same operands. Now the merged form is an `alt` and the sharing-aware extraction keeps the
  one adder. lhdtrack aegraph/classic: area 1.0114 to 1.0028, delay 1.0154 to 0.999. Fixture `aeg_sum_chain_shared`.
* `mux_share` (shared by both engines) no longer builds the priority decode of an equality chain. `match op { == 0 {A} == 1 {B} .. }`
  lowers to Muxes selected by `op == k` for distinct constants, so arm i is `op == i` alone; the flattened Hotmux used to read
  `op != 0 and op != 1 and .. and op == i` (dino ImmediateGenerator: 51 to 66 nodes under aegraph, 10 priority terms). A positive
  `v == k` now drops the earlier negative conjuncts that compare the same `v` with another constant. dino aegraph kernel
  instructions 3083 to 2989 (classic 2983).
* The Hotmux-over-path-conjunctions flattening (three or more value groups) trades data selects for predicate gates: a win in
  hardware (picorv32 pre-CTS STA 11.4 to 12.8 ns without it, dino +1% area), a loss for the simulator (dino -4%, picorv32 -5%
  kernel instructions without it). `compile.aegraph.cost=sim` therefore skips it (`Cprop::set_hotmux_trees`); the two-group
  select tree always runs. `aegraph+classic` is a measurement engine: its classic slot still flattens.
  `lhd sim` with `compile.cprop.engine=aegraph compile.aegraph.cost=sim`: dino kernel 2869 (classic 2983), picorv32 4155 (classic
  4502), +4% and +7% cycles/s.
* Measured and dropped: `Mux(s, a, ?) = a` and the same for a Hotmux whose arms are `?` (picorv32 has about 1970 such arms): the
  upper bound is -2.7% area and -1.1% kernel instructions, and a faithful version needs un-interned `?` constants in hhds.
  Skipping `vectorize_bit_muxes`, `muxctx::prune`, `mux_op_share` or `vectorize_bit_reductions` changes nothing on dino/picorv32.

Cranelift-style additions (all in the DSL, so each is fuzzed and bv-proved; fixture `aeg_cmp_sum_const`). On dino, picorv32, lhdtrack and the equiv corpus they are
neutral in QoR (they fire on counter/compare code, which these designs have little of); they are cheap and exact:

* `and_not_self`, `or_not_self`, `xor_not_self`, `sum_not_self` (`x & ~x`, `x | ~x`, `x ^ ~x`, `x + ~x`): `arith.rules`.
* `sum_double` (alt): `x + x = x << 1`, one adder fewer in hardware.
* Constant across a comparison (`icmp.isle`): `eq/lt/gt_sum_const_*`, `lt/gt_const_sum_*`, the wrapped counter compare
  `eq_masked_sum_const_*`, and a difference tested against zero `eq_diff_zero`, `eq_masked_diff_zero`. Fixture `aeg_cmp_sum_const`.
* Measured and dropped (no hardware gain through ABC, and a loss on some designs): `(a & b) | (a & c) = a & (b | c)` and its dual
  (picorv32 -0.9% gates but pre-CTS STA 11.4 to 12.8 ns), and `x * c` as a canonical-signed-digit shift-add (identical mapped area
  on `x * 7`, `x * 255`; `bit_sel_sext` 21 to 25 from `x * 1000`). ABC already finds both.
* `getmask_sext_low` (`shift.rules`): a window that ends at or below bit b of `Sext(x, b)` reads x.

Left for later milestones: the shared-cell Sum splice, the `Hotmux` rules, the Sum/Xor/Mux/EQ low-lane producers (milestone L: `loop_ref_arg`
still builds its partial sums as one flat Sum where classic narrows each).

## Cost profiles (milestone I)

Rules never encode a preference. A `simplify` is only written when its right-hand side is no dearer than its
left in EVERY profile (the build checks it, below); anything that is cheaper in one target and dearer in another
is an `alt`, and the extraction decides with the profile `compile.aegraph.cost` names.

```
cost/synth.cost   gates: width-aware (W is the driver stamp, else the range analysis, else 32), wiring is free
                  (Get_mask, Set_mask, Sext, Concat, a shift by a constant), x * 2^k is wiring, an n-ary Mux is
                  A - 2 mux layers per bit
cost/sim.cost     host instructions of the LLVM backend (inou/cgen/cgen_llvm.cpp), quantized to 64-bit words (N):
                  a bit select is a shift and a mask, a shift by a variable is a compare + shift + select, a
                  multiply by an immediate is one instruction, a divide by a constant a multiply-high, a two-arm Mux one
                  select per word (its compare folds into it), a multi-word divide a loop
```

```
(profile NAME [:default-width N] [:doc "..."])
(cost NAME PATTERN [:when GUARD...] PRICE [:doc "..."])      first match wins; the last entry is `_`
PATTERN := OP | _ | (OP item...)      item := _ | (k) | (k name) | ..
PRICE, GUARD over: W A Wmax Wsum N Nmax and the (k name) binders, with the rule DSL's builtins
```

`rulegen/cost_model.{hpp,cpp}` is the one implementation: rulegen lints a profile (unknown op or name, a
missing catch-all, an unreachable entry) and embeds its text in `gen/cost_<name>.gen.cpp`; the engine parses it on first
use; the per-profile rule lint and the generated `:expect` tests call the same `price`.

* **Extraction (`Engine::compute_best`).** For a union the engine prices both sides: a node's own price
  (`op`, result width, operand widths and constants) plus its operands. **Width-aware**: the width is the range
  analysis bound of the class in bits. **Sharing-aware**: an operand with another reader costs nothing (it is
  needed whichever member is taken), a single-reader operand costs its whole subtree, so the narrowing the post
  steps do on purpose is not undone and a lane Mux shared by a run of lanes can beat the scalar Mux. Reader counts are
  optimistic on the first pass (every e-node counts, including alternatives that may lose) and are recounted under the
  selection for at most two more passes, so two alternatives that only "share" an operand with each other do not
  look shared. A tie keeps the older (original) side; no decision iterates an unordered container.
* **The per-profile cost lint.** `simplify` rules are sampled (the constants their guards admit, widths 1, 8 and 70) and may
  not price their right-hand side above their left in any profile; the diagnostic names the profile and says "make it alt".
* **`:expect (PROFILE lhs|rhs)`** is an assertion on the extraction: rulegen emits
  `<group>_<rule>_expect_<profile>_<side>`, which builds the rule's `:example`, runs the engine with only that rule under the
  profile and checks which side was kept. Retuning a table that silently undoes a rule's purpose fails that test.
* **`compile.aegraph.cost`.** The default is `auto`: `sim` under `lhd sim`, `synth` for every other command (a bare
  `lhd compile` gets `synth`; it cannot know what the graphs are for, so set it there). An explicit `synth` or `sim` overrides the
  automatic choice. `sim` prices the LLVM simulator backend. The kernel resolves it, passes the resolved name to `pass.aegraph` and names it in the compile-cache descriptor
  (`pipeline=cprop[aegraph:both:cost=sim],bitwidth`), so a profile switch never replays the other profile's graphs.

## The rule DSL (milestone E)

`rules/<group>.rules` are S-expressions; the group is the file name. `rulegen`
(`rulegen/`, a C++ host `cc_binary` over `//graph`) reads them and
`aeg_rules()` (`tools/aegraph.bzl`, called in `BUILD`) turns them into rule C++,
a per-group fuzz test, a per-group proof test, `RULES.md` and its staleness test.

```
(simplify NAME [PRIO] LHS [:let (v EXPR)...] [:when GUARD...] => RHS [OPTS])
(alt      NAME [PRIO] LHS [:let ...] [:when ...] => RHS [OPTS])
(choice   NAME [PRIO] LHS [:let ...] [:when ...] => RHS1 [?q := C1] | RHS2 [?q := C2] [OPTS])
OPTS := :example TERM | :expect (PROFILE lhs|rhs)... | :fuel N | :proof bv|int|lean|none | :doc "..."
```

| pattern | meaning |
| --- | --- |
| `x` | binds a class; a repeated `x` is the same class |
| `_` | wildcard |
| `0` `-1` | a constant of that value |
| `(k c)` | binds a fully known (int64) constant: as a class and as the value `c` in guards |
| `?q` | binds a `?` literal leaf |
| `(Op p...)` | positional operands, exact arity, pin order of the cell (`Get_mask` is `a lo hi`; `Mux` is `s f t`); on a banked op (`Sum Mult And Or Xor Ror EQ`) the operands are one unordered bank, `LT`/`GT` take `(left right)` |
| `(Op lo: p ...)` | operands by pin name |
| `(Op (as p.. ..r) (bs ..))` | bank multisets; `..r` binds the rest of the bank; a bank the pattern does not write must be empty, so `(Sum (as x))` does not match `Sum(as x)(bs y)` |
| `Op{attr}` | on a right-hand-side constructor: a registered contract attribute (`proven` is registered; it needs the Hotmux obligations of milestone F and is rejected until then) |

Guards and constant expressions: `+ - * min max abs log2 pow2? popcount mask_of < <= > >= = and or not`
over int64 (`rulegen/rule_expr.hpp`, one table for the generated code, the tests
and the lints; an overflow or an undefined result is "does not match"), plus the
analysis predicates of `rules/analyses.decl` (see "The analyses"; a constant argument takes any constant expression). `:let` names are constants usable later in `:let`,
`:when` and `(k EXPR)`. A bare `x` on the right is the class, a bare `:let` name
or `(k c)` name is its constant, `(k EXPR)` builds a constant.

* A `simplify` is Cranelift's subsume (the first match in priority order replaces the class), an
  `alt` is unioned (extraction picks), a `choice` is an alt tagged with its `?` assignment
  (the engine ignores choice results while `choices=off`; constants and `NONZERO` only until
  milestone J). The generated matcher stops at the first match of a rule.
* Priority: higher first; ties by name within the group, then group, as the registry sorts.
* `:example` is required. `:expect` and `:fuel` are parsed and stored; the `:expect` tests are
  emitted by rulegen (milestone I: `<group>_<rule>_expect_<profile>_<side>`) and `:fuel` is not wired to the matcher yet.

**Lints that fail generation** (so a bad rule fails the build that compiles it):
unknown op or pin; an op that is not a pure e-graph op; an unbound variable; a
`simplify` that builds more nodes than it matches or an op priced above its
root (`make it alt`; priced per cost profile since milestone I, the structural form only when rulegen is given no profiles); a fresh
`?` or an atom that would `create_const` a `?`; a `choice` arm without
`[?q := C]` (or assigning a `?` that is not bound on the left); an unregistered
`{attr}`; an unknown cost profile; a missing `:example`; a duplicate rule name
(also against the hand-written rules, which rulegen scans for `AEG_RULE` /
`AEG_NATIVE_RULE`). Two rules with one left-hand side and one priority are a
warning.

**What one rule produces with no hand edit**

* The rule C++ (`gen/<group>_rules.gen.cpp`, with `#line` back to the `.rules` line, so the
  `check=` diagnostics name `arith.rules:21`), compiled into `pass_aegraph`: the registry
  entry, the dispatch per root op, the counters, `rules_only` / `rules_disable` / `max_rewrites` /
  `explain` names, the `aegraph-rule` census record.
* `aeg_fuzz_<group>_smoke`: per rule, LHS vs RHS on random values with the engine's own folds
  (`aegraph::eval_op`, the table the constant analysis uses): small values, 64-bit extremes and
  values up to ~130 bits, negatives included, 1000 samples (`LHD_AEG_FUZZ_SAMPLES`), fixed seed
  (`LHD_AEG_FUZZ_SEED`, echoed on failure). A rule with a `?` on the left is checked in refinement
  mode (every known LHS bit kept, no new `?`); a choice arm with its assignment substituted. The
  sampler must find a legal assignment for 90% of the samples (a guard it cannot satisfy would
  make the check vacuous). `*_example_fires`: the `:example` term is built as a micro-LGraph and
  the engine, with that one rule enabled and `check=full`, must apply it.
* `aeg_prove_<group>_smoke` (the bv tier): the instantiated LHS and RHS become micro-LGraphs proven
  equal by `lec::prove_equal`. Inputs at width {1, 2, 3, 8, 16, 65}, signed, unsigned or
  mixed; `(k c)` values from a fixed pool filtered by the guards; a `bool01`-guarded variable is a
  1-bit input; `..r` rests of 0 or 1 operands. Every node is stamped with its own width bound and the
  outputs compare 2 bits wider than the widest node, so nothing truncates. At most 8 instances per
  rule, picked by a fixed per-rule hash (`LHD_AEG_PROVE_FULL=1` runs all; `LHD_AEG_PROVE_DEBUG=1` dumps the
  two graphs of each instance). Unknown/timeout and encoder refusals are a pass, Refuted fails and
  prints the instance and the counterexample. This is bounded evidence, not a proof for all widths:
  `RULES.md` calls the tier `bv-swept`. A `?`-literal or choice rule is covered by the fuzz.
* `RULES.md` and `aeg_rules_md_fresh`: the checked-in table must equal the generated one.

**Adding a rule**

1. Add one entry to `pass/aegraph/rules/<family>.rules` with an `:example` (and `:expect` for an
   `alt` meant for one target). Example, `rules/shift.rules`:
   ```
   (simplify shl_shl 30
     (SHL (SHL x (k a)) (k b))
     :when (>= a 0) (>= b 0) (<= (+ a b) 268435456)
     => (SHL x (k (+ a b)))
     :example (SHL (SHL $x 2) 3)
     :doc "SHL(SHL(x, a), b) = SHL(x, a + b).")
   ```
2. `bazel run //pass/aegraph:aeg_rules_refresh` (rewrites `RULES.md`), then
   `bazel test -c opt //pass/aegraph/...`: the lints, the fuzz, the example, the bv sweep and the
   staleness test.
3. For an analysis-guarded or native rule also add an equiv fixture to the `prp-lec-*` tier: a base
   `inou/prp/tests/equiv/aeg_<rule>.prp` and a header-only `aeg_<rule>_1.prp` with
   `:set: compile.cprop.engine=aegraph` and
   `:compile_grep: aegraph-rule <rule> .*extracted=[1-9]` (see `aeg_xor_bool_one*`,
   `aeg_mux_sel_not*`). No BUILD edit: the group is wired by file name.
4. A fact no analysis provides: add an analysis with a `:spec` to `analyses.decl` and its runtime
   implementation, never C++ inside a rule. Never edit an enum, a knob list or a generated table by hand.

### Knobs (`--set compile.aegraph.<name>=...`)

| knob | default | meaning |
| --- | --- | --- |
| `rules_disable` | empty | rule names or `group:NAME`, joined with `+` (a comma would split the `--set` list) |
| `rules_only` | empty | keep only these (same syntax) |
| `max_rewrites`, `bisect_graph` | 0, empty | stop applying rules after N rewrites per graph, in forward-walk order; the pass then runs on one worker and logs `aegraph-bisect graph= rewrite= rule= enode= op=` for the Nth. `bisect_graph` limits the log to one graph |
| `explain` | empty | print `aegraph-explain graph= rule= node=` for each cell this rule built that the extraction kept |
| `check` | `unions` in dbg, `off` in opt | `unions`: both sides of every rewrite on 8 random vectors over the cone below them (up to 4096 classes), aborting with the rule name and `file:line` on a mismatch; `full`: also every original node against the class extracted for it on 64 vectors |
| `rewrite_depth` | 5 | nested rule-built e-nodes that still meet rules |
| `matches_limit` | 5 | `alt` results unioned per e-node |
| `eclass_limit` | 5 | members of one class |
| `extractor_fuel` | 500 | cost saturation of the extractor, in units of 1024 |
| `edge_budget` | 32 | rule work (operands scanned) per input edge of a graph; 0 = unlimited; keeps the pass O(V+E) |
| `cost` | `synth` | extraction cost profile: `synth`, `sim`, or `auto` (= `sim` under `lhd sim`, else `synth`); see "Cost profiles" |
| `choices` | `off` | `off|const|expr` (no choice rules yet) |

With `lhd.stats` the pass emits one `aegraph-rule` diagnostic per rule that ran
(message `aegraph-rule NAME tried=N matched=N applied=N extracted=N`; attrs `rule group
tag tried matched applied subsumed limit_rejected extracted`, which the sweep script parses),
and `rules_fired` of `cprop-summary` is the sum of `applied`. Counters are local
to one engine run and are merged after the workers join.

## Testing the engine on the whole corpus

The default suite runs the default engine (aegraph). To run the same `inou/prp` tests with the
design under test compiled by the classic engine instead:

```
bazel test -c opt //inou/prp:all --test_tag_filters=-manual,-external-simulator,-fixme \
    --test_env=LHD_PRP_COMPILE_SETS=compile.cprop.engine=classic
```

`LHD_PRP_COMPILE_SETS` (space separated `k=v`) feeds `PrpRunner.compile_sets`,
the `--set` list that rides only the compile and sim commands of the design
under test. It is deliberately separate from `equiv_sets` (the `--bitfuzz`
list), which is also appended to `lhd lec`. `pyrope_test.py --aegraph` is the
same thing for one fixture, and `//inou/prp:prp-aegraph-sim` / `prp-aegraph-lec`
are manual targets that run a whole tier that way (`bazel test -c opt
--test_tag_filters= //inou/prp:prp-aegraph-lec`). Three header-only equiv variants
(`loop_carry_kinds_3`, `runtime_index_store_lanes_3`, `hotmux_unique_1`) pin
`:set: compile.cprop.engine=aegraph` in the default suite.

## Measuring the engines (milestone C)

Everything below works for BOTH engines with the same fields, so a number is
always an A/B number.

* **`lhd.stats` -> `cprop-summary`.** With `--stats` (or `--set lhd.stats=true`)
  every cprop step, `pass.cprop` and `pass.aegraph` alike, emits one `info`
  diagnostic per graph, code `cprop-summary`, attrs `graph nodes_in nodes_out
  by_op ms rules_fired creates aeg_bytes aeg_cap_bytes lg_bytes lg_bytes_v1` (`--emit diagnostics:PATH`
  writes them as JSON lines). `by_op` is `Op=count,...` after the step; `creates`
  counts body nodes whose class index did not exist before the step (a lower bound);
  `aeg_bytes` is the bytes in use by the e-graph tables at the end of the build, the peak since they only grow (0 for classic);
  `aeg_cap_bytes` is the same tables at capacity (up to 2x in use); `lg_bytes_v1` is the original yardstick `nodes_out*32 + edges*16`; `lg_bytes` is the hhds footprint of the body at its largest (input or output): `nodes * 64 + driven sink edges * 48` (32 B NodeEntry + 32 B driver PinEntry per node, 32 B sink PinEntry + 16 B edge per driven sink); `rules_fired` is
  the number of committed rewrites (0 for classic, which has no rule counters). The kernel hands the INTERNAL `stats` label to the
  two methods; a cache-replayed compile runs no pass, so measure with
  `--set lhd.incremental=false`.
* **`LHD_AEGRAPH_PROFILE=1`** prints `aegraph-profile graph=G phase=P ms=M
  calls=N` per graph, the record shape of `LHD_CPROP_PROFILE`. Phases: `prepass`
  (SCC and the classic false-cycle cutter), `build` (rule time is NESTED in it),
  `rules` (the outermost rewrite call of each new e-node), `extract` (the union
  cost pass), `elaborate` (diff back into the graph and the dead sweep) and
  `post` (the classic region passes).
* **`//pass/aegraph:aeg_parity_smoke`** runs 25 value-oracle cases of
  `pass/cprop/cprop_test.cpp` under both engines (`livehd::aegraph::optimize_body`
  is exactly the per-body path of `pass.aegraph`). The evaluators
  (`mux_eval`, `Mux_graph`, the Dlop evaluator) live in the test-only
  `pass/cprop/cprop_test_eval.hpp` (`//pass/cprop:cprop_test_eval`), so the
  `pass/cprop` tests gain no aegraph dependency. Shape-pin assertions stay in
  `cprop_test.cpp` (classic only).
* **`//pass/aegraph:aeg_diff_smoke`** generates random unbounded-integer DAGs
  (Sum with both banks, Mult, And/Or/Xor, Not, Mux, EQ/LT/GT, constant SHL/SRA,
  Sext, Get_mask, `?` literals), copies each with `GraphLibrary::copy_from`, runs
  classic on one copy and the aegraph on the other, and checks both against the
  original with the Dlop vector oracle: under SOME value of its literals the
  optimized outputs must be among the original's outputs under ALL values of its
  literals (one value per literal at all its uses). `prove_equal` only annotates
  a vector mismatch, plus once per run on a literal-free iteration.
  `LHD_AEG_FUZZ_ITERS` (default 1000) and `LHD_AEG_FUZZ_SEED` rescale and reproduce a run.
* **`scripts/cprop_engine_sweep.py`** is the numbers table: per fixture and engine
  ms, RSS, nodes in/out, nodes per op, creates, bytes, plus `--lec` (A==B and
  B==source), `--determinism`, `--synth` (gates/area/delay/pred_aig), `--sim`
  (out_digest, instructions, cycles/s) and the `aegraph+classic` parity-gap report
  (what classic still removes after the aegraph, per op and per fixture). The
  baseline is recorded in `todo/livehd/2a-aegraph.html`.
* **Siblings.** `../lhdtrack`: flow `syn_lhd_pyrope_aegraph` and
  `sim_lhd_pyrope_aegraph_llvm`, or `LHDTRACK_CPROP_ENGINE` on any sim flow;
  `../lhdsuite`: `BENCH_PYROPE_SETS="compile.cprop.engine=aegraph"` (it rides every
  Pyrope compile, synth, sim and the lec impl side). Exact commands are in the
  header of `scripts/cprop_engine_sweep.py`.
