# pass/aegraph: acyclic e-graph constant propagation

`pass.aegraph` is a second constant-propagation engine for LGraph, an
alternative to `pass/cprop` behind one knob. It is a Cranelift-style acyclic
e-graph ("aegraph"): hash-consing, eager rewrites at insertion, no rebuild,
extraction, then elaboration back into the graph. The design and the plan are
`todo/livehd/2a-aegraph.html`; this file says what exists today.

**Status: milestone E (the rulegen DSL) on top of D (rule runtime), C (the A/B
harness) and B (the skeleton engine).** The engine hash-conses, folds fully known
cones and runs 28 rewrite rules through the rule runtime (`runtime/match.hpp`):
the pattern-shaped ones are written in `rules/*.rules` and generated by `rulegen`
(`tools/aegraph.bzl`), the rest are hand-written C++ (`rules/*.cpp`, native).
Classic cprop stays the default and is not removed. Adding a rule is one entry in
a `.rules` file (see "Adding a rule").

## Selecting the engine

```
lhd compile foo.prp --set compile.cprop.engine=classic          # default
lhd compile foo.prp --set compile.cprop.engine=aegraph
lhd compile foo.prp --set compile.cprop.engine=aegraph+classic  # aegraph, then classic, in each slot
lhd compile foo.prp --set compile.cprop.engine=aegraph --set compile.cprop.engine_slots=first
```

* `compile.cprop.engine` accepts only `classic|aegraph|aegraph+classic`. There
  is no `none`: at least one engine always runs. A bad value is rejected when
  the options are read, not when the pass runs.
* `compile.cprop.engine_slots=both|first|second` swaps only one of the two
  compile cprop slots (`first` runs before `pass.legalize`, `second` after
  `enableopt`); the other slot stays classic. Default `both`.
* The kernel does the dispatch (`compile_graph_passes`, `lhd/lhd_kernel_common.cpp`):
  the set name stays `compile.cprop` for every engine, and the driver merges the
  `compile.aegraph` set into a `pass.aegraph` step. `Pass_cprop::optimize`
  refuses any non-classic `engine` that reaches it.
* `low_lanes`, `loop_hoist` and `engine` are registered on `pass.aegraph` as
  INTERNAL labels (hidden from `lhd list options`): each knob has ONE
  spelling, `compile.cprop.*`, and `--set compile.aegraph.low_lanes` (or
  `loop_hoist`, `engine`, `engine_slots`) is rejected with that hint.
* The compile-cache descriptor names the resolved engine
  (`pipeline=cprop[aegraph:both],bitwidth`), so an engine switch never replays
  the other engine's graphs. `//pass/aegraph:pass_aegraph` is in
  `//lhd:compile_salt`.

## What one run does (`aegraph.cpp`)

1. **Pre-pass.** Tarjan SCC over the combinational structure (state and IO break
   cycles). A non-trivial SCC, or a self edge, is a combinational cycle that may
   be false at word level (a packed struct written field by field); its members
   are OPAQUE: never hash-consed, never folded. The classic packed-slice folds
   run later, in the post steps.
2. **Build.** One forward walk. IO, state, `Sub`, `AttrSet`, `Clock_cell`, `LUT`,
   `runtime_check` nodes and non-exclusive `Hotmux` cells are skeleton leaves:
   their driver pins are leaf classes. A pure node is normalized (commutative
   banks sorted by class id, multiplicity kept: `Sum(a,a)` is `2a`, `Xor(a,a)`
   is `0`) and hash-consed on `op + operand classes + color + synth_policy +
   proven`. The `proven` code is in the key so a proven `Hotmux` never merges
   with an unproven twin. Names are not in the key.
3. **Constant analysis.** Every class carries a three-valued `Dlop` (or no
   value). A node whose operands all have values is evaluated with the same
   Dlop semantics classic folds with. The result becomes a constant ONLY when it
   is fully known (the P7 contract): a result with `?` bits stays a node, and a
   `?` literal is one const node that is never merged by value and never
   re-minted. A fold that is exactly an operand (constant-selector `Mux`, a
   shift by zero, a window covering a whole literal) forwards that operand's
   class. An out-of-range or disconnected `Mux` selection stays a `Mux` (Q1).
4. **Rewrite rules** (milestone D, see below). A node that is NEW in the e-graph
   is offered to the rules of its root op in priority order. A `simplify` result
   replaces the node's class (subsume); an `alt` result is unioned with it.
5. **Extract.** A class without unions is its first member (the original node).
   A union keeps its original side unless the alternative has a STRICTLY smaller
   expression tree (one per e-node; constants and leaves are free; `extractor_fuel`
   saturates the size), so a tie never changes the graph.
6. **Elaborate (diff).** Original nodes that are class representatives are
   reused untouched: nids, names and srcids survive. An original node whose class
   a rule replaced is REBUILT IN PLACE as the rule's e-node (same cell, name,
   output pin and consumers; only its op and operands change, like the classic
   in-place rewrites); e-nodes no original node realizes become new cells. A duplicate is retired by
   reconnecting each consumer sink to the representative (snapshot the edges,
   `connect_sink`, then `del_node`). Guards: a ring that closes over a compact
   loop keeps the node (`closes_loop_self_edge`); a parallel edge that hhds
   would dedup keeps it; two named twins both stay (a named twin absorbs an
   unnamed one and moves its name). The retired root's width stamp is copied to
   the representative when that has none. Dead pure nodes are then deleted.

After elaboration `Cprop::do_post` runs the classic region passes (pack
canonicalization, vector-mux narrowing, muxctx, mux/op sharing, flop-enable
folding, dead-code sweep) and, with `low_lanes`, low-lane narrowing; then the
library-wide `loop_hoist`. These are classic *sub-routines*, shared with
`Cprop::do_trans` through `Cprop::region_passes`; the engine never runs the full
classic forward sweep (that is what `aegraph+classic` does).

With every rule off (`rules_only=` naming no rule, or `rules_disable` listing
them all) the result is the input graph except for shared and folded nodes. The
engine is deterministic: class ids follow forward-walk order, the rule table is
sorted by (priority, group, name), and no decision iterates an unordered container.

## The rule runtime (milestone D)

```
runtime/match.hpp, match.cpp   Ctx, Results, PatternMatch-style combinators, the registry
rules/arith.cpp                bank algebra, booleans, comparisons               (group arith, native)
rules/shift.cpp                mixed shift composition                           (group shift, native)
rules/mux.cpp                  constant-arm Mux logic                            (group mux, native)
rules/*.rules, analyses.decl   the pattern rules, in the DSL                     (generated, see below)
```

A rule is a function over the e-graph; it never touches an LGraph handle.

```cpp
AEG_RULE_GROUP(arith);
AEG_RULE(not_not, simplify, 30, Ntype_op::Not) {         // name, tag, priority, root ops
  Class_id x = kNoClass;
  if (match_root(ctx, root, Ntype_op::Not, m_op(Ntype_op::Not, m_bind{&x}))) {
    out.subsume(x);                                      // Not(Not x) = x
  }
}
```

* **`Ctx`** reads classes (`known`, `is_int`, `small_int`, `bool01`, `eq_against`,
  `each_member`: fuel-limited iteration over the members of a union) and builds
  e-nodes (`make`, `make_bank`, `konst`). `make` folds, normalizes, hash-conses and
  runs the rules of the new e-node, `rewrite_depth` levels deep. Pointers and
  spans obtained from `node_of`/`operands_of`/`known` are invalidated by `make`.
* **`Results`**: `subsume(c)` (tag `simplify`: the first match in priority order
  replaces the class), `add(c)` (tag `alt`: unioned with the class, up to
  `matches_limit` per e-node and `eclass_limit` members), `choice(...)` (tag
  `choice`, skipped while `choices=off`; no choice rule exists yet).
* **Combinators**: `m_any`, `m_bind`, `m_same`, `m_int`, `m_k`, `m_op(op, pats...)`
  (positional, exact arity), `match_root`, `match_root_each`. A pattern calls its
  continuation per matching member, so a later failure backtracks into the next
  member of a union.
* **`AEG_NATIVE_RULE`** is the same registration for rules no pattern can express
  (loops over a bank, region walks); `native` is recorded in the table: rulegen
  generates no proof obligation for them, so a native rule needs an equiv fixture.
  `Ctx::admits(literal, v)` / `admits_nonzero(literal)` are the `(admits ?q C)`
  guard of generated `choice` arms.
* **Registry**: `Rule_id` (1-based, in the order of the sorted table) and the
  dispatch table per root op. A rule registered after the first use is a bug.
* **Union nodes.** `Egraph::add_union(a, b)` makes a new class `uni(a, b)`; an
  aegraph never rebuilds, so neither side changes. A rewritten class leaves an
  `alias` to its replacement: a later hash-cons hit reads the replacement.
  `eclass_limit` is at most 32.
* **Soundness rules the hand rules obey.** Every rule is exact in cprop's
  unlimited-integer algebra. No rule creates a `?` spelling (P7): constants are
  combined only from FULLY KNOWN classes and a `?` literal is an opaque operand.
  A rule that flattens a cell requires the inner cell to have no other reader and
  equal attrs (color, `synth_policy`).

## The rule DSL (milestone E)

`rules/<group>.rules` are S-expressions; the group is the file name. `rulegen`
(`rulegen/`, a C++ host `cc_binary` over `//graph`) reads them and
`aeg_rules()` (`tools/aegraph.bzl`, called in `BUILD`) turns them into rule C++,
a per-group fuzz test, a per-group proof test, `RULES.md` and its staleness test.

```
(simplify NAME [PRIO] LHS [:let (v EXPR)...] [:when GUARD...] => RHS [OPTS])
(alt      NAME [PRIO] LHS [:let ...] [:when ...] => RHS [OPTS])
(choice   NAME [PRIO] LHS [:let ...] [:when ...] => RHS1 [?q := C1] | RHS2 [?q := C2] [OPTS])
OPTS := :example TERM | :expect (PROFILE lhs|rhs)... | :fuel N | :proof bv|int|lean|none | :doc "..."
```

| pattern | meaning |
| --- | --- |
| `x` | binds a class; a repeated `x` is the same class |
| `_` | wildcard |
| `0` `-1` | a constant of that value |
| `(k c)` | binds a fully known (int64) constant: as a class and as the value `c` in guards |
| `?q` | binds a `?` literal leaf |
| `(Op p...)` | positional operands, exact arity, pin order of the cell (`Get_mask` is `a lo hi`; `Mux` is `s f t`); on a banked op (`Sum Mult And Or Xor Ror EQ`) the operands are one unordered bank, `LT`/`GT` take `(left right)` |
| `(Op lo: p ...)` | operands by pin name |
| `(Op (as p.. ..r) (bs ..))` | bank multisets; `..r` binds the rest of the bank; a bank the pattern does not write must be empty, so `(Sum (as x))` does not match `Sum(as x)(bs y)` |
| `Op{attr}` | on a right-hand-side constructor: a registered contract attribute (`proven` is registered; it needs the Hotmux obligations of milestone F and is rejected until then) |

Guards and constant expressions: `+ - * min max abs log2 pow2? popcount mask_of < <= > >= = and or not`
over int64 (`rulegen/rule_expr.hpp`, one table for the generated code, the tests
and the lints; an overflow or an undefined result is "does not match"), plus the
analysis predicates of `rules/analyses.decl` (`bool01` today; milestone G adds
range, known bits, ...). `:let` names are constants usable later in `:let`,
`:when` and `(k EXPR)`. A bare `x` on the right is the class, a bare `:let` name
or `(k c)` name is its constant, `(k EXPR)` builds a constant.

* A `simplify` is Cranelift's subsume (the first match in priority order replaces the class), an
  `alt` is unioned (extraction picks), a `choice` is an alt tagged with its `?` assignment
  (the engine ignores choice results while `choices=off`; constants and `NONZERO` only until
  milestone J). The generated matcher stops at the first match of a rule.
* Priority: higher first; ties by name within the group, then group, as the registry sorts.
* `:example` is required. `:expect` and `:fuel` are parsed and stored; the `:expect` tests are
  emitted when the cost profiles land (milestone H) and `:fuel` is not wired to the matcher yet.

**Lints that fail generation** (so a bad rule fails the build that compiles it):
unknown op or pin; an op that is not a pure e-graph op; an unbound variable; a
`simplify` that builds more nodes than it matches or an op priced above its
root (`make it alt`; the structural form until the cost profiles land); a fresh
`?` or an atom that would `create_const` a `?`; a `choice` arm without
`[?q := C]` (or assigning a `?` that is not bound on the left); an unregistered
`{attr}`; an unknown cost profile; a missing `:example`; a duplicate rule name
(also against the hand-written rules, which rulegen scans for `AEG_RULE` /
`AEG_NATIVE_RULE`). Two rules with one left-hand side and one priority are a
warning.

**What one rule produces with no hand edit**

* The rule C++ (`gen/<group>_rules.gen.cpp`, with `#line` back to the `.rules` line, so the
  `check=` diagnostics name `arith.rules:21`), compiled into `pass_aegraph`: the registry
  entry, the dispatch per root op, the counters, `rules_only` / `rules_disable` / `max_rewrites` /
  `explain` names, the `aegraph-rule` census record.
* `aeg_fuzz_<group>_smoke`: per rule, LHS vs RHS on random values with the engine's own folds
  (`aegraph::eval_op`, the table the constant analysis uses): small values, 64-bit extremes and
  values up to ~130 bits, negatives included, 1000 samples (`AEG_FUZZ_SAMPLES`), fixed seed
  (`AEG_FUZZ_SEED`, echoed on failure). A rule with a `?` on the left is checked in refinement
  mode (every known LHS bit kept, no new `?`); a choice arm with its assignment substituted. The
  sampler must find a legal assignment for 90% of the samples (a guard it cannot satisfy would
  make the check vacuous). `*_example_fires`: the `:example` term is built as a micro-LGraph and
  the engine, with that one rule enabled and `check=full`, must apply it.
* `aeg_prove_<group>_smoke` (the bv tier): the instantiated LHS and RHS become micro-LGraphs proven
  equal by `lec::prove_equal`. Inputs at width {1, 2, 3, 8, 16, 65}, signed, unsigned or
  mixed; `(k c)` values from a fixed pool filtered by the guards; a `bool01`-guarded variable is a
  1-bit input; `..r` rests of 0 or 1 operands. Every node is stamped with its own width bound and the
  outputs compare 2 bits wider than the widest node, so nothing truncates. At most 8 instances per
  rule, picked by a fixed per-rule hash (`AEG_PROVE_FULL=1` runs all; `AEG_PROVE_DEBUG=1` dumps the
  two graphs of each instance). Unknown/timeout and encoder refusals are a pass, Refuted fails and
  prints the instance and the counterexample. This is bounded evidence, not a proof for all widths:
  `RULES.md` calls the tier `bv-swept`. A `?`-literal or choice rule is covered by the fuzz.
* `RULES.md` and `aeg_rules_md_fresh`: the checked-in table must equal the generated one.

**Adding a rule**

1. Add one entry to `pass/aegraph/rules/<family>.rules` with an `:example` (and `:expect` for an
   `alt` meant for one target). Example, `rules/shift.rules`:
   ```
   (simplify shl_shl 30
     (SHL (SHL x (k a)) (k b))
     :when (>= a 0) (>= b 0) (<= (+ a b) 268435456)
     => (SHL x (k (+ a b)))
     :example (SHL (SHL $x 2) 3)
     :doc "SHL(SHL(x, a), b) = SHL(x, a + b).")
   ```
2. `bazel run //pass/aegraph:aeg_rules_refresh` (rewrites `RULES.md`), then
   `bazel test -c opt //pass/aegraph/...`: the lints, the fuzz, the example, the bv sweep and the
   staleness test.
3. For an analysis-guarded or native rule also add an equiv fixture to the `prp-lec-*` tier: a base
   `inou/prp/tests/equiv/aeg_<rule>.prp` and a header-only `aeg_<rule>_1.prp` with
   `:set: compile.cprop.engine=aegraph` and
   `:compile_grep: aegraph-rule <rule> .*extracted=[1-9]` (see `aeg_xor_bool_one*`,
   `aeg_mux_sel_not*`). No BUILD edit: the group is wired by file name.
4. A fact no analysis provides: add an analysis with a `:spec` to `analyses.decl` and its runtime
   implementation, never C++ inside a rule. Never edit an enum, a knob list or a generated table by hand.

### Knobs (`--set compile.aegraph.<name>=...`)

| knob | default | meaning |
| --- | --- | --- |
| `rules_disable` | empty | rule names or `group:NAME`, joined with `+` (a comma would split the `--set` list) |
| `rules_only` | empty | keep only these (same syntax) |
| `max_rewrites`, `bisect_graph` | 0, empty | stop applying rules after N rewrites per graph, in forward-walk order; the pass then runs on one worker and logs `aegraph-bisect graph= rewrite= rule= enode= op=` for the Nth. `bisect_graph` limits the log to one graph |
| `explain` | empty | print `aegraph-explain graph= rule= node=` for each cell this rule built that the extraction kept |
| `check` | `unions` in dbg, `off` in opt | `unions`: both sides of every rewrite on 8 random vectors over the cone below them (up to 4096 classes), aborting with the rule name and `file:line` on a mismatch; `full`: also every original node against the class extracted for it on 64 vectors |
| `rewrite_depth` | 5 | nested rule-built e-nodes that still meet rules |
| `matches_limit` | 5 | `alt` results unioned per e-node |
| `eclass_limit` | 5 | members of one class |
| `extractor_fuel` | 500 | tree-cost saturation of the extractor |
| `edge_budget` | 32 | rule work (operands scanned) per input edge of a graph; 0 = unlimited; keeps the pass O(V+E) |
| `cost` | `synth` | extraction profile label (profiles arrive with the cost milestone) |
| `choices` | `off` | `off|const|expr` (no choice rules yet) |

With `lhd.stats` the pass emits one `aegraph-rule` diagnostic per rule that ran
(message `aegraph-rule NAME tried=N matched=N applied=N extracted=N`; attrs `rule group
tag tried matched applied subsumed limit_rejected extracted`, which the sweep script parses),
and `rules_fired` of `cprop-summary` is the sum of `applied`. Counters are local
to one engine run and are merged after the workers join.

## Testing the engine on the whole corpus

The default suite keeps `classic`. To run the same `inou/prp` tests with the
design under test compiled by the aegraph (the reference and any golden Verilog
stay classic):

```
bazel test -c opt //inou/prp:all --test_tag_filters=-manual,-external-simulator,-fixme \
    --test_env=LHD_PRP_COMPILE_SETS=compile.cprop.engine=aegraph
```

`LHD_PRP_COMPILE_SETS` (space separated `k=v`) feeds `PrpRunner.compile_sets`,
the `--set` list that rides only the compile and sim commands of the design
under test. It is deliberately separate from `equiv_sets` (the `--bitfuzz`
list), which is also appended to `lhd lec`. `pyrope_test.py --aegraph` is the
same thing for one fixture, and `//inou/prp:prp-aegraph-sim` / `prp-aegraph-lec`
are manual targets that run a whole tier that way (`bazel test -c opt
--test_tag_filters= //inou/prp:prp-aegraph-lec`). Three header-only equiv variants
(`loop_carry_kinds_3`, `runtime_index_store_lanes_3`, `hotmux_unique_1`) pin
`:set: compile.cprop.engine=aegraph` in the default suite.

## Measuring the engines (milestone C)

Everything below works for BOTH engines with the same fields, so a number is
always an A/B number.

* **`lhd.stats` -> `cprop-summary`.** With `--stats` (or `--set lhd.stats=true`)
  every cprop step, `pass.cprop` and `pass.aegraph` alike, emits one `info`
  diagnostic per graph, code `cprop-summary`, attrs `graph nodes_in nodes_out
  by_op ms rules_fired creates aeg_bytes lg_bytes` (`--emit diagnostics:PATH`
  writes them as JSON lines). `by_op` is `Op=count,...` after the step; `creates`
  counts body nodes whose class index did not exist before the step (a lower bound);
  `aeg_bytes` is the peak capacity of the e-graph tables (0 for classic);
  `lg_bytes` is `nodes_out * 32 + driven sink edges * 16`; `rules_fired` is
  the number of committed rewrites (0 for classic, which has no rule counters). The kernel hands the INTERNAL `stats` label to the
  two methods; a cache-replayed compile runs no pass, so measure with
  `--set lhd.incremental=false`.
* **`LHD_AEGRAPH_PROFILE=1`** prints `aegraph-profile graph=G phase=P ms=M
  calls=N` per graph, the record shape of `LHD_CPROP_PROFILE`. Phases: `prepass`
  (SCC and the classic false-cycle cutter), `build` (rule time is NESTED in it),
  `rules` (the outermost rewrite call of each new e-node), `extract` (the union
  cost pass), `elaborate` (diff back into the graph and the dead sweep) and
  `post` (the classic region passes).
* **`//pass/aegraph:aeg_parity_smoke`** runs 25 value-oracle cases of
  `pass/cprop/cprop_test.cpp` under both engines (`livehd::aegraph::optimize_body`
  is exactly the per-body path of `pass.aegraph`). The evaluators
  (`mux_eval`, `Mux_graph`, the Dlop evaluator) live in the test-only
  `pass/cprop/cprop_test_eval.hpp` (`//pass/cprop:cprop_test_eval`), so the
  `pass/cprop` tests gain no aegraph dependency. Shape-pin assertions stay in
  `cprop_test.cpp` (classic only).
* **`//pass/aegraph:aeg_diff_smoke`** generates random unbounded-integer DAGs
  (Sum with both banks, Mult, And/Or/Xor, Not, Mux, EQ/LT/GT, constant SHL/SRA,
  Sext, Get_mask, `?` literals), copies each with `GraphLibrary::copy_from`, runs
  classic on one copy and the aegraph on the other, and checks both against the
  original with the Dlop vector oracle: under SOME value of its literals the
  optimized outputs must be among the original's outputs under ALL values of its
  literals (one value per literal at all its uses). `prove_equal` only annotates
  a vector mismatch, plus once per run on a literal-free iteration.
  `AEG_FUZZ_ITERS` (default 1000) and `AEG_FUZZ_SEED` rescale and reproduce a run.
* **`scripts/cprop_engine_sweep.py`** is the numbers table: per fixture and engine
  ms, RSS, nodes in/out, nodes per op, creates, bytes, plus `--lec` (A==B and
  B==source), `--determinism`, `--synth` (gates/area/delay/pred_aig), `--sim`
