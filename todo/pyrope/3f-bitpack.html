3f-bitpack tuple bit packing replaces concat

X#[..] means the full bit vector of X: if X is a positional tuple/array that is its packing, and if X is an integer assigned into a declared ordered destination the bit vector is laid into that destination's entries. Entry 0 is at bit 0 in both directions. concat is removed — it read like SystemVerilog {a,b} and was the only bit spelling in Pyrope that ran high-to-low, while x#[0] is the low bit, ranges are written low-to-high, and the documented string encoding already puts the first character in the low bits.

Depends on

None.

Already working

Verified against bazel-bin/lhd/lhd on 2026-08-27 — the ORDER is already the target order, so this task is mostly closing gaps around it, not re-plumbing the lowering.

  • Packing a declared array variable: x#[..] with x[0]=i, x[1]=j emits Verilog {j, i} — entry 0 low.
  • Unpacking into an array: const x:[2]u4 = b#[..] emits x[0]=b[3:0], x[1]=b[7:4].
  • Per-entry sign extension on unpack: const x:[2]s4 = b#[..] emits $signed(b[3:0]) / $signed(b[7:4]).
  • x#sext[..] on an array, and sub-ranges of the packed word: const x:[2]u4 = (3,1) gives x#[0..=3] == 3 and x#[4..=7] == 1.
  • The one-field named bundle exception: (const only:u4=3)#[..] == 3.
  • Packing keeps each entry's declared window, not its value's width: const x:[2]s4 = (-1, 1) packs to 0x1F.

Subtasks — pending

  • A — ... must expand a declared [N]T array.
    • Today ... expands an unnamed tuple (3,1) and an untyped array literal [3,1], but a declared array splices as a SINGLE entry: const x:[2]u4 = (3,1); const y = (...x, 5) gives Pyrope array index 2 is outside [0, 2) for `y`.
    • The blessed packing spelling depends on this — a tuple-valued entry must be spliced, so (...stages, inp)#[..] is the form the docs now teach.
  • D — exact-width check in both directions, with wrap.
    • Unpack silently truncates today: const x:[2]u4 = b#[..] with b:u9 compiles and drops bit 8.
    • Worse, comptime unpack does not split at all: with const b8:u8 = 0ub1010_0110, const x:[2]u4 = b8#[..] folds BOTH x[0] and x[1] to 0xa6 — every entry gets the whole word. The runtime path is correct (b[3:0] / b[7:4]), so this is a constprop-path bug, and another silent wrong value.
    • The total is exactly the sum of the entry widths; a destination declaring a different width is an error in both directions — never a zero-extension, never a silent truncation.
    • wrap (the existing statement-level prefix modifier) permits dropping the HIGH bits and is the only lossy spelling. Widening stays an error — no modifier invents bits. sat is an error on a bit layout.
  • F — the whole #<mod>[range] family accepts a tuple.
    • x#|[..] is rejected today with bit reduction (`#|`/`#&`/`#^`/`#+`) requires an integer or boolean operand.
    • A tuple IS its bit vector, so the whole family operates on the packed word. #[..], sub-ranges and #sext already do — the reductions #| #& #^ #+ are the only members left out, so this subtask is lifting one guard, not adding a family. x#[..] is non-negative; x#sext[..] is the signed reinterpretation.
    • range keeps its own rule: (1..=3)#[..] == 0ub1110 is a one-hot SET encoding, not a positional packing, even though the docs also say 1..=3 == (1,2,3).

Subtasks — landed

  • B — pack a tuple LITERAL. LANDED.
    • (a, b)#[..] now packs at comptime AND at runtime, entry 0 at bit 0. The silent entry-0 fold is gone.
    • A positional tuple literal used as a bit-selection base lowers straight to the n-ary concat node in prp2lnast (bit_selection_to_node), lanes reversed into that node's MSB-first order. That reuses the whole existing lane machinery — declared window per lane, array-splice lanes, the untyped-lane error — instead of adding a second one.
    • TRAP found the hard way: the LNAST concat node has TWO producers, prp2lnast and inou.slang. Flipping lower_concat itself silently miscompiled the REFERENCE side of every Verilog LEC (equivalent designs, deterministic false REFUTED). The order flip belongs at the Pyrope producer, never at the shared node.
    • A bare #[..] over a packing keeps the concat node rather than wrapping it in a no-op get_mask: the mask temp records no declared width, which a nested pack and the destination-width check both need.
    • upass.constprop now sizes a scalar lane from decl_facts when the width operand is still nil, so a comptime packing folds during elaboration instead of surviving as a graph node no cassert can read.
  • C — declared-width guard. LANDED.
    • Inherited with the lane machinery: an untyped entry reports concat lane `u` has no declared bit width and a literal entry reports the literal form, both through the #[..] spelling.
  • E — named-field rule. LANDED.
    • x#[..] on a multi-field named bundle reported unresolved reference 'x', which named neither the rule nor the fix. New uPass_runner::check_bitsel_named_bundle gives it the real diagnostic, the twin of the concat-lane check on the other spelling.
    • The one-field exception still packs, and (x.lo, x.hi)#[..] is the documented way to order a named bundle.
  • G — concat removed. LANDED.
    • The builtin now reports concat-removed naming the replacement AND the order reversal — a rename that keeps the argument order miscompiles silently, so the message says so. Pinned by errors/concat_removed.prp.
    • All 17 fixtures migrated to (...)#[..]; the concat_array_lane golden's {} order was flipped by hand and re-proven. upass.prp_writer needed two fixes to keep the round trip: its own copy of the array-expansion order, and an all-ones mask that was emitted as x & -1 (a hard type error on re-parse once the source is a tuple).
    • 29/29 concat tests green.
