2f-sim Agent-oriented lhd sim query API

Give a coding agent a stable, non-interactive way to inspect a simulation without generating and parsing a whole VCD or learning a collection of presentation-oriented CLI flags. The interface is one stateless invocation with a versioned JSON request and result. A request may batch several questions; lhd chooses the nearest compatible checkpoint, replays once, and answers every question whose time range is covered.

lhd sim design.prp test.name \
  --workdir run \
  --query queries.json \
  --result-json out.json

--result-json keeps its existing meaning — the whole result envelope. The answers are a new envelope member query, a sibling of the existing tests and debug members, delivered through the same mechanics those use today: the generated driver writes a sidecar (<simdir>/sim_query.json, mirroring --debug-json) and the kernel embeds it verbatim. The existing --list-signals, --probe, and --break-when options remain supported as compatibility sugar over this query engine. VCD remains an export for waveform viewers, not the query database. lhd sim's ln:/lg: IR positionals keep working — the query API must answer when the DUT is a pre-compiled artifact (a .prp testbench is still required).

Architecture seam

lhd sim is a codegen-plus-shell-out design: all observability, checkpoint and restart machinery runs inside the generated drv.cpp binary, reached through the argv seam. The query engine therefore spans two layers and the plan names them explicitly: the kernel parses and validates the request, plans the batch, and forwards it to the generated driver via a new driver flag pair (--query FILE plus --query-json <simdir>/sim_query.json, mirroring --debug-json); the driver evaluates queries during its single restart-capable tick loop and writes the answers sidecar the kernel embeds. Any change to the emitted C++ shape (catalog metadata, evaluator hooks) must bump kSimGenVersion, or stale sim dirs silently no-op the extension.

Request and result contract

--query accepts a file path, - for stdin, or an inline JSON object when the argument starts with {. The batch-JSON form is chosen over an --eval-style expression flag because batching is what enables the single-replay planner and per-query structured errors; the legacy flags remain the low-ceremony spelling. Versioning follows the repo-wide convention (integer schema_version plus kind, as in the envelope, formal_report.json and the witness JSON):

{
  "schema_version": 1,
  "kind": "sim_query",
  "queries": [
    {
      "id": "pc",
      "op": "value",
      "signal": "cpu.fetch.pc",
      "at": {"cycle": 10420}
    },
    {
      "id": "r5",
      "op": "value",
      "signal": "cpu.rf.regs[5]",
      "at": {"cycle": 10420}
    },
    {
      "id": "redirect",
      "op": "next_change",
      "signal": "cpu.fetch.redirect",
      "after": {"cycle": 10420}
    },
    {
      "id": "rob_delta",
      "op": "diff",
      "scope": "cpu.rob",
      "from": {"event": "fail", "offset": -1},
      "to": {"event": "fail"}
    }
  ]
}

Timestamps are objects. {"cycle": N} is an absolute cycle; {"event": "fail", "offset": K} resolves to the first failing assert's cycle of the selected test (plus optional offset), during the same run — so the canonical agent loop, "the test failed, show me the state," is one invocation that both reports the verdict and answers failure-anchored queries. phase defaults to "post" and is the only accepted value in v1; any other phase fails explicitly rather than aliasing to post.

The response preserves request order and IDs. Each result is independently ok or carries a structured error {"class", "message", "hint"?, "suggestions"?} with an enumerated class vocabulary (unknown_signal, ambiguous_selector, invalid_range, unsupported, timeout, limit); one bad signal must not erase unrelated answers. Process-level rules: an unparseable or unknown-schema request file is error_class usage (exit 2); a well-formed batch that executes exits 0 with per-query errors in-band; an assert failure during replay still maps to assert (exit 11) and the query member is still emitted. While touching this code, register the existing unlisted "compile" error_class in exit_code_for instead of inheriting its silent exit-1 hole.

{
  "schema_version": 1,
  "kind": "sim_query_result",
  "run": {
    "test": "test.name",
    "design_hash": "9223116190210617913",
    "run_id": "c6e1f0a2b3d4e5f6",
    "query_hash": "77aa12bc90de34f1",
    "seed": 12648430,
    "rng_draws": 0,
    "clock": "clock",
    "checkpoint_used": 10000,
    "checkpoints_skipped": [{"cycle": 12000, "why": "design_hash_mismatch"}],
    "cycles_replayed": 421,
    "phase": "post"
  },
  "results": [
    {
      "id": "pc",
      "ok": true,
      "at": {"cycle": 10420, "phase": "post"},
      "value": {
        "bits": 64,
        "declared_bits": 64,
        "signed": false,
        "hex": "0000000080001040",
        "dec": "2147487808",
        "known_mask": "ffffffffffffffff"
      }
    }
  ]
}

Value objects are full-width hardware bit vectors, never host integers: bits is the catalog (internal) width — today's pinned behavior, e.g. 9 for a u8 register — and declared_bits is the source-declared width; hex is exactly ⌈bits/4⌉ lowercase digits of the two's-complement value truncated/zero-padded to bits (binary, when requested, is exactly bits digits); dec is the signed decimal rendering via the existing Slop formatters so agents never re-implement sign extension (an s12 holding −3 renders hex:"ffd", dec:"-3"). signed is interpretation metadata only.

known_mask is reserved and definitionally all-ones in v1. The compiled simulator is strictly 2-state: Slop resolves x/? literal bits to seeded-PRNG concrete values at parse time, and an ordering="none" collision read is a fresh draw per read. The honest unknown-ness disclosure is the run metadata's seed and rng_draws, which the response must surface whenever randomness was drawn. The field exists so a future four-state backend (the existing, never-emitted Dlop plane) can report real unknown bits without a schema bump; an engine must never report a bit unknown unless a backend actually tracks it.

Within-v1 evolution rules: unknown request fields, operations, phases and invalid ranges are usage errors (reject, do not ignore); response objects may gain additive fields within v1 and consumers must ignore unknown result fields; any change to the meaning or default of an existing field bumps the version. Deterministic ordering (request order for results, catalog order for expansions) makes the JSON suitable for agent tools and tests. The --query file follows the observability-flag precedent and stays outside run_id; query_hash (a content hash of the request) is the transcript key — benchmark tooling keys on (run_id, query_hash).

Time model

  • cycle = the tick-loop variable's value at the post-step sample — the same index asserts, probes, break-when and checkpoints already report. There is exactly one sample per tick-body iteration.
  • A body that advances more than one clock period per iteration (step 3, multiple step statements) exposes only the settled per-iteration sample. The response discloses this (run.multi_step_body: true), and transitions inside those interior periods are structurally unobservable — a changes/next_change result is defined over consecutive samples, not clock periods.
  • Sequential tick loops each restart a fresh 0-based counter, and the restart prologue is emitted only for the first loop; v1 therefore answers queries on the first tick loop's timeline only. A query whose range extends past it returns a structured unsupported error, and the run metadata reports the loop's clock-variable name and iteration count.
  • phase:"post" is not a simplification — it is the only observation point the generated code exposes: all latch low/high windows, negedge fall-phase commits and secondary-clock edge detection are internal to one cycle() call. A pre phase is the first planned protocol extension (with mem_ordering_sim as its acceptance fixture: that test samples outputs pre-step because post-step reads hide the old-vs-fwd memory-ordering distinction).
  • Honest divergence disclosure: testbench asserts that read outputs before step observe a pre-step (peek) value, so a failure-anchored query may legitimately disagree with the failing assert's operands. When the failing assert line precedes the step in its tick body, the result carries a note saying so.

Five v1 operation families

  1. signals. Enumerate queryable signals by exact name, scope/module, glob or ECMAScript regex, and kind. v1 kinds are flop, pipe, memrd, input, output and memory — outputs and memories are added to the catalog by subtask B (today it holds only the first four). Each record carries the hierarchical name, kind, declared and internal widths, signedness, direction, memory size where applicable, and supported operations; source location, clock domain and aliases are optional-absent (null) until plumbed. The signal's identity IS its hierarchical name, stable only for a fixed design_hash: names derived from RTL identifiers persist across recompiles, synthetic <type>_<nid> names (e.g. memory_60) carry no cross-compile guarantee — a stable-ID field is reserved until graph-side name preservation lands (B2). Inputs are catalogued under the clean port name (acc.din) with the legacy __in.<field> spelling kept as an alias for checkpoint compatibility. Unknown and ambiguous selectors are errors with suggested matches. Catalog order is the describe_signals DFS emission order and is the sort key for every deterministic expansion.
  2. value / values. Read one signal or a selector-defined set at an exact cycle and phase. value requires its selector to resolve to exactly one signal (ambiguous_selector otherwise); values takes a selector object {scope?, glob?, regex?, kind?} and returns an array of {signal, value} in catalog order. Values are full-width per the contract above. Single-element memory word reads are in scope: "cpu.rf.regs[5]" reads the committed contents post-step (staged same-cycle writes are transient by definition). Memory words are addressed by explicit index only — selectors and scope expansion never enumerate memory contents, and whole-memory dumps/diffs stay excluded from v1.
  3. changes / next_change. Return value transitions for a signal or scope over a bounded interval, or the first transition after a point. Semantics against the sample stream: all from/to intervals are closed; after is strictly exclusive; a change reported at cycle c means sample(c) ≠ sample(c−1) — c is the first observation of the new value, not a subcycle edge time. changes over [from,to] includes the baseline value at from; a scope result is a flat event list [{signal, cycle, old, new}] sorted by (cycle, catalog order). A count_only mode returns {count, complete} with no rows, and every changes/find result carries the count of qualifying events seen even when rows were truncated — a truncated row list must never leave the agent unable to state a count. next_change without an explicit bound scans to the test's final sample and reports the searched interval either way, so every query has a finite range the planner can union.
  4. find. Search a bounded interval, forward or backward, for the first cycle satisfying a typed expression. The expression is a JSON tree, not a string: nodes all/any/not, leaves {sig, cmp, value|sig2, slice?} with comparators ==, !=, <, <=, >, >=, changed, rising, falling. Literals are decimal or 0x-hex strings parsed at arbitrary precision (never a host integer — the --break-when 64-bit strtoull hole must not be recreated); comparisons evaluate at full width using catalog signedness (signal-to-signal: widen to the larger width; signed compare iff both operands are signed); slice:[hi,lo] results are unsigned; changed means differs from the previous sample; rising/falling are legal only on 1-bit operands. Backward find returns the greatest qualifying cycle (implemented as forward traversal retaining the last match — no reverse execution exists). An optional "sample": [sig, ...] field returns those signals' values at the found cycle in the same pass — the one-replay answer to "value of X when Y first rises", mirroring the full-state snapshot --break-when already records at its hit cycle (break_state). Forward searches stop replay early only under the verdict-neutrality rule below.
  5. snapshot / diff. Return all selected state at one cycle, or only values that differ between two cycles. The selector is required — omitting it is an error, not an implicit select-all. snapshot returns {signal, value} pairs and diff returns [{signal, from_value, to_value}] listing only differing signals, both in catalog order, both bounded by max_results; a response reports truncation rather than silently omitting state. Every interval/selection result carries {complete, truncated, searched:{from,to}}.

Execution and semantics

  • Require exactly one selected test, matching today's observability modes (the generated driver already enforces this).
  • Plan the complete batch before replay: union its time ranges, select one checkpoint, and traverse the interval once.
  • Checkpoint compatibility is a planner rule, not a warning. In the agent edit loop, workdir checkpoints are stale almost every time — any edit flips design_hash (it folds a cell-count logic fingerprint). The batch planner treats a hash-mismatched checkpoint as unusable and falls back to the next older matching checkpoint or a cycle-0 replay — never warn-and-load, which would produce silently wrong answers from stale state. This is deliberately stricter than --restart-at, whose warn-only cross-version reload is preserved unchanged for the editable-checkpoint use case. The response reports checkpoints considered, the one used (null when replaying from 0), and why others were skipped. A "compatible" checkpoint includes the per-net __clkprev_* secondary-clock edge state (pinned by lhd_sim_restart_test.sh).
  • PRNG rule. The PRNG stream position is not checkpointed (only seed and the draw count are recorded), so replay from a checkpoint of a randomized run diverges. Default: if the selected checkpoint's rng_draws != 0, replay from cycle 0 for deterministic answers; a request may opt in with "allow_rng_divergence": true, which proceeds from the checkpoint and marks every result reproducible:false.
  • Early-stop is verdict-neutral. A query run is still a test run: stopping replay early would skip later asserts and truncate the verdict. Early-stop is allowed only when no other batched query, legacy sugar, or full-run verdict needs the tail; when it triggers, the envelope's tests member is marked partial (replay_stopped_at) so an agent can never mistake a truncated replay for a passing run, and no checkpoints are written from the truncated replay. Legacy --break-when keeps its pinned full-run traversal.
  • Sample only the settled post-step state (see Time model). Unsupported phases fail explicitly.
  • Output sampling is inline, never peek(). The only output-read path today is peek(), which deep-copies and restores the entire design state per call. The query evaluator instead observes outputs from the pre-commit values inside cycle() (the same machinery the VCD pre-commit snapshots use): one shared evaluation per replayed cycle serves all output queries. peek()'s snapshot/restore path remains reserved for the testbench grammar.
  • Honor max_results and a query timeout. Return complete, truncated, and the searched interval so absence is distinguishable from an incomplete search.
  • Exact checkpoint-cycle reads without replay are legal only when every selected signal at that cycle is a checkpointed kind (flop/pipe/memrd/input, or a memory word via the .hex image); any output read forces loading the state plus one recompute.
  • Cost model. A query invocation against an existing --workdir must reuse the built drv.bin when the structural digests match (the same contract as --run-only): its cost is binary startup plus replay from the nearest usable checkpoint. Checkpoints default to a 10-second wall-clock cadence floor, so short runs — most fixtures, most agent debug loops — produce zero checkpoints and replay from cycle 0; when replay distance is large the response includes a hint naming --set sim.checkpoint_every for denser checkpoints on the next run.
  • Combining --query with --restart-at, --vcd-from/--vcd-to or --vcd-on-fail is rejected as a usage error in v1 (--vcd-from silently doubles as a restart target today, and the two planners would fight); composition can come later.

Relationship to existing tasks

  • 4c — the durable checkpoint format 2f-sim needs is already landed and regression-pinned (ckp<cycle>/ with regs.json, per-memory .hex, tb.json, meta.json, atomic _done, nearest_checkpoint_cycle); 2f-sim builds on it directly and is not blocked on 4c. 4c may later formalize partition-keyed state_shape_hash; any 4c reload validator must remain disclosure-only — warn-only cross-version reload is a standing ruling ("editable checkpoints are cross-version on purpose"), and the query planner's stricter skip-mismatched rule is a planner policy layered on top, not a change to reload semantics.
  • 4e remains the later queryable indexed trace store. It may become a backend for repeated historical queries, but 2f-sim's public request and response contract must work first with checkpoint plus replay and must not depend on a persistent trace index.
  • 2f-simqa owns the external WaveformQA benchmark harness (VCD-replay adapter, coverage manifest, agent baselines, re-simulated RISC-V workloads). 2f-sim ships on subtasks A–F below; WaveformQA results are a report produced by 2f-simqa, never a 2f-sim acceptance gate — the cited artifact repo is not yet public.
  • 5f owns benchmark contracts and agent-loop latency. It may promote a stable smoke subset and performance thresholds after 2f-simqa's harness is calibrated.
  • lhd tool --diag-fmt jsonl already exposes structural LGraph inspection. Joining runtime signal IDs to fan-in/fan-out/source-cone queries is a follow-on, not one of the five v1 simulation operations.

WaveformQA as design rationale

WaveformQA (also published at IEEE ICLAD 2026) is the external benchmark for agent-generated queries — 360 questions with programmatic ground truth across eight categories and 24 subcategories over 13 RISC-V traces. The harness, artifact gating and metrics live in 2f-simqa; the category table stays here because it is the design rationale for the five operation families:

WaveformQA categoryExpected v1 building blocksExamples covered
Lookupvalue, values, findvalue at time/edge, value when another signal changes, first match
Countingchanges (count_only), findtransition, rising-edge and conditionally gated counts
Arithmeticchanges plus agent arithmeticcycle-count differences only; physical-time period/frequency is extension-required (no cycle-to-time mapping exists beyond the VCD period-10 convention)
Temporalchanges, next_change, findbefore/after, event ordering and last value before an event
Multistepfind with sample, then value/findcycles after trigger, nth-event value and conditional sequences
Correlationfind, values, next_changedual/triple conditions and which signal changes first or last
Misdirectionsignals, find, valuehigh-order occurrences, event-after-event; subcycle glitch questions are extension-required
FSMchanges, findstate sequences, next state and return counts

Do not add an operation merely to mirror a benchmark subcategory. First record whether an agent can compose the five primitives correctly and efficiently. A category that requires excessive result rows, tool calls or replay work is evidence for a later aggregation or expression-language extension.

V1 boundaries

No interactive debugger or resident daemon; no VCD parser/index as a prerequisite for the shipped engine (2f-simqa's harness-only adapter is exempt); no arbitrary combinational-temporary observation (module outputs are in scope; interior comb nets are not); no whole-memory dumps or memory diffs (single-word indexed reads are in scope); no pre-phase or subcycle observation (reserved as the first extension); no multi-clock phase queries; no structural-cone or causal/provenance queries. Those can extend the versioned protocol after the five operations establish a reliable agent loop.

Acceptance

  • One batch asking for a value, a next transition and a scope diff near cycle one million loads one checkpoint and performs one bounded replay, with that plan — checkpoint considered/used/skipped and why — disclosed in JSON.
  • A value wider than 64 bits round-trips exactly in hex and decimal; no numeric truncation is permitted. known_mask is present and all-ones, and any run with rng_draws != 0 discloses it in the run metadata.
  • A batch containing snapshot at {event:"fail"} and diff from offset −1 answers in the same single run that reports the test failure; find with sample answers a value-at-event question in one invocation and one replay.
  • next_change and find return the first qualifying post-step cycle inside their bounds, or a complete not-found result; forcing a smaller result or time limit produces an explicit incomplete result that still carries the qualifying-event count.
  • A memory word read (cpu.rf.regs[5]) at a checkpointed cycle matches the checkpoint's .hex image at that cycle.
  • Every signal named by a result resolves back to one catalog record; for --query operations, invalid or ambiguous names error with suggestions and never become zero or disappear silently (the legacy sugar keeps its pinned warn-only behaviors unchanged).
  • A query batch whose planner would use a design_hash-mismatched checkpoint falls back rather than loading it, and the fallback is visible in the response.
  • A second query batch against an unchanged workdir performs no re-generation and no re-compilation.
  • The existing observability test suite remains green, and equivalent legacy and JSON queries report the same cycles and values on runs with zero PRNG draws.
  • The engine-oracle smoke (subtask F) reproduces programmatic ground truth exactly for every canonical query sequence and publishes per-subcategory covered/total counts, including zeros.
