2f-scalability Placement that fits one chunk at a time

A chunk budget applies to the downstream worker. The color floorplanner, the current flat exporter and a whole-design timing or routing run have different memory footprints. See the working flow and replay commands and the clean-run checks.

Remaining work

  1. Export without a flat physical design. Read cells, pins, obstructions and boundary summaries by home from mapped storage. Today a selected worker can load only its packet, but the producer still builds the flat view. Measure producer and worker RSS separately on a design too large to place flat; a large synthetic color graph tests the planner only. Profile the remaining graph, net and name copies before choosing the next memory optimization.
  2. Reuse and stitch physical implementations. An interface match helps choose how pins face; it does not prove interchangeable netlists, rows, rails or SRAM pin access. Carry logical instance and pin identity through inlining and extract arbitrary colored chunks without requiring separately supplied RTL. Store oriented cell and macro poses and stitch one owner per movable instance. Reject incompatible masters, fixed obstacles, row phase or unmatched required pins. Acceptance: reproduce a representative in another instance from saved collateral; check the stitched DEF in OpenROAD, then compare crossing-net wirelength and routed DRC against independent placements.
  3. Bound timing and negotiate edges. Exchange arrival/required time, exterior load and RC at cut pins. Compare local deltas with a flat reference, including multi-clock and reconvergent paths. Then try moving a contact or cell between neighbors. Charge overlap capacity once, preserve unique cell ownership and stop or roll back a round that oscillates. Test a pair and a ring before running workers in parallel under one aggregate memory budget.
  4. Calibrate on unfamiliar designs. Challenge the worker RSS envelope at 1, 2, 4, 8 and 16 GB across technologies, sparse and macro-heavy homes, and detailed placement. Separate a completed peak from a killed worker’s lower bound. Check simultaneous producer and worker memory on a constrained machine; polling an individual RSS is not a hard machine limit.
  5. Incremental replacement and precision. After stitching works, remap one edited color and show which home and neighbor results really need invalidation. Compare with a clean run. For the proposed FP32 solver, benchmark local normalized coordinates first; retain exact integer legal poses and verify timing, wirelength and memory before changing default precision.

Browser controls, agent feedback and the remaining interactive work belong to 2p-placereason. Related: incremental synthesis and timing.
