2c-fpcolor Placement colors and adaptive FP pins

Create macro-centered placement colors after synthesis, immediately before floorplan placement (FP). Use them for centroid attraction and local space reservation, while allowing unconstrained IO pins to follow the evolving placement.

Implemented and evaluated locally The implementation is opt-in and preserves existing defaults. Focused graph, centroid, IO, native-GP and buffer-repair checks pass. Controlled runs and their artifacts are under repros/fpcolor_20261018/comparison.html; no reports are tracked.

Depends on

None of the outstanding tasks must finish first. This extends the existing three-stage native placement flow tracked in 3p-placement, using mapped cell semantics and technology area information already available to LiveHD.

Design notes

Execution boundary and flow

synthesis → mapped graph + technology geometry
    → optional placement-color analysis and local area reservation
    → initial IO assignment (bus ordered when fp.pin_adjust is enabled)
    → FP: moving centroids + repulsion + optional periodic IO adjustment
    → existing hierarchy-local centroid snap; freeze targets and IO positions
    → macro placement with fixed centroid targets
    → existing macro snap/legalization; lock macros
    → final cell placement with fixed macros/IOs and no centroid anchors
  • The new graph colors describe physical placement regions. They do not recolor synthesis partitions, rerun synthesis, or replace synthesis provenance.
  • Use instance-aware identity on the post-synthesis graph. Shared module definitions must not accidentally share a color between unrelated instances.
  • Ordinary flops are boundaries, not seeds for thousands of small centroids. SRAMs/macros are the initial seeds; IOs do not seed colors or centroids.
  • Leave unrelated logic uncolored. Large non-memory regions could qualify by area if a later seed policy exposes them; exhaustive flop-to-flop coloring is outside this first implementation.
  • Use the current native C++ placement path. OpenROAD remains a comparison and downstream CTS/routing tool, not an implementation dependency of this pass.

Macro-centered colors

  1. Identify physical SRAMs/macros using mapped interfaces and technology metadata, including Liberty-backed memory instances. A memory need not remain an explicit high-level Memory operation after synthesis.
  2. Seed one provisional color per macro. Walk backward from address/data inputs and forward from data outputs through combinational logic. Stop at flops/latches, other macros, and top-level ports; never traverse memory internals.
  3. Exclude clock/reset paths and constants from expansion and merge evidence. Resolve pin roles from cell semantics rather than a technology-specific name heuristic. Functional enable/write-mask inputs are excluded from seed expansion in this first version. Unrecognized non-memory block macros use non-clock signal ports.
  4. Merge colors that share combinational logic, including transitive overlap. Sharing only a boundary flop, clock, reset or constant does not merge colors. Report unusually large merged groups; do not silently impose synthesis stop_* limits on this different analysis.
  5. Apply a configurable equivalent-cell-area threshold for creating a centroid. A color can exist below that threshold, and still acts as a boundary for reservation walks. Use the same technology area normalization as the existing centroid flow, including macro area; do not substitute node count.

One extra pipeline stage reserves space

colored cone → first flop → uncolored logic → second flop
                            reserve area       stop

Apply this reach in both the input and output directions. The reservation walk crosses the first boundary flop but does not continue beyond the second. It stops immediately at another color or any macro, including one without a centroid. A distant cache/core region reached through further pipeline stages therefore contributes no allowance. Physical proximity alone never qualifies a cell.

For each eligible uncolored cell u, collect the set R(u) of distinct recipient colors. Multiple paths from the same color count once. If two colors reach the cell, each receives half its area; three receive one third each. Cells reached by no eligible recipient remain unassigned.

reserved_area[g] = Σ over u with g in R(u): area[u] / |R(u)|
effective_area[g] = allocated_member_area[g] + reserved_area[g]
radius[g]        = sqrt(effective_area[g] / (pi * target_density))

centroid[g] = Σ(member area * member position) / member_area[g]
  • The first version adds no attraction to reserved cells. They remain freely placeable and contribute their ordinary physical density exactly once. A much weaker optional attraction is a possible later experiment.
  • Reserved area changes circle size, not the centroid's member list, area-weighted center, attraction normalization, LEF size or GP density charge.
  • Circle repulsion stops at the sum of radii. The additional area does not create a hard region, require filler cells, or force the design to fill an explicitly supplied core to a density target.
  • Store recipients and shares explicitly so accounting can be checked after merges and FP repair. Decide boundary-flop ownership and subthreshold-color recipients explicitly; neither may silently lose or multiply physical area.

Hierarchy and color leaves

  • Repeated-hierarchy discovery keeps its existing structural/area criteria. Changing color source changes the membership used by FP, not the definition of structural repetition.
  • Color centroids are leaves. Split a graph color into portions belonging to each deepest selected hierarchy candidate; keep the outside portion at the root. Shared external logic cannot promote the inside portion to the root. Evaluate centroid eligibility on each portion. The hierarchy still provides soft attraction, without introducing hard physical bounds.
  • A parent continues to attract its descendants through their member cells. Repulsion is among peers in the applicable candidate hierarchy, not between a parent and its child. Local portion ownership prevents shared graph colors from manufacturing competing circles across structural branches.
  • Reserve each uncolored cell's area once across peer recipients. Parent summaries must aggregate the underlying ownership/shares without adding the same allowance again for every descendant level.
  • Unique color leaves do not participate in repeated-family centroid snap. Existing hierarchy snap stays local to matching siblings and inherits the parent's snapped translation. Macro alignment/snap classes are separate from this FP-color selector.

IOs follow the evolving floorplan

synth.place.fp.pin_adjust enables an FP-only adjustment of unconstrained IO locations. The existing initial per-bit assignment must also respect bus order when this option is enabled. IOs influence centroids through their connected nets, without their own colors or centroid springs.

  • Represent the die boundary as a circular sequence of available slots. Periodically test small clockwise/counterclockwise moves following the nets' edge pull, scored using current timing-weighted wirelength. An artificial perimeter origin must not prevent a move around a corner.
  • Read bus identity and numerical bit indices from port metadata. Each bus keeps ascending or descending order around the perimeter. Variable gaps, other buses/scalar pins between bits, and spanning corners are allowed; contiguous bus blocks are not required.
  • Evaluate reversal of the whole bus's physical order when its connected pins favor the opposite ordering. Use connection geometry as a crossing proxy and verify the placement cost; no routing-crossing claim follows from that proxy alone. Preserve bit-to-net connectivity.
  • Respect explicitly fixed pins, reserved slots, pin dimensions/spacing and edge constraints. Partially fixed buses only admit moves/reversals compatible with those pins. Reject infeasible proposals rather than moving a fixed pin.
  • Bound each update's movement and require an improvement margin before a reversal or reassignment. Use deterministic tie-breaking and suppress back-and-forth motion while centroids and cell placement settle.
  • Keep pin updates independent of the expensive STA/resize cadence and its density gate. They must work with either color source, without STA, and when FP is requested but no color passes the centroid threshold.
  • Update the native terminal coordinates, exported floorplan and subsequent RC/STA inputs consistently. Refresh any optimizer history invalidated by changing fixed terminals; do not leave stale forces or stale timing geometry.
  • Freeze the resulting IO positions after FP for macro and final placement. The imported-fixed-IO comparison path remains constrained by its input DEF.

Boundary accounting: the first register contributes reservation; the second is excluded. Subthreshold colors remain barriers but receive no share. Eligible recipients divide each uncolored cell equally. Cross-scope graph colors are split into hierarchy-local centroid portions. Reservation reachability is recomputed from each portion's members. Structural candidates keep attracting their physical descendants; member budgets are propagated once through the parent chain. Reports distinguish attracted physical area, allocated member budget, and reserved area.

During in-FP graph edits, color identities and surviving member owners stay stable; inserted buffers inherit their recorded physical origin. Areas and one-stage allowances are recomputed on the edited graph. A new placement starts a fresh color analysis. Color leaves never snap independently but inherit their parent's snap translation. Pin updates use native terminal-only callbacks, independent of density-gated STA, and reset momentum/history when pins move.

Bounded memory-first alternative

synth.place.fp.color_source=memory_first adds post-synthesis memory input cones with bounded, round-robin best-overlap merging. It adapts synthesis's scheduling rule to physical standard-cell area; it does not run synthesis or overwrite synthesis colors. The opt-in growth cap is synth.place.fp.color_maximum=30000 equivalent average standard cells. SRAM footprints count fully for centroid sizing, separately from the logic budget. Ordinary state/output cones are potential merge partners; only macro-containing groups become colors. See the pass README for the algorithm and repair contract.

The evaluation compares the same saved mapped netlists with the previous color sources, holding the rest of placement fixed. Results and images remain in the ignored local report.
