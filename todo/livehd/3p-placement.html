3p Placement feedback for synthesis

Status: M0 and the M1 standard-cell baseline implemented (2026-10-14); mixed-memory estimates and later optimization milestones remain pending. Goal: a working compile → synth → map → place flow inside lhd synth, with legal DEF output and placement-aware timing. The structure must already support (a) a later loop in which placement-critical paths trigger re-synthesis and remap of the affected logic cone under input/output timing constraints, and (b) pin placement, macro placement (Re2MaP-like) and floorplanning tools.

Agreed decisions

  • Placer engine: torch-free C++ DREAMPlace.
    • DREAMPlace 4.3.1's global-placement loop is Python (NonLinearPlace.py, PlaceObj.py, Nesterov optimizer). Its kernels are torch C++/CUDA extensions on at::Tensor. LiveHD has no torch, CUDA or pybind dependency and will not gain one.
    • Fork the code under masc-ucsc/DREAMPlace (like the OpenTimer fork) with a torch-free C++ library target, and pin it with http_archive, using its shipped BUILD files. License is BSD-3. LiveHD supplies a plain LEMON archive with the registry compatibility patches so dependency consumers need no root-only override.
    • Keep these kernels, with their raw-pointer cores and without the *_forward(at::Tensor)/PYBIND11_MODULE wrappers:
      • weighted-average wirelength
      • electric potential/density, with the DCT moved off torch FFT (pocketfft or a plain DCT)
      • greedy and Abacus legalization, macro legalization (Hannan + LP)
      • k-reorder, independent-set matching, global swap
      • legality check, flute
    • Rewrite the Python control loop in C++ (about 1–2k lines): Nesterov steps, density-weight and gamma schedules, filler insertion, stop on overflow. Use OpenROAD gpl (RePlAce, nesterovPlace.cpp) as the reference for a C++ structure.
    • CPU with OpenMP only. A GPU backend is a possible later option, not a goal.
    • Do not use DREAMPlace's PlaceDB: its builder methods are protected, and the kernels never read it anyway. LiveHD exports DREAMPlace's flat arrays directly:
      • nodes: node_x/y, node_size_x/y
      • pins: pin_offset_x/y, pin2node, pin2net
      • connectivity in CSR form: flat_net2pin(_start), flat_node2pin(_start)
      • nets: net_weights
      • layout: rows, site width, row height
      Node order is movable, then fixed, then terminals; fillers are private to the native solver and never written back. The fork also has an HHDS adapter, but LiveHD resolves its remaining bus-alias nodes into the flat-array interface.
  • Placement state: one flat placed graph.
    • After map, flatten and uniquify the region hierarchy (the <mod>__cN modules) into one HHDS module for the top (flatten_hierarchy()). Instance names keep the dotted path that opentimer already uses.
    • Extend the existing unused place_t attr (graph/ann_place.hpp) to hold integer DBU x/y, orientation and status UNPLACED/PLACED/FIXED/LOCKED (the OpenROAD status model). Net weights are a per-driver attr.
    • This graph is the single source of truth. Placement, STA, DEF/Verilog writers and re-synthesis all read or edit it. Graph edits notify the STA and placement caches through observer hooks (insert/delete/rewire), like OpenROAD dbBlockCallBackObj.
  • CLI: a stage inside lhd synth.
    • --set synth.place=true enables it. The default is false, so plain lhd synth output does not change (defaults are a contract).
    • The stage runs after map (stage 3) and before the final STA (stage 4), in the same process, so the graph stays in memory for the later loop.
    • Knobs are synth.place.* rows in kSynthSetOptions: mode, utilization, aspect, density, floorplan, wire_rc, …
    • Outputs go to <workdir>/synth/place/{out.def,qor.json}, with --emit-dir def:DIR and an optional SPEF dump for debugging.
  • Physical inputs: synth.lef.
    • Mirrors synth.liberty: a comma-separated list with the tech LEF first, then cell/macro LEFs, and the same $HAGENT_TECH_DIR default rule.
    • Per-layer wire RC comes from LEF RESISTANCE/CAPACITANCE, with synth.place.wire_rc=<ohm/um>,<fF/um> as an override (needed for techs like ASAP7, where ORFS keeps RC in setRC.tcl).
    • Revive inou/lefdef on HHDS. It was deleted in the HHDS migration (e446552a8), but the Si2 parsers are still vendored in third_party/misc/{lef,def}.
    • LEF loads into a read-only tech DB: units, sites, layers and RC, and macros with their size and pin shapes. DEF provides floorplan input and placed output.
  • Parasitics: in-memory RC into STA.
    • After placement, build a FLUTE Steiner tree per net and push RC trees straight into ot::Timer, the same pattern as DREAMPlace's TimingCpp.
    • The same estimator supplies the mapper's abc_boundary PI arrival and PO load for re-synthesis. There is no SPEF round trip inside the loop.
  • Macros and memories.
    • Memories stay black boxes in synthesis (pass.abc.memory=false).
    • If a LEF MACRO matches the black box, use its size and pins. Otherwise use a placeholder sized from bits × a per-tech area/bit, with pins spread on its edges, and tag it estimated in qor.json.
    • M1 uses DREAMPlace's mixed-size flow plus macro legalization. A dedicated macro placer comes later behind synth.place.macro=.
  • Floorplan and IO pins.
    • By default, size the core from cell area / utilization and aspect, with rows from the LEF SITE.
    • IO pins: a ppl-style Hungarian slot assignment on the die edges, alternating with GP (GP → assign pins → GP).
    • Optional synth.place.floorplan=fp.def supplies DIEAREA, ROWS, fixed PINS and fixed macros, all with status FIXED and never moved. A future floorplanner or macro placer fills this same hook.
  • Modes.
    • synth.place.mode=full: GP + LG + DP, writes a legal DEF.
    • synth.place.mode=gp: global placement only. Cells may overlap, no DEF is written, and timing is tagged approximate.
    • The re-synthesis loop iterates in gp and finishes in full.
  • Re-synthesis unit (designed now, built after M1): a critical cone on the flat graph.
    • Starting from failing endpoints, walk back to flops/PIs, capped by size and depth.
    • Wrap the cone as a Region_body and send it through the existing region backend (pass.abc/usyn). abc_boundary carries the placed arrival/required times, input drives and output loads.
    • Splice the result back, seed new cells at the centroid of their boundary pins, and lock everything else. Run windowed incremental GP + LG + DP with limited displacement.
    • Keep the change only if WNS/TNS improves.
    • This follows OpenROAD rmp/cut (LogicExtractorFactory → BuildMappedAbcNetwork → InsertMappedAbcNetwork, arrival/required on cut boundaries). It improves on rmp, which leaves new cells unplaced.
  • Validation.
    • In repo:
      • our own legality checker: on site/row, no overlap, inside the core
      • a DEF write/read round trip
      • tests on a trimmed sky130hd subset (tech LEF plus a cell LEF matching sky130_test.lib), each under 20 s at -c opt
    • Optional external leg, opt-in in the LHD_EXTERNAL_* style (it fails if requested but the tool is missing):
      • OpenROAD check_placement on our DEF
      • HPWL within ~3% of stock DREAMPlace 4.3.1 (Python) on the same LEF/DEF for a few lhdtrack designs
    • qor.json reports HPWL, overflow and placed WNS/TNS.
    • Full sky130/ASAP7 LEFs go into lhdtrack as http_files next to the existing ORFS liberty pins.

Depends on

  • pass.opentimer (STA) and the abc_boundary table (PI/PO constraints for re-synthesis).
  • pass/partition flatten_hierarchy() and Region_body.
  • masc-ucsc/DREAMPlace at fc5e043a, with native CPU targets. LiveHD carries a narrow fix for zero-area IO terminals in its overlap checker.

Milestones — pending

  • M1 — Complete mixed-design placement support.
    • The standard-cell baseline is implemented (see landed below). Missing-LEF memory estimates and physical timing at native-memory boundaries remain to be implemented; current flows require matching geometry and Liberty models and diagnose missing ones.
    • Extend the native floorplan boundary for row gaps/blockages and other unsupported layouts. Current imports accept contiguous equal-width N/FS rows in the LEF DBU.
    • Add high-fanout RC estimation beyond FLUTE's current 1000-location limit.
    • Run the optional independent OpenROAD placement check and stock-DREAMPlace QoR comparison. These are not established by the hermetic tests.
  • M2 — Timing-driven placement.
    • Turn slack into per-net weights, in the style of gpl's linear formula or DREAMPlace's momentum weighting. Re-weight at overflow checkpoints.
    • Consider weights computed after virtual buffering, as gpl does with rsz::findResizeSlacks.
  • M3 — Place → resynth loop.
    • Cone extraction on the flat graph, then remap through the region backend with placed boundary constraints.
    • Splice the result back with seeded positions, then windowed incremental placement.
    • Keep or revert based on WNS/TNS.
  • M4 — Macro placement and floorplanning.
    • A macro placer behind synth.place.macro=, writing FIXED macros into the floorplan hook.
    • Re2MaP (arXiv 2511.08054) is a DREAMPlace fork with no LICENSE file, so it is a reference only and cannot be vendored. Usable alternatives are OpenROAD mpl (Hier-RTLMP, BSD) and DREAMPlace's two-stage macro flow.
  • C — Gate sizing and buffer insertion: our own resizer (decided 2026-10-13).
    • Write a LiveHD-native resizer instead of linking OpenROAD rsz. It works on the flat placed graph with in-memory STA and FLUTE RC.
    • Design repair: fix max slew/cap/fanout violations by buffering and splitting nets on the Steiner tree.
    • Timing repair: swap drive strength among liberty cells with the same footprint and function, then buffer critical nets. Keep a change only if slack improves.
    • Each new or resized cell is placed at once: a seed position on the Steiner tree, then single-cell legalization (OpenROAD Opendp::legalCellPos is the model). This is the same "never leave new cells unplaced" rule as M3.
    • Runs after GP, before the final LG + DP, and inside each M3 iteration after re-mapping a cone. Opt-in knob synth.place.resize, default false (owner ruling 2026-10-13; changing it later needs explicit approval).
    • Also produces the "after virtual buffering" slacks that M2 net weighting uses (gpl's findResizeSlacks idea), run under a journal that is restored afterwards.
  • D — Incremental placement reuse: block anchors + remembered color (decided 2026-10-13).
    • Partially implemented: unchanged blocks restore and lock their cells, anchors are saved, and reuse follows lhd.incremental. Explicit windows/displacement bounds, changed-block anchor seeding and cross-color replacement ownership remain pending.
    • A color region (block) is the unit of placement reuse. The flat placed graph keeps each cell's color id as a provenance attr.
    • After each run, save a block anchor per color: its bounding box/centroid and its cells' positions. It lives in the cache under --workdir, follows lhd.incremental, and is salted at build time. Macros get anchors the same way.
    • On an incremental edit:
      • Blocks whose content hash did not change restore their cells' positions and are anchored (LOCKED).
      • Changed blocks are re-placed inside or near their previous anchor box, with windowed GP + LG + DP.
      • Only new or removed colors trigger wider re-placement.
    • After a partial resynthesis (an M3 cone or a C resize), new cells inherit the color of the block they replaced, or of the boundary cells driving them, so the color map stays stable. The next incremental run then maps them to the same anchor instead of treating them as new logic. The cache key uses the color id plus the block content hash.
    • Open detail: how a cone that crosses several colors assigns color to new cells, e.g. the majority of the replaced cells, or the color of the endpoint.

Future (not scheduled) — soft color macros

  • F1 — Soft macro per color, with flexible pins and aspect ratio, and leaky boundaries. Brainstormed 2026-10-14; not part of M0–M4.
    • Each color region becomes a soft macro:
      • fixed area, with the aspect ratio free within a range (possibly rectilinear around hard memories);
      • boundary pins placed in slots on the block edges and optimized together with the floorplan.
      Hard macros (memories) share the same floorplan.
    • Boundaries are soft. Timing-critical cells may leave their macro's area, e.g. a cone feeding a macro that is not adjacent can sit between the two, instead of being forced inside a hard fence. Make the fence a per-color penalty whose tightness can be tuned: tight for stable blocks (incremental reuse), loose around critical paths.
    • Fits the current interface. The macro stage outputs fixed blocks, and a color block is a macro whose shape and pins can change between iterations, so the M1 data model needs no change. The block anchors from D are the reuse unit.
    • References, with details partly from abstracts or slides only:
      • ACCO, "PPA-driven Placement via Adaptive Cluster Constraints Optimization" (DATE 2026): per-cluster soft/hard bound tightness tuned from PPA.
      • GrandPlan (ISPD 2026, doi): flat placement with grouping penalties, then rectilinear partition extraction and fence placement.
      • Hier-RTLMP (TCAD 2024, OpenROAD mpl, BSD-3): standard-cell clusters as soft macros with an aspect range, plus one pin per edge segment.
      • "Modern Fixed-Outline Floorplanning with Rectilinear Soft Modules" (ICCAD 2024): moves overlap into whitespace to make rectilinear shapes.
      • Piano (arXiv 2508.13161): pins in slots on block edges and feedthroughs, chosen together with the floorplan.
      • Kahng et al., DAC 2024, clustering-driven placement: the "guide but don't fence" baseline.
      • FloorSet (Intel, Apache-2.0/CC-BY): benchmarks.
    • Base to build on: DREAMPlace's fence regions (a separate density field per region), with each fence turned into a penalty term.

Notes from how OpenROAD connects its tools

  • One database, with adapters. Each tool (gpl, dpl, ppl, mpl, rsz) builds a compact private model from odb and writes results back. sta::dbNetwork lets OpenSTA view odb without a copy. LiveHD's equivalent is the flat placed graph plus per-tool array exports.
  • Integer DBU coordinates, a row/site model, and a placement status enum are what keep incremental flows simple (Replace::doIncrementalPlace locks placed cells and places only unplaced ones).
  • Parasitics are re-estimated after every netlist edit (estimate_parasitics -placement). Re-synthesis and resizing always call it before re-timing.

    • Generated rectangular floorplans or compatible DEF input, bus-aware physical net export, GP → Hungarian IO assignment → GP → legalization/detail, and fixed-object preservation.
    • FLUTE RC enters OpenTimer in memory and persists with per-bit IO geometry; STA cache identity includes physical parasitics. Placed QoR reports HPWL, legality, convergence, overflow and WNS/TNS when timing constraints supply them.
    • Unchanged-block placement reuse and saved anchors under the shared incremental switch.
    • Hermetic tests cover both ABC and USYN mapping, independent legality, DEF and graph round trips, fixed floorplans, saved-graph STA replay, RC cache invalidation, and explicit proof-mode logical equivalence. A local 61-cell full-sky130 trial also produced a legal DEF and an unbounded equivalence proof; 16 bins and 1500 iterations reached the GP overflow target. The default 32-bin/500-iteration trial legalized but did not converge in GP. No OpenROAD or stock-DREAMPlace parity claim is made.
