3p-pnrflow One place and route flow, one legalization

Plan of 2026-11-26. Nothing is built. Today placement and routing are two commands joined by a DEF on disk, three legalizers run, and the router never sees the positions global placement wished for.

The goals, in order: a clean, consistent LiveHD flow; then efficiency and room to explore options. The flow as it is today is on the place and route page; the router's own list is 3r-routefirst.

The rules

  1. Routing is a stage of lhd synth. It is enabled by an option and needs placement: routing with placement off is a usage error.
  2. Route-first is the only mode when routing is on. Placement hands the router wished positions and which cells may move. The router gives cells their sites while it routes, and may move them well beyond the nearest site.
  3. Handoffs are in memory, as synthesis to placement is today. A stage can be saved and restarted from the work directory, but a file is not the interface between two LiveHD stages.
  4. Nothing legalizes unless it is explicitly called. Two things call it: the router, and writing a placed DEF. Global placement, the optimization steps and legroute work on wished positions, which may overlap. A legalization ahead of the router moves cells off their wished positions, which is what route-first exists to avoid.
  5. One DEF at the end, always legal: routed when routing is on, placed when it is off. A placement with overlapping cells is never a deliverable, only a debug snapshot.
  6. The clock tree comes before routing. Enabling routing turns the native clock tree on, with the power grid and taps; setting it off with routing on is a usage error. A frame read from an OpenROAD post-CTS result keeps the tree it has.
  7. The standalone lhd route stays for a legal DEF from another tool. Cells start on their sites, FIXED cells and macros stay, and options decide whether PLACED cells may move. It refuses a DEF with overlapping cells.
  8. Clock tree and routing stay together in one run, because they will have to iterate: build the tree, route quickly, improve the tree from what the route measured, route again.

What happens today

  • Three legalizers. Native legalization and detailed placement right after final global placement, because sizing, buffering and the resynthesis steps time legal positions and place each edit with a legal local move. Terminal legalization and tile spread at the end. The router's own, when route.prelegal is on.
  • The route-first runs so far did not start from wished positions. They read legroute's round DEF. Round 0 is the placement the optimization steps left, already legalized; on one ASAP7 Eyeriss run it was the selected round and 99.5% of its cells were on sites. Only a later round, which resumes global placement, has continuous positions again.
  • The handoff is a file. lhd route reads the DEF and LEFs again and writes its result by patching wires into the text of the input DEF. Route-first therefore needs a DEF with overlapping cells, written only with synth.place.snapshots=true and picked by hand.
  • No clock tree by default. synth.place.pcrs.clock=false leaves the clock as one net with every flop on it.

Stages

  1. The router as a stage, in memory.
    • An entry point that takes the floorplan and technology the placer already holds, and returns the routed floorplan and its statistics. Today the router is file based.
    • It is a session, not one call: route a set of nets, release nets, report what it measured per net (length, layers, vias), finish. The clock loop of rule 8 needs exactly this, and the resident router of lhd route chunk already has release and retry.
    • A synth.route option in the driver, with the placement and clock rules. It starts from whatever positions placement has at that point, so it can be measured against the two-command flow before anything else changes.
    • Done when: the same placement routes to the same result through the stage and through the command, on the router tests and on two HighTide designs.
  2. Optimization on wished positions.
    • Audit first: every place where sizing, buffering, wirelength, cone and color resynthesis assume a legal placement (the legal local move of each edit, the legality checks, the trials that place and then time).
    • Remove native legalization after final global placement. An edit gets a wished position, such as the mean of what it connects to. Density is absorbed by global placement; the repair loop already re-places after each round.
    • One step at a time, each compared on HighTide against today's flow: final timing, cells, and routed result.
    • Done when: no step legalizes, and the routed results are no worse than with native legalization on the designs that route today.
  3. Placement-only path. Terminal legalization becomes the step that writes a placed DEF and runs only then. A run that asks for no DEF reports timing on wished positions and no legality.
  4. The clock loop. Build the tree, route the clock nets quickly, feed the routed lengths and RC back into the tree, route again. The measured limits of the current tree are in 2p-pcrs-review.
  5. Defaults and the page. Switch the defaults once stages 1 to 3 hold on the HighTide ASAP7 and Sky130HD designs, and rewrite stage 5 of the place and route page as part of one flow.

Open

  • How an imported frame is recognized as post-CTS, so that the native tree is not built for it.
  • Legroute's role once the router is in the same run: it stays the routability estimate that feeds back into global placement, but its rounds and the router's first pass measure related things.
  • How far the router may move a cell by default, and which route.* options expose it (the nearest site rule, spreading out of dense tiles, room around pin-dense cells, the displacement caps).
  • What the final timing is measured on after routing: the router's positions with the placement wire estimate, until LiveHD has its own extraction.
