3d-sim-color Occurrence-wide colored simulation schedule

Goal. Replace the module-local eval_posedge/eval_negedge/__settle emitter with one occurrence-wide acyclic color plan. Each active color instance executes at most once per simulated period, directly reads and writes bound storage, and may reuse the same generated C++ kernel as structurally identical colors elsewhere in the design.

The historical Minion baseline was 8.17–8.20 s for 50K cycles versus 0.33 s under Verilator. Direct port access and narrower snapshots helped only modestly; the remaining 2,925 static __settle_gN() calls require a new schedule rather than more memoization around the old module walk. The measured baseline and rejected experiments are retained separately in sim_evindence.md — reference only: the performance gates re-baseline fresh (see Validation).

Pre-implementation review. 3d-sim-color-review.md (2026-08-10, 62+9 verified findings with file:line evidence). Its blocker dispositions and three rulings — fix-plus-carve-out versus the documented-stale old-scheduler shapes, fresh same-tree re-baseline for the performance gates, checkpoint restore stays warn-never-reject — are folded into the subtasks below.

Depends on

None. HHDS occurrence traversal, structural clock analysis, compact-loop descriptors, and Taskflow are already available. This task must consume those facilities without physically expanding hierarchy or compact loops.

Subtasks — pending

  • A — read-only occurrence plan.
    • Build a simulator-private Color_plan over a TWO-view walk: the outer view is grouped_hierarchy() (loops collapsed; a compact loop's carry is the descriptor-bearing Sub's literal self-edge — cut carries via Subnode_group::carries() before any acyclicity check), descending into occurrences(policy) for ordinary instances. occurrences(policy) alone cannot host the plan: an opaque verdict still enumerates a loop site once per ordinal and fans parent edges to every ordinal. Never materialize or clone an LGraph occurrence (one diagnosed exception: the external-ring loop fallback, G).
    • Derive producer-before-consumer order from the streaming walk plus loop/region descriptors. Do not use nodes(Node_order::forward) — it materializes the entire expanded virtual hierarchy before Kahn-sorting.
    • Color_plan owns its Hierarchy_policy object: lazy edge resolution calls the non-owning function_ref whenever a retained node/pin walks an unmemoized site, long after a builder-local lambda died. Construct the plan after ALL graph-preparation mutations — specifically after gate_activation_clocks, whose Clock_cell boundaries only exist afterwards — since hhds epoch asserts kill handles retained across mutation. Verdicts are memoized per view; two-phase discovery needs two views, not revised verdicts.
    • Conditional-call regions are not graph objects; reconstruct them by protocol pattern — an input port literally named __valid, the inserted Clock_cell(en=__valid|reset) on structural clocks, caller-side output muxes — honoring the forwarded-__valid exemption (a child whose guard root is the definition's own __valid input is NOT a new boundary). This is a deliberate carve-out from the no-name-identity non-goal: it keys on a compiler-generated protocol port, never on user names.
    • Represent occurrence nodes/pins by full Occurrence_index in memory only: it is raw (Gid, Nid) storage slots — unstable across library build history, unordered, unserializable. The deterministic plan report, checkpoints, and digests use a STRUCTURAL serialized identity (the Commit_class::key() precedent), never raw indices and never user names. Preserve original IO and persistent-state names only in an observation map for VCD, query, and checkpoint surfaces.
    • Recursive instantiation is silently skipped by the walk: the coverage invariant must count live nodes independently rather than trusting walk completeness.
    • Dump a deterministic plan report before changing emission: color membership, execution slot, activation/control owner, state endpoints, boundary values, estimated gate equivalents, dependency edges, and the old-scheduler carve-out list (see I).
  • B — legal colors and single-call scheduling.
    • Cut combinational logic at registers, memories, control boundaries, and any point needed to give every color one legal execution window. Membership is per (node, state-version), not per node: a comb cone feeding both edges, a latch's din/enable cone (low and high windows), and logic downstream of a latch Q legally evaluate at several state versions per period, and each version site may join a different color.
    • Model state versions explicitly — pre-rise, post-rise, post-fall is the minimum — and model clock LEVELS as slot values: every clock port and derived/gated clock net (including secondary ports tied to the same net) has a defined level per slot. Latch windows today rebind only the one reference pin — the live latch_sim_nonref_clock_window bug; this plan fixes that class, not inherits it.
    • Define the design-wide period first: today's reference clock is per module DEFINITION, and children nest inside the parent's rise via __tick channels plus deferred-fall and negedge-only placements. Map every child occurrence's local rise/fall onto plan slots deterministically before any slot assignment.
    • A color is placed once per period according to the edge versions it reads, not merely the edge types it updates. If one color cannot fit a single window, split it; never repair the conflict by scheduling A → B → A.
    • Where today's emitter diverges from event semantics — a transparent-high latch fed by a posedge flop samples the PRE-commit Q today — follow EVENT semantics and put the shape on the carve-out list (ruling, see I). Prerequisite: a fixture pinning the flop-feeds-transparent-high-latch direction against Icarus, landed BEFORE window assignment; none exists today.
    • The color condensation graph must be acyclic, computed after loop carries are cut (see A). First retry a legal split; diagnose a genuine combinational SCC rather than iterating a fixpoint or substituting zero.
  • C — size and cut policy.
    • Start from legal fine-grain colors and greedily coarsen while preserving the DAG, execution slot, activation class, and control boundary. The legality-constrained merge loop is NEW work: pass.color's Best-Choice merges check only size cap and connectivity (a merge can create a condensation cycle) and know nothing of slots or activation. Actual reuse is ge_weight/mappable_ge_weight (already in graph/node_util.hpp) plus roughly sixty lines of scoring — copy them or carve an engine target; do not link the alwayslink plugin (and viecut) into inou/cgen.
    • Score a merge by eliminated task overhead and eliminated live-across-color bits, minus compile-size and lost-reuse costs. Use a soft initial ceiling near 10K mappable gate equivalents. Below it, crossing an ordinary module boundary is encouraged when it removes storage/calls; above it, hierarchy crossing needs a positive measured gain.
    • Keep the cost model replaceable by a min-cut refinement. The objective is not the fewest nodes per color: every cut forces a value out of compiler registers into a persistent boundary slot.
  • D — direct storage ABI.
    • Give every live-across-color value exactly one storage slot, normally owned by its producer. A value ending at a register/memory uses that state's own current or pending slot. The public top-IO slot holds the POST-settle value (the testbench peek contract); the during-period query surface ("sampled":"during_period", today's __last_out) is the pre-commit VERSION of the same output cone, captured for observation — two version sites of one cone under B's membership, not a second handoff copy.
    • Slots may be slice-granular: a packed slice-group word is produced by different sources in different windows (packed_bus_bit_ring), so either give each slice its own slot or name ONE merge-owner color; the one-dominating-writer gate needs a bit-level notion of writer. A memory's whole write side (all write ports, the update bus, reset priority) is ONE producer protocol, and its pend_ slots are also READ by ordering=fwd/none/program read resolution — staged-write to read-resolution is a first-class dependence edge in the plan.
    • Each color object binds typed references/pointers to its source, destination, and state slots once at construction. eval() has no In/Out value arguments and performs no boundary copies. Internal color temporaries remain ordinary C++ locals. Direct binding removes the slop_update funnel that today's __gen change-gating counts on: designing the replacement per-color dirty/activation gate is a G/H obligation (none exists yet), and the idle-subtree quiesce win is a promotion-gate dependency, not an optimization.
    • Keep the public top-level signal surface as references/accessors into these slots; do not recreate per-module In/Out structs as copied storage.
  • E — direct state-update fast path.
    • Prefer a color that computes and directly updates its register/memory state in one call. Prove that every reader requiring the old value precedes that update and every reader requiring the new value follows it — counting the readers the EMITTER creates, not only dataflow readers: the pre-edge output capture reads old values with no graph edge; forested single-fanout cones are string-pastes evaluated at their consumer's position (freeze or materialize every bound expression reading a q that updates in place); pipeline stages read their predecessor pre-commit, so in-place chains commit tail-first.
    • When that proof fails, compute into a state-owned pending slot and perform a small edge commit. The commit is a scheduler state action, not a second evaluation of the color.
    • Initially split colors that update different edge classes. For a child owning a rise-half latch AND fall-half state (today's refresh_negedge repair) the edge-class split is mandatory, not an initial choice: its fall half gets its own post-rise slot, and the shapes today's pure-input-capture restriction knowingly leaves stale are FIXED and carve-listed (ruling, see I). Permit a cross-edge merge later only when one-call legality is proven. Memories are rise-only today and a secondary-clocked memory slips the refusal probe — enumerate memory edge classes independently of flops. Preserve memory ordering, latch transparency, sampled clock guards, secondary-clock history, and reset semantics; decide whether the secondary-clocked-memory refusal hole is closed or preserved; conservatively stage shapes not covered by a direct-update proof.
  • F — canonical kernel reuse.
    • Before emission, compute a process-independent 128-bit signature for each color view: operation topology, widths/signs/constants, canonical boundary-slot roles, state/memory semantics, execution slot, activation/control contract, and direct versus staged update mode. Exclude occurrence paths and user signal names. This anchor scheme is NEW design, not semdiff code motion: every existing semdiff anchor is name-based, canonical_digest hard-codes matching_names and refuses anonymous state, and loop_descriptor_key leaks loop-variable names. Keep digest-affecting helpers inside pass/semdiff, or extend //lhd:formal_salt's srcs when moving them — otherwise the formal verdict cache is silently de-salted.
    • Slot identity inside the signature is the edge class RELATIVE TO the reference — never the clock-net identity of the per-port __tick machinery. N identical cores behind N distinct ICG output nets must hash into ONE class; prove two gated nets may share a slot. Keying by net silently zeroes dedup on exactly the replicated gated cores that motivate this subtask.
    • On a hash hit, verify exact identity by lockstep traversal of the two color views, comparing EVERY attribute the emitter reads — per-pin signedness (semdiff's verify checks op/out-width/iface/edge-multiset only, while emission branches on is_unsign), sum-with-subtrahend widening, latch contract, memory ordering, clock/reset roles, and update mode. A collision or ambiguous symmetry may cause a missed reuse, never an incorrect reuse.
    • Emit one C++ color class per verified equivalence class and one bound object per runtime occurrence, each unique class in its own digest-named translation unit for object-cache and host-compile reuse. This replaces sim_into's per-graph {hpp,cpp,iface.json} contract: redesign the existence check, generated BUILD srcs, manifest hashing, and prp_sim's iface.json driver discovery together, and define a pruning policy for superseded digest TUs — today's never-delete workdir plus scan-all-*.cpp discovery would link stale kernels.
  • G — Taskflow execution backend.
    • Construct one reusable Taskflow graph from the color DAG; one task calls one bound color object. Precedence edges are exactly the value, phase, state-version, and control dependencies in Color_plan.
    • An if control color is a Taskflow condition task whose predicate is __valid || reset (active-low normalized); when the reset cone is not exactly representable, do NOT skip — run the region unconditionally behind its Clock_cell/__tick guards, exactly today's fallback (skipping on __valid alone withholds reset from held state). Validate conditional joins in BOTH directions: a condition-task successor may have no other strong in-edge (the bundled fork force-zeroes the selected successor's join counter and schedules it immediately, racing any pending data producer), and no join may be reachable only through one branch (a skipped branch never decrements, so the color silently never runs while run() completes normally).
    • A compact-loop control color remains one outer task containing the native for. Analyze its body once and reuse its color kernels across ordinals; do not create one source body or one outer Taskflow task per lane. An if-region nested inside the body degrades to in-kernel control (no condition tasks inside the loop task); forwarded-__valid children are not re-guarded. Carry/break/continue ordering remains sequential unless a later proof admits chunking; the loop control color also owns where post-edge loop outputs and per-ordinal carry slots live — bind-once body kernels need an indexed slot view or per-ordinal rebinding, stated explicitly. A loop whose activation/carry ring passes through the parent body keeps today's materialization fallback as an explicit, diagnosed exception during migration (see Non-goals); per-ordinal interleaved scheduling is a later improvement.
    • Add sim.workers — NOT sim.jobs, which already means host-compile fan-out, while the global --jobs already sizes the formal executor — and measure 1, 2, 4, and physical-core counts. Specify the per-color dirty/activation gate that replaces __gen change-gating: the sequential parent-sums-children scheme cannot survive direct binding or workers, and losing the idle/clock-gated quiesce win forfeits the promotion gate on gated workloads. Taskflow is the initial API and execution backend; a generated serial topological backend is a later option if measured per-period submission/dispatch overhead dominates.
    • Do not add a second Taskflow to the lhd binary: it already uses the OpenTimer-bundled copy. That copy is unreachable from BOTH generated build paths today, so wire all of: an opentimer.BUILD filegroup exporting the ot/taskflow headers; an //lhd data dep staging them like sim_runtime_hdrs; a runfiles-probe extension plus an explicit sim.taskflow_dir knob for the Ninja path (no absolute sandbox paths baked into build.ninja); the generated Bazel scaffold vendoring the SAME copy (a bazel_dep would resolve upstream taskflow, not the OT 4.0 fork — version divergence poisons H's digests); and -pthread on both paths.
  • H — observation, persistence, and determinism.
    • Generate a name-to-slot registry for VCD, probe/query, and checkpoint operations. Original hierarchy names remain stable even though color IDs and kernel sharing do not correspond to module boundaries. Define the guaranteed observable set: original persistent state and top IO always; an interior name survives only while live-across-color, and a --probe/--break-when on a swallowed name forces its slot to materialize — an instrumented plan may differ from the bare plan, but losing the instrument during bring-up is not acceptable.
    • Observed slots keep their pre-rise version materialized (double-buffer or in-period capture tasks): VCD dumps pre-commit values at the rise timestamp and the query surface is during-period — post-period publication cannot reconstruct either after in-place updates. After the period's Taskflow completes, publish VCD/query results and reduce dirty state deterministically; state whether dirty-gating/skipping is disabled while VCD tracing (today's inactive-region freeze is observable in traces). Color tasks must have one writer per slot and no unsynchronized global generation counter.
    • Determinism under workers: hlop's thread_local PRNG makes X/unknown draws scheduling-dependent — --seed reproducibility and the workers=1-versus-N differential require a partitioned or per-draw-site PRNG scheme, and checkpoint draw accounting must count every thread. fork()-based periodic checkpointing requires the executor provably quiesced at every fork point, or an in-process snapshot mechanism.
    • Include the color plan, binding schema, state schedule, Taskflow/runtime version, and generator version in design/checkpoint digests — as DIAGNOSTICS. Checkpoint restore stays name-keyed, cross-version warn-never-reject (ruling): a plan/schema mismatch warns; coarsening-sweep and old-scheduler-to-new-scheduler restores remain supported debugging moves.
  • I — migration and retirement.
    • Land analysis-only plan construction first, then a staged-state flat/single-edge emitter, hierarchy crossing and canonical reuse, direct updates, and finally control colors plus parallel execution.
    • Keep an oracle-selectable old scheduler during differential bring-up, and fold the scheduler choice into the per-module emission digest (or refuse a shared workdir): today's digest ignores options, so toggling schedulers in a warm workdir silently reuses the other scheduler's generated C++. Define the gen_digests.json transition while per-module and cross-module color-TU keyings coexist. The old-versus-new lockstep harness is new work; its comparison surface is the canonical trace hash over top-level outputs (todosim.md's methodology), not exact retire counts.
    • Ruling: the new path implements CORRECT event semantics where the old scheduler is documented-stale — the mixed-phase child whose fall half samples parent inputs a period late, refresh_negedge's uncovered shapes, non-reference latch clock windows, latch-high transparency — and the old-scheduler differential EXCLUDES that explicit carve-out list, which is checked against Icarus/trace-hash instead. The carve-out list lives in the plan report.
    • Once the new path passes the full semantic and performance envelope, delete Split_group, __settle_gN, module-local settle generation, and the selective trailing-settle workaround; do not maintain two default schedulers. Retirement rewrites the doc comments of live fixtures that describe the retired emitter (negedge_through_sub and siblings) — permitted, since they describe a deliberately retired API.

Execution contract

  1. Discover. Stream the grouped (loop-collapsed) hierarchy, descending ordinary instances through the occurrence view; control boundaries stay collapsed in the outer walk.
  2. Version. Add state/edge anchors — including per-slot clock-net levels — and derive each operation's legal execution window per required state version.
  3. Color. Form large acyclic partitions while minimizing the weighted live boundary and respecting execution/control compatibility.
  4. Order. Build the lightweight color DAG from the streaming walk and descriptors (carries cut); topologically validate it without copying the LGraph or materializing the expanded node set.
  5. Deduplicate. Hash each color view, then exactly verify hash matches — over every emitter-read attribute — before assigning a shared kernel ID.
  6. Bind. Instantiate color objects with direct references to their unique storage slots and construct the Taskflow once.
  7. Run. Execute each active color once, perform only the necessary staged commits, and observe after the graph completes.

Validation and promotion gates

  • Analysis invariants: every live (occurrence node, state version) site belongs to exactly one data or control color; every cross-color read has one dominating writer (bit-level for slice-granular slots); every color has one execution slot; every active color instance is invoked at most once per period; the color graph is acyclic after carries are cut. A compact-loop body color executes once for each active virtual ordinal, through the one generated loop body rather than unrolled source — with one escape mirroring G: when an activation cone is not exactly representable, the region or lane evaluates unconditionally with guarded commits, and "active" reads as "scheduled". The coverage count is independent of the walk (recursion is skipped silently).
  • Focused semantics: retain live tests for partition handoff, shared logic, false hierarchy loops, transparent latches, activation-class splitting, compact loop carry/break/continue, posedge-to-negedge transfer, gated memories, secondary clocks, reset, VCD hierarchy, checkpoint/restart, and query/probe — including the three review fixtures (same_module_shift_chain, posneg_sub_cross_ring, cond_call_always_consumer), flop_sim_negedge_sole_clock, latch_sim_nonref_clock_window, and the NEW flop-feeds-transparent-high-latch-versus-Icarus fixture required before window assignment (B).
  • Differential semantics: compare the old scheduler, the new sim.workers=1 path, multi-worker Taskflow, and independent Verilator/Icarus oracles. The comparison metric is the canonical trace hash over top-level outputs with valid/write-enable-gated payloads (todosim.md) — exact retire-count match versus Verilator is documented-impossible on minion. Old-scheduler comparisons exclude subtask I's carve-out list, which is checked against Icarus/trace-hash instead. Minion must retain self-consistent retired/last_pc figures across schedulers at the re-baseline before performance numbers count.
  • Granularity experiment: sweep the soft color ceiling and report unique kernels, runtime instances, boundary bits, task count, source/object size, host-compile time, and cycle time. Include chain and wide-DAG microbenchmarks to expose Taskflow dispatch and synchronization overhead. The kernel-dedup property itself is asserted by generated-structure tests on the lhd/tests side — the prp-sim harness observes values only.
  • Performance decision gates: both schedulers are measured fresh on the same tree in the same session (the historical 8.17–8.20 s / 0.33 s figures are context, not the gate). The first hierarchy-complete path must beat the re-baselined old scheduler by at least 2x before replacing the old default; the promotion target is at least 4x with no more than 10% regression on Dino and small fixtures. Treat these as go/no-go gates, not predicted results. Report sim.workers=1 and best parallel results separately.
  • Repository gates: focused optimized tests, full //inou/prp:all, bazel build -c opt //lhd:all, generated Bazel and Ninja builds, git diff --check, and unchanged known-failure accounting.

Non-goals

  • No physical hierarchy or compact-loop expansion — one diagnosed exception: the external-parent-ring loop fallback retained during migration (G).
  • No runtime combinational fixpoint as the normal scheduler.
  • No name-based partition identity; names belong to observation metadata. Carve-out: control-region detection keys on the compiler-generated __valid protocol port (A), never on user names.
  • No promise that more Taskflow workers are faster. Parallel promotion is measured, while the color/task API remains useful even at one worker.
