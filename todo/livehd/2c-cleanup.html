2c-cleanup Codebase deduplication & drift cleanup

Open follow-ups from the codebase deduplication review. Each item records the behavior a shared implementation would need to preserve.

Graph and coloring

  • Factor common wiring and port-fit logic from partition emission, flattening, and inlining. Top and region bodies use different forwarding and storage layouts. Keep cut decisions explicit in the port-reachability summary and the legalization walker.
  • Review leaf ICG classification, same-color connectivity, and coloring_info reads for shared helpers. The recognizers disagree on flop and latch shapes and on which pin operations to peel. A shared classifier needs coverage for those shapes before callers adopt it.
  • Review the remaining graph traversal, profiling, and rule-generator helpers for common primitives. The profiler counters have different consumers, and cost-model parsing and rewrite-rule parsing currently accept different integer spellings.

Pyrope and simulation

  • Review the remaining small frontend helpers in the parser, Slang, Yosys, and uPass. Preserve each frontend’s source locations and diagnostics when sharing code.

Synthesis and timing

  • Evaluate common demanded-bit transfer, arithmetic-option parsing, and USYN endpoint formula evaluation and compaction. These are separate from the earlier correctness repairs and must preserve backend defaults, option precedence, and endpoint representations.
  • Define a shared what-if test for fast timing and OpenTimer. Corner selection, supported arcs, and unknown-pin handling need explicit expectations. A single fallback clock period cannot represent a pin’s clock domain.
  • Review typed SDC adoption in OpenTimer and further sharing of Liberty scanning and STA report writing. OpenTimer resolves selectors in script order. Full Liberty group construction and cell inventory scanning serve different consumers. See the fast timer task.

Placement and routing

  • Factor common node-append and ECO trial preparation across placement and GUI builders. Warm-settle options vary with the cells each stage can move and the hooks it can use.
  • Review identity-buffer selection, repeater slew and load checks, and edge-rail extraction for common primitives. Clock, reset, PCRS, and sizing apply stage-specific Liberty and geometry rules. Repair uses directional RC bounds, while ranking uses estimates.
  • Share suitable GUI and probe I/O, geometry, and acceptance helpers. The callers still need their own error reporting and stage-specific acceptance criteria.

Core and persistence

  • Evaluate smaller shared persistence primitives for technology mapping, Lean, and file export. The mapping cache publishes through a generation pointer, Lean publishes companion files together, and export streams large inputs and preserves modes. See the JSON metadata task.
  • Validate memory profiling and watermark handling on Linux. The regression ran on macOS and could not exercise the Linux /proc paths.
