LLVM simulation with a shared runtime

In progress. Requested end state: generate all design/test-specific code directly as native objects; keep only design-independent support in a prebuilt C++ library. Normal LLVM simulation must not invoke a C++ compiler. Native generation must use bounded parallel workers.

The previous LiveHD checkout, including new Bazel inputs and graph/legalization changes, is committed as bbec12fd7. The previous native-color work is the baseline, not completion of this larger conversion.

Implemented foundation

  • Cgen_llvm::State_layout defines a two-argument native ABI: packed state and a data-resource table. Inputs load at fixed word/bit offsets. Output writes, change detection, and dirty propagation execute inside the object. Aliasing is supported; outputs compare against snapshots before any output store.
  • Native phase-barrier functions copy register banks or commit staged memory entries. Large copies expand inside the object and retain the no-external-symbol audit.
  • sim_native_rt is a separately built shared implementation of packed state, dirty scheduling, and native object loading. LLVM ORC relocates already-generated machine code; no C++ compilation or host link process is needed in this path.
  • write_state_object emits one exported allocation/initialization descriptor, with object-local native code and sparse constant defaults. Each runtime instance owns its mutable storage. Only the public boundary prefix is exposed; the private tail has no per-field symbols. Instances retain the loaded code's lifetime. Worker-generated objects with identical private function names link together without collisions.
  • Compile_workers is integrated into existing simulator generation. Workers are reused across modules; submitting work waits only until any worker completes. Outstanding jobs are bounded, threads start on demand, and each job owns its LLVM context. The default samples available CPUs/load once, always permitting one worker.

Incremental locality

Private per-color storage is an incremental-compilation requirement. A color's object key should depend on its own operations, local layout, boundary contract, and compiler configuration. Whole-program offsets, dense schedule numbers, and neighboring implementations belong in binding/scheduling metadata, outside that key.

LLVM object files and symbols use the color's storage identity instead of its dense schedule number. Cold coarsening retains the original larger partitions. Persisted terminal anchors let subsequent discovery repair an edited interval without moving every later pressure cut. Phase/control fences and the live-word budget still apply. Changing the partition settings discards incompatible hints.

A regression with 32 independent chains adds one operation and exposes one intermediate result. All four unaffected previous partitions survive with saved anchors; the original global repacking preserved none. Another regression inserts/removes a color and checks that unchanged LLVM objects retain filenames, bytes, and mtimes, including 200-byte module names.

Native object reuse now hashes unoptimized IR plus emitter/toolchain salt and validates the retained object bytes before skipping optimization/code generation. Missing and damaged objects are rebuilt. The single lhd.incremental switch controls these lookups and the partition hints. IR construction and generated C++ dependencies remain costs.

Rejected experiment: independently cutting computation cones expanded Minion from 4,981 to 28,480 native objects and slowed pinned 100k-cycle execution from 2.51 s to 4.45 s. Raising the cone-size threshold still produced 25,960 objects. This policy is removed. RepCut and gsim motivate minimizing boundary traffic and keeping useful work together; preserving cuts across revisions is LiveHD's additional constraint.

Remaining causes include repeated-shape occurrence ranks, lost anchors after topology changes, shared generated C++ headers, and emission of per-design C++ scheduling/state support. These changes do not yet establish LEC-like incremental performance or the requested one-to-two-object edit cost.

Reachable build inputs and code sharing

The host builder follows generated driver includes and the module artifact manifest. Unused standalone exports are retained for export but excluded from the executable. Within each module, exact finalized IR equality (normalizing only the entry name) shares native code across occurrences with independent state.

Rolled-loop simulation follow-up (2026-10-07)

Committed as 1b8e2a600 and 33d391bc9. Stateless leaf reductions with a complete native color now execute as a rolled loop inside that object. LLVM explicitly inlines the body once; invariant transport occurs once per invocation, carries remain in SSA, and unroll-disable metadata preserves the loop. Count, first and step are runtime arguments. Slop pure evaluators and reduction helpers now require host inlining explicitly and retain their no-unroll hints.
