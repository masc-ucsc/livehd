3g-partitions One vocabulary and shared code for placement grids, regions and bins

Implemented 2026-10-25 (steps 1–6); step 7 (new detail-final features) remains open

What landed

  • Re-survey. After the pending patches merged, the only new partition is preroute.bins (64, the pre-route capacity/RSMT grid). It stays stage-scoped, like <stage>.warpspace.bins. The name tables below were applied as written.
  • Region_mesh (pass/place/region_mesh.{hpp,cpp}): built once in place.cpp, passed by const reference to Busorder and Boundary_pins; the throwaway partition Busorder is gone. It records explicit membership and writes region_mesh.json; the busorder/boundarypins reports keep their mesh blocks unchanged.
  • Capacity_bins (pass/place/capacity_bins.hpp): the terminal legalizer's grid geometry, apportioned deposit, joint capacity check and ring scan. Terminal_legalize_report::bins is its Capacity_bin vector; reports are byte-identical.
  • Cell_criticality (pass/place/cell_criticality.{hpp,cpp}, ruling R2 alternative): shared slack/clock/untimed inputs for SAT spill (eligibility and diagnostic evidence) and terminal slacks; node_weight_criticality()/limit_displacement() for bus order and boundary pins; timing::Feedback::find_pin for the pin lookup.
  • Options: every name in the table below, plus legalize.bin.grid and satlegalize.bin.grid=none|route. Old spellings are DEPRECATED registry entries; lhd rewrites them before use and emits a deprecated-option diagnostic. grid.route=N is independent of the density count (R4). R3: the mesh is built only when a consumer is enabled.
  • Docs: docs/placer.html (glossary, grid/region/bin panels) and the README partition section.

Deviations from the plan

  • The SAT fixed-region path was not ported to Capacity_bins. SAT capacity counts every non-movable component (also fixed logic cells) as an obstacle and uses exact geometry. Terminal capacity rounds to sites and counts fixed logic as occupancy. One function for both would change SAT results, and steps 2–4 must not change behavior.
  • Cell_criticality has no protected_cell or mobility fields. Protection (critical locks, accepted alignment endpoints) changes during each transaction, so it stays in each consumer. GP mobility is computed inside DREAMPlace from the same net weights as node_weight_criticality(). Each consumer computes its own Cell_criticality, because SAT reads prects-filtered feedback and terminal legalization reads raw feedback with ignored nets.
  • No resolved-options JSON exists, so the deprecation warning goes to the diagnostics stream. dynamic_bins/auto_bins could be combined, so they only warn and are read when grid.density_mode is absent. Diagnostic JSON keys (dynamic_bins, fixed_regions, …) are unchanged so report parsers keep working. They move when the aliases are removed.

Why

Placement currently carries at least seven spatial partitions, each introduced by the algorithm that needed it, each with its own option names and its own idea of which cells are allowed to move:

Only two of these share a definition (terminal bins and SAT route_grid both read the routing grid). Busorder's mesh is private to it even though two other features depend on it. Terminal and SAT both compute "usable capacity minus halos and taps, occupancy before/after, density" with separate code. And four places decide which cells are movable with four different rules. New detail-final features (density-triggered region IO pins, per-region critical-cell pre-legalization) would add a fifth of each unless the shared parts are extracted first.

Three roles, three names

Partitions are named by their role in the flow, not by the algorithm that first needed them. Each role has one option prefix and one C++ type.

RoleNameStageSemanticsOption prefixC++ type
Continuous force fieldsgridglobal GP (FP, macro, final)Uniform tiles over the core. No cell membership; cells deposit area/demand and read forces. Never gates movement.synth.place.grid.*native Options::bins_x/bins_y/auxiliary_bins (DREAMPlace); no new type
Discrete refinement blocksregiondetail final: after final GP converges, before legalizationIrregular rectangles aligned to macro edges and IO bus spans, each holding at most max_cells movable cells. Explicit cell membership. Crossings, virtual pins and bus order live on region edges. Fixed for the whole detail-final phase.synth.place.region.*Region_mesh (new, extracted from Busorder)

Consequence: satlegalize.region_size is misnamed under this vocabulary. It defines bins (uniform, capacity-checked), not regions. URoute's 256×256 is a model constant resampled from and back to the routing grid; it is never a user option and never appears in the glossary as a partition.

Shared types

Region_mesh (pass/place/region_mesh.{hpp,cpp})

struct Region_mesh {
  std::vector<Busorder_rect>   rects;    // renamed Region_rect; xl,yl,xh,yh, cells
  std::vector<Busorder_edge>   edges;    // renamed Region_edge; split at every endpoint incl. T junctions
  std::vector<std::vector<int>> members; // movable cell indices per rect
  unsigned initial_rectangles, removed_h, removed_v; double build_seconds;
  static Region_mesh build(const dp::Design&, std::span<const int> macros,
                           std::span<const Busorder_io> ios, const Region_options&, double dbu);
  std::optional<int> rect_of(double x, double y) const;
};

Built once per detail-final phase in place.cpp, passed by const reference to Busorder, Boundary_pins and align_boundary_pins. The mesh construction code is today's Busorder::Busorder lines 150–262 moved verbatim. The busorder/report.json mesh block becomes region_mesh.json written by the mesh itself, so every consumer's report references the same file.

Capacity_bins (pass/place/capacity_bins.{hpp,cpp})

struct Capacity_bin { physical::Rect bounds; double capacity, before, after; };
struct Capacity_bins {
  unsigned nx, ny; std::vector<Capacity_bin> bins;
  static Capacity_bins build(const physical::Technology&, const physical::Floorplan&,
                             unsigned nx, unsigned ny, int64_t halo_x, int64_t halo_y);
  // usable capacity = row sites inside the bin − macro/halo-covered sites − fixed WELLTAP/SPACER
  void deposit(const Ann_place&, double area, bool after); // apportioned across overlapped bins
  double density(size_t i, bool after) const;
  std::vector<size_t> neighbors(size_t i) const;
};

Terminal legalization keeps its report format; it fills Terminal_legalize_report::bins from Capacity_bins. SAT legalize's fixed-region path (satlegalize.cpp ≈ lines 805–900 and the spill acceptance checks) replaces its private capacity/density computation with the same type, so "receiving bin may not exceed usable capacity or the donor's previous density" is evaluated by one function in both legalizers.

Cell_criticality (pass/place/cell_criticality.{hpp,cpp})

struct Cell_criticality {
  std::vector<double> slack_ps;        // min data-pin slack, NaN when untimed
  std::vector<bool>   clock_connected; // clock/reset/supply endpoint
  std::vector<bool>   protected_cell;  // never spilled/redistributed: critical lock, alignment endpoint, …
  std::vector<double> mobility;        // 0..1, today's timing_spread_weight response
  static Cell_criticality from(const timing::Feedback&, const dp::Design&, const Criticality_options&);
};

Computed once at the final-GP timing refresh and passed to every region and bin consumer. Today the same question is answered four ways: GP timing_spread_weight (mobility), busorder's timing-reduced max_displacement_um, SAT spill_slack_margin_ps + clock-connected exclusion + "no reliable positive slack", terminal critical_fraction top-10% selection. These are not identical (SAT requires strictly positive slack; terminal takes a fraction regardless of sign), so unifying them is the only step in this plan with QoR risk and needs the ruling below.

Rulings needed

  1. R1 names. Accept the three role names grid/region/bin and the option table above, or amend after the pending-patch re-survey.
  2. R2 criticality definition. One rule for "movable by region/bin refinement": proposal — not clock-connected, not protected, slack ≥ margin with a per-consumer margin (terminal keeps its fraction as a selection of what to protect, not as a movability rule). Alternative: keep per-consumer rules but compute inputs from one Cell_criticality.
  3. R3 region mesh ownership. Build the mesh unconditionally in detail-final when any consumer is enabled (today), or always when fixed macros exist so reports include it. Proposal: only when a consumer is enabled; building is cheap but the report noise is not free.
  4. R4 route grid independence. Allow grid.route=N ≠ density count without dynamic mode. Today they can only differ through dynamic_bins. Proposal: allow it; it is already what auxiliary_bins encodes natively.

Non-goals

  • Changing any default grid count, cap or budget. Steps 2–4 are no-behavior-change refactors.
  • Merging the density grid and the region mesh. They answer different questions (force vs membership).
  • Exposing URoute's model resolution.
