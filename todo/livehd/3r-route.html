3r-route RSMT-RUDY routability feedback

Add a Steiner-tree (FLUTE) congestion estimator, RSMT-RUDY, next to the existing bounding-box RUDY used by native DREAMPlace in LiveHD. The estimator is chosen at run time per placement stage. In auto mode, a stage starts on plain RUDY and, once congestion is low enough, switches once to RSMT-RUDY and never switches back. The same ladder leaves room for a fast global router as a more accurate third rung.

Why

Today dp::rudy() (sibling DREAMPlace repo, dreamplace/native/rudy.cpp and rudy_obstacles.cpp) is plain RUDY. Each net contributes its pin bounding box, spread uniformly over the bins it covers, scaled by net weight and by DREAMPlace's pin-count table (netWiringDistributionMapWeight, 1.0 for 1–3 pins up to about 1.9 for 16–20). There is no Steiner tree. The box smears demand across the whole box, so it overestimates mid-box congestion and underestimates demand near the pins, and in legacy mode it drops any net whose box has zero width or height. The macro-aware path adds obstacles, detours and pin access to the capacity side only.

The estimate drives three things: cell inflation in the final cell GP, direct macro channel pressure (macro_routing_pressure) in the FP/macro stages, and the GP convergence test (route_overflow <= 1e-9). A better estimate near convergence should push the right cells and macros apart. It is only worth its cost once the gross congestion is already gone, which is the reason for the Rudy-first, RSMT-later ladder.

Facts to confirm first (R0)

  • Two different overflows exist and must not be confused. The density overflow (previous_overflow < .3) gates when routability sampling starts at all. The route overflow (RudyResult::overflow, mean excess of max(h, v, pin) over 1 across all bins, plus enhanced-mode unreachable-net and blocked-pin penalties divided by bin count) is what the switch and success levels below refer to.
  • RUDY is evaluated every 20 GP iterations and once more as a convergence recheck (two call sites in dreamplace/native/placement.cpp). Both must use the same active model.
  • The IO-prototype GP already disables routability (pass/place/place.cpp, prototype control); it stays that way.
  • Which of FP, macro (H2D / macro-source GP) and final cell GP currently consume the map, and through which consumer (inflation vs macro pressure), is to be written down before choosing defaults.

Subtasks

  • R0 — Baseline and decision data.
    • Use the read-only tools/rudy_metrics.cpp on saved snapshots (for example repros/rudy_macro_eval_20261019, cnn, and the Eyeriss layouts) to record net-degree histograms and current RUDY time per call and per stage.
    • From gp_history.json, record how route overflow evolves in each stage today (when it first falls below 0.3 density overflow, when it reaches zero, how often it never does). This sets the candidate switch and success levels.
    • Build the reference for validation: congestion maps from a real router on the same placements (NCTUgr is vendored in DREAMPlace thirdparty; OpenROAD global routing is the alternative), so RUDY and RSMT-RUDY can be scored by correlation of overflow maps and hotspot overlap, not by their own numbers.
  • R1 — Native RSMT-RUDY model (sibling DREAMPlace repo).
    • Add RudyModel {bbox, rsmt}, a degree cap and the FLUTE accuracy to RudyOptions; keep bbox bit-identical to today.
    • Add //thirdparty/flute to the native placer target. FLUTE lookup tables must be loaded once; take an init hook from the caller (LiveHD already does this in init_flute()) and fail clearly when the tables are missing. Tests need the table data in runfiles.
    • Per net: clamp pins to the core, convert to FLUTE's integer type with the existing range guard, call flute(). Fall back to bounding box times the pin-count weight above the degree cap (candidate 30–50, never above MAXD=1000). Do not apply the pin-count weight to FLUTE nets: it approximates the same Steiner-to-HPWL ratio and would double count.
    • Rasterize each tree edge with the existing per-bin formula applied to the edge's box. Straight edges need a one-site/row corridor, like the macro-aware path's gx/gy, because most edges are straight and today's code discards zero-extent boxes.
    • Macro-aware path, phase 1: keep per-net connectivity and detour detection on the net box, then distribute the tree's wirelength over the reachable free component. Per-edge channel detours are a later refinement, not part of R1.
    • Tests: tree length at least HPWL and bounded by an independently computed Manhattan spanning tree on random nets (the original 1.12 × HPWL upper bound was invalid: four corners alone require 1.5 × HPWL); straight and degenerate nets; duplicate pins; huge-coordinate guard; cap fallback; deterministic repeat; both models agree on 2-pin L-nets.
  • R2 — Runtime switching state machine in the GP loop.
    • Replace the fixed rudy(...) calls in placement.cpp by one stage-local estimator that holds the active model: rudy until a sample satisfies the switch level, then rsmt for the rest of the stage. The latch is one way. An optional hold count (default 1 sample) guards against a noisy single sample.
    • At the switch sample, evaluate both models once and record both overflows, so the scale step between them is visible and the inflation history stays explainable. Inflation remains monotone; a higher RSMT demand simply adds inflation, it never removes any.
    • The convergence test uses the active model's success level. If the stage ends before the switch level was reached, report it as "never switched".
    • Record route_model, both overflows at the switch, the switch iteration and per-call time in gp_history.json(l).
  • R3 — Per-stage options and LiveHD plumbing.
    • Options in lhd/lhd.hpp, pass/place/place.hpp and the mapping near pass/place/place.cpp (control assembly), with lhd describe text and README documentation. Proposed names, per stage S in fp, macro, final:
      Option (synth.place. prefix)Meaning
      route.modelGlobal default: off, rudy, rsmt or auto (Rudy, then one-way switch to RSMT)
      S.route.modelPer-stage override; inherit by default
      S.route.switchRudy route-overflow level at or below which auto switches to RSMT
      S.route.targetRoute-overflow level, measured with the active model, counted as success for the stage; must be at most switch, otherwise rejected
      S.route.probeOne diagnostic RSMT evaluation at the stage's convergence candidate; see R4
      S.route.holdConsecutive samples below switch required before latching
      route.degree, route.accuracyFLUTE degree cap and accuracy
      Existing routability* options keep their meaning. Exactly what off means per stage (no inflation, no macro pressure, no convergence test) is pinned down in R0.
    • The model, switch, success level, hold, degree and accuracy are part of the placement cache identity (the hashing next to the macro-route-pressure key), and of the resolved-options JSON.
    • Reject inconsistent combinations early: target > switch, FLUTE options without a model that uses them, non-finite levels.
  • R4 — Stage policy: FP, macro, final.
    • Final cell placement: the main user. Default candidate auto.
    • Macro placement (H2D and the macro-source GP): candidate auto, since channel pressure sets macro spacing before cells are placed. Measure whether RSMT changes the macro layout at all; if it does not, leave Rudy.
    • FP (floorplan GP): uncertain value. Start with Rudy only plus probe: at the FP convergence candidate evaluate RSMT-RUDY once, without feedback. If its overflow is at or below the success level, accept the stage as is. If it is above, continue the FP GP with RSMT feedback for a bounded number of extra iterations. If the probes show it never changes the outcome across the evaluation set, FP stays on plain Rudy and the probe is off by default.
    • Defaults for switch and target per stage are set from R0/R5 data. Initial sweep candidates (not decided values): switch in {0.02, 0.05, 0.10}, target in {0, 0.005, 0.01}. Success must be at or below the switch level. Neither estimator is uniformly stricter: omitting the box-model degree correction and localizing tree demand can change the scale in either direction, so both switch measurements are required.
  • R5 — Calibration, validation and QoR.
    • Retune what was calibrated against the bounding-box model: route capacities from LEF pitches, the 5% inflation growth and 3× ceiling, the macro pressure range/weight, and the existing rudy_test / rudy_macro_test expectations.
    • Compare Rudy-only, RSMT-only and auto against the router reference from R0: overflow-map correlation, hotspot overlap, and then the final metrics that matter, namely routed overflow or wirelength where a router is available, plus pre-CTS WNS/TNS, HPWL and legalization displacement. RUDY numbers remain proxies.
    • Performance budget: the extra time of RSMT calls must stay a small fraction of the stage time; measure it, do not assume it (see Cost).
    • Decide, from these results, per stage whether auto becomes the default or the option stays opt-in.
  • R6 — Performance, only if R5 shows it matters.
    • Rebuild tree topologies only every N calls and reuse them in between, refreshing coordinates.
    • Parallelize the net loop with per-thread bin maps and a fixed reduction order. The estimator is deliberately serial and deterministic today, so this must preserve exact repeatability. First check whether FLUTE's global state is thread safe.
    • Special-case degree 2 and 3 nets without calling FLUTE.
  • R7 — Future: fast global router as a third rung.
    • Keep the estimator interface model-agnostic: input is the design, grid and capacities; output is the existing result (horizontal, vertical, pin maps and overflow). A router backend then plugs in as route.model=grt with the same one-way ladder semantics, rudy → rsmt → grt, each transition with its own level.
    • Candidates: an in-process fast router in the style of FastRoute/CUGR, or the vendored NCTUgr op as an external process. Run it rarely (a handful of times per stage), because it is far more expensive than any estimator.
    • Only specified here; no implementation until R5 shows RSMT-RUDY is still not accurate enough.

Design notes

  • The current routability capacity sums all LEF routing layers, while the matched ASAP7 downstream flow uses M2–M7 with its capacity adjustment. After the fixed-route-grid density screens, evaluate explicit layer/capacity selection consistently for both capacity and macro obstructions; keep existing defaults unchanged.
  • The switch is one-way per stage and per run, to keep the control loop stable: inflation is monotone and the convergence test must not flip scale mid-stage. A new auto stage starts on Rudy; continuation within a stage retains the active model. Cached H2D reports restore their active model, and placement cache identity includes every route-policy option.
  • Levels are mean overflow over all bins, so small values are significant on a fine grid; record the bin count with every reported level.
  • FLUTE nets must not also get the pin-count weight. Nets above the degree cap keep the old bounding-box-times-weight model, so a mixed design is consistent.
  • RUDY is not differentiable here: it only drives inflation, macro pressure and convergence. Topology changes between calls therefore do not disturb the gradients.
