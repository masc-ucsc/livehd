Verdict discipline

PASS means definitively equivalent and FAIL means definitively different; timeout, unsupported timing, and ambiguous correspondence remain INCONCLUSIVE. Collapse, pairing, phase scheduling, and every retry must preserve that contract. An abstraction may cause more work or an UNKNOWN, never a wrong verdict. rc 7 ("could not decide") and rc 10 ("here is a counterexample") must never be conflated — pass/lec/tests/lec_verdict_policy_test.sh is the contract.

An encode ABORT compared nothing — LANDED 2026-08-01, but NOT the way this page asked, and the difference matters. The page said to set BOTH nothing_compared and unsupported at all four encode-failure returns, "including the plain fail() (structural) path". Implemented literally that is a WRONG-VERDICT bug, and it was caught by an adversarial re-check after being written:

  • nothing_compared is not a synonym for "hard-fail". The driver's FIRST guard maps it to equiv_fail → exit 10, i.e. "the designs DIFFER, here is a counterexample", under the headline "the module is empty or has no output/state to check".
  • A plain fail() is ALSO how a formal.timeout budget-out during encode reports. Flagging that nothing_compared turns a pure TIMEOUT into a disproof — the exact conflation the contract forbids, and the opposite of "timeout stays INCONCLUSIVE".
  • It is factually wrong besides: a BMC encode that aborts at unroll step k already asserted the compares for steps 0..k-1, so "compared NOTHING" is false.

What actually shipped is the sound reading. A STRUCTURAL encode failure — the encoder cannot ORDER the cone (a real word-level combinational cycle, or a driver it cannot build) — is a REFUSAL, so it now rides fail_unsupported() (encode.cpp, the post-fixpoint unresolved-node diagnosis). That hard-fails by NAME regardless of formal.strict, at exit 7, which is what the item wanted. A budget-out keeps plain fail() and stays an ordinary strict-gated Unknown, because a bigger timeout genuinely can change it. nothing_compared is left to the empty-miter case it was built for.

This replaces formal coloring and single-edge graph normalization. What actually changed in the driver: the M8 preflight stopped being MANDATORY, not stopped running. A decline used to end the run ("lec refused the <side>", nothing compared); it now hands the design to the schedule instead. The rewrite is still PREFERRED where it applies, for one measured reason: it also normalizes a SYNC reset into the enable/din shape on BOTH sides, and that is what lets semdiff's state pairing match a flop whose reset the other front-end spells in the body (tests/equiv/flop_reset_matrix). Skipping it where it would have worked costs real verdicts until the pairing learns that fold — so the split is "M8 when it applies, schedule when it declines", and the schedule is what every previously-refused shape now takes.

Three refusals inside pass.single_edge were tightened while doing this, because a decline is now cheap: a state element clocked through a recognized Clock_cell declines by name (a slot lowering has no sub-period to sample the gate's enable in, so it would either drop the gate or read it half a period early), and the probe's rule-4 / plan diagnostics are suppressed on a dry run (an error-severity diagnostic would fail an otherwise clean, PROVEN run through the CLI's error count).

Clock-graph propagation (runs first)

Before any scheduling, run one top-down pass that traverses only the clock input signals and propagates them through the whole hierarchy, deciding the relationships between clocks once for the entire design. The normal case is a single root that propagates and splits. If a def presents two clock inputs, assume they are synchronous — same frequency, unknown offset — emit a warning, and allow an explicit ratio specification to override the assumption.

This pass is what makes leaf proofs possible at all, so it cannot be folded into per-def scheduling. The leaves-first driver proves every def with that def as its own top, where its clock ports are unbound free inputs. prim_rf_3r2w_preview refuses standalone today with 2 clock nets and no known integer ratio between them, yet at all 32 instantiation sites both of its clock ports are bound to one net (rf_clk_i = clk_i / = clkgt). Resolving clocks only "starting at the selected top" would therefore fail closed on the whole 14-member prim_rf_*_preview family — the largest block of the trust list this work exists to retire, and the family that gates vpu_lane and minion_dcache_top.

Schedule analysis and cone construction

With clock relationships fixed by the pass above, assign a semantic phase to every instantiated register or latch and to every synchronous memory port. For each endpoint and phase, walk its data, enable, reset, address, write-data, and observation cones backward across non-opaque hierarchy. Stop at constants, primary inputs, state boundaries, and opaque boxes. Memoize a gate within one phase; if one gate feeds two phases, encode it in both cones.

A batch evaluates from an immutable incoming-state snapshot and commits its endpoints simultaneously. A later batch in the same source period observes the state committed by earlier batches. This ordering is formal metadata; it must not be materialized as graph state.

Single-root v1 schedule

  1. active-low clock-role latches close immediately before rise;
  2. posedge flops, posedge memory ports, and data-gated latches update simultaneously;
  3. active-high clock-role latches close immediately before fall;
  4. negedge flops and negedge memory ports update simultaneously.

A latch-close microstep shares the symbolic input snapshot of its adjacent edge. Rise and fall have distinct input snapshots, each shared between REF and IMPL. LEC compares external outputs after rise and after fall; an unclocked assertion is checked at the full-period boundary by default. Bounds and reset counts continue to mean source periods.

Clock-role and data-role latches are different. Only a latch whose controlling cone resolves to the root clock receives close-before-edge scheduling. A data-gated latch keeps Pyrope's ordinary tick semantics and joins the rise/base batch; active-low polarity changes its write condition, not its phase.

Clock_cell

A Clock_cell is timing metadata, not an SMT data value and not a scheduled state endpoint. It is never passed to formal. The cell may be built from a latch or an AND, but that structure is not modeled: it is recognized as "this clock got gated (or divided)" and its only effect is to control the enables of the endpoints — register, memory port, or nested cell — that consume its clock output. Canonicalize a chain to its root clock, edge parity, and active-high guard, and combine that guard with each endpoint's own enable as endpoint_enable & clock_guard. Inversion swaps the consumer edge; div != 1 remains a named refusal.

The guard's sample point follows the cell's own parity — the inactive phase immediately preceding the cell's active edge — and one sample serves every consumer of that cell in the period. For an ordinary gate the consumers fire at the root rise, so the pre-rise sample is right, and that holds for a negedge consumer too because a gated clock can only fall if it rose. For an inverted cell the active edge is the root fall, so the guard is the pre-fall sample. Pinning the sample unconditionally to the rise would read a guard half a period early on an inverted cell, which is a wrong-verdict direction rather than an UNKNOWN, and it would also contradict the microstep list above, where an active-high clock-role latch already closes before the fall. Deriving it from parity needs no look inside the cell.

Memories

Retain read and write polarity for each synchronous port in the Memory IR, including RD_CLK_POLARITY from Yosys; keep a compatibility fallback for graphs that only carry the legacy global polarity (posclk is a single global pin today). Schedule only the ports active in a phase. Ports in one batch keep the existing simultaneous write, forwarding, and collision policy. This fixes formal timing only; the separate Verilog-codegen work remains in 2m-multiport_mem.

A WHOLE-ARRAY update does not mix with per-port writes. The whole-array update is last: any provisional per-port write is simply dropped. Read forwarding is not allowed on that shape, and reads always see the last-cycle (pre-write) contents. Anything else is an error — reject a whole-array memory that carries a per-port write, any fwd/ undef bit, or any ordering other than read-old, and reject it in upass/tolg where the shape is built, not downstream.

Two facts to reconcile while doing it. First, the encoder currently documents and implements the inverse priority — encode.cpp's whole-array branch says "per-port writes below STORE on top of it (per-port wins)" — and rd_source() returns the post-update array for an is_whole memory whenever fwd is set, so it honours forwarding on exactly the shape that must now refuse. Under this ruling both become unreachable, and the explicit tolg error is what keeps the encoder's silent priority from deciding anything. It also retires the soundness caveat on Encoded::Mem_whole, which exists only because the per-port chain's base is not the shared a_cur. Second, upass_tolg.cpp:3581 already builds the per-(read,write) fwd/undef matrix only when !mi.has_update, so ordering= on a whole-array declaration is accepted and then ignored; today's behaviour is correct only because the encoder's is_whole fallback happens to read committed state. The error above turns that coincidence into a stated contract.

Unrelated but in the same import path: WR_PRIORITY_MASK has zero hits repo-wide, so the Yosys reader still drops two-write-port priority that the slang reader gets right.

Pending — same-shape memory permutation retry

Memory state currently pairs by shape and occurrence. The landed diverged-use guard prevents a confident semdiff mismatch from being collapsed, but it cannot distinguish structurally symmetric, same-shape memories reordered between REF and IMPL.

v1 is the SOUNDNESS half only. On reset-based BMC an occurrence pairing must never be allowed to turn crossed initial arrays into a trusted refutation: when a result touches an ambiguous same-shape bucket, the verdict stays UNKNOWN rather than becoming a disproof. That guard is cheap and unconditionally right.

The completeness half — enumerate the bucket's alternative permutations as uncertain memory pairs, let a proof under a complete candidate mapping pass and disclose the mapping, recheck a candidate refutation without it, cap the search and report a skipped bucket, and include the chosen permutation in the cache key and pair hint only when the hint revalidates — is DEFERRED until a live instance appears. None has been found on this corpus.

The obvious candidate is measured NOT to be one. intpipe_csr_file holds exactly two [2]u49 arrays (reg_stval, reg_mtval) — the textbook ambiguous bucket — and its two mem:2x49#* cuts are the def's only unproven obligations, cvc5-SAT in about 1.2 s each. Swapping the two declarations in a copy of intpipe_csr_file.prp and re-LEC'ing leaves both cuts DIFF, so the pairing is not crossed and the two sides genuinely compute different next-state contents. What makes exactly those two arrays unusual is a variable-index read of their NEXT (comb) value at intpipe_csr_file.sv:2410 — the needs_array forwarding case at query.cpp:4855-4880. That, not permutation retry, is what keeps the def UNKNOWN.
