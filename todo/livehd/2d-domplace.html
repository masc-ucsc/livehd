2d-domplace Provisional domino placement

Turn USYN's selected endpoint functions into a mixed CMOS/domino physical netlist, place two-row domino cells, and measure stage timing with an explicit provisional model. Deliver reproducible placement experiments before a real domino cell builder and characterized LEF/Liberty exist.

Reviewed plan — 2026-10-25; implementation pending This page incorporates and supersedes the supplied pre-plan, using the current interfaces. One domino evaluation phase is confirmed for v1: one terminal domino gate plus its output latch per converted stage, with earlier logic in CMOS. Two domino phases are future work. The estimates cover this scope and distinct variant widths derived from the confirmed inverter-plus-register area model below. The externally owned odd/even placement-row convention is an input to domino pin geometry. This task generates compatible pin locations and handles placement, legalization and resizing of double-height domino cells; routing-policy implementation remains with its owner. Assumptions inherited from the pre-plan and new recommendations are distinguished below. This page does not approve changes to existing user-visible defaults.

Depends on

  • USYN supplies the implemented Gate_formula, endpoint selection, frozen netlist and source-state correspondence. Physical emission and the restricted selection policy belong here; the rest of the USYN roadmap is not a prerequisite.
  • native placement supplies physical netlist import, native DREAMPlace GP, legalization, RC and DEF export. Reuse these interfaces and extend their two-row handling.
  • 2t-timeclosure B–C supplies the proposed standalone timing proxy and wire model. These are still planned, not an existing topological timer. Implement/reuse the minimum supported proxy before E; geometry bring-up can proceed without it. The full seven-phase controller, virtual-buffer optimization and resynthesis are not prerequisites.

Design notes

Confirmed decisions and scope

Q1 — confirmed 2026-10-25: only one domino evaluation phase for v1. Each converted stage ends in one domino gate plus its output latch; earlier logic remains CMOS. Ordinary CMOS+DFF stages remain supported. Two domino phases are future work and are excluded from the implementation steps and estimates here. Precharge/evaluate windows within the one-phase macro do not introduce a second cascaded domino logic phase.

Q2 — confirmed 2026-10-25: drive variants have their own estimated widths. Area is x * A_NOT + A_register(strength), where x is the domino transistor proxy expressed in two-transistor inverter units. Use the full drive-specific technology register area for the registered output, not an incremental register-area difference or a multiplier on the entire domino gate. This supersedes the pre-plan's fixed-width assumption and seven-inverter overhead. Geometry is fixed between explicit sizing edits; post-placement resizing requires two-row ECO legalization. One-shot USYN remains.

Q3 — clarified scope, 2026-10-25: odd/even refers to placement rows: odd = vertical, even = horizontal. Another task owns that routing work; this task must account for the convention when generating domino pin locations. C consumes the row-access convention and technology geometry, and F/G preserve compatible pin access through placement, flips, legalization and width-changing sizing. The routing implementation and its enforcement policy remain external.

Corrections to the pre-plan

  • PDN construction is largely available. Reuse Gate_formula and Endpoint_netlist; the new work is physical selection, rails, modeling and emission.
  • Logical dual-rail assumptions must be removed from physical cost. The frozen representation currently aliases Q/!Q and can share phase-one implementations. Two output macros need independently legal formulas, clock loads and storage correspondence; shape binning must not merge their functions.
  • The proposed timing proxy is not landed. Physical_session backs the current what-if interface with OpenTimer. Include the base-proxy dependency in estimates instead of describing E as only an endpoint annotation change.
  • Q2 resolves widths and sizing. Charge the domino transistor proxy plus a full drive-specific register, generate each variant's own width, and include two-row ECO legalization in sizing. Keep the PDN fixed across drive variants and report site/pin-access rounding separately from estimated area.
  • Clock/load/setup terms belong in the period equation. The two raw maximum segment delays omit margins, launch delays and full-cycle paths unless their definitions explicitly include them. Hold and precharge also need separate checks.
  • Custom-cell integration is more than a new node type. Mapping, graph emission, proof/simulation models, timing, repair, library lookup, export and cache replay all need the same registered identity.

Proposed single-terminal timing convention

time             nT                     nT + T/2                 (n+1)T
source Q         launch ─── CMOS + wire ─── inputs stable ────────────┐
domino network   precharge                evaluate                  │
output storage   holds previous Q ─────────────────────────────── capture
next stage Q                                                     + t_cq

ordinary stage   launch ───────────── CMOS + wire ───────────────── capture

This is a specification to implement under Q1's confirmed scope, not a claim that pulse-latch electronics already satisfy it. Macro inputs settle before evaluation starts and remain stable through the declared evaluation/capture hold window. This is stricter than ordinary edge-register setup alone. Treat storage as an edge element in the functional model while retaining pulse-width/skew requirements in early timing.

  • Let a be latest arrival relative to launch, including source clock-to-Q, static-cell delays, physical rail generation and wire delay. Into domino: a + setup_eval + uncertainty_first ≤ T/2.
  • Inside domino: evaluate_delay + setup_capture + uncertainty_second ≤ T/2. Evaluation delay excludes the subsequent output clock-to-Q; the latter is charged to the next stage exactly once.
  • Into an ordinary DFF: a + setup_DFF + uncertainty_full ≤ T. Independently require precharge_delay + precharge_margin ≤ T/2.
  • The estimated setup/precharge period is the maximum of twice the worst first-half requirement, twice the worst internal requirement, the worst full-cycle DFF requirement, and twice the worst precharge requirement. Include only present, constrained classes; report absent and unsupported classes.
  • Check the earliest next data transition against the stability window and capture hold requirement, using source minimum clock-to-Q, minimum cell/wire delay, pulse width and relative clock skew with an explicit sign convention. Increasing T does not automatically repair a hold violation. An unavailable early model means hold coverage is unknown, not passed.

Area, geometry and model identity

N_domino_proxy  = N_PDN + N_aux_nonregister
x               = N_domino_proxy / 2
A_domino(s)     = x * A_NOT + A_register(s)
H_domino        = 2 * H_row
W_area(s)       = ceil(A_domino(s) / (2 * H_row * W_site)) * W_site
W_domino(s)     = site_round_up(max(W_area(s), W_pin_access(s)))
A_footprint(s)  = W_domino(s) * H_domino

N_PDN counts literal devices in the checked factored network, including repeated physical occurrences. Define and report N_aux_nonregister for precharge, keeper, foot and other domino-only devices actually included in the proxy; exclude anything already represented by the output register. Their counts remain provisional model parameters to specify in C. Do not retain the old seven-inverter lump sum or add another latch term. The confirmed formula charges the full register exactly once.

A_NOT and A_register(s) are areas of named cells in the selected technology, with all register strengths taken from the same compatible family/corner. Use a consistent physical-area basis and units across the cell references; document LEF/Liberty normalization if their areas differ. The register family supplies strength scaling while the same PDN proxy is shared by all variants. Fractional inverter equivalents are allowed; round geometry to sites only after computing total area. Independent variant estimates can round to equal widths when site pitch or pin access dominates; retain and report their distinct electrical identities rather than inventing an area increment.

Report estimated area, rounded physical footprint, quantization/pin-access overhead and separately materialized rail-generation area. Placement uses the selected variant's actual footprint, not a reservation for the largest drive.

Use the supplied row-access convention, actual track/layer geometry and explicit master/site symmetries for orientation legality; the LEF/DEF reference gives specific double-height cell and row-site examples. The provisional absence of a power-rail-parity restriction remains an explicit model assumption, separate from the externally owned row routing policy and to be rechecked when real cells arrive. LEF/DEF 5.8 Language Reference, “Double-Height Cells” and SITE/SYMMETRY.
