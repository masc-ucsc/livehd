2t-timeclosure Timing closure inside global placement

Implement a single-threaded, non-ML timing loop in native DREAMPlace GP: optimize achievable period with a LiveHD timing proxy, model buffering and reserve its space early, then materialize buffers and resize cells in phase 7.

Implementation plan — reviewed 2026-10-24; not implemented The design rationale and algorithm references are in timing_closure_plan.md. This page translates that proposal into ordered deliverables, integration points, review resolutions and acceptance checks. Constants are initial experiment values, not validated settings or approval to change existing defaults.

First delivery: complete A–C and the observation/replay part of H. Establish trustworthy proxy timing and gate decisions before enabling forces or graph edits. The core loop must work with resynthesis disabled; K adds it independently.

Depends on

  • 3p-placement supplies the native placement stages, mapped physical graph, technology RC, checkpoints and export. Reuse the implemented interfaces; this task does not wait for every outstanding placement experiment.
  • 3r-route supplies RSMT-RUDY and full-footprint congestion measurements. Its pending stability-based timing warm-up is implemented by H for the new loop, avoiding a second independent gate controller.
  • 2p-plan E and 3s-terminal-legalize supply legalization and timing protection for the phase-7 handoff. Existing legalizers remain usable; optional SAT alignment is not a prerequisite.
  • 2is-incsynth is needed only for K: reuse color environments, mapped-body remapping and equivalence checks. Its once-per-run policy remains the legacy policy.

  • D — Define the period objective and shared LR state.
    • Compute achievable period T* with the supported launch/capture, setup and IO constraints. For a fully covered single-period setup model, T* = T_SDC − worst_setup_slack; raw maximum arrival alone omits capture/output requirements. Record both fixed-SDC slack and rebased optimization slack. Select endpoints within ε·T* of the worst endpoint and optimize toward (1−ε)·T*, initially ε=0.10.
    • Implement numerically stable log-sum-exp and normalized rise/fall arc multipliers, with endpoint mass summing to one and node flow conservation. Normalize delay/path weights so changing ps to ns does not change placement. Update multipliers from phase 3 even though actual size selection waits for phase 7.
    • Specify the LR-to-DP interface mathematically: physical required-time feasibility and absolute electrical limits remain distinct from the multiplier cost. Do not treat a dimensionless multiplier as a time offset. Share that state between pin weights, buffering selection and sizing.
    • Guard the best T*, equivalently fixed-reference worst setup slack, not WNS measured against a moving target or the soft-window sum. Compare candidate and retained state under the same timing/calibration generation and compatible density/legality conditions. Shrink the softmax temperature after a rejected regression; keep rejection tolerance above measured repeatability noise.
    • Exit: an infeasible 1 ns request on a roughly 6 ns fixture concentrates work near the worst paths; window-sum improvement cannot accept a worse worst path. Cover path-rank swaps, empty/unconstrained endpoint sets, zero-delay circuits, unit changes and temperature bounds.
  • E — Implement buffering candidates by net class.
    • Build a common candidate/tree interface containing topology, cell choices, positions, cap, required time, slew, area and resource demand. Short unblocked nets stay unbuffered when electrically feasible; a length cutoff never overrides an actual pin-load or slew violation.
    • For long unblocked nets, use the early linear buffered-delay estimate, fitted against this proxy's discrete-library van Ginneken solutions. The late tree DP supports multiple buffer types. Compare early delay and reserved area with the real tree before materialization.
    • For blockage-crossing fanout ≤3, implement Chen–Pedram–Buch on the extended Hanan graph, retaining the full nondominated frontier rather than keep-two/early exit heuristics. Replace fixed-gain estimates with library NLDM stages for late selection. For larger fanout, implement BEN-style tile rerouting followed by resource-aware van Ginneken. Measure the crossover at fanout 4 instead of treating 3 as a proven optimum.
    • First try critical-sink isolation on high-fanout critical nets: decouple noncritical sinks while retaining the critical connection. Verify the new buffer input load and every affected sink. Critical candidates maximize required time; off-window candidates minimize area then wirelength while remaining outside the window and satisfying electrical constraints.
    • Make DP slew feasibility explicit for NLDM input-slew dependence; justify discretization and dominance before pruning. Bound state count/time and report budget exhaustion separately from infeasibility. A bounded search may keep a previous feasible candidate, but cannot claim the unrestricted optimum.
    • Exit: exhaustive tiny-tree comparisons, multiple cell types, fanout 1–4, critical isolation, and a feasible/infeasible slew crossing. Cache Hanan geometry and measure frontier size and runtime on representative dirty nets.
  • F — Model gap capacity and competing virtual buffer demand.
    • After full macro exclusions are established, build the union of halo-grown macro rectangles, gap connectivity and legal buffer sites. Decompose nonrectangular obstacles consistently. Count discrete row sites for narrow gaps, respecting buffer footprints and a legalization margin; zero-capacity gaps are wire-only.
    • Distinguish buffer placement exclusions from routing obstructions. Over-macro wires require legal layers, characterized upper-layer RC and crossing capacity. Current native RUDY treats macro bodies as opaque; extend its capacity model in DREAMPlace before claiming consistency with over-macro buffering. Do not invent upper-layer RC when technology data is missing.
    • Price gap slots and crossing capacity by current demand plus history. Negotiate critical/window nets first; other nets pay the congestion surcharge. Promote a net when it enters the window. Never divide by zero slots, and never price away a hard slew/cap or routing obstruction.
    • Return reservations and bounded gap-entry pseudo-nets for G. Reserve only predicted or electrically mandatory buffers. Account for shared gaps/halo unions once, and release demand when candidates disappear. Limit negotiation rounds and report unmet demand rather than manufacturing capacity.
    • Exit: competing nets cannot each claim the same last slot; one-site, zero-slot, L/T-shaped and overlapping-halo fixtures have consistent capacity. An over-macro span beyond its electrical limit is rejected.
  • G — Add per-pin timing forces and virtual density reservations.
    • Extend the native DREAMPlace objective with a smoothed weighted driver-to-sink distance term alongside existing wirelength/density. Expose pin weights and driver indices through a typed checkpoint update; a per-net scalar cannot express this. Use LR plus worst-path delay/k² contributions, attributed to the influencing sink/input pin.
    • Normalize graph and path components; start experiments at α=0.5 and global RCWL weight t=0.25. Bound the per-pin blend factor to [0,1] and weights to finite nonnegative values. Clear obsolete weights and identities when paths leave the window or topology changes.
    • Apply gap reservations through one density accounting path. Adding reserved charge and independently subtracting the same capacity would double count it. Convert reservation to physical occupancy exactly once when a buffer activates; reconcile filler charge, local target density and RUDY inflation at that boundary.
    • Give critical gap-entry pulls priority over their conflicting straight driver-to-sink pull, with bounded strength relative to the net's timing force. Cap congestion inflation around critical buffers; retain ordinary congestion pricing for others. Recompute reservations and pulls together at checkpoints.
    • Exit: finite-difference gradient checks, translation/unit checks, selective attraction on a two-sink net, no force from removed pins, and area conservation across reserve/activate/remove cycles. Measure non-window HPWL and overflow, not only the critical path.
  • H — Implement and replay the latched phase controller.

    • Use Theil–Sen slope, residual MAD, history range and turning-point checks as specified in the Markdown. Make integer cadence explicit: with N=5, evaluate every ceil(N/2)=3 samples, require two passing evaluations, and define overlapping three-sample halves for the turning-point test.
    • During dwell, sample/log but do not evaluate gates. Restart affected histories after dwell or changes to timing model, topology or geometry. Checkpoints update the frozen forces/virtual solutions; correction refresh also occurs at overflow milestones and dirty events. Add a maximum correction age so a flat or rising overflow does not indefinitely retain stale geometry.

Deadlines force a decision, not completion of prerequisites: reserve ramp/settle and timing-response time before repair, skip optional resynthesis when it does not fit, and report unmet preconditions or budget exhaustion explicitly. Inactive entries must contribute to no wirelength, density, filler sizing, routability, legalization or exported netlist.

Review resolutions and remaining decisions

Proposal issueImplementation treatment
Rebased WNS versus achieved periodUse rebasing for optimization priority; compare fixed-reference worst slack or T* for acceptance. Include setup, clock and IO requirements before calling the result a period/Fmax.
“Netlist changes come last” versus optional phases 4–5Buffers and sizing wait until phase 7. Explicitly enabled resynthesis is the earlier topology exception; ordinary phases 3–6 buffering remains virtual.
Best-WNS rollback versus cumulative resynthesisRollback is complete within a topology epoch. Accepted resynthesis begins a new epoch and is not undone by restoring an old buffer/size snapshot.
Continuous model versus checkpoint-only workFrozen topology and forces are used between decision checkpoints; positions still change continuously. Sampling, decisions and Steiner refresh have separate cadences.
Corrections that “survive sizing”Only load-independent geometry is reused unconditionally. Library pin caps are not scaled by a wire-length ratio; load/slew-dependent terms are invalidated or reevaluated.
Pin-weight smoothingThe stated exponential η formula can exceed one. Normalize its inputs and clamp the blend before using it as smoothing; test large jumps and publish this implementation refinement.
GPU run-to-run noise in the rationaleThis implementation targets native CPU placement with one thread. Measure its actual repeatability; do not assume GPU noise numbers apply.
Calibration designsStill to select in A/C: representative routed gap/over-macro cases for each technology and routing setup, with a held-out split. Missing styles remain uncovered; sky130 calibration is not portable to ASAP7.
Acceptance thresholdsStill to freeze in A from baseline coverage, runtime and repeatability. The plan specifies the measurements, not fabricated accuracy or speed claims. Gate tuning is evaluated on CNN and Eyeriss.

Source review

Keep the full bibliography in the Markdown reference list. A focused check of Fu et al., ICCAD 2024, sections 3.3–3.4 supports hybrid pin weighting and cached RC correction. Its calibration derivation isolates wire capacitance; it also retains a Steiner impulse reference for slew. Implementing just a load ratio and delay offset therefore needs a separate slew-fidelity check. The paper's overflow-triggered calibration is distinct from the phase-3 activation proposed here.

The TimingPredict dataset documentation lists 21 sky130/OpenROAD circuits with raw Verilog, DEF, SDC, SPEF and SDF. It is an offline fidelity source, not a default regression dependency or evidence of coverage for macro-gap routing styles. Download availability, reproducible tool/library versions and the relevant design coverage must be checked before using it. Remaining buffering/LR/hold bibliography entries, especially those marked unverified in the Markdown, require primary-source verification during their implementation milestones; no optimality or signoff claim follows from their inclusion in the proposal.
