2s-satopt Standalone, bounded logic simplification

Make pass.satopt rewrite the current LGraph to help subsequent synthesis, simulation, and LEC. Use stronger simulation signatures to nominate constant, equal, and complementary values for proof, followed by shallow local observability don't-care (ODC) replacement by constants and bounded SAT-assisted Hotmux collapse. Split the optimizer into selectable stages with shared, demand-created analysis services; add bounded simulation-guided resubstitution after measuring the initial sweep and Hotmux stages.

Depends on

None beyond the existing compiler and proof infrastructure. Run after cprop and bitwidth inference; synthesis coloring or technology mapping is not a prerequisite.

Design notes

Implementation order: A and B establish the shared semantic contract, with K's stage separation established early; C–F add stronger discovery and unconditional sweeping; G adds local ODC constants; I adds bounded Hotmux collapse using the same proof infrastructure. J supplies the refinement architecture and Hotmux discovery hints, then adds limited expression resubstitution after baseline measurements. Apply H throughout. Unrestricted resubstitution, multi-LUT decomposition, and multi-entry indexed-mux collapse remain outside the initial implementation. Lnet integration is deferred.

Control-only Boolean resynthesis (simp_ctrl)

Implemented, opt-in: pass.satopt.stages=simp_ctrl derives a function over up to three existing one-bit signals for mux selects, Flop enables, and memory port/bulk-update enables. It can remove or substitute inputs instead of trying only a fixed list of two-input gates. Word-level simulation supplies per-bit truth-table samples; conflicting samples reject a support set, and SAT counterexamples refine incomplete tables. Every committed replacement is proven exactly equivalent and must remove more cells than it adds. Hotmux exclusivity checks remain observable; no ODC or one-hot assumption is used.

Wide selectors, write masks and data readers are excluded. Boolean cones may reuse comparison/reduction outputs without resynthesizing their wide datapaths. Search bounds: 12 divisors, four Boolean levels, three replacement inputs, 320 support attempts, 16 proof queries per control, eight refinements per support, a 48-cell gain estimate, and a 512-pin proof-cone cap, all under the shared budget. Neighboring divisors must be independent of the target. Proof state is lazy. Persistent proof-cache replay and contextual resynthesis remain future work for this stage. To combine it with the default stages, explicitly select constants,hotmux,memory,simp_ctrl.

Stage selection and future Lnet reuse

Implemented stage selection: an explicit stage list is sufficient initially; avoid overlapping presets and individual booleans with ambiguous precedence. For example, --set pass.satopt.stages=equiv,complement,resub requests only those searches plus the analysis services and correctness validation they require. The names constants, equiv, complement, odc, hotmux, memory, resub, and simp_ctrl are stage identifiers. Here complement means A == ~B at the same finite width. With odc absent, resubstitution must preserve the target function on all inputs; it cannot rely on downstream unobservability. Hotmux arm proofs may still use their selection conditions, provided the entire replacement preserves the region's output and checks on all inputs.

Separate algorithm selection from network capabilities. The future Lnet backend should declare what it can evaluate, prove, and rewrite; callers choose which supported searches to run. An unsupported stage should be reported as inapplicable, not force a conversion back to LGraph. Combinational LUT networks can still benefit from shallow ODCs, but there is no need to enable ODC for ordinary equality/complement or unconditional resubstitution. Representation, proof boundary, and cost decisions for LUTs remain an explicit later review.

Follow-up review: word-level sweeping

FORWORD: Accelerating Formal Datapath Verification via Word-Level Sweeping (v2, reviewed 2026-09-23) groups word expressions by simulation signature, proves candidate equivalences with SMT, and refines signatures with counterexamples. It also bounds and ranks candidate searches. These ideas fit C–F; its verification-specific assumptions must not become implicit assumptions of the standalone optimizer.

Recommended LiveHD adaptation, to validate during C–F:

  • The main candidate index is D's per-bit signature map, populated from C's word-level evaluations. Coalesce matching adjacent bits into whole-word/range proofs and rewrites when profitable. A whole-word hash is an optional accelerator, not a prerequisite or a first stage that suppresses partial-bit discovery. Preserve signed interpretation at uses and finite-width complement semantics.
  • For fully concrete samples, derive candidate constant masks directly: M0 = ~OR(samples) and M1 = AND(samples), clipped to the declared width. With M = M0 | M1, prove (value & M) != M1 unsatisfiable. For aligned equal/complement runs, prove ((a XOR b) & M) != C unsatisfiable, where C = 0 or M. These are proposals for grouped proof APIs, not operations already exposed by formal::Prover.
  • If a grouped claim is refuted, remove bits falsified by the concrete model and recheck the remainder under a retry budget; Unknown proves no part of the group. Return structured counterexample values with width and instance scope instead of parsing Query_out::witness's diagnostic string.
  • Reuse Seeds' existing word-level evaluation and the cvc5 encoder. The current prover memoizes terms but creates a fresh solver per query; grouped queries are a first step. Measure before adding persistent solver sessions, and never keep encodings across invalidating mutations. SMT may still bit-blast internally, so width/encoding and solver budgets remain necessary.
  • Rank by constants first, removable operation cost, existing fanout, and bounded structural metadata. Do not add repeated full-cone similarity walks. The paper's fivefold AST-size rejection rule is unsuitable for our constant priority: a large cone simplifying to a constant is valuable, not disqualified by its size difference.
  • Keep constraint-guided sampling and array shortcuts out of the initial implementation. Sampled agreement of memories is not semantic equality, and verification-environment constraints cannot justify a general graph rewrite. The reviewed paper measures verification runtime; its speedups do not establish LiveHD synthesis or simulator gains.

Brainstorm: use unknowns as an analysis abstraction

Experimental suggestions, not additional implementation commitments. An analysis ? denotes either 0 or 1, so a ternary word represents a set of concrete words. This is different from granting permission to choose a value for an unknown literal in the source. Keep source unknown semantics, independent state identities, and observable obligations intact.

  • Known-bit discovery. Evaluate with free inputs/state bits unknown and preserve any bits that remain known, for example ???? AND 0000 = 0000. A known result from a sound over-approximation holds for every represented assignment. An all-free-input evaluation can expose global constants; a partially fixed input cube gives only conditional facts. Reuse cprop/bitwidth information first and measure additional discoveries before adding another whole-graph sweep. Initially send candidates through the existing proof gate; bypassing SMT requires validated abstract transfer semantics.
  • Local ODC discovery by injecting unknowns. Starting from a concrete sample, override one candidate bit with ? and reevaluate its bounded fanout using word operations. If every affected window exit and check stays known and equal to the original sample, changing that bit is unobservable for this sample. This supplies a conservative ODC mask for G; an unknown exit is inconclusive, and sampled unobservability is not a global replacement proof. Include all affected fanouts and treat truncated exits as observable. Limit candidate injections and reevaluation work; do not run a full-design experiment for every bit.
  • Generalize and pack counterexamples. Start with a concrete witness that rejects a proposed replacement. Under a small trial budget, replace groups of input/state bits with ? only while the rejection predicate remains definitely true (including any required context). The resulting cube describes many witnesses. Compatible cubes can share a concrete sample by combining their nonconflicting fixed bits and filling the remaining unknowns; recheck the intended rejections before adding that sample. This can make C's bounded sample set more informative. Related pattern compression appears in A Simulation-Guided Paradigm for Logic Synthesis and Verification, section V-C; using Dlop ternary evaluation to generalize cubes is our proposed adaptation.
  • Keep unknown evidence separate from concrete hashing. For ternary signatures store a known mask K and values V. Two signals are definitely different on a sample only where (Va XOR Vb) AND Ka AND Kb is nonzero. Matching unknowns prove nothing: two independent bits both evaluating to ? need not be equal. Wildcard compatibility is nontransitive and cannot replace equality in a hash map. Keep concrete signatures as the primary index; ternary evidence supplements discovery and filtering. The constant-mask formulas above apply to concrete samples; ternary processing must explicitly use known-zero/known-one masks.
  • Audit the evaluator before using this abstraction. Current satopt Seeds rejects unknown values and selects mux arms with !is_known_zero(), which is only valid for its concrete inputs. A ternary path must merge possible outcomes instead of treating unknown controls as true. Audit Hotmux separately: the inspected HLOP helper can use one-hot semantics to resolve other unknown controls, which cannot silently discharge an unproved exclusivity check. Propagate uncertainty in both data and obligations; unsupported/invalid evaluation never authorizes a rewrite. Plain ternary values also lose correlation, so identities such as x XOR x = 0 can be missed when both operands are represented by ?; retain structural reasoning and SAT/SMT for these cases.

Suggested experiment order: bounded ODC injection and counterexample generalization, with known-bit discovery measured against what cprop already provides. Compare saved solver calls and sample evaluations with the extra ternary simulation cost.
