Where this stands (M10 LANDED 2026-07-31)

M0–M10 are LANDED. Latches, negedge state and clock gating work in formal, through hierarchy, with no graph rewrite. The formal encoder now has a real model of WHICH CLOCK a state element commits on: a read-only, hierarchy-aware phase schedule (pass/lec/phase_sched.{hpp,cpp}) assigns every instantiated register, latch and synchronous memory port one of four ordered microsteps per source period, and the encoder gates each commit on its own microstep. All eight false-PROVEN clock-blindness holes are closed, and a Latch is encoded NATIVELY rather than normalized away.

Measured on lhdsuite //bench:minion_lec (opt): 166/170 definitions proven (from 110/140), 1 trusted (from 32), 0 clock-modelling refusals — no schedule refusal, no derived clock, no latch/negedge decline. Eleven previously-fixme targets are green: the six prp-v2prp2v-phase_* pairs, the three prp-equiv-phase_* pairs, latch_always_transparent, and lec_comb_box_cone_test. livehd //... is 1564/1564.

Scope ruling (user, 2026-07-20) — BINDING: SIMPLE LATCHES, NO TIME BORROWING

Time borrowing is a backend / physical-design technique. LiveHD's scope ends at the ABC call, and ABC's output netlist has no clock borrowing either. This ruling collapses the expensive half of the problem. Under it a latch is exactly a flop-with-enable that commits at the CLOSING edge of its transparent window:

  • transparent-HIGH latch (transparent while gate == 1) → commits at the FALL of its gate
  • transparent-LOW latch (transparent while gate == 0) → commits at the RISE of its gate

That is Conformal's set flatten model -latch_fold / the IBM LEC normalization (US7624363). It is an ABSTRACTION WITH A PRECONDITION, not a semantics — and the scope ruling is that precondition, so it must be CHECKED, never assumed (M3 does, in graph/latch_contract.cpp). What it buys: no transparency mux in the sim scheduler, no settle/fixpoint loop, no MDL phase abstraction, no counterexample lifting — nothing research-grade on the critical path.

The abstraction changes OBSERVABILITY, and that must be stated: while a window is OPEN a real latch reads through (Q follows D combinationally) but the commit-class model shows the previous commit. The two agree exactly at closed-window, end-of-cycle observations. Three consequences run through everything below: (1) any latch encoding in LEC is sound only as a both-sides normalization — never encode one side with transparency and the other without; (2) sim asserts and differential oracles may observe a latch Q only under the observation-visibility rule; (3) the shared observation point for sim / BMC / Icarus is end-of-cycle, all edges settled — pinned executable by inou/prp/tests/fixme/flop_verify_posneg.prp (under the alternative "between rise and fall" convention that fixture's correct answer would be indistinguishable from today's clock-blind encoding).

The abstraction is for SIM and LEC ONLY. Verilog emission must still emit a real always_latch — the netlist handed to ABC has to contain a real latch. Terminology trap: an AIGER/ABC "latch" is an edge-triggered unit-delay register on an implicit global clock, NOT a level-sensitive latch; ABC's BLIF reader silently discards the .latch control tokens, so a real latch reaching ABC is a silent mismodel, not an error. Everything on this page means level-sensitive.

Rules — BINDING

Cross-model gating is mandatory. "PROVEN before AND after the transformation" cannot see a transformation that is WRONG but applied identically to both sides — two identically-wrong machines prove equal, so a symmetric gate is vacuous by construction. Every latch/clock transformation must be gated against an INDEPENDENT checker: lgyosys for latch polarity, iverilog for anything clock/edge-shaped, never our own encoder on both sides. This one mechanism catches mux placement, posclk double-negation, a flavour-blind ICG fold, and an unstable phase gate.

There is NO in-repo formal oracle for flop EDGES. lgcheck's cascade ends in a bounded miter (LGCHECK_BMC_STEPS default 5, inou/yosys/lgcheck:399) that decides latch designs and genuinely discriminates enable polarity — pinned by lhd/tests/lec_latch_polarity_test.sh. But it is exactly as edge- and gate-blind for flops as our own encoder was (reproduced: PROVEN on negedge-vs-posedge and gated-vs-ungated). So an equiv pair of mixed-edge designs "proving" via lgcheck is vacuous with respect to the edges; only event-driven simulation discriminates them.

Verdict discipline (inherited from 2f-lec): PASS ⇒ definitively equivalent; FAIL ⇒ definitively different; anything else is inconclusive. An abstraction may only cause extra work, never a wrong verdict. Trackers that demand a refutation must grep a verbatim REFUTED — an encoder that merely degrades a false-PROVEN to UNKNOWN has not fixed the bug.

Observation-visibility rule (used by every sim/BMC fixture): an observation of a latch Q — a settled-region assert, a differential-oracle sample, or a sequential element in Q's fanin cone at its firing boundary — is valid iff (a) the latch was OPAQUE in the tick immediately preceding the observation, (b) at least one closing edge has completed since power-on, and (c) the data was STABLE across the closing edge being observed. Under (a)-(c) the real-transparency semantics (Icarus), the commit-at-closing-edge model, and a flop-with-enable encoding all agree, so fixtures pin the RULING, not an implementation choice. Divergence is not confined to transparent ticks — it PERSISTS through any state element that sampled a latch while open (taint).

M9 — Clock_cell: ONE recognized clock operator LANDED 2026-07-26

An ICG is the commonest latch structure in real hardware, and real designs instantiate it rather than spelling it inline — minion has 32 prim_clk_gate u_cg(.clk_i(clk), .en_i(en), .clk_o(gclk)); sites, which were exactly the 32 names on lhdsuite's lec_trust list. A Sub output is an opaque symbol, so a flop whose clock_pin comes from one could not be given a commit condition at all: 30 defs refused to encode. For a clock gate, blackboxing the proven leaf is precisely what breaks the parent — every other leaf is fine opaque because its outputs become free symbols the parent compares, but an ICG's output is a clock. "Prove it, then box it" does not compose for an ICG, which is why prim_clk_gate sitting on a trust list was self-defeating.

  out_clk = Clock_cell(clk_ref, en, div=1, invert=false)
  • Ntype_op::Clock_cell = 52 (even ⇒ combinational), pins clk_ref=2 / div=3 / en=4 / invert=6. The pin ids are NOT free: get_sink_pid's fast path derives the pid from the leading char for a-f (pid == c - 'a'). Mirroring Flop's clock_pin/enable is what makes that safe.
  • clk_ref and en are runtime inputs; div and invert are comptime attributes. en is sampled at the ACTIVE EDGE of clk_ref — the glitch-free ICG contract. Encoding the CONTRACT, not the latch, is what keeps the physical enable latch out of the graph, so every latch-counting consumer stops seeing ICG latches entirely.
  • Recognition lives in graph/latch_contract.cpp: match_icg_def (STRUCTURAL — the port both AND-ed into the output AND gating the latch's window is the clock; no name heuristic), Cone_cloner (clones ONLY the combinational enable cone into the parent, re-rooted on the instance's drivers; fails closed on any state, Sub or Memory in the cone), and materialize_clock_cells, which creates the cell, rewires the gate's readers and DELETES the instance.
  • The enable is a CONE, not a wire. prim_clk_gate.sv latches en_i | dft_i.scanmode (scan forces the clock ON), and dft_i is a packed struct graph flows keep as one FLAT bus, so the compiled latch din is or(en_i, and(sra(dft_i, k), 1)) behind tolg's hold mux. Dropping the scanmode term is UNSOUND, not conservative — gate sites wire a live dft and minion_top exposes it as a primary input.
  • resolve_phase has a Clock_cell arm so a gated clock's ROOT is its REFERENCE clock. Without it Design_clocks inserts the cell's own output into roots_, is_clock starts answering true for gated nets, and two flops committing on the very same edge land in different phases.
  • Wired CONSUMER-SIDE ONLY (lhd_kernel_formal.cpp, both lec_command and verify_command). It deliberately passes NO is_boxed: recognition RESPECTS trust rather than fighting it, which is what lets a TRUSTED gate be recognized.
  • Gate: lhd/tests/clock_cell_test.sh, 8 cases, every proof paired with a refutation that must still fire — including the two shapes inlining structurally cannot reach (a TRUSTED gate, and a gated MEMORY).
  • The binding rule is enforced for Pyrope: illegal_clock_op (upass/tolg/upass_tolg.cpp) rejects an arithmetic or data-merging op in a clock cone with a clock-op-unsupported diagnostic; fixture inou/prp/tests/errors/clock_or_data.prp. It is a DENY-list, not an allow-list, and it is scoped to the Pyrope front end: a hard error on any derived clock would break lec_clock_blindness_test's clk ^ sel case, which wants an ENCODER refusal, not a compile error. (Trap: the tests/errors/ harness runs tolg:false, so a lowering-stage error needs :tolg: 1 in the header or it silently reports “no error emitted”.)

Rules — BINDING

  • A Clock_cell output is legal ONLY on a clock sink: a state element's clock_pin, a Latch's gate, another cell's clk_ref, or a Sub instance INPUT port (minion exercises all four). Reading it as DATA is an error, or forces the blackbox path. People do sample gated clocks in DFT and clock-monitor logic; without this rule the “it is an enable” model and the “it is a bit value” reading diverge silently. This is the dual of “nothing may be done with a clock”.
  • Anything else on a clock (clock+1, an odd divider, arbitrary logic) ⇒ error naming the blackbox escape hatch. posedge ~clk is NOT in that set — it is legitimate and lhd/tests/lec_clock_blindness_test.sh pins it PROVEN equal to negedge clk.
  • is_clock is STRUCTURAL: a net is a clock iff it is a declared clock input, a Clock_cell output, or a Sub input port fed by a clock in the parent — clockness propagates TOP-DOWN through the instance tree. The formal driver's clock forest is that propagation. The name heuristic in Design_clocks::is_clock survives ONLY as the top-level seed, because no “declared clock input” mechanism exists yet — the slang reader's only clock ID is itself a name match.
  • WHERE recognition runs is part of the contract: inside the formal and sim pipelines ONLY, never on the compile/emission path — mirroring pass.single_edge's placement, for single_edge_scope_test's byte-identical-emission rule, the ABC incremental cache's digest-keyed regions, and lhdsuite's checked-in trees. Revisit only when the synthesis ICG lowering ships.

Traps — measured, do not re-derive

  • Enable-latch bypass: a real ICG latches its enable on the opposite phase purely to suppress glitches — the latch CLOSES exactly when the flop SAMPLES, so the flop sees the value the latch is passing THROUGH, not its held Q. Taking Q is a full cycle late (the classic L1 error) and is INVISIBLE to a symmetric before/after comparison, because both sides would be wrong identically. Measured: the first cut did exactly that, because the rewrite loop had already retyped the latch to a Flop by the time it reached the gated flop. Resolution now happens during PLANNING, before any mutation. Pinned by single_edge_icg_test.sh, whose iverilog leg agrees over 29 cycles and whose negative control (use the held Q) FAILS.
  • Polarity: for gclk = clk & g the commit condition is enable & g — NOT & !g. Also invisible to a symmetric check.
  • A CONSTANT operand is a width MASK, not an enable. Reading And(Not(Get_mask(clk)), 1)'s 1 as an enable made an INVERTED clock look like a gated one and silently un-fixed the negedge case.
  • cgen_verilog's only unknown-op guard was an I() that compiles out under -c opt, after which it emitted the cell's FIRST OPERAND — the ungated clk_ref, gate silently DROPPED. Named fail-closed arms now sit in build_simple_expr, create_registers (which otherwise emitted always @(posedge 'hx)) and cgen_sim::node_expr. Any new op needs its emitter arms in the SAME commit as the Ntype_op slot.
  • A Clock_cell is skipped in the encode fixpoint because it has NO DATA VALUE — and so is a Get_mask/Sext WRAPPER on a gated clock. Measured regression on minion: a typed 1-bit port read wraps the clock, and every such wrapper became “operand has no encodable driver”.
  • The same pin reached through an EDGE and through Node::out_pins() does not compare equal, so a pin-keyed “does this instance drive a clock?” set silently matched nothing — key on the driving NODE instead.
  • Inlining a TRUSTED def to expose its gate is not the answer: it pulls internals the user declared out of scope into the compared cone. Pinned by single_edge_hier_latch_test.sh case 5b — trusting a clock gate may return UNKNOWN, never a REFUTATION. Recognition at the Sub boundary avoids this entirely.
  • Do NOT eager-fold a gate into an enable as the REPRESENTATION. It destroys the shared ICG (power and area at synthesis), changes the netlist ABC sees, invalidates incremental-synth cache regions, and collides with single_edge_scope_test's byte-identical-emission requirement. Represent as a node; lower per consumer. That is also why the cell is a representation to KEEP: gating-coverage metrics, automatic clock-gate insertion (the REVERSE lowering) and power-gating domains all hang off it.
  • memory_clock_shape_ok accepted any Sub on a memory clock_pin — an exemption written for the ABC-mapped clock BUFFER cell that an ICG Sub satisfied by accident, so a gated memory encoded as “commits every step”. All 21 memory clock_pin edges in minion are Sub-driven. Now narrowed to a buffer-shaped def, with a named accept arm for Clock_cell.
  • Gate-of-gate occurs ONLY across Sub boundaries in minion (clock→cgate in vpu_lane, re-gated in txfmafrac_top) — never inside one def — so per-def recognition sees at most one gate level and the canonicalization is pinned by a SYNTHETIC test, off minion's acceptance path.

M10 — hierarchy-aware formal phase scheduler v1 LANDED 2026-07-31

No coloring and no graph rewrite. Starting at the selected top, the formal driver resolves clocks through the actual instance bindings and assigns a semantic phase to every instantiated register/latch and every synchronous memory port. For each endpoint it walks data, enable, reset, address and write-data cones backward across non-opaque hierarchy, stopping at constants, primary inputs, state and opaque boxes. Because nothing is rewritten and no timing state is threaded through ports, the analysis composes across hierarchy. Compile, synthesis, simulation and emitted LGraphs stay on the source representation.

Single-root v1 schedule

  1. close_low — active-LOW clock-role latches close, immediately before rise;
  2. rise — posedge flops, posedge memory ports and data-gated latches update simultaneously;
  3. close_high — active-HIGH clock-role latches close, immediately before fall;
  4. fall — negedge flops and negedge memory ports update simultaneously.

A same-batch state read sees the incoming value; a later batch in the same period sees the earlier committed value. The latch-close microstep and its edge batch share one symbolic input snapshot, while rise and fall get independent snapshots shared between REF and IMPL. LEC observes external outputs after rise and after fall. A close microstep only runs when something happens in it, so a plain posedge/negedge design costs two encodes per period, not four.

Data-role is not clock-role. A data-gated latch has Pyrope's ordinary tick semantics and joins the rise batch; active-low polarity changes its write test, not its phase. Only a latch whose controlling cone resolves to the root clock gets close-before-edge treatment, and its gate is ABSORBED (commit unconditionally in the close microstep, din = the transparent arm) rather than AND-ed into the enable.

The clock forest is built design-wide, TOP-DOWN, before any def is proven — seed from the def's clock ports unioned across every instantiation site, propagate reverse-topo, derive THROUGH a Clock_cell to its reference, close under a single top root, then the narrow implicit-clock rule (a def's clock port joins the unique OTHER root). Resolving each endpoint bottom-up is not enough and all three ways it fails were live on minion; they are written up in pass/lec/README.md §5.

Three traps this cost, all measured. (1) An always-transparent latch is a WIRE. tolg wires no enable when every path writes the reg, and treating that as a flop-with-enable inserts a full period of delay the hardware does not have (cgen already emits it as always_comb with a blocking assign). It must be classified before any clock question is asked — otherwise its constant control cone resolves to a “derived clock” and a combinational buffer gets refused. (2) Clock_cell.invert is the active-low gate FLAVOUR, not an inverted clock. clk & en and clk | ~en transition on exactly the same reference edges — neither output moves while the enable is deasserted — so the consumer's edge is UNCHANGED. What differs is WHEN the enable is latched: pre-rise for the ordinary gate, pre-FALL for the active-low one. Folding it into the parity bit gets both the edge and the sample point wrong at once. (3) A SYNC reset must move inside the commit gate under a schedule. At P=1 one step is one commit so it does not matter; at P=4, applying it on all four microsteps resets a negedge flop three microsteps early, and against a front end that spells the same reset inside din that is a real divergence.

What the schedule is NOT. It does not normalize definitions, synthesize a phase counter, or port-thread timing state through hierarchy — the three things that made M8 stop at a module boundary. That is why hierarchy stopped being the blocker on minion's trust list: it went 32 → 1.

Memories are scheduled per synchronous port — but the Memory IR still carries ONE global posclk, so today a memory is scheduled whole. Per-port polarity (plus the Yosys reader's dropped RD_CLK_POLARITY) is the open half, tracked on 2f-lec along with the cache-key signature, edge-labelled witnesses and multi-root scheduling.

Hierarchy composes through the sequence-transducer box, not through phase-aware state contracts: a proven child's outputs are one shared free symbol per (instance, port, cycle), which has no transition to be phased, so a collapsed child is already schedule-agnostic. See pass/lec/README.md §2 — the earlier plan for per-phase transition and Moore-output contracts was superseded by deleting the state cut.

Scope and failure policy. v1 orders one root clock. An unrelated-root, flop-only design retains the encoder's existing detected-edge path. If a latch, phase-sensitive memory or phase box would require a total order between unrelated roots, formal fails closed with the clocks and endpoint named. Fluid flops, unresolved latch clock/data classification and clock division also remain named refusals.

Traps and ruled-out approaches — do not re-derive

Every entry below is MEASURED. They are kept because each one cost real time and none is visible from the code.

  • posclk on a Latch is the ENABLE POLARITY, not a clock (user ruling 2026-07-20, graph/cell.cpp:266-288). unset/true ⇒ active HIGH, commits on the net's FALL; known-false ⇒ active LOW, commits on its RISE. The name is inherited from Flop and is a poor fit, but find_sink_pin() resolves an unknown pin name to invalid silently, so a rename that missed one consumer would drop the polarity without a word. Pyrope may spell it enable_high.
  • enable_high=false is REFUSED from Pyrope — a bare polarity-pin flip is a measured SILENT MISCOMPILE. tolg lowers if cond { l = d } to BOTH din = cond ? d : q AND enable = cond, so the enable is active-HIGH by construction; flipping only the pin emits if (!cond) q <= (cond ? d : q), so while transparent the latch writes ITSELF forever and never captures d. The polarity still lives on the CELL for the yosys importer, whose raw-D + EN shape has no hold mux and for which the flip IS sound. Two shapes, and any latch consumer must handle both.
  • Do NOT change the Ntype_op encoding. is_loop_break() reads bit 0 of the type word; graph/cell.hpp:113 static_asserts Latch = 45 odd. Flipping it ripples into abc/lec/semdiff/color/isabelle/lean.
  • Any new Query_result/Verify_result field must be added to the fork-race wire codec. lhd lec and lhd formal verify run their ind|bmc portfolio in a FORKED race through a hand-rolled codec; a field missing there is SILENTLY LOST and the parent reports a clean exit-0. This already bit M0 once (fixed for Query_result at query.cpp:347) and is still live for Verify_result — see step 0a.
  • Folding the commit class into the state key is PROVABLY INSUFFICIENT. Implemented and measured pre-M4: the keys really did diverge (k:iclock+ vs k:and(get_mask(…) and gated-vs-ungated still returned PROVEN. Keying only decides which state symbols CORRESPOND; it puts nothing about the clock into the transition function. Necessary for correspondence, never sufficient to refute a clocking difference.
  • The dynamic edge model was REVERTED — do not retry it as-is. Encoding the clock as an ordinary signal with a previous-level bit and gating on a real edge made all three reproducers REFUTE, then broke ~40 existing tests with FALSE REFUTEDs. Root cause: the BMC reset prologue assumes ONE STEP = ONE COMMIT, so a prologue step where the clock does not toggle commits nothing and a SYNC reset never lands. M8 sidesteps this entirely by keeping one free-running clock and a statically scheduled phase counter.
    Two things worth keeping if it is ever retried: the previous-level element must be SHARED by both miter sides, keyed by FRAME (drop a leading r/i from the caller's prefix); and the "~half the cycles at the same formal.bound" cost belongs to this reverted model, not to M8.
  • The state-pairing diagnosis in the old M4 was WRONG. It read "the work is in the state-pairing layer … not in the encoder". Measured cause: a Latch never reaches shared_inputs at all — the seed loop encode.cpp:610-612 and all eight state collections in query.cpp (:2713, 2883, 2924, 3060, 3836, 3914, 5543, 5642) are != Ntype_op::Flop → continue, so encode.cpp:605-607 mints a per-side free constant. That is the q(ref=254 impl=255) step-1 CEX. The tier-2 confirm step (query.cpp:1801-1818) runs only after a paired solve already refuted and can never break a working pairing. M8 sidestepped it; M10 FIXED it — under a phase schedule a Latch is collected into flops and pairs like any other state element.
  • NEW (M8) — a CLOCK-gated latch's gate must be ABSORBED by the slot, never AND-ed with it. After normalization ONE CLOCK TICK IS ONE SUB-STEP, so any combinational cone that reads the clock as data — which is exactly what a latch gate is — gets evaluated P times per source period. The enable becomes clk & (phase == slot) and only commits when the free clock input happens to be high at the slot step. Measured with iverilog: the latch outputs stay x forever. The fix is that the enable becomes the slot predicate ALONE and din becomes the TRANSPARENT arm of tolg's hold mux. A DATA gate must be left completely alone — collapsing the two cases is what blinds the transparent-low polarity canary.
  • NEW (M8) — rule 4 must key on the COMMIT CLASS, not the slot. Two elements can share a slot without sharing an edge: a data-gated latch defaults to slot 0 alongside the posedge flops, and that pairing IS the ordinary flop-with-enable abstraction the task is scoped to. Keyed on the slot, rule 4 immediately rejected latch_mixed_flop, a live fixture.
  • NEW (M8) — the period boundary is phase == 0, not phase == P-1. A step READS state and COMMITS at its end, so the state visible at the phase-k step is what committed through slot k−1. The period is fully settled at the phase-0 step that STARTS the next period. Off by one sub-step, the guard checks mid-period and an equivalent design refutes.
  • NEW (M8) — a SYNC reset must move INSIDE the slot gate, and its initial pin must go with it. The encoder nests reset outside the commit for every flop (async for all), which is harmless only while one step is one commit. Folding it into the data path needs THREE things together: din := rst ? initial : din, enable |= rst (reset still wins over the enable, as Verilog says), and drop initial — keeping it leaves a concrete power-on value the other miter side does not have, the state pairing reports "kind/init mismatch", and the unpaired reset-less flop gets a FREE per-side constant, i.e. the q(ref=254 impl=255) step-1 CEX all over again.
  • NEW (M8) — the trigger must SKIP what the pass does not OWE. The plan's trigger includes "≥2 clock input nets", and refusing on it immediately degraded lec_clock_blindness_test's CORRECT two-clock-vs-one-clock REFUTED into an unsupported exit. The pass owes a lowering only for what the engines get WRONG (a Latch the encoder refuses; a negedge edge it is blind to). A second clock domain that ALSO holds a latch cannot be skipped and must fail closed by name.
  • NEW (M8) — the yosys reader's register NAMES are not stable across two variants of the same design ($procdff$32 vs $procdff$34, n12 vs n13). Any LEC fixture that needs state CORRESPONDENCE has to come from Pyrope, or every verdict is a per-side free-constant CEX that looks like a real inequivalence. This is what made the first cut of the four-class fixture unusable.
  • NEW (M8) — a computed single-fanout flop enable was emitted UNDECLARED by cgen_verilog (get_wire_or_const ignores pin2expr). The same bug M1 fixed for the latch's din/enable and for clock_pin, previously unreachable because every emitter gave a flop enable fanout ≥2. iverilog refuses to elaborate it; yosys silently invents an implicit wire reading X, which is worse. Any pass that synthesizes a control pin with exactly one consumer will hit this class again.
  • NEW (M8) — lhd sim cannot take a yosys-read design with a Pyrope test block ("cannot mix pyrope and verilog sources"; via lg: the test block cannot resolve the module name). So the sim oracle is scoped to tolg-emittable shapes, and any cgen_sim fix for a yosys-only cell shape (an active-low $dlatch) is unreachable-today code — the same status as M7's importer guards.

M8 — edge normalization LANDED; NO LONGER ON THE FORMAL PATH

One conditional LGraph→LGraph pass — pass.single_edge, pass/single_edge/ — that removes latches and negedge state before the solver sees them, by retyping every state element to a posedge Flop carrying a synthesized phase counter plus per-flop slot enables. Commit-class→slot is a table, not an analysis: it is the output of M3's commit_class_of().

Trigger. Any Latch cell, or any Flop with posclk known-false. None present ⇒ the pass is SKIPPED entirely, not run-as-a-no-op — so a plain posedge single-clock design never enters the code path, is never re-emitted, and cannot change verdict. That is the whole blast-radius argument.

Scope, settled by the user 2026-07-24: verification and simulation only, never on the synthesis path (slot enables and a divider cost QoR) — but it must stand as a genuinely semantics-preserving transformation, not a formal-only hack. It is validated against an INDEPENDENT oracle: single_edge_four_classes_test.sh runs the SOURCE netlist (real always_latch, real negedge) and the NORMALIZED one side by side under Icarus Verilog, the normalized side clocked P times per source period and sampled per the observation-visibility rule; they agree over 39 periods, and two negative controls prove the harness discriminates.

M10 superseded it inside formal. LEC and verify no longer REQUIRE the pass: a decline hands the design to the phase schedule instead of ending the run. It is still preferred where it applies, because it normalizes a SYNC reset into the enable/din shape on BOTH sides, which is what lets semdiff pair flop_reset_matrix's flops. It also declines by name (clock-cell-unsupported) on a Clock_cell in the control cone. It remains a landed standalone transformation and the independent Icarus oracle.

What it never grew, and now will not need to: P>2, a port-threaded phase counter across a module boundary (a stateful Sub fails closed), known-integer-ratio multi-clock slotting, and witness-index decimation back into source periods (it ships an honest SKIP). Those are exactly the walls the read-only schedule was built to avoid.

  • M3 — shared commit-class classifier + contract check (graph/latch_contract.{hpp,cpp}). commit_class_of() resolves an enable/clock cone back to a ROOT NET plus a parity, walking the shapes tolg emits for a boolean control (Mux(s,0,1), EQ(x,0)/EQ(x,1), Not, Get_mask/Sext) — which is what makes if clk and if !clk land on the same net at opposite parity, so a master/slave pair is recognizable. check() enforces rules A (self-gated enable), B (Q→own D) and C (simultaneously-transparent pair).   • M4 — the first two clock-blindness holes (d572ad005): the inline ICG cone folded to “commit iff the enables are true”, and ≥2 clock INPUT nets given per-net detected edges with the previous level SHARED per FRAME. Both survive as the unrelated-root fallback. The third hole (negedge vs posedge on ONE clock) was closed by M8, not by teaching the encoder about edges — provably impossible at step granularity — and properly by M10.
  • M5 — simulation (4af917e6e, hardened by 17b29f574). All 5 trackers green in inou/prp/tests/sim/. Latches needed no scheduler machinery — a Latch joins the flops vector and the ordinary flop update is transparency observed at end-of-tick. The two-phase tick commits posedge state at the rise, then drops the pin2var bindings reachable from a posedge Q and re-emits that cone so negedge state observes post-rise values. A Sub in that cone is REFUSED (re-running it would double-advance the child).
  • M6 — multiple clocks (design side). A flop whose clock_pin resolves to a graph input that is NOT the reference clock commits on a DETECTED EDGE of its own net, one shared previous-level bit per net. Coincident edges come out right by construction — every secondary commit reads PRE-TICK state, pinned by sim/multiclock_two_domain.prp (qb == 28, not 45).

Dual-fixture conventions (every sim+BMC twin follows these; they exist because of verified harness traps, not style):

  • State the property TWICE: design-body asserts for lhd formal verify, test-block asserts for lhd sim — the two planes cannot see each other today.
  • assert(guard implies p), never if guard { assert(p) } — the formal obligation DROPS the if-guard and refutes spuriously at cycle 0.
  • Snapshot every reg before any write (const c = cyc) — a reg read after a write sees the written next-state.
  • Closed tb: ZERO data inputs; all stimulus is a pure function of an explicitly-initialized cycle counter. A cyclic schedule lets obligations prove INDUCTIVELY, not just to the bound.
  • Validate every assert schedule against iverilog on the golden BEFORE baking it.
  • REFUTED cycle numbers include the 2-cycle reset prologue: design-cycle k reports “REFUTED at cycle k+2”.

The one fixture worth reading before writing a similar one: inou/prp/tests/verify/latch_negedge_enable.prp, a transparent latch QUALIFYING a negedge flop's enable — the register-file write-strobe shape, and the one design where the latch and the negedge interact. The latch there is gated by the CLOCK, not by data, deliberately: a negedge flop samples its enable AT THE FALL, and a DATA-gated latch is generally still OPEN then, so the flop would sample the latch READING THROUGH — an observation the visibility rule forbids and a point where the commit-at-closing-edge model and real hardware genuinely disagree. A transparent-LOW latch is closed for the whole high half, so the fall lies inside its opaque window. Its sim twin gets away with a data gate only because it samples q at end-of-tick and never through the enable.
