Algorithm and defaults

CLI defaults are pass.color.synth_alg=cones, pass.color.ctrl_cones=true, pass.color.forward=all, pass.color.max_gate=30000, pass.color.stop_mux=true and pass.color.stop_arith=true. The benchmark profiles explicitly record these settings, with stop_mux=false for Sky130.

Mux/select and register/memory-enable cones share control colors whenever they overlap; overlapping data cones merge separately. Shared zero-cost wiring and primary-input pins count as overlap without acquiring an artificial cost. Distinct primary-input pins do not alias merely because they share the builtin input node. Input sharing remains node/pin-granular, like the coloring model. Control and data use separate ownership maps.

Shared control nodes have one owner, eliminating copies between control families. Overlap merges prioritize shared logic before zero-cost contacts. Primary-input contacts retain a star and a chain, allowing later groups to pack after the first reaches its budget without a quadratic fanout clique. Oversized control components split into budgeted colors; data walks and register attachment check size before adding nodes. An indivisible operation can exceed the soft estimate alone; an explicit tighter control cap rejects such a node.

The mux boundary switch controls ownership: enabled puts muxes in control groups; disabled places muxes in data groups while select/enable logic stays separate. Internal constant masks and shifts that start and end within a mux group remain visible to ABC. External variable data arms remain outside that control group. Large adders, multipliers and dividers retain boundaries in all benchmark runs; the independent arithmetic switch is tested.
