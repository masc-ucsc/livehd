2a-treeaeg The aegraph rules on LNAST (a upass step), then retire classic cprop

Plan, 2026-11-14. Two parts, in this order (decided with the owner): (A) a fast tree version of pass.aegraph that runs as a upass step, so the algebra simplifies before upass.tolg builds the LGraph and less reaches lnast2lg and the graph engine; (B) delete the classic cprop engine, now that aegraph is the default.

A. Tree aegraph (upass step)

Design

  • One rule source. The rules (pass/aegraph/rules/*.rules and the hand-written AEG_NATIVE_RULEs) are written against rt::Ctx, which reads the Egraph and builds through the virtual rt::Builder. The tree step builds a small e-graph per straight-line LNAST block (one member per class, no saturation) and runs the same generated rule code; no second rulegen backend, and the rule fuzz/prove tests cover both IRs.
  • Shared core. pass/aegraph/rewriter.hpp: Rewriter (fold, hash-cons, rule application; LGraph-free). The LGraph Engine derives from it; the tree front end will too.
  • Op mapping (the one upass/tolg lowers with): plus → Sum bank a, minus → Sum banks a/b, mult, div, bit_and|log_and → And, bit_or|log_or → Or, bit_xor, eq, lt, gt, shl, sra, ne|le|ge → negated EQ|GT|LT, get_mask, set_mask, sext. Only an untyped bit_not is Not (−x−1); a typed bit_not(dst,x,N) is (2^N−1)−x and stays an opaque leaf.
  • Rule subsets. Pre-bitwidth: simplify rules with no analysis guard (35) or only structural facts (bool01, zero, nonzero, known_zero, distinct: 7). Post-bitwidth: the range-guarded simplify rules (11: div_pow2, rem_pow2, div_shl_pow2, getmask_above, concat_single_fits, concat_zero_top, lt/gt_always/never, sext_fits), reading the ranges upass bitwidth already stamped on the operands. alt/choice rules (17) need extraction with a cost model and stay graph-only: that is what makes the tree step fast.
  • Invariant #6 (upass/README: only bitwidth derives ranges, nothing folds on them): the post-bitwidth subset needs it amended. The owner approved running a range subset; it ships behind its own upass label and the README changes in the same commit.

Constraints found in upass (survey 2026-11-14)

  • A uPass push hook only votes keep/drop and writes the symbol table; the runner copies the SOURCE node (emit_op_with_fold). A rewrite must be a runner pre-dispatch step, like dispatch_bit_not (scratch tree, push_source, re-dispatch to every pass).
  • No def table: the step keeps its own name → {op, operands, generation} map, filled per statement, cleared per iteration. Look through tmps (%-prefixed, Lnast::is_tmp), constants and inputs only; a user mut rewritten since, or a write in an uncertain arm, invalidates the entry.
  • Limit rewrites to tmp destinations (scratch nodes skip stream-SSA LHS versioning). delay_assign is a barrier; single sweep, no fixed point; regs/wires/io outputs stay.

Steps

  1. Rewriter split (in review): move make/rewrite/check_pair and the rule state out of the LGraph engine; behavior unchanged, full regression green.
  2. Tree front end: block → e-graph import (operand classes from the def map; leaves for everything else), the pre-bitwidth subset, write-back of a changed statement as a scratch node through the runner seam. Unit tests on hand-built LNAST; Pyrope fixtures that show the rewrite (e.g. ~~x, x*8, x&~x) and LEC against the plain compile.
  3. upass label (upass.aeg), order entry after constprop; measure lnast2lg node counts and compile time on the prp corpus.
  4. Post-bitwidth range subset behind its own label; README invariant #6 amended.

B. Retire classic cprop

  • aegraph still calls cprop's do_scalar (scalar rewrites on combinational SCCs), do_post (region passes) and the cprop_value facts bitwidth reads. Those move under pass/aegraph; what goes: do_trans/cse_pass, pass.cprop, the classic and aegraph+classic engines, compile.cprop.engine, engine_slots, formal.lec.preflight_engine (owner: remove the knobs; a --set of one is a usage error), the parity smoke and the engine sweep script.
  • The preflight refusal (a new cell aegraph cannot stamp) no longer hands the graph to classic: aegraph gets a small fast node removal (delete a node and its dead fanin chain).
