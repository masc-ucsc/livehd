2w-warpspace Density warp for FP centroids and macro anchors

Use the demonstrated density deformation to guide memories toward space that should contract or expand. During fp_plan, shift centroid targets before alignment snapping. During macro_plan, periodically refresh a virtual pull edge per movable memory; the placement optimizer performs the movement.

Placement integration implemented; full-flow trials stopped for fixed-macro isolation The standalone C++ tool and its 32-bin smoothing default are implemented. The shared in-memory engine and both opt-in placement hooks are implemented. The checks and evaluation status below distinguish implementation from measured QoR.

Depends on

  • The existing native FP → macro → final-cell placement pipeline, described in native placement, supplies geometry, centroid membership, hierarchy and stage handoff.
  • Reuse the placement-color membership and hierarchy accounting when placement colors are selected. Synthesis-color and hierarchy-only FP must also remain supported.

Implementation and verification (2026-10-21)

The final-legalizer setup was reviewed and committed before pulling upstream (47ca568d5 after rebase). Both LiveHD and DREAMPlace were updated; LiveHD now pins published DREAMPlace 121fea0, which includes atomic virtual pulls, density-gated anchor freezing and settling, and the review fix preventing wire-only rollback from discarding macro guidance. Anchors remain local to the macro solve and are not stored in GP continuation state.

pass/place/density_warp.cpp factors the prototype’s fixed-grid, union reservation, smoothing, alternating sparse LP, no-fold validation and conservative transport into one in-memory engine. The standalone density-grid mode consumes the same implementation and its smoke suite passes.

Both independent CLI controls default to false. FP shifts a saved centroid-target snapshot before the existing snap; macro GP refreshes absolute optimizer-only pulls without timing callbacks or physical connectivity changes. Policy, report files and units are described in the placement README.

Focused tests pass for uniform and empty demand, reflected/oversized filters, macro-union reservation, rigid anchor sizes, unique ownership, uneven hierarchy averaging, independent warmup/cadence, endpoint replacement, fixed macros, failed-field clearing and all four placement option combinations. The native hook also tests actual attraction in opposite directions and atomic invalid-input rejection. The full debug build passes (3,940 targets); the latest focused tests also pass. Controlled results and remaining acceptance limits are recorded below.

Iteration exposed a DBU/micron objective-scaling mismatch and excessive LP dual values. The adapter now solves in microns and converts sampled vectors back to DBU. A common power-of-two scaling bounds LP objective magnitudes without changing relative penalties or relaxing feasibility tolerances; failed IPM solves can retry simplex within the remaining axis budget. Regression tests check unit equivalence and that objective scaling is actually applied.

CNN’s completed matched profiles are all legal and pass independent row, site, orientation, padding, fractional area/cap and macro-handoff audits. Subtasks — specification and acceptance checklist

  • B — Extract an in-memory density-warp engine.
    • Factor the demonstrated bin-mass and macro-anchor path out of tools/warpspace.cpp into a reusable C++ library. Feed it current physical coordinates, cell areas, die bounds, macro centers and oriented sizes; return displacement vectors and diagnostics. Reuse fixed-grid and sparse solver structure where possible, and measure the total cost of repeated refreshes. No DEF/LEF round trip, subprocess, OpenROAD or PNG generation in the placement loop.
    • Keep the tool as a consumer of the same engine. Preserve its reference behavior: 32-bin smoothing, half original/half smoothed free-area density, reserved macro union area, smooth deformation and fixed die boundary.
    • Use actual standard-cell area overlap on bins; memory bodies consume capacity, not cell demand. Do not count virtual centroid circles, reserved color allowances or virtual anchor edges as extra physical occupied area.
    • Keep macro width/height unchanged in the returned anchor records. The transported occupied-area field is an approximation; it does not guarantee that rigid anchor boxes are legal or match that field.
  • C — Independent opt-in stage controls.
    • Add synth.place.fp.warpspace=false and synth.place.macro.warpspace=false to the CLI registry, option validation, stage configuration, reports and cache keys. These are the canonical existing-prefix spellings of the requested fp_plan.warpspace and macro_plan.warpspace controls; do not introduce undocumented aliases.
    • Allow FP only, macro only, both, and neither. Disabled stages do no warp work and retain current placement behavior and defaults. The standalone tool's approved 32-bin filter default remains independent of these opt-in controls.
    • Define and document stage-local edge weight, refresh budget and warmup controls during implementation. Keep new values explicit and bounded; do not change existing centroid, timing, density or snap defaults as a side effect.
  • D — Shift FP centroids before snapping.
    • After the FP placement has produced the current density and centroids, but before alignment/symmetry snapping, compute a warp displacement for every movable memory. Use the FP stage's provisional member positions for these samples; this does not assume that a final macro placement already exists. This is a field sample, not a physical macro placement update.
    • For each leaf centroid, average the displacement vectors of its distinct owned movable memories and add that vector to its unsnapped centroid target. Resolve nested memberships to a unique owning leaf using the existing instance-aware ownership policy. Retain vector magnitude; do not average unit directions. A centroid with no movable memories receives zero shift.
    • Propagate the average of the contributing leaf-centroid movements to each hierarchy node before snapping. Carry sums and contributing counts so unequal subtree sizes do not turn an average of leaf movements into an unweighted average of child averages. Do not count the same leaf or memory again through nested hierarchy membership.
    • Apply each target shift once, using a snapshot of the original targets; never move descendants a second time by adding an ancestor shift. Recompute hierarchy target geometry consistently, then run the existing hierarchy-local snap and freeze those snapped targets for macro placement.
    • Preserve macro/cell coordinates and centroid membership at this handoff. With FP snapping disabled, pass the shifted unsnapped targets to macro placement.
  • E — Refresh virtual macro pull edges during optimization.
    • After a warmup period of macro GP iterations, compute the warp from the current cell density and current macro geometry. For each movable memory at p, set an absolute virtual endpoint a = p + Δwarp(p).
    • Add one optimizer-only pull edge from the memory center to that endpoint. Do not assign the endpoint directly to the memory coordinate, create a physical cell/net/pin, alter STA connectivity, or change macro size/orientation. Existing centroid attraction and the new per-memory attraction remain separate terms.
    • Hold endpoints fixed between refreshes. On refresh replace the existing endpoint, computed from current placement; do not append another edge or add the new vector to the previous endpoint. Exclude fixed/locked macros from pull edges while retaining their occupied space in density calculations.
    • Refresh several times, aiming for 5–30 updates on a sufficiently long run with memories. Candidate bring-up policy: a 10% iteration-budget warmup followed by about 10 evenly spaced refresh opportunities. Tune against runtime and oscillation; this is a proposed schedule, not an implemented default.
    • Reuse safe GP checkpoint boundaries. Every other timing checkpoint is a possible cadence, but warp updates must also work when timing feedback is off; provide independent iteration scheduling and avoid running STA solely for a warp. Avoid duplicate refreshes if iteration and timing events coincide.
    • Report actual refresh count and early termination. Short runs may finish before five opportunities; do not prolong convergence merely to hit a quota. Skip all work for designs without movable memories.
    • Feed pulls through the existing optimizer's supported anchor mechanism; reset affected optimizer state if required by an objective change. Preserve ordinary macro snapping/legalization, fixed IOs, and the final locked-macro handoff. Remove warp edges before final cell placement.
  • F — State, diagnostics and bounded failure handling.
    • Include warp policy and algorithm version in affected stage reuse keys. Invalidate membership/geometry-dependent state after resize, buffering, graph rebuilds or changes in macro identities; never reuse stale per-memory indices.
    • Use deterministic ordering, bounded solver iterations/time, and explicit status. An infeasible or nonfinite field must not apply a partial update; retain the last valid targets only while identities and geometry remain compatible, otherwise clear the affected virtual pulls and report the reason.
    • Export FP targets before warp, after warp and after snap; per-memory samples; hierarchy sums/counts; and the frozen handoff. Export macro refresh iteration, endpoints, displacement, edge weight, solve status/time and count.
    • Keep density scales comparable within each before/after plot. Report peak, p99 and overflow on the original evaluation grid, mass/occupied-area conservation, mean and maximum movement, mean vector, HPWL, timing, legality and total runtime. Distinguish anchor predictions from actual optimizer movement.
  • G — Focused checks and controlled evaluation.
    • Use small generated in-repository fixtures: uniform free-area density gives zero field, boundary/oversized filters preserve the average, and macro overlap reserves its union once. Retain no-fold and conservation checks.
    • Test exact vector averaging for multiple memories, zero-memory/fixed-only centroids, uneven hierarchy subtrees and overlapping membership. Check ordering before snap, no direct macro movement in FP, and the snap-disabled handoff.
    • Test macro warmup, independent no-timing refreshes, bounded counts, endpoint replacement, no accumulation, fixed macros, early stop, objective-state reset and edge cleanup before final placement. Verify unchanged physical connectivity.
    • Exercise all four option combinations and unchanged off/off behavior. Keep each focused optimized test below 20 seconds and benchmark runs separate.
    • Compare the five placement regularity examples, CNN, and real/synthetic Eyeriss against identical input snapshots and frozen binaries. Include uniform, off-center and corner-heavy demand, not only cases where the desired direction is toward the die edge. Run synthesis serially with whole-process-tree memory monitoring.
    • Use source changes in ../DREAMPlace/dreamplace/native/ if its optimizer needs a new hook. Consume a published dependency commit before merging; never commit a sibling-path override or patch a fetched copy of an owned repo.

Design notes

Accepted density model

D[b] = standard-cell area overlapping bin b
O[b] = union area of physical macro bodies overlapping bin b
F[b] = bin_area - O[b]
B    = 32 × 32 box filter (global average when it spans the block)
smooth_rho[b] = B(D)[b] / B(F)[b]
rho_target[b] = 0.5 * D[b]/F[b] + 0.5 * smooth_rho[b]
requested_free_area[b] = D[b] / rho_target[b]
normalize requested free areas to sum(F); add O per bin
solve the smooth no-fold mesh warp; sample Δwarp at each memory center

Use the prototype's regularization and empty-bin conventions. This is a soft area target, not an exact density cap after resampling. The 32-bin filter width is distinct from grid resolution; the comparison runs used 32×32 bins, so their smoothed density is block-wide. The die boundary stays fixed, physical cell mass and reserved occupied area are conserved, and macro shapes are metadata for anchor suggestions rather than deformable physical cells.

FP handoff

snapshot = current FP density, physical macros, leaf/hierarchy centroids
field = warp(snapshot)
for each leaf centroid c:
    memories = unique owned movable memories(c)
    shift[c] = mean(field.delta[m] for m in memories), or zero
for each hierarchy node h, bottom-up:
    shift[h] = sum(shift[c] for contributing descendant leaves c) / count(c)
shift each unsnapped centroid target once using the saved original target
snap hierarchy/centroid targets using the existing snap policy
freeze targets and hand them to macro_plan

The hierarchy reduction averages centroid movements, rather than pooling all memories under the parent. A leaf with ten memories does not get ten times the parent weight of a leaf with one memory. Only contributing leaves enter the parent count; a branch with no movable memories does not dilute the average.

Macro optimization

run macro GP warmup with existing objectives
at each scheduled refresh, up to the configured budget:
    field = warp(current placement density and macro geometry)
    for each movable memory m:
        anchor[m] = current_center[m] + field.delta[m]
    replace virtual pull edges atomically; resume GP
between refreshes:
    optimize existing objectives + sum_m weight[m] * pull(center[m], anchor[m])
perform the existing macro snap/legalization and lock macros
clear virtual warp edges before final cell placement

The exact pull penalty should reuse a supported optimizer anchor term, with its weight reported separately. A refresh changes the objective endpoints, not placement coordinates. Benchmark pull strength, warmup and cadence for oscillation, wirelength and timing before proposing any enabled-by-default placement policy.
