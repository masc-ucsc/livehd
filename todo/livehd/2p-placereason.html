2p-placereason Interactive placement reasoning and portable intent

Let a human or agent explore placement through the live GUI socket, with fast RC/timing feedback, explicit control of expensive repair, bounded local movement, and several candidate checks running side by side under a host limit. Preserve useful relationships beside RTL so they can be resolved again after a floorplan change. The actual goal is to fit the constrained floorplan and achieve good timing after routing. Because routed timing is expensive, LiveHD exposes cheaper measurements with their limitations; the external agent chooses proxies, search strategy and when to route. Implementing that agent is outside this task.

Implementation plan — not implemented. Written 2026-11-13, revised 2026-11-13. The revision follows a reading of two papers (arXiv:2609.21263v2 and arXiv:2611.12048v2), of the first one's code, of the PDAGENT-BENCH repository and of the GUI session code, and the rulings below. It adds explorations, scratch copies of the main line used for feedback and then discarded, in the foreground or as parallel workers (H, design); deterministic checkers and a leverage test (I); a table of code facts with their source lines; and a delivery order. All new commands, policy fields, options and UI controls are proposals. This task changes no existing defaults. Initial scope is macro placement and the surrounding cell placement; source attributes and memory-bounded execution follow after the basic experiment loop works.

Depends on

  • 2i-interact — reuse the live session, agent socket, shared selection, phase gates, replay and region edit path; this task adds exploration policy, explorations and persistent intent.
  • core/job_manager.hpp and pass/lec/fork_race.hpp — the admission control (lhd.jobs, host load, memory) and the forked-worker discipline (process groups, parent watch, wall deadline) that formal and synthesis already use. Explore jobs are a new job class on the same manager, not a second scheduler.
  • json-metadata and the existing placement hints — extend the class-tagged bundle and scope binding instead of introducing another constraint-file format.
  • 3g-partitions — reuse Region_mesh and legality capacity accounting for local active sets. A synthesis color, geometric region and memory chunk are distinct selectors.
  • 2is-incsynth and 2t-timeclosure — gate every resynthesis, sizing and buffering entry point; reuse their acceptance and proof checks.
  • 2q-fasttimer — coordinate incremental RC/timing and boundary timing contracts. Its single-threaded engine (ruling R11) fits the separate snapshot owner in H0; a single-threaded timer alone does not make a threaded GUI process safe to fork. Threaded timer/placer configurations use spawned replay workers unless the snapshot architecture supports them safely. Label cost and coverage honestly.
  • 2f-scalability — required for later execution with bounded resident memory. Freezing most cells in an existing flat design does not by itself provide chunked memory usage.

Rulings (2026-11-13)

#Ruling
P1The number of parallel exploration workers is a configuration option. Workers compete for lhd.jobs slots with the other jobs of the session; they have no pool of their own.
P2An exploration is available even when no slot is free: “I am going to try something here; do not remember it.” An exploration never changes main. To use its findings, the agent reads or exports them, returns to main and issues ordinary macro moves, coordinates or relative commands itself. Main is the real plan and measures its own resulting state. There is no attach, process promotion or automatic segment merge.
P3An exploration reports WNS and TNS, and whatever else the page can show for the main line: routing congestion, density, regions, critical cells, the placement itself.
P4Three numbers lead every summary, for main and for each exploration: timing (WNS, with TNS), routing density, and one composite quality score. The score is agent-configured feedback, not an acceptance rule. Non-rectangular placement areas are in scope.
P5The agent explores and edits main on its own; no person has to confirm. The way in is a coding agent (claude, codex) opened in the repository and given the agent socket path that lhd synth --gui prints. Changes that should outlast the session are edits the agent makes to files of the repository.
P6An exploration lives where the agent socket lives: on the session's host, in the session's temporary directory. It has no long-term side effect; once closed, it is gone.
P7PlaceReasoner-Bench (published through PDAGENT-BENCH) is the bring-up and benchmark set. Edits go through the local socket; a tool imports a task and exports a result in the benchmark's own formats.
P8Nangate45 and the benchmark's DEFs are supported inputs. Where one of them fails to read or place, that is a LiveHD defect to fix, not a limit of the benchmark work.
P9The GUI/socket controller is a separate process from main's evaluator and exploration workers, remaining responsive during computation. Snapshots come from an isolated single-threaded state owner, not from the threaded GUI process.
P10LiveHD follows commands and reports numbers. The external agent owns long-term strategy, candidate selection, timing tradeoffs and proxy choice. Worse TNS, low macro leverage or similarity to a prior candidate does not cause LiveHD to reject a requested exploration or edit.
P11Illegal intermediate geometry is allowed, with a prominent ILLEGAL GEOMETRY warning in the GUI and structured violations in socket responses. An explicit Legalize button/command uses the existing macro/cell legalizer, halos, density and other constraints, including its failure semantics.
P12An illegally placed macro cannot acquire a new GUI pin. Existing pin intent and anchors are preserved: a move that makes a pinned macro illegal is allowed and temporarily suspends its effective pin, with a warning; clearing the conflict automatically restores the pin. Moving another macro around must not erase pins or change their anchors. Authored FIXED constraints remain distinct.
P13Excluded floorplan areas prohibit both placement and routing. The placer, legalizer, estimators and GUI use the same exclusion geometry.
P14Coordinates preserve the precision required by the design's DEF database units. Relative moves, alignment and edge/gap relationships let LiveHD resolve macro sizes and coordinate arithmetic.

Delivery order

  1. Separate control and evaluation (H0). Establish the responsive controller, evaluator protocol and single-threaded snapshot owner. Verify the process/thread lifecycle before measuring snapshot latency and memory. Use spawned replay for configurations that cannot meet the snapshot preconditions.
  2. Foreground explorations (H7), the agent's way in (H9) and the fast check. Begin, inspect, export, discard, the banner and private segment trace; hello and explicit main edits. With it: policy gates (A, B), geometry warnings, pin suspension/restoration and explicit legalization (I), the first acceptance milestones, and one small benchmark task imported as the bring-up design (J).
  3. Parallel explorations. Job table, limits, workers, result documents and protocol (H1–H5, H8) with the geometry and frozen-timing tiers, plus the ledger (E). This is the point where an agent that connects can fan out.
  4. Checkers and pictures (I). Cheap findings and pictures that help the external agent decide what to evaluate; LiveHD does not select candidates.
  5. Local exploration (C), intent (D), source binding (F).
  6. Validation (G) runs with every step; the 16 benchmark tasks scored under the benchmark's own downstream flow (J) come last.

    • Geometry checks as pure functions of a published frame plus a proposed patch: core bounds, overlap, halo and minimum channel, narrow channels and dead pockets, standard-cell area continuity, periphery, pin side facing its logic, cluster locality, pin-access demand. Each returns the objects and the cause, not a pass/fail bit. Reuse the rules behind macro_edge, macro_dead_space, macro_tracks and the RUDY map where they fit; do not write a second definition of legal.
    • An explicit Legalize button and socket command reuse the existing macro/cell legalizer and its halo, density, channel and other constraints. Report every displacement and the existing placement-failure conditions; do not silently legalize a move. Geometry checks report illegal intermediate states prominently without rejecting those moves or deciding whether an agent may evaluate them.
    • Keep GUI pin intent separate from effective enforcement. Reject a new pin on an illegal macro; suspend an existing pin only while its macro has a reported geometry conflict, preserving its identity and anchor. Clear that suspension automatically when the conflict clears. A transient drag through other macros cannot erase their pins, rewrite their anchors or leave them unpinned afterward. Show suspension/restoration and causes in the GUI and socket. An explicit move of the pinned macro itself updates its requested anchor as an ordinary move would; movement of another object does not. Legalization respects active pins and authored FIXED constraints, using its existing failure reporting when constraints cannot be met.
    • Non-rectangular areas (ruling P4). The placer already excludes rows and sites through hard __lhd_frame_mask_* instances, but the scene has one die box, the area command moves the edges of a rectangle, and frame masks are not routing obstacles, so the congestion maps treat a missing corner as routable. For this task, publish one usable outline (core minus the declared excluded areas) as a rectilinear polygon with exact macro sizes and pin positions. Placement and routing both exclude those areas (P13): check proposals against them, draw them, and remove routing capacity there in every estimator. This is an explicit extension of today's frame-mask behavior. Compute utilization, periphery and “distance to edge” against the polygon, whose concave corners are not edges a macro can hide behind. An L-shaped region must not look like free space. (In the second paper 9 of 12 runs of agents that could not read the geometry delivered macros outside the die or overlapping.)
    • A leverage query: the share of failing endpoints and of TNS whose worst path has a macro pin on it or crosses a macro channel, reported with the per-family timing of H8 (register to memory and memory to register are the families a macro move reaches directly). Report the evidence; stopping or continuing exploration is the external agent's decision.
    • Strips: standard-cell area enclosed between long macro edges, with its entrances. Both papers find the congestion there, at equal global utilization.
    • Macro orientation in the vocabulary: move carries positions only today. Add an orientation to the patch, the pin-side distribution of each macro to describe, and a pin-side layer to the rasterizer so every job result has a picture a vision model can read.
    • A structural signature per candidate (side, order within its group, orientation class, quantized position) to report similarity to prior candidates. Similarity does not refuse a requested job.
    • An agent guide: one page with the loop, the tiers, the limits and the command reference, the equivalent of the first paper's skill pack. cmd=help stays the source of truth for the vocabulary.
  • G — Validate correctness, speed and transfer.
    • Add focused regressions for policy enforcement at every mutation site, deferred triggers, stale commands, atomic batches, cancellation, baseline restoration, replay and cache separation.
    • Explorations: main's deterministic design state and action trace are unchanged by scratch work; a discarded foreground exploration leaves main's next frame equal to one that never began it. Main changes only through ordinary commands from the agent/user and produces independent measurements. Test target isolation and stale expected-revision refusal. The number of running workers never exceeds the limit under an injected load and memory probe; a killed controller leaves no worker; failed workers publish no successful partial result. Verify supervisor cleanup and stale-session cleanup after a whole-session crash.
    • Illegal geometry: a conflicting move succeeds with the prominent warning; pinning an illegal macro fails; existing pin intent suspends and restores when the cause moves away. Drag a macro across several pinned macros and back: their anchors and final pin states must be unchanged. Exercise explicit legalization success/failure with halos, density, active pins and FIXED constraints, plus an excluded L-shaped corner in placement and every routing estimator. Exercise DEF-precision export and relative edge/gap commands.
    • Check that frozen-netlist evaluation changes neither connectivity nor masters; check frozen exterior geometry and inventory before/after local movement, legalization and allowed repair. Preserve immutable contract tests.
    • Compare local RC/timing with a full evaluation of the same candidate, including cross-boundary fanout, reconvergent paths, multiple clocks, exceptions and changed external loads. Report coverage and error.
    • Test hint transfer across translated cores, aspect/size changes, macro-size changes, repeated hierarchy and split/deleted memories. Include infeasible arrangements and explicit relaxation reports.
    • Measure interaction latency, placement iterations, RC/STA/repair time, touched cells/nets, peak memory, legality, hint residuals, WNS/TNS, routed quality and total search cost. Run multiple seeds and held-out floorplans.
    • Use declared repository fixtures/dependencies for tests; no runtime dependency on sibling benchmark repos. PlaceReasoner-Bench (8 designs at 1:1 and 2:1) is an external bring-up and comparison set driven by J and kept under ignored repros/, not a Bazel test. Run backend regression for placement-only work and all-group regression for synthesis/repair changes. Keep normal Bazel scheduling and coverage; an exploration budget is not a regression timeout or reason to skip tests.

Existing foundation and gaps (source inspection, 2026-11-13)

Existing facilityReuse and limitation
tools/lhd_gui.py and agent dispatchThe Unix socket shares selection, highlights, state and page commands with the browser. Extend this interface; do not build a separate agent placer.
Finding the sessionlhd synth --gui prints the socket path and writes it to <workdir>/synth/place/gui_agent.json; tools/lhd_gui.py takes --socket, LHD_GUI_SOCKET or --workdir. help lists the commands but nothing tells an agent which design, files or repository the session belongs to.
Server threads (gui_server.cpp:350) One detached thread per connection, so several agents can already talk at once. The transport is not the bottleneck.
Flow thread as the only evaluator (gui_agent.cpp:225, gui_session.hpp:109) critical, timing and map are answered by the single flow thread at its next poll or gate. critical admits one pending query and gives up after 15 s. A second check waits for the first; a check during a long stage times out. This is the serialization background explorations remove.
Timing refresh (gui_timing, place.cpp:5030)Copies the solver design, writes poses onto the shared graph's place attribute, estimates RC and calls the ranking evaluation. It is a ranking estimate (~WNS, no refreshed TNS). Because it writes graph attributes it cannot simply run on a second thread of the same process: parallel timing needs separate address spaces.
Region fork (gui_session.cpp:670, launcher at lhd_kernel_synth.cpp:1955) Writes the region as its own design and starts a child lhd synth --gui with posix_spawn. Gaps: no limit on the number of children; a child is not reaped after its first 60 s and does not watch its parent; the parent learns the child's URL and nothing of its result; a macro with bus pins is refused (place.cpp:5235), so it cannot hold a macro experiment; the child re-runs synthesis and renames cells; cut-pin timing is not the parent's timing.
Restart from a checkpoint (lhd_kernel_synth.cpp:2011)execv of the session itself with the trace replayed to the checkpoint. One alternative at a time, the live state is gone, and the cost is a replay of the flow. The recipe (trace, --gui-replay-seq, flag overrides) is what a replay worker can reuse. H0 additionally needs a private evaluator protocol and separate supervision; changing execv to spawn alone does not provide the new architecture.
Job_managerProcess-wide admission shared across forked children through one shared mapping: a ceiling (lhd.jobs, 0 selects the available CPUs), host load with its own jobs subtracted, memory from predictions that it corrects from observed peaks, slot adoption by pid, reap_tree, stop/resume of a child's process group. Classes today: formal arm, simulation compile, synthesis region. A spawned (exec) child gets a manager of its own, so the parent must hold the slot for it and pass it a thread share.
fork_raceFork per method, result over a pipe, _exit without destructors, wall deadline, kill of the whole process group, a child that dies with its parent. Its stated precondition is a clean parent (no solver object, no worker threads); a paused placement is not clean, which is why H0 exists.
Threads a fork would dropOpenTimer owns a tf::Executor whose default size is the machine's hardware concurrency (../OpenTimer/ot/timer/timer.hpp:187); the placer uses OpenMP only in the dreamplace_openmp build with synth.place.threads above 1 (default 1); the GUI server threads. A forked child has only the forking thread. The 2q engine is single-threaded by ruling R11 and is already wired for GP ranking (timing_engine == "fast", lhd_kernel_synth.cpp:3598). Graph storage is heap memory (no shared file mapping in hhds), so a child's writes stay private.
GUI alignment/matrixCurrently computes absolute coordinates and sends move/pin commands. The durable relationship is lost. move has no orientation, and a scene node carries a pin count but no pin side (gui_session.hpp:31).
Non-rectangular areas (__lhd_frame_mask_*, README “frame masks”)Hard masks are missing-row/site exclusions and soft masks are initial-placement blockages; both are fixed instances in the solver. They are not routing obstacles, the scene exposes a single die Box (gui_session.hpp:51), and the map code leaves mask instances out of its macro list (place.cpp:5135). The geometry exists; the agent, the page and the congestion estimate do not see it as an outline.
Placement_hintsExisting module-scoped cluster, align, direction and snap soft pulls; position is an initial seed, not FIXED. Relative pulls refresh periodically. Results distinguish accepted/relaxed/discarded and preserve authored input.
Interactive placement referenceRegion ECO edits exist after legalization, but crossing a region can fall back to the whole core. Replay re-executes the flow; it is not a constant-time solver checkpoint. GUI runs use neither the placement cache nor the whole-flow physical replay.
What-if timing (core/timing_whatif.hpp, used by the path-based resize engine) Transient edits on the evaluated timer with a mark and rollback: master swap, new cell, and set_net, which moves pins onto a net and attaches its wire RC. The basis for H6.
Registered controlssynth.place.resize controls sizing/buffer removal/Steiner repair; synth.place.resynth controls cone resynthesis; synth.place.io_resynth controls a separate whole-color path. Legacy GP resize knobs are not a complete mutation gate. Timing intervals can disable timing itself and therefore are not a substitute.
Synthesis orchestration and placement callbacksEnforce the new policy at both levels, including FP repair, post-placement repair, stage feedback and pre-placement cached-feedback resynthesis.

The baseline is an already initialized mapped design. “No resynthesis” prevents subsequent exploration from remapping it; it does not promise that an uncompiled RTL input can be opened without initial synthesis. Entering a preset is explicit and leaves ordinary batch/GUI defaults unchanged. The policy is typed CLI/config and session state, not a new environment switch. Explorations: scratch copies of main, in the foreground or in parallel

Main is the real plan: its commands are traced and its state is what the run delivers. An exploration is a scratch copy taken at a named baseline. Its moves, runs, flags, policy and repair never change main. The external agent uses the feedback to decide which ordinary commands to issue to main itself. There is no attach operation, segment merge or promotion of an exploration process (P2).

The GUI/socket controller is a separate process. It serves published immutable views, acknowledges and queues commands, and supervises evaluators even while placement or timing is busy. Main's evaluator owns computation state and applies commands at safe boundaries. A single-threaded snapshot owner provides copy-on-write workers only under H0's lifecycle contract; unsupported threaded configurations use spawned replay. An acknowledgement is distinct from an applied edit or a fresh measurement.

Limits: never saturate the host

  • One admission point (ruling P1). Every background worker takes a Job_manager slot of the new class. There is no separate pool: formal, synthesis and exploration jobs of the same session compete for lhd.jobs. The manager also refuses when other processes load the machine (load average minus its own jobs) or when predicted memory does not fit.
  • A configured share. explore.jobs caps how many of those slots explorations may hold, so they cannot starve the rest of the flow; a smaller cap applies to T3 and T4. One CPU stays reserved for main's evaluator whenever main is not blocked; controller responsiveness is measured separately.
  • Foreground needs no extra slot (ruling P2). Main waits while its scratch evaluator uses main's reserved CPU capacity. Make this reservation explicit across the controller/evaluator boundary; do not infer a blocked-parent relationship from process ancestry. Memory admission still applies.
  • Threads are divided, not multiplied. Each worker receives an explicit share for the placer, for the timer executor and for its nested lhd.jobs. OpenTimer's default of one thread per hardware core in every worker is the saturation to avoid.
  • Memory. Predict snapshot divergence conservatively from H0 measurements and node count; predict replay at the measured full evaluator peak. Account for retained main state, parent/child writes and all workers in the session budget. Use address-space backstops where supported, plus live host/session memory monitoring: a per-process virtual-address limit alone does not bound aggregate copy-on-write memory. Report admission failures and terminate over-budget work through the supervised worker lifecycle.
  • Bounded queue. Beyond explore.queue a request is refused at once with the reason. Nothing is dropped silently. Clients are served round-robin by their client label, so one agent cannot starve another or the person at the page.
  • Deadlines and cleanup. A wall deadline per tier; then a kill of the worker's whole process group. Workers watch the session controller and die with it, independently of which evaluator forked them. The supervisor reaps children and cleans result directories. At most explore.open finished result sets may remain open for inspection/export; further requests are refused until some are closed. Bound result bytes/history too; a count alone does not bound temporary storage. Recover abandoned directories after a whole-session crash using ownership and session-identity checks.
  • Several sessions on one server do not share a table. They see each other only through load and available memory, which the manager reads before every admission; that is sufficient to back off and is stated as the guarantee, not more.

Baseline and queueing

A snapshot can only be taken where its eligible single-threaded owner is. While that evaluator is held (gate, pause, edit), queued background explorations wait for a slot and fork from the same state, so all candidates share one baseline. When the parent leaves that state (Run, Continue, an applied edit), running workers are unaffected, since each owns its copy; those still queued end as stale, and the reply to the command that moved the parent says how many. With an eligible running evaluator a snapshot forks at the next safe poll if a slot is free and is refused as busy otherwise. Keeping stopped snapshots for later is a possible extension (Job_manager::suspend_child exists) and is not in the first delivery.

Contracts

  • Beginning, running and discarding explorations never changes main's placement, timing state or trace. Only ordinary commands explicitly targeting main change it. Main's trace records those commands, not any scratch computation; batch replay uses main's recorded inputs and settings.
  • An exploration carries its own policy. Under the fast preset a worker proves at exit that connectivity and masters equal the baseline's. Changes to an exploration's policy never loosen main's policy; the agent must explicitly request that on main.
  • Lookahead reports its own thread count, engine and complete evaluation identity. Main may produce different results after the agent reissues edits, particularly under different settings; it always measures its own state.
  • Exploration options are session options like the other --gui flags and are not part of the run id.
  • No long-term side effect (ruling P6): an exploration writes only inside the session's temporary directory, never to the workdir, its caches or the repository. What outlasts a session is main's trace and result, and whatever the agent chose to edit in the repository.

Large moves, WNS/TNS and repair escalation

A fixed-netlist evaluation answers “what happens to this implementation if it moves?” A repaired candidate answers “what implementation can we recover at these positions?” Both are useful and neither substitutes for the other. New coordinates require fresh RC; stale old timing must never look like a new evaluation.

Track displacement relative to macro/window size, changed crossing-net lengths and loads, slew/capacitance violations, critical-path changes and slack degradation. Use these as configurable, calibrated escalation signals rather than an arbitrary universal distance threshold. WNS is sensitive to a single newly long path; TNS can be more informative about broad changes, but is also implementation-dependent and can change greatly after sizing/buffering. Neither metric exempts a large move from validation.

When the policy forbids repair, report “repair recommended” with reasons and retain the frozen-netlist measurement. The agent can widen the timing scope, request one permitted repair round or stop. Any optional virtual-buffer estimate must be a separately named prediction, never substituted for actual-netlist timing.

Each measurement records placement/topology/master revisions, active and timing scopes, stage, engine/model, corner/clock/SDC coverage, units, elapsed time and legal/approximate status. WNS and TNS require a declared, consistent endpoint population. A partial cone's TNS is scoped TNS; global TNS needs a maintained global endpoint ledger or full evaluation. Missing or stale timing is not zero. Compare candidate improvements only at matched coverage and evaluation level. Today's panel refresh is a ranking estimate with no TNS; an exploration runs the flow's full evaluation and reports both (ruling P3).

Frozen exterior, live electrical boundary

There are three separate scopes: objects allowed to move, objects allowed to change implementation, and paths/nets whose electrical effect must be evaluated. A selected macro may move alone, with its cluster, or with a declared surrounding cell halo. The choice is explicit and shown in the GUI. Fixed exterior objects still occupy area and contribute pins, forces, loads and routing demand.

For a net with an active pin and exterior sinks/driver, retain the exterior pin positions and loads and update the affected net's RC, including exterior branches when topology changes. Timing propagation can extend outside the movement window through changed arrival times, slews and required times. Freezing coordinates does not freeze timing. A local edit may worsen an endpoint far outside the selected region.

First implement local movement against the retained full design and verify against full timing. Then add incremental electrical updates. Chunk execution can use boundary summaries of arrival/required times, slew, loads, clock groups and constraints, with an identity and validity condition for each summary. Refresh/invalidate summaries when a changed crossing net or feedback dependency invalidates them; iterate boundaries or fall back to a declared broader evaluation. Unsupported clock/exception coverage must be reported, not assumed.

Record explicit outcomes: accepted within scope, infeasible within scope, budget exhausted, boundary summary stale, or expansion required. Expansion is a new recorded policy decision within a preauthorized bound or a new user/agent request. Region fork is useful for hypotheses but its cut-pin timing and current bus-macro limits make it insufficient as the correctness model for this mode. A successful local experiment still needs global validation before a final QoR claim.

A snapshot worker holds the whole design, so a local experiment inside one is checked against full timing at no extra design cost. Local kernels reduce the time of a job; they are not what makes jobs parallel.

Prefer “bank B east of bank A”, “left edges aligned”, “these named banks occupy these matrix slots” and “keep this channel open” over stored dx/dy nudges. Nudges remain useful exploratory actions. Save successful intent in a versioned sidecar, for example cpu.placement.json, supplied beside RTL through the existing positional JSON input. Source annotations later lower to that same intent.

  • Matrix membership/order is explicit, not re-sorted from coordinates on each replay. Fixed row/column layouts and allowed reflow are separate policies; check capacity and heterogeneous macro sizes.
  • Support object/group/boundary anchors and normalized placement within a declared frame. One absolute anchor is allowed when intentionally needed. Specify center versus edge and physical body versus halo.
  • Positions/preferences can scale; macro dimensions and technology-required clearances do not. Minimum channels use physical units or technology pitches. Preferred extra spacing may scale independently.
  • Keep hints advisory, with weights and residuals. They cannot redefine physical legality or overwrite pin intent. Temporary illegal geometry and suspended pin enforcement follow P11–P12; legalization reports conflicting hints and existing failure conditions. A future required-placement mode needs its own approved contract.
  • Show intent overlays before applying and residuals afterward. A drag cannot uniquely reveal whether the user wanted an edge affinity, a channel or proximity to logic; propose a conversion rather than guessing silently.
  • Preserve livehd.placement.hints, livehd.placement.state and livehd.placement.hint_results as separate records. A trace describes an execution; it is not the portable intent. Keep exact physical names and logical identities distinct.
  • The transfer test is a set of replay workers: the same intent under other core areas and aspect ratios, side by side, each reporting legal realization or the relaxed relationships.

External agent example and first acceptance milestones

The following is an example use of the interface, not an agent implemented or prescribed by this task. The agent may accept worse proxy measurements as part of its own long-term plan.

  1. Inspect a consistent main snapshot: geometry, pins, connectivity, maps, timing, capabilities, policies, limits and budgets. Query leverage or candidate similarity if useful.
  2. Request foreground or background explorations from a named baseline. Geometry findings are feedback; the agent may continue with an illegal intermediate state, request legalization or change its proposal.
  3. Read metrics, warnings, maps and cost. Choose further experiments or stronger evaluation, including routing, according to the agent's strategy. LiveHD does not discard candidates for poor TNS or other proxy regressions.
  4. Export desired moves, coordinates or relationships, close the exploration and return to main. The agent issues the selected ordinary edits to main with its current identity, then requests fresh measurements.
  5. Save useful intent/configuration beside RTL and evaluate transfer to other floorplans as desired. The constrained floorplan and post-route timing remain the real objective.

Planner/checker agent design, training, stopping rules and winner selection are outside this task. The session supplies commands, deterministic findings and measured evidence for any external agent or human.

  1. Fast check: move a macro, recompute RC/timing and perform bounded placement with all mutation gates closed; prove netlist/masters unchanged across a normally eligible repair/resynthesis checkpoint. Re-enable one gate and verify its scheduled operation is recorded and budgeted.
  2. Try and forget: begin a foreground exploration, move two macros, request legalization and read WNS/TNS and congestion. Export the coordinates, then discard: main's next frame and state remain unchanged. The agent separately issues those moves to main; only those edits enter main's trace, and main reports fresh measurements. Closing the exploration removes its files. No process or command segment is promoted.
  3. Parallel check: from one paused macro gate, submit five arrangements plus a baseline with a share of two slots. Never more than two workers run; all results include timing, maps and geometry status. The controller remains responsive throughout. Main is unaffected until the agent sends an explicit main edit; poor results and duplicate proposals are still returned. Killing the controller leaves no running workers; cleanup/recovery handles abandoned files. Compare wall time with serial replay.
  4. Illegal moves and pins: drag through overlapping, halo-conflicting and excluded positions. Each reports the warning. Reject new pins there, preserve existing anchors while enforcement is suspended, then restore the pins when the cause moves away. Run the explicit legalizer and verify existing success/failure semantics with density and other constraints. Check both GUI and socket feedback.
  5. Precision and exclusions: round-trip absolute coordinates through DEF units and export; resolve relative displacement, alignment and edge/gap commands using actual macro dimensions. An excluded corner must prohibit placement and carry no routing capacity in every estimator.
  6. Local check: relax a selected cluster while preserving exterior geometry/masters/connectivity; validate crossing-net timing against the full model and measure cost relative to whole-design exploration.
  7. Transfer: preserve four macros as a 2×2 arrangement, change core aspect ratio and replay without coordinate edits; show legal realization or explicit relaxed/infeasible relationships.
  8. Benchmark: import bp_fe at 2:1, let an external agent given only the socket path explore, issue its chosen edits to main, export the macro placement, score with the benchmark flow and produce a result row. Then the other 15 tasks.
  9. Quality: compare ordinary placement, absolute-coordinate replay and relative-intent exploration at equal total search budgets, with and without repair and local restriction. Report routed results under a fixed downstream flow, proxy-to-routed agreement, costs and all failures. This evaluates the interface and feedback quality without prescribing the external agent's strategy.

Measure median and tail latency separately for command acknowledgement, geometry preview, RC/timing, relaxation, repair, job start (fork or replay) and queue wait, on small and large designs. Establish achievable latency targets from these measurements; do not promise subsecond timing or speed proportional to active-cell count before profiling crossing nets and boundary propagation. Keep generated benchmark outputs under ignored repros/.

Risks and open points

  • Snapshot lifecycle. Separating the controller removes GUI threads from the computation owner, but timer/OpenMP runtimes also need an explicit safe lifecycle. A paused flow or idle pool is not enough. Fork only from the isolated single-threaded owner; configurations that cannot satisfy H0 use spawned replay and advertise that reason in state. Measure controller responsiveness during long evaluator work.
  • Replay cost. A replay worker repeats the flow to the baseline (the 668k-cell design of 2q-fasttimer takes about half an hour end to end). It is the right tool for a few flag-changing or repair candidates, not for many quick checks.
  • Memory under divergence. Copy-on-write is cheap only while parent and children leave most pages alone. Global placement rewrites the coordinate and field arrays; the graph and libraries stay shared. H0 measures the real fraction; the prediction starts conservative.
  • Cost of a full evaluation per exploration. Ruling P3 asks for WNS and TNS, so a T1 result costs a full evaluation rather than a ranking pass. Measure it per design size; H6 keeps small moves cheap.
  • Main needs fresh evaluation. The agent applies chosen macro moves or relationships to main, which remains authoritative. Its resulting timing may differ from an exploration, and reevaluation has a cost. Never avoid that cost by promoting the scratch process or relabelling its measurements.
  • One session, several clients. A foreground exploration changes what everyone connected sees. The banner and state must make that impossible to miss, and a client that sends expect revisions is refused rather than applied to the wrong line.
  • Benchmark import. Nangate45 with fakeram45 memories is already exercised (the HighTide nangate45 designs, the pg_nangate45 power grid, the SDC reader), but these 16 netlists and DEFs have not been read. Placing the mapped netlist without remapping, the DEFs' rows and pins (the synth.place.floorplan option asks for contiguous N/FS rows), and the exact instance names are the points to check first; what fails is fixed (ruling P8), so the cost is schedule, not scope.
  • Benchmark submission. No public way to submit and no stated license; a comparison may stay a local table.
  • Open: defaults. The proposed share of 4 slots. Snapshots run on the session's host and are enabled only where H0's architecture and lifecycle contract is met; other configurations use replay with the same isolation semantics and an explicit replay cost.
  • Not in scope. Distributing jobs to other machines; sharing one admission table between unrelated lhd processes; implementing the external reasoning agent, its search strategy, proxy-selection policy or long-term plan.
