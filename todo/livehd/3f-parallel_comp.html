3f-parallel_comp Dependency-driven parallel compilation

Status: exploratory; not committed work. Record a possible cold-build architecture in which a module is the scheduling and cache-locality unit: once its semantic dependencies are ready, one worker continues through prp2lnast → upass → tolg → cprop and publishes milestones that release its parents. This revisits the bottom-up compiler described in the CC’23 LiveHD paper, but does not propose restoring the removed implementation unchanged.

Motivation snapshot (2026-08-19). A cache-disabled optimized compile of XiangShan Backend completed in 205.72 s: import parsing 40.21 s, upass 81.32 s, LNAST-to-LGraph lowering 25.62 s, and graph cprop 43.88 s. Import parsing and cprop already use up to 16 workers, while upass and tolg retain substantial serial module loops. Stage-wide barriers also discard locality between a freshly produced LNAST and upass, and between a freshly produced LGraph and cprop. These numbers are one checkout/host snapshot, not a performance contract.

Depends on

None. If pursued, coordinate with the landed incremental compile cache (lever L8 of docs/opt_loop_incr.md) so semantic dependency summaries, immutable artifacts, diagnostics, and publication ownership have one meaning in cold and incremental compilation.

Subtasks — pending

  • A — Go/no-go evidence.
    • Add per-unit timings for parse, parser validation/rewrite, upass, tolg, hierarchy finalization, and cprop; record worker utilization and peak live bytes.
    • Measure whether frontier imbalance and stage barriers leave enough CPU idle to justify the scheduler complexity. Do not start the refactor solely from aggregate phase timings.
    • Measure the scheduling crossover by source bytes, scan-tree descendants, and estimated LNAST work. Most files/entities are small; parallel dispatch must show a benefit above a threshold instead of assuming every discovered leaf deserves a job.
    • Use DINO and Minion as correctness/overhead gates and XiangShan Backend as the scale gate. A proposal must preserve or improve single-thread time as well as multi-thread wall time.
  • B — Explicit dependency model.
    • Distinguish the conservative source-discovery graph from the live semantic graph and the hardware-instantiation graph. They are DAGs/SCCs, not trees; several instances share one compiled definition.
    • Classify edges as pub-value/type, comptime comb, inline comb, interface-only comb/mod/pipe, template specialization, or state/activation ABI. A lexically scanned import in a dead comptime arm discovers a file but must not block a job.
    • Detect SCCs explicitly. Diagnose illegal import/hierarchy cycles, while retaining the supported terminating recursive-comb/specialization semantics.
  • C — Closure-first parse scheduling.
    • Use the existing lexer-only Prp2lnast::scan_imports plus the canonical resolver to discover the complete source closure before full parsing.
    • Parsing itself does not need bottom-up order, but do not submit every small file as an independent job. Coalesce a small scan subtree into serial work and expose parallel jobs only when estimated work across its discovered children exceeds a measured threshold. Prefer large files/subtrees early to reduce the generated-monolith tail.
    • A file may contain several entities. Keep a file job through parsing, then split it into unique module/entity jobs after lambda discovery rather than equating files with modules. Apply a second measured threshold before splitting tiny entities into jobs.
  • D — Compilation context and milestone jobs.
    • Replace pass-wide mutable singletons with an invocation-owned context: function and import registries, verifier aggregates, pending imports, diagnostics, specialization publication, cancellation, and graph-library ownership.
    • Represent one unique definition with one job. Publish at least Parsed, PubReady, InterfaceReady, GraphBodyReady, HierarchyStable, and Optimized; different consumers wait on the earliest sufficient milestone.
    • Use continuations/readiness counters, not a blocked OS thread. Prefer resuming a module on the same worker for locality, but never reserve a worker while dependencies are unresolved.
    • Buffer per-job diagnostics and publish them deterministically. A failed job cancels dependents without exposing a partially valid library.
  • E — Dependency-driven upass.
    • Run local lambda extraction, detuple, SSA, and runner work per ready entity while preserving the existing pass ordering and diagnostics.
    • Replace whole-file retry rounds with suspension on exact missing pub/comptime milestones. A converged unit is never walked again.
    • Allow dynamic template/specialization jobs to enter the same scheduler with deterministic names and O(1) unique-definition deduplication.
    • An ordinary non-inlined call requires only a finalized interface; a comptime or inlined comb call requires the callee body. Record this on the call edge rather than classifying every comb globally.
  • F — Final interface and hierarchy ABI.
    • Keep two immutable summaries: a preliminary syntax interface and a final interface. No consumer may bind a provisional port count, width, signedness, aggregate layout, or implicit port that can later change.
    • The final summary includes io_meta, body-derived bitwidth facts, template specialization, and local state/call facts. Clock/reset need propagates bottom-up; conditional activation propagates top-down.
    • First implementation may keep one short global ABI fixed-point after parallel upass. Register final GraphIOs serially in deterministic name/port order before any body relies on them. A later implementation may replace the barrier with bidirectional summary propagation if measurement justifies it.
  • G — Fused lowering and optimization.
    • After GraphIO publication, lower independent LNAST bodies in parallel. The caller needs the callee GraphIO, not the callee’s completed or optimized body.
    • Convert the current whole-registry activation/Sub refresh into an explicit hierarchy-finalization milestone, or retain a short correctness barrier initially.
    • Run a worker-local Cprop immediately after that module’s graph is structurally stable. Do not make a parent wait for child cprop: current cprop is module-local and neither reads nor mutates sibling graph bodies.
    • Keep genuinely whole-design or hierarchy-observing recipe/formal/emit work outside the fused task unless its dependency contract is separately proven.
  • H — Resource control and correctness gates.
    • Use one bounded pool across stages, with weighted admission/backpressure from source bytes, LNAST nodes, and graph size. Overlapping parse, upass staging, LGraph, and cprop must not turn the current high-RSS compile into swapping.
    • Preserve deterministic graph names, gids, port ids, warnings, and emit inventories. Shared GraphLibrary operations must be narrow and explicit; never hold a library lock while executing a module pass.
    • For every thread count, require zero errors, the same diagnostics modulo timing, strict structural LGraph identity with the sequential cold build, and no partial artifacts after an injected failure.
    • Treat Heisenbugs as a design-level objection, not merely a testing inconvenience. Keep a deterministic single-thread reference mode, make task/publication order observable and replayable, and stress repeated builds with randomized legal schedules. Do not enable the parallel flow by default until those runs are reproducible and race-free.
    • Regress shared definitions, multiple roots, diamonds, dead imports, pub constants/types, inline/comptime combs, templates, recursive combs, transitive clock/reset, conditional activation, and hierarchy cycles. Run under thread sanitizer.

Design notes

Preferred execution model

closure scan
  └─ thresholded file/subtree parse clusters (parallel only above crossover)
       └─ entity jobs
            ├─ await pub/comptime/body dependencies
            ├─ upass
            ├─ publish final local summaries
            ├─ await/finalize hierarchy ABI
            ├─ tolg
            ├─ hierarchy stabilization
            └─ cprop → publish optimized graph

The ideal common case executes prp2lnast → upass → tolg → cprop on one worker with hot data. The scheduler may yield at milestones when semantics require it. Strictly waiting for an entire child pipeline to finish is too coarse: a parent can parse immediately, can often upass once pub/comptime facts are ready, and can lower once the callee’s final GraphIO exists even while the callee body is still being optimized.

Granularity and reproducibility

The scan graph should decide where parallelism begins. A leaf or a shallow collection of tiny files stays in its current worker as one serial cluster; only accumulated descendant work above a calibrated threshold becomes a separately scheduled subtree. The estimate can start with source bytes plus discovered-child count and later incorporate historical LNAST node/pass cost. This avoids queue, synchronization, allocation, and cache-locality overhead for the common small-file case.

Concurrency also makes rare failures harder to reproduce. Any prototype therefore needs a stable job id, a trace of dependency releases and publications, and a replay mode that can force the recorded legal order. Shared state must be removed or made transactionally owned; adding locks until tests usually pass is not an acceptable architecture. If equivalent outputs cannot be demonstrated across serial, deterministic-parallel, and randomized schedules, the go/no-go result is no, even when median wall time improves.

Historical precedent and differences

The CC’23 compiler used module tasks, an atomic pending-child count, bottom-up release, and pass clustering. Its uIO tuples deferred hierarchical port resolution until cprop. The removed implementation also exposed failure modes that the new design must not repeat: top-required traversal, duplicate visits of shared definitions, shared pass objects, global graph-library mutex contention/deadlock, and nondeterministic shared maps. Relevant history includes 46b3c5d00 (bottom-up traversal), 4ca738851 (Pyrope bottom-up compile), and 933c1a9db (visited-table and phase separation).

Current LiveHD already has a cleaner substitute for part of uIO: tolg registers every final GraphIO before lowering any body. Also, today’s cprop is module-local; the historical bottom-up cprop contained tuple-I/O and hierarchical bitwidth responsibilities that no longer belong to it. Reuse the scheduling principle, not obsolete dependency assumptions.

Decision gate

Keep this page as a record until measurement shows that module-pipeline scheduling has a credible end-to-end win after accounting for memory, synchronization, and single-thread overhead. If the majority of the critical path remains inside one or two generated monoliths, prefer local O(n) algorithm/representation improvements over scheduler complexity. If the task is rejected, delete this page rather than leaving an inactive implementation backlog.
