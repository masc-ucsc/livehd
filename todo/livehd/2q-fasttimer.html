2q-fasttimer Fast approximate timing engine for synthesis and placement

Plan written 2026-11-11 from a question-and-answer session. Steps A, B (without the SDC reader) and C are implemented in pass/timing (2026-11-11), see Progress. Names of options, targets and directories are proposals.

Replace OpenTimer inside synthesis and placement with a small native timing engine that is fast, uses a few hundred bytes per cell and times several Liberty corners in one walk. OpenTimer stays for the final report, for validation and for an occasional calibration on a small part of the design. The engine does not need exact slack. It needs to order paths correctly (which are more critical than others), give gate sizing a consistent delay model, and work on one chunk of the design at a time.

Why

  • Time. One detailed OpenTimer evaluation on minimax (about 18k cells) has a median of 14 s, and 74% of its cycles are in the RC driver model (fitting a driver ramp and an effective capacitance), not in Liberty lookups. After the 1f reductions, timing is still 24–34% of placement time (1f-fixes).
  • Memory. The OpenTimer model costs about 6 KB per gate (2.85 GB for 476k gates). Minion placement with timing on went over 40 GB and did not finish in 3 hours (2f-scalability).
  • Scalability. OpenTimer holds one flat design. 2f-scalability needs timing per memory-bounded chunk.
  • One corner. lhd synth takes one Liberty file, so hold is checked on the same library as setup, and no decision looks at a second cell speed.
  • Unreachable targets. Most runs ask for a period the design cannot meet. Against that period almost every path is negative, which hides the difference between the paths that set the frequency and the rest.

Design

Where it lives

A new library, proposed pass/timing (namespace livehd::timing, where Feedback and Whatif already are). It depends on the Liberty model and on hhds for binding. It does not depend on OpenTimer, DREAMPlace or pass/place, so synthesis and placement can both link it.

Numbers, not names

Following the 2f ruling (no copy of what the graph holds, no table keyed by a string where a graph is in hand):

  • Cell-type table, built once per set of corners. Per type: pins, arcs with their sense and conditions, setup and hold constraints, pin capacitance and electrical limits. Each arc points at one delay and one slew table per corner and transition. Tables live in one pool and share their axes. Corners are matched by cell name; a cell missing from a corner is a diagnostic.
  • Binding, built once per topology of a chunk: a type index per cell, a pin index derived from the cell and the type, a net index per pin, and the pins in levelized order so a walk is a linear scan. The hhds pin handle of each index is kept for writing results back; names are produced only for reports.
  • State per pin, as flat arrays of 32-bit floats: late arrival, slew and required time for each corner and transition; early arrival for the hold corner; a depth count for the margin of R14; the worst predecessor. The delay of each arc is kept from the forward walk, so the backward walk and incremental updates do not repeat table lookups.

Estimate for three corners: about 80 bytes per pin and 24 per arc, so roughly 0.4–0.5 KB per cell at four pins per cell, against about 6 KB per gate today. This is an estimate to confirm in step C.

Delay calculation

  • Net load per corner: sink pin capacitances plus the wire capacitance of the tree.
  • Cell arc: delay and output slew from the NLDM tables at (input slew, net load), with the same interpolation and extrapolation as Table::lookup. Rise and fall follow the arc sense. Worst arrival and worst slew are tracked per transition, as OpenTimer does, so the two timers can be compared like for like.
  • Wire: Elmore delay per sink on the numeric tree. Sink slew combines the driver slew with the wire's time constant (root-sum-square form, adjusted to the library's slew thresholds).
  • Checks: setup and hold from the constraint tables with ideal clocks, as the default flow does today. Maximum capacitance, transition and fanout are counted the way the current detailed evaluation counts them.
  • Constants and conditions: case analysis over cell truth tables and when conditions, ported from late_timing.cpp, which already does this for up to six inputs.

The known cost of R2: total load is pessimistic on long resistive nets, where the far capacitance is shielded from the driver. The plan accepts a uniform error and controls the non-uniform part with the per-length-class wire factor of the calibration (step I).

Constraints and false paths

Today there are two SDC readers: the one inside pass.opentimer and pass/place/sdc_subset.hpp. The engine takes one typed constraint object (clocks, IO delays, loads, driving cells, case constants, cuts, false paths) from one reader, and OpenTimer is fed from the same object, so both timers see the same constraints.

  • set_false_path -from / -to a port or pin: the start or end point is removed, the net stays wired and loaded.
  • -through a pin, reset distribution and other control nets: an arc cut, the same mechanism as today's timing_cuts and data exclusions.
  • Clock-to-clock false paths and asynchronous groups: launch-domain tags per clock.
  • Pin-to-pin pairs (-from A -to B between data pins) would need a tag per start point. They are reported as unsupported in the first version; step B measures how often the benchmark SDCs use them.

Criticality

Per clock, the achievable period is the SDC period minus the worst setup slack over the setup corners, after the depth margin.

  • Target not met (the common case): slack is rebased so the worst path has zero. Criticality falls from 1 on the worst path to 0 at the edge of a window, proposed 10% of the achievable period. Pins outside the window have criticality 0 and are candidates for area recovery, not for more pull or larger cells.
  • Target met: the SDC period is the reference, with the same window. Paths with positive slack beyond the window are not critical.
  • Corners: each setup corner is evaluated against its own worst path, and a pin's criticality is the largest over the corners. A corner can be marked setup-only or hold-only.
  • Depth margin (R14): at each endpoint the arrival is increased by a fraction that shrinks with the square root of the logic depth of its worst path. Random variation averages out over many stages, so short paths keep a larger relative margin.

Consumers get a criticality per pin and the achievable period per clock. The net-weight formula in timing_place.cpp (percentile of the net's worst slack, blended with the previous weight) is replaced by a function of criticality with the same smoothing; nets with criticality 0 fall to the minimum weight.

Wire trees

  • One compact tree per net: nodes with coordinates, a parent index and a segment length. Per-unit R and C come from the existing technology_wire_rc.
  • Topology from the existing driver-aware Prim-Dijkstra code (timing_steiner_topology), with the FLUTE-group fallback for very large nets.
  • Between samples the topology is frozen and only segment lengths follow the pins, which is cheap and continuous. A net's tree is rebuilt when a pin has moved more than a fraction of the net's bounding box, or when the frozen tree is longer than a fresh estimate by a set margin. Rc_cache is prior art for the keys.
  • Delay-driven refinement (Wu, Li, Chen, Yu, Zhu, "Delay-Driven Rectilinear Steiner Tree Construction", TCAD 44(5), 2025) for nets with a sink in the critical window: edge replacement to bound the source-to-sink path length, then edge shifting to reduce Elmore delay, weighted by each sink's criticality (their critical-sink problem). This models what a timing-driven router does for critical nets. It is only valid if the router builds comparable trees, so it is an experiment measured against routed RC (step K) before it becomes a default.
  • Before placement (synthesis) there are no coordinates: wire capacitance comes from a per-technology table by fanout, fitted offline, or is zero when no table exists.
  • physical::Parasitics is generated from the same trees when OpenTimer needs it, so both timers see the same RC. The 1.39 GB that estimate_rc holds on minion is then no longer part of the loop.

Chunks and boundary times

An engine instance times one chunk. A boundary input carries arrival and slew per corner and transition; a boundary output carries required time and the external load. The same interface serves a synthesis color (the per-port times of 2is-incsynth) and the top level (IO delays from the SDC).

Between rounds only the boundary values are stored. Stitching is a worklist over chunks: a chunk is timed again when one of its boundary inputs changed by more than a tolerance, and its new boundary outputs feed its neighbours. The design graph is acyclic between state elements, so this settles after at most one sweep per chunk crossing on the longest path, with one chunk in memory at a time.

Note on R5: the question that led to R5 described stitching with port-to-port delay summaries per chunk. The plan uses boundary values and re-timing instead, because a port-to-port table grows with the square of the port count. To confirm with the user.

Until 2f chunking exists, the whole design is one chunk and the worklist has one entry.

Calibration

  • Offline, per technology (OpenSTA). A tool takes saved placed and routed runs, exports the engine's RC, runs OpenSTA and fits: a cell-delay factor and a wire-delay factor per corner, the wire factor per net-length class, the depth-margin numbers of R14 and the fanout wire-load table. The result is a small data file next to the technology data, named by an option and part of every cache key that depends on timing.
  • In a run (OpenTimer), once before sizing. When placement is stable, OpenTimer times the chunk that holds the worst paths, with the same boundary times and RC. Two factors per corner (cell, wire) are fitted on the endpoints inside the critical window and applied to the whole design. The fit is skipped when the chunk is above a size limit, and ignored with a warning when a factor falls outside a sane range.

Hold (best effort)

  • Early arrival on the fastest corner, ideal clocks.
  • GP does not raise the weight of short flop-to-flop nets.
  • Sizing and repair reject a change that creates a hold violation or worsens one.
  • Repair fixes clear cases only: a hold slack well below zero on a path whose setup slack on every corner exceeds the added delay with margin. Downsizing first, then a delay cell.
  • Residual violations are reported and never fail a run. Real clock skew does not exist before routing, so the post-route ECO keeps the final responsibility.

Findings in E

  • SDC numbers are in the Liberty units. The first version read -period 10 as 10 ps (the sky130 library is in ns), which made every slack 10 ns too low. liberty::timing::Library now carries the units of its first library group, and the reader takes them.
  • The ranking returns the true slack, not the rebased one. Weights use only the rank order, but the GUI estimate and the acceptance of rounds read the sign and size of the slack. Options::true_slack_in_rank adds one backward walk against the true requirements (criticality stays the rebased one).
  • An unconstrained output is an endpoint in OpenTimer, not in the engine. Without set_output_delay OpenTimer gives a primary output a required time of 0, so a test SDC with only create_clock shows a worst slack of −407 ps in OpenTimer and +4.6 ns in the engine. With real IO delays they agree. Decision for R-list: the engine keeps the SDC meaning (no delay, no check).

Deviations and findings

  • Combinational loops are cut, not left untimed. Minion has 4,004 loops (79k pins). Left untimed they hid the longest paths, which all run through them, and OpenTimer cuts them silently. The engine cuts a loop at one pin (the one with the fewest arcs still waiting among the first unordered pins, so the rule depends only on the netlist), and the count is in Report::unsupported.
  • Primary inputs launch at time 0 by default, as OpenTimer does without input delays; cut_pins on the input ports turns it off.
  • The binder time is graph access: on minion flatten takes 2.2 s and bind 3.3 s, ten times the evaluation. The numeric netlist is built once per topology, so this is paid once, but it is where an incremental rebuild will need care.
  • Not timed, listed: latches, memories and clock gates (2,535 cells in minion), falling-edge elements, state-dependent arcs are all treated as separate arcs (the worst wins; the case analysis of step B is not done), sinks driven by constants (9,257 in minion).
  • Single clock tags: arrivals carry no launch-clock tag, so several clocks are timed against the capture clock's period with the worst launch; asynchronous groups are not supported yet (to be reported as unsupported when the SDC reader lands).

Steps

  • A — cell-type tables for N corners. Built from liberty::timing::parse. Pooled tables, shared axes, pin capacitances, constraints, electrical limits. Exit: lookups match Table::lookup within float tolerance on asap7 and sky130; load time and size reported.
  • B — binding and constraints. Numeric binding and levelization of a flat mapped graph, for a whole design, a chunk or a color, with boundary pins. One SDC reader feeding the typed constraints (also to OpenTimer). Clocks, IO delays, false paths, cuts, case constants. Exit: the benchmark designs bind with every unsupported item listed; F4 answered.
  • C — propagation. Forward and backward walks for all corners, zero wire. Endpoints, achievable period per clock, criticality, depth margin, worst predecessor. Exit: analytic unit cases; a zero-wire comparison with OpenTimer on the benchmark set as a diagnostic; measured time and bytes per cell against the targets below.
  • D — wire trees. Numeric trees, Elmore delay and slew, frozen topology with length updates, the rebuild rule, Parasitics export. Exit: same-RC comparison with OpenTimer on placed designs as a diagnostic; tree memory and update time reported.
  • E — ranking in placement. An option selects the engine for the rank callback: seed, GP checkpoints, legalizers. Consumers read numeric criticality. Exit: the benchmark flows complete; period and timing share reported against F1.
  • F — detailed evaluation. evaluate with all corners, early mode, electrical checks and worst paths. Timing rounds, region refinement, IO resynthesis and final legalization move over.
  • G — edits and what-if. Incremental update, journal and rollback. Legacy repair, the new resize engine and preroute move over. Exit: incremental results equal a fresh evaluation within tolerance after every edit and rollback in the tests.
  • H — synthesis. Join trials, the post-synthesis seed, per-color port times, usyn accept/reject and region scoring on the engine, with the fanout wire table. Stored measurements are keyed by the engine's source salt instead of OpenTimer's.
  • I — calibration. The offline fit tool with OpenSTA and its data file; the in-run chunk calibration with OpenTimer.
  • J — hold. The guard in sizing and repair, then best-effort fixing.
  • K — delay-driven trees. The refinement for critical-window nets, measured against routed RC on the reference runs. Default decided by that measurement.
  • L — chunk stitching. Boundary storage and the worklist, scheduled with the 2f chunking steps.
  • M — acceptance and default. The R9 comparison; flip the default; OpenTimer remains selectable for comparison.
  • N — cleanup. See below.

A to G are in order and put the engine in the placement loop. H, I, J and K are independent of each other once F is done. M can be run for placement before H lands and again after.

Cleanup this plan owns (R7, R12)

  • timing::Feedback: numeric pin indices instead of sorted label tables and the string map; one representation instead of sparse, dense and ranking variants.
  • Physical_session shrinks to building OpenTimer for the report and the calibration; the what-if journal, the ranking purpose and the binding caches go.
  • estimate_rc and Parasitics are computed only when OpenTimer runs.
  • One SDC reader instead of two.
  • Dead code: repair_gp_buffers has no caller and gp_resize is not consumed.
  • The evaluation budget (eval_budget, the private allowances of sizing and buffering) exists because one evaluation costs seconds. Revisit it once the cost is measured.
  • Port the domino stage timer (provisional cells, capture budgets, inverted clocks, clock-gate checks) and the timeclosure pin weights, then delete late::Proxy, gate_waveform, star_rc and the probes that only serve them.

Targets (proposed, to confirm in step C)

  • Timing is at most 5% of placement time on the 1f set (24–34% today; the 1f target was 10%).
  • At most 0.5 KB per cell for three corners, trees included.
  • A full evaluate of minimax at least 100 times faster than the 14 s OpenTimer median.
  • A what-if probe costs time proportional to the edited cone, not to the design.

Acceptance (R9)

  • On the 1f set, with the engine in the loop and with OpenTimer in the loop, same inputs and options: the final OpenTimer-reported period is within 2% (or the measured run-to-run spread, if larger), area within 2%, and no additional electrical violations.
  • The time and memory targets above are met, and reported per consumer.
  • Reported but not gating: rank correlation and overlap of the near-critical set against OpenTimer on identical RC, split by path style (local, long, high fanout), and hold residuals.
  • With the engine option off, every existing result is unchanged until the default flips.
  • Minion with timing on completes placement, which it does not today.

Risks

  • Wire-heavy against cell-heavy paths. Total-load pessimism affects long resistive nets more than short ones, which can reorder paths. The per-length wire factor addresses it; the per-style diagnostic shows whether it is enough.
  • Sizing without effective capacitance. Drivers of long nets may be upsized more than needed. Compare cell area after sizing against the control.
  • Criticality jumps. When the worst path changes identity, the rebased reference moves. The existing weight smoothing damps it; watch for oscillation in GP weights.
  • False-path coverage. An unsupported form leaves false paths in the critical window and misdirects the whole flow. Unsupported items must be reported, never timed silently.
  • Calibration from one chunk. Factors fitted on the worst chunk are applied everywhere. Bounds and the offline fit limit the damage; compare with calibration off.
  • Corner mismatch. A cell missing or different in one corner removes that corner for the paths through it.
  • Final report. The report can no longer reuse the placement session's timer, so OpenTimer is built once at the end for the whole design, with its full memory cost. A report per chunk is outside this plan.
  • Domino port. The stage timer relies on features of late::Proxy that the main flow does not need; porting them must not complicate the common path.
  • Delay-driven trees. If the router does not build such trees, the estimate is optimistic exactly on the critical nets.

Open points

  • Stitching by boundary values and re-timing instead of port-to-port summaries (see the note on R5).
  • Option names: proposed synth.timing.engine=opentimer|fast, synth.corners=slow:a.lib,typ:b.lib,fast:c.lib, synth.timing.window, synth.timing.fit, synth.timing.calibrate.
  • The window width (10% proposed) and whether it differs between GP weights and sizing.
  • Whether pin-to-pin false paths need support in the first version (F4).
