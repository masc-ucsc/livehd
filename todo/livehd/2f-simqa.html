2f-simqa WaveformQA external benchmark harness for the sim query API

Kept 2026-08-09. This measures agent usability and query coverage; it is intentionally separate from raw simulator-throughput comparisons and from the product's correctness gates.

Evaluate the lhd sim query API against WaveformQA: Benchmarking LLM Temporal Reasoning on Digital Waveforms (Liu, Cummings, Vadlamudi; abridged version in IEEE ICLAD 2026 — cite the venue as the durable reference). WaveformQA supplies 360 questions with programmatically generated ground truth across eight categories × three subcategories, over 13 VCD traces from five open-source RISC-V cores (PicoRV32 338 signals, DarkRISCV 394, SERV 957, biRISC-V 1,642–2,295 across its four traces, Ibex 4,185), with windows extracted at five transition thresholds (5,000 / 7,000 / 15,000 / 30,000 / 60,000 — five discrete sizes, not a continuum). Workloads are custom firmware per core: fibonacci, CoreMark, bubblesort, Dhrystone, simulated with Icarus Verilog or Verilator.

This is a benchmark harness, not a product gate: 2f-sim ships on its own subtasks plus its internal engine-oracle smoke. The benchmark target is agent plus tool, not an agent reading a raw waveform: for every question, the coding agent gets the natural-language question, the signals result, and the v1 query schema; it emits JSON queries, invokes lhd sim --query, and returns the final answer, with the complete query/tool transcript retained.

Artifact status — BLOCKED (checked 2026-08-02)

  • The paper's cited code/data repository, github.com/tenstorrent/waveformqa, returns 404 (verified unauthenticated and via authenticated gh api); no mirror exists on GitHub or Hugging Face. The published questions, ground truth, VCDs, event-time JSON and the question generator are all unavailable.
  • No dataset license exists anywhere yet — the paper carries only IEEE text copyright plus the arXiv preprint license. Gating rule: do NOT vendor WaveformQA questions, answers, traces or generator code into any LiveHD repo until the upstream repository publishes an explicit license permitting redistribution. When it appears, the harness fetches by pinned URL + checksum into a gitignored cache at run time; if no acceptable license ever appears, the harness runs only on internally generated question sets.
  • What is independently available today: RTL for all five cores (YosysHQ/picorv32 ISC, darklife/darkriscv BSD-3-Clause, olofk/serv ISC, ultraembedded/biriscv Apache-2.0, lowRISC/ibex Apache-2.0) — pin those repos now. The matching firmware images and exact simulation setups live only in the unreleased repo, so exact trace equivalence cannot be checked until it ships; the paper does describe the event-time JSON format (Appendix VI-A) and the generator method (select signal, sample time point, compute answer from trace, f-string template) well enough to reimplement.
  • Fallback ladder while blocked: (a) reimplement the generator and the event-time JSON converter from the paper's descriptions, producing WaveformQA-style questions with the same 24-subcategory stratification, labeled reimplemented-baseline (not directly comparable to published numbers); (b) swap in the published artifacts at a pinned commit with checksums when released. Nothing downstream may be worded or built as unconditional on the artifact.

Layer ordering — adapter first

Build the VCD-replay adapter first. It is harness-only: it implements the same sim_query request/result contract over a parsed VCD file, so engine-oracle and query-synthesis scoring can run on published (or regenerated) traces without re-simulation, and it doubles as the coverage classifier's oracle (below). 2f-sim's "no VCD parser as a prerequisite" boundary constrains the shipped query engine, not this harness. Adapter-scored results are labeled semantics-only; only real lhd sim re-simulation produces the speed/cost numbers (checkpoint selection, replay time), and that track is staged as the stretch layer.

Coverage manifest — mechanical, frozen

WaveformQA is an event-time benchmark while v1 observes one settled post-step value per cycle, so the full published score is not a valid acceptance number without qualification. Classification is a TOOL, not a judgment call: it emits a checked-in manifest of question_id → {class, reason_code, referenced_signals, mechanical_rule | manual_override+rationale}. Mechanical rules:

  • A referenced signal absent from the query catalog (or unmappable, below) → extension-required.
  • Signal mapped AND the cycle-sampled transition sequence over the question's window equals the event-time sequence (checked via the adapter) → eligible for coverage; answered by one canonical query → V1-native; by a composed sequence → V1-composable (measure excess calls/rows as an API-efficiency signal).
  • Transitions hidden between post-step samples, physical-time period/frequency, subcycle glitches, true four-state behavior → extension-required, with the missing capability recorded; never dropped, never counted as ordinary wrong answers.

The final arbiter of "covered" is the engine-oracle layer itself: a question is covered iff a reviewed canonical query sequence reproduces the ground truth; if no reviewer can write one, it is extension-required. The manifest is frozen before any agent run; changing it afterwards requires a new benchmark version number — otherwise "accuracy on covered questions" is not a stable metric. Because v1 catalogs only state elements, ports and memory words, initial coverage may be a minority of the 360 questions and some subcategories may be empty: publish the per-subcategory covered/total counts including zeros — the coverage number is a headline result, not a failure. Canonical query sequences are required only for subcategories with at least one covered question. If physical-time conversion is to be agent-doable, the query response's run metadata must first grow a timebase field (today the only cycle-to-time mapping is the VCD period-10 convention); until then those questions stay extension-required.

Re-simulation track — staged, with named prerequisites

Regenerating the cores as real lhd sim workloads is the stretch layer, staged by frontend risk: Stage 1 is PicoRV32 only (plain Verilog-2001, smallest, ISC) with a reconstructed firmware build, as the feasibility spike; DarkRISCV and SERV follow; Ibex and biRISC-V (heavy SystemVerilog, far beyond the current 31-fixture sim scale) are explicitly stretch. Two prerequisite deliverables the plan names because nothing existing covers them:

  • Memory preload. There is no mechanism today for loading firmware into a simulated memory — pokes are port-only. Deliver one: e.g. sim.meminit=<mem>=<file.hex> reusing the checkpoint $readmemh codec, or documented initial-checkpoint injection.
  • Signal-name mapping. A published-VCD-name → catalog-name map per core, with a reported mapping-coverage percentage. lhd names can be synthetic (memory_60), carry __in. aliases, or lose flattened comb scopes; an unmappable signal is a distinct setup-failure class (unmapped-signal), not extension-required.

Trace equivalence is defined concretely: per mapped signal, the cycle-sampled value sequence over a declared window must match the reference VCD's values at the corresponding sample times; publish the compared window and mismatch count. A non-equivalent regenerated trace is a setup failure, not an agent error.

Evaluation layers and metrics

  1. Artifact gate. Pin the artifact commit + checksums and record its license — currently blocked (see Artifact status); do not sequence layers 2–5 behind it. Until then layers 2–4 run on the reimplemented question set and/or the adapter over regenerated traces.
  2. Engine oracle. Translate each covered question to a reviewed canonical query sequence and require exact reproduction of ground truth. Isolates API semantics and simulator correctness from model behavior. (The hermetic CI version of this layer — internal fixtures, no LLM — lives in 2f-sim subtask F.)
  3. Query synthesis. Score whether the agent emits valid queries, selects correct signals/time bounds and reaches the canonical answer. Keep query-schema, unknown-signal, wrong-signal and wrong-order failures separate from final arithmetic mistakes.
  4. End-to-end agent answer. Exact/normalized accuracy for all eight categories, binned a priori by the five transition thresholds × five cores (13 traces) — never an invented continuum. Report aggregate accuracy, accuracy among completed runs, and incomplete/resource-limited runs separately.
  5. Speed and cost. Agent planning time, tool calls, input/output tokens, simulator setup/build time, checkpoint selected, cycles replayed, query execution time, result bytes, peak RSS; median/p95 per category. This layer requires the re-simulation track — adapter runs are semantics-only.

Baselines: the paper's raw-VCD prompt, its event-time JSON prompt, and agent-generated lhd sim queries. The first two depend on unreleased artifacts — while blocked, reconstruct them from the paper's descriptions and label results reimplemented-baseline. Bound the cost: baselines run on the covered subset plus a stated stratified sample (up to N per subcategory), a declared trial count, and a single pinned model for the headline table; full-matrix runs are optional deep-dives. Pin the agent model/version, prompts, query schema, sampling policy, context limit, temperature/seed and maximum tool calls; keep per-question transcripts (keyed on run_id + query_hash) and run repeated trials when nondeterministic. Because the public benchmark may enter model training data, also generate held-out questions and trace windows with the same stratification (generator: published when released, reimplemented until then).

Relationship to existing tasks

  • lhd sim query API — the product API this harness evaluates; its subtask F engine-oracle smoke is the hermetic CI cousin of layer 2. Evidence gathered here (excess calls per category, extension-required clusters) feeds 2f-sim's post-v1 protocol extensions; it does not overturn v1's explicit cycle/post boundary.

Acceptance

  • The adapter answers the engine-oracle layer exactly on a regenerated or published trace, and the coverage manifest is frozen, mechanical, and published with per-subcategory denominators including zeros.
  • Query-synthesis and end-to-end reports decompose failures (setup-failed, unmapped-signal, unsupported/extension-required, context-exceeded, invalid-query, resource-limited, wrong-answer) without silently dropping any class.
  • The PicoRV32 re-simulation spike either produces a trace-equivalence report (window, mismatch count, mapping coverage) or a named blocker; speed/cost numbers are published only from re-simulated runs.
  • No WaveformQA-derived content is vendored into any LiveHD repo before an explicit upstream license permits it.
