2p-piper Pyrope clock and timing type checking

Goal. Extend Pyrope's type system so it captures clock and pipeline timing intent, then checks that the generated LGraph implements that intent. A clock, edge/domain relationship, or cycle constraint must not be lost silently while lowering source code into flops, latches, memories, submodules, and Clock_cells.

Existing foundation

@[N], ranged pipeline depths, pipe_min/pipe_max, attrs::time_range, and pending_time already carry part of the timing contract. The current inline Time_checker in upass/tolg/upass_tolg.cpp propagates cycle intervals and checks many fixed pipeline constraints. Keep that behavior and its existing error/equivalence tests while turning it into a coherent type check.

Pending

  1. Define the clock/timing type contract. Specify the source-visible and inferred facts needed to distinguish clock domains and edges and to express fixed or ranged cycle offsets. Decide which facts belong to a value, state element, lambda interface, or module boundary.
  2. Make the check reusable after lowering. Move the inline timing checker into a standalone pass.piper (or an equivalently clear type-checking boundary) so it can validate the generated graph. Persist or structurally recover the lowering facts that currently exist only in temporary maps.
  3. Solve timing ranges as constraints. Intersect inferred ranges with @[N], interface, and pipeline-depth constraints; choose the minimum legal depth when a range remains free; reject an empty intersection; and discharge a constraint when the computed range is a subset of the asserted range.
  4. Check generated clock structure. Verify that each generated Flop, Latch, memory port, submodule boundary, and Clock_cell is driven by a clock/edge compatible with its Pyrope type and that its realized latency is within the declared range. Clock-domain crossings or lost clock metadata must produce a diagnostic rather than silently generating different hardware.
  5. Keep hierarchy-visible results. Preserve the inferred clock/timing summary per module so callers and later checks can consume it without re-solving the lowered body.
  6. Add focused positive and negative tests. Cover an unsatisfiable depth range, a leftover timing obligation, mismatched clock domains/edges, clock-gated state, memory-port clocks, and a hierarchical design whose generated graph agrees with the source-level contract.

Scope

This task checks clock and timing intent; it does not perform physical retiming, pipeline rebalancing, or synthesis placement.
