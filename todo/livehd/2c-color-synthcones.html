2c-color-synthcones Cone-seeded synthesis coloring (pass.color synth --set synth_alg=cones)

Goal. Add a second synthesis-boundary coloring next to pass.color synth: seed one backward cone per register data input (and one per register enable), let cones record how much logic they share with cones that reached it first, then merge the most-sharing color pairs while the merged color stays under a configurable soft clustering threshold expressed in a predicted AIG-size score (predict_abc_size), not in LGraph node counts or the current synthesis-GE unit. The score guides region granularity; it is not an ABC admission limit, and the existing pass.abc memory/time checks remain the backstop. Both algorithms stay; a --set selects one. No default flip in this task — after both have been iterated on, a later ruling decides whether to delete one, alternate, or keep both.

Rulings (2026-08-25, do not relitigate)

  1. Walk-through, budgeted. When a cone reaches a node already owned by an earlier color it keeps walking through it (so overlap = the shared sub-cone), but a cone stops expanding once its traversed predicted score (owned + foreign) exceeds max_gate. The threshold is heuristic, like the merge threshold itself: it bounds positive-score work on shared hubs without claiming that the score is an exact ABC size or admission certificate.
  2. Roots per register: din is one color, enable (when connected) is a separate color. Clock and reset never seed and are never colored through the register. (Reset/clock driver logic that nothing else reaches is picked up by the leftover sweep, §A4.)
  3. Unit = predicted generic-AIG complexity. predict_abc_size(node) is a stable, technology-independent heuristic derived from the structure of pass.abc's default bit blast and the measured per-op scale. It intentionally does not reproduce every simplification or configurable adder architecture. max_gate is a soft, user-configurable clustering threshold: lowering it usually produces more/smaller (and potentially worse) regions, but neither side of the threshold guarantees ABC success or failure. No Liberty-specific calibration or runtime fitting is part of v1.
  4. No floor, no split. A zero-overlap cone is its own ABC block. Once the overlapping colors are merged nothing further is added even if the result is far below the bound. A single cone already over max_gate is left intact and reported.
  5. Exposure: third synth_alg value (synth|pipe|cones) dispatched inside Color_synth; knob pass.color.max_gate (flat leaf — pass.color.synthcones.max_gate is not an expressible --set key: the kernel splits at the last dot, lhd/lhd_kernel_common.cpp check_known_set_passes). lhd synth --set color.synth_alg=cones and the lhdsuite bench's BENCH_COLOR_SYNTH_ALG=cones then work with zero kernel/harness changes, and absorb, seeded-color exclusion, --stats and the "packed" plumbing are inherited.
  6. Overlap unit = predicted AIG-size score of the shared nodes, i.e. overlap(A,B) = Σ predict_abc_size(n) over the A-owned nodes B's walk traversed — same unit as max_gate.
  7. Keep the arithmetic cuts. Mult/Div and Sum wider than 8 bits are roots of their own cone (own color), exactly the boundary synth mode uses; register cones stop at them and record contact overlap, so the merge can still fold an adder into a consumer cone when it fits.
  8. Acceptance = keep both, measure. The A/B (§F) is a report, not a gate on landing; synth remains the lhd synth default.
  9. Zero-score nodes stay zero. Wiring-like nodes are treated exactly like every other node by ownership and traversal; there is no walk-only minimum charge or second node-count budget. A zero score therefore consumes no max_gate budget.
  10. V1 coloring remains node-granular. A Flop/Latch/Fflop node gets one din root regardless of width; v1 does not track or assign colors per bit. Large register arrays should normally lower to Memory, whose surrounding input logic is seeded once per logical read/write port. Register storage width is not a separate merge guard: the storage element itself scores zero, while any folded enable/reset mux complexity is ordinary predicted combinational cost. A true bit-demand coloring is deferred.
  11. Default max_gate=30000. It remains user-configurable; this is the shipped starting point for the A/B evaluation, not a claim that 30k is universally safe or optimal.

Why (measured, 2026-08-25)

The existing window bounds regions in synthesis_ge_weight (GE). Over 1930 regions from 7 lhdsuite designs, GE predicts mapped gates with a median error of 1.8x and p90 of 5.6x, in both directions: runtime shifts over-count up to 24x (the x6 in graph/synthesis_cost.hpp is an ABC time safety factor), Sum under-counts ~5x, Mult 1.5–6x, register-file arrays 8–11x (the 25k-GE window certified RenameTable_2__c10 at 24.8k GE; it mapped to 195k cells). ABC time correlates with mapped gates (r≈0.9) far better than with GE (r≈0.31 on cva6). A per-op sky130 fixture (ops.sv, one module per (op, 8/16/32/64 bits)) gives the ratios the table below encodes structurally: and/or/xor/mux2 1/bit, eq 1.35, lt 2.6, add 5.5, mux4 3.1, mul ≈ 5.9·a·b, shifts ≈ 1.15 per bit×amount-bit, flops 0 (+1/bit per folded enable/reset mux).

A. Algorithm (per def, inside Color_synth::label when synth_alg=cones)

  1. A1 — Preparation, one pass. Dense per-node arrays indexed by nid>>2 (user nodes start at index 4): owner (color id, 0 = none), visit_epoch, pred (cached predict_abc_size), and a per-node list of (sink port, driver node) entries materialized from ONE inp_edges() call per node. This cache is load-bearing: hhds inp_edges_local scans every edge slot of the node including its out-edges (graph.cpp inp_edges_local, the vid & 2 filter), so calling it on a 100k-fanout enable/reset driver inside a per-cone loop is the quadratic re-scan trap (memory sta_cache_and_two_quadratic_walks). Root discovery and the per-cone loop use this cache and never call inp_edges() or get_driver_of_sink_name(). Seeded (block-attr) nodes, builtins, constants and IO are marked non-traversable up front (is_partitionable, Color_synth::is_seeded).
  2. A2 — Roots, in body().nodes(Node_order::forward) first-encounter order (HHDS's deterministic dependency order with storage-index tie-breaking and cut nodes emitted first by default — therefore a flop may appear before its din cone, so roots are collected in one pass and walked in a second, never during the iteration):
    • Flop/Latch/Fflop: root R_din = cached driver of sink din, for the whole node regardless of Q width; root R_en = cached driver of enable when connected, a separate color. Nothing for clock/reset/async/initial.
    • Memory: one root per logical port, decoded from the Ntype::Memory_port_stride blocks and each port's rdport metadata. A write-port root starts from that port's addr/din/enable drivers; a read-port root starts from its addr/enable drivers. Clock and comptime pins do not participate. Whole-array update/update_enable form one additional logical write root. The Memory node remains one hard-stop node with one color; the per-port colors describe its surrounding logic, not multiple colors on the Memory node itself.
    • Stateful Sub (is_loop_break() after the set_subnode re-stamp): one root per node over all non-clock input drivers. A comb-only Sub is a pass-through node in every walk (blackbox, 0 AIG).
    • Arithmetic cuts (ruling 7): every Mult/Div and Sum with driver_bits > 8 (reuse Color_synth::is_cut minus the loop-break arm) is a root of its own color and is pre-owned before any walk; its cone is its operand logic.
    • Graph outputs: one root per output pin (they overlap and merge like registers).
    Within a node, emit roots in fixed semantic order (din then enable; Memory port blocks in ascending raw port index; graph output pins in ascending port id). Ids are minted 1,2,3,… in that root order. Ordinary din/enable/output root drivers remain traversable by later cones — that traversal is what measures their shared sub-cone. Only loop breaks and arithmetic cuts are hard stops and are never claimed by another walk.
  3. A3 — Walk (explicit LIFO worklist, never recursion; epoch-stamped visited). For root r with color c, initialize traversed with the predicted score of an arithmetic-cut node owned by that root (ordinary din/enable/output/memory-port roots start at 0), then push the root driver node(s). Registers are placed only in A4, so their folded enable/reset score contributes to the final color weight and over-max report, not to this earlier walk cutoff. Pop n:
    • skip if not partitionable, seeded, already visited in this epoch (also covers compact-loop self edges and comb cycles);
    • if n is a loop break: stop without claiming it or recording a pair (crossing a register/memory/stateful Sub is not sharing logic);
    • if n is an arithmetic cut: it was pre-owned by its own root; add pred[n] to pair(owner(n), c) when nonzero (contact overlap), then stop without claiming or expanding it;
    • else if owner[n]==0: claim it (owner[n]=c); else add pred[n] to pair(owner[n], c) when nonzero (foreign visit). Never materialize zero-valued pair-map entries: zero overlap must remain "no edge" for ruling 4;
    • traversed += pred[n]; if max_gate != 0 && traversed > max_gate: count it in budget_truncated, clear the worklist and end this root's walk — the popped node is still claimed/counted, but no already-queued sibling is visited after the threshold crossing;
    • push n's cached drivers.
    A root whose entire reachable cone was already claimed may own no node (an enable or output root has no fixed state node of its own). Its overlap still contributes to merge ordering, but with max_gate=0 the empty root naturally emits no color; "separate root" means a separate cone seed, not duplicated ownership of shared logic. SRA demand-slice group (best effort): when a cone claims a runtime SRA it also claims that SRA's still-unowned constant-mask Get_mask consumers (one forward hop), so the demand-sliced barrel that pass.abc builds only when both share a region is not split when ownership permits it (the same reason topo_chunk never chops a weightless Get_mask off its SRA). A consumer already owned by an earlier root stays with that root; §G records the resulting prediction exposure rather than violating first-wins.
  4. A4 — Root placement and totality. The register node itself takes the color of its din driver when that driver is an owned non-cut node (data_cone_id semantics: "the stage is the logic plus the register it writes"), else the fresh R_din id — a register fed by a PI or another register is a one-node color, by ruling 4. A Memory or stateful Sub node takes one fresh anchor color of its own; its per-port/input roots color the surrounding logic and never assign multiple colors to the state/boundary node. Leftover sweep: after all roots, walk body().nodes(forward) once more and root every still-unowned partitionable node that has no unowned consumer (a sink of the uncolored subgraph — reset/clock glue, output glue nobody reached, dead logic), same walk as A3. Finally, root every still-unowned node in forward order; this is the totality fallback for an isolated combinational cycle, whose members all have an unowned consumer and therefore have no sink seed. Result: no partitionable node is left at NO_COLOR (pass.partition warns and pass.analyze flags uncolored otherwise).
  5. A5 — Merge. Sizes are additive because ownership is disjoint: size(A∪B) = size(A)+size(B), and the same holds for folded overlaps overlap(A∪B, C) = overlap(A,C)+overlap(B,C) (the A–B entry is erased). That additivity is what makes "discard forever" sound. Driver:
    • Region graph over colors: weight = Σ pred, adjacency = the pair map (key (min<<32)|max, value overlap score). Only encountered pairs exist, so zero-overlap colors have no entry and never merge.
    • Max-heap of (overlap desc, min id asc, max id asc) with a version per adjacency pair and lazy invalidation: an entry is valid iff both ids are live roots and its stored pair version matches. A merge increments and re-pushes only the pairs whose overlap changed; untouched survivor pairs remain valid even though the survivor's size grew.
    • Pop the best valid pair (a,b). If weight(a)+weight(b) ≤ max_gate: merge through Region_graph::merge (survivor = larger degree, fold the dissolved side's adjacency additively, push only the dissolved side's updated pairs — small-to-large, O(P log P)) and also union the two original cone-id classes in Int_union_find. Region_graph's degree-selected storage representative and the union-find's minimum-id semantic representative are deliberately independent. Otherwise discard the pair for good (sizes only grow).
    • When max_gate==0, skip the merge driver entirely: zero means raw cones, not an unlimited merge cap.
    • A color whose own weight exceeds max_gate never merges and is counted as over_max (ruling 4).
  6. A6 — Finalize. Resolve owners through the union-find (union-by-min, Int_union_find), renumber 1..k in forward first-encounter order (lift the tail of apply_size_window, color_size.cpp "Final renumber", into a shared helper), force continuous=false, skip apply_size_window entirely in cones mode (ruling 4: min_ge/max_ge do not shape cones; min_ge still drives absorb, see §C), then apply_coloring. Emit "packed":true unconditionally for cones: a first-wins cone can be split by an earlier owner (flopB ← n1 ← n2[A] ← n3 gives B = {flopB, n1, n3}), so colors are not connected components; without the flag pass.partition shreds them into <def>__c<id>_r<k> modules ordered by min-nid (unstable cache keys). Disjoint clouds behind one port list are sound for partition/ABC/LEC/cgen (documented in color_size.hpp).
  7. A7 — Cost. Preparation O(N+E). The walk costs O(total node visits before each root's score truncation), with O(1) work per visit from cached drivers and epoch arrays. Zero-score wiring does not consume the score budget, so #roots × max_gate is not by itself a node-visit bound; §G records this accepted exposure. Pair map ≤ number of foreign visits. Merge O(P log P). Memory: four dense per-node arrays plus the pair map; no per-cone hash sets (40k roots on one XSCore def).

B. predict_abc_size (new graph/predict_abc_size.hpp, next to synthesis_cost.hpp)

[[nodiscard]] uint64_t predict_abc_size(const hhds::Node_class&). Unit: a predicted 2-input AIG-size score informed by pass.abc's default blast (pass/abc/abc_map.cpp blast arms, abc_arith.hpp builders), before ABC optimization. It is deliberately a stable heuristic rather than an exact count: ABC performs constant simplification while building, the adder architecture is configurable, and mapped size is the quantity the calibration ultimately tries to track. A pure (Ntype_op, bits) key cannot express the ops that dominate region size, so the function reads op + output bits + the op-specific extras below; the per-op constants are a single table and are pinned by a test. Initial values:

  • Nconst, IO, Concat, const-mask Get_mask/Set_mask, Sext, const-amount SHL/SRA, Not (AIG complement edge): 0.
  • And/Or: bits × (inputs − 1); Xor: 3 × bits × (inputs − 1); Ror: bits.
  • Mux: 3 × bits × (arms − 1); Hotmux: 2 × bits × arms.
  • Sum (rca full adder = 2 XOR + carry with the shared half-XOR): 8 × bits × (terms − 1); LT/GT (subtractor chain): 5 × max(a_bits, b_bits); EQ (XNOR + AND chain): 4 × max_bits × (inputs − 1).
  • Runtime SHL/SRA: 3 × muxes, where muxes is the structural count synthesis_ge_weight already derives (SHL out_w × amount_bits; SRA the backward need[k] prefix trim at cw = max(operand, result)). Factor that calculation out of synthesis_cost.hpp into a shared shift_mux_count(node) so the two never drift; the x6 there stays x6 (it is a time factor, see §G).
  • Mult: 9 × a_bits × b_bits (partial-product ANDs + an adder row per operand bit) — operand widths, not out_width² as ge_weight uses.
  • Flop/Latch/Fflop: 3 × bits × [enable connected] + 3 × bits × [reset connected] (the next-state muxes pass.abc folds into the latch D); the DFF itself 0.
  • Memory (default memory=false), Div, Rem, Sub (comb or stateful), Clock_cell, LUT, AttrSet: 0 — blackbox / not blasted. (a % 2^k Rem rewrites to an And before ABC; charge as And.)

All products and sums saturate at UINT64_MAX; an unknown required width degrades to 1 rather than making a live operation free. This table is a sizing heuristic, not a pass.abc support list: assigning a score to an operation such as Ror does not add a missing blast arm or make that operation synthesizable.

Scope of the unit: only cones mode's budget, overlap and merge test. synthesis_ge_weight stays the unit of the window, --stats GE columns, absorb, reduce, pass.abc size tiers and Region_qor::input_ge. Replacing it design-wide is a separate task with its own pinned tests.

G. Risks and open items

  • OPEN (not the coloring's bug, but it blocks minion's STA number). pass.opentimer refuses minion's cones netlist: internal: Concat lane 0 (of 2, MSB-first) driver 'concat_7722340' occupies 33 bits but its declared window is 32. The same refusal happens under the shipped pass.color flat, and NOT under synth (at any max_ge, including a 2000-GE window that produces far more regions) nor under synth_alg=pipe — so it is region-membership dependent, not region-count dependent. The pre-ABC design passes cgen_verilog's identical concat_lane_violation check, so the width is widened somewhere between pass.partition and pass.abc's read-back, not present in the source. ABC itself completes: minion's cones QoR above is real, only the whole-design STA is missing. Reproducer (one -c opt pair): 
    lhd synth ../lhdsuite/minion/pyrope/minion_top.prp --top minion_top --workdir W \
  --set synth.liberty=$LIB --set color.synth_alg=cones --set color.max_gate=30000 \
  --set synth.opentimer=false --emit-dir lg:net
lhd pass opentimer --top minion_top.minion_top lg:net $LIB --workdir OT
    Unrelated and also pre-existing: a -c dbg build aborts inside ABC (Abc_ObjAddFanin: !Abc_ObjIsNet(pObj) || !Abc_ObjFaninNum(pObj)) on minion under BOTH synth and cones, so every minion measurement above is -c opt.
  • Very wide flop nodes. V1 deliberately follows the graph's node-granular color contract: even a very wide Flop/Latch/Fflop has one din cone. If real designs retain large register arrays instead of lowering them to multi-port Memory nodes, record those cases in §F; per-bit demand tracking would be a separate design because a single LGraph node cannot carry multiple colors.
  • Zero-score traversal. Concat, masks, constant shifts and other wiring score 0, so a score-only walk threshold does not bound the number of visited nodes. By ruling, there is no special walk charge: a wiring-dominated shared cone may be revisited once per root. Measure this explicitly on the 40k-root XSCore case; if it is a problem, a future change must revisit the ruling rather than silently introducing another metric.
  • Shift-heavy ABC time. The AIG unit charges a runtime barrel 3 per mux; the window's x6 was calibrated on ROB colors that ran past 15 minutes. If §F shows a merged shift/Mult color breaching abc.time_budget_ms, report it and sweep a lower max_gate and/or revise the single prediction table. V1 does not silently add a second time metric.
  • SRA demand ownership. The predictor uses constant-mask consumers to discount unused high barrel stages. If first-wins assigned such a consumer before its SRA is reached, the best-effort forward claim cannot reunite them and the owning SRA color can be under-predicted. Record split SRA/Get_mask pairs in verbose statistics during §F; if they are material, a future revision needs atomic group ownership or a conservative full barrel score, not silent reassignment.
  • Cache-name stability. A global "most overlap first" order is chaotic under small edits (one changed count flips one merge; union-by-min then shifts later ids). Deterministic per run by construction (roots, heap order, renumber). If pass3 hits collapse versus synth, the mitigation is to break equal-overlap ties on min id (already the heap order) and to reconsider whether the final ids should come from the min forward-order seed of each merged class rather than the dense renumber.
  • Threshold scale. In the current measurements, a 30k predicted score is conservative for ordinary logic (57k-cell colors mapped in ~5 s), but that observation is not an admission guarantee. Cones are expected to produce more, smaller colors than synth's 25k-GE window on datapath-heavy defs and fewer on shift-heavy ones. This is expected by ruling 3 (granularity/soft bound, not an admission recalibration); the pass.abc RSS/time guards remain the backstop.
  • memory=true lowers memories to flops/muxes after coloring, stamped with the memory's color; the 0-AIG Memory entry under-predicts those colors. Same limitation as today's GE; documented, not solved here.
  • Enable cones that share everything with their din cone (e.g. en is one AND of the same operands) merge back by overlap when small — expected; the separate root only matters when the enable logic is a hub.
  • hhds forward-reference Subs: a stateful Sub whose body is not yet materialized reads as combinational until set_subnode re-runs; same exposure as synth today.
  • Stale references to todo/livehd/2c-color-size.html in color_size.hpp, color_common.hpp, color_size_test.cpp and lhd/tests/BUILD point at a file that no longer exists; do not add more.
