Design notes — findings

  • 314 tracked shell/Python files; 285 outside paths containing “scripts”. The latter include 181 in lhd/tests, 33 in pass/lec/tests, 25 in inou/slang/tests and 17 directly in inou/prp/tests. The remainder are pass/writer helpers, imports, generators and utilities.

  • The fixture infrastructure is substantial. These are file counts, not independently runnable test counts.
  • Slang discovery is the weak point. Pyrope sim/errors/equiv use globs and conventions. Slang's Yosys corpus ladder iterates a hand-maintained SLANG_LADDER map, and many tests/sv cases have individual BUILD declarations. Merely moving a .v file there will not automatically test it.
  • Same source does not mean same coverage. A sim fixture can already pass value assertions while a wrapper uniquely checks physical loop compactness, scheduler selection, dirty edges or kernel reuse. A paired golden can already prove while a wrapper uniquely checks negative mutants or an unbounded proof.
  • Two regression scripts are currently unwired: lhd/tests/inline_cross_unit_test.sh and pass/lec/tests/lec_min_timeout_default_test.sh. No BUILD/bzl reference or test srcs/data registration was found. Migrate/register their unique checks before considering deletion.

Retirement criterion — simplicity with meaningful coverage

User direction: it is acceptable to weaken ordinary tests somewhat when integration already covers most of their value. The detailed checks listed below identify what a wrapper adds; they are not a requirement to preserve every grep in a new metadata framework. Do not recreate all 285 scripts as 285 equally complicated specifications.

  • Delete after confirming redundancy: duplicate compile/run invocations and generated-code spelling checks with negligible incremental coverage and no unique behavioral failure oracle.
  • Move the fixture, drop the wrapper: useful stimulus not yet in the corpus, but ordinary sim/LEC/error assertions express its main value. Retire incidental text checks explicitly.
  • Keep one representative family check: code size, compact-loop storage, kernel reuse or scheduler choice when functional tests would allow a meaningful performance regression; do not repeat these assertions on every fixture.
  • Keep a dedicated scenario: cache invalidation, corruption/recovery, checkpoint restart, protocol, missing-tool/runfiles and solver soundness/negative mutants when corpus runs do not exercise or distinguish them.
  • Use coverage as evidence, not a proof: zero additional lines may still add input values, a stronger assertion or a negative mutant. Conversely, extra lines solely for profiler setup, log formatting or host-build dispatch may already belong to another workflow test.

LEC policy — user direction

  • Equiv tests are proof gates. Keep small independent reference/implementation pairs and explicit negative mutants; require the intended definitive result. Retain explicit bounded-depth contracts where they already state a bounded claim.
  • Other integration LEC calls are sanity checks. Set the LEC timeout option to approximately five seconds, accept an explicit solver timeout, and fail a discovered mismatch. Report pass/proven versus pass/inconclusive separately. This is a best-effort bug finder, not a claim that five seconds finds every bug.
  • Enforce an outer watchdog. The LEC option supplies the internal formal-work budget, not the entire setup/loading wall time. Give the script approximately twice the configured solver budget: for a five-second LEC option, allow about ten seconds for the LEC subprocess including setup/loading. A reported solver timeout may pass a sanity check; exceeding the outer watchdog is a test failure, not an accepted inconclusive result. Apply the same two-budget pattern to proof gates, which still require their expected verdict.
  • Timeout is not every unknown. Unsupported encoding, bad top, missing outputs, crash or invalid setup must not disappear into timeout acceptance. Use structured status/reason when available; distinguish solver timeout from watchdog violation explicitly.
  • Control total cost. Rely on the existing LEC option for its internal budget and check the external wall-clock bound. Limit the profile matrix and batch/split targets so total opt/dbg runtime remains reasonable.

Fixture placement rules

  • Keep a regression in its original source language and reader path. Do not translate SV into Pyrope just to fit a Pyrope-only runner; that would lose the frontend regression.
  • Use inou/prp/tests/equiv for hand-written Pyrope/Verilog pairs and Pyrope variants; sim for DUT/test blocks; errors/warnings for compiler diagnostics; and the existing verify directory for formal properties.
  • Use inou/slang/tests/sv for new native Slang regressions. tests/verilog currently contains three sky130 unknown-module cases; it is not the general successful-SV corpus. Keep Yosys-specific reader fixtures under inou/yosys/tests. Select cross-reader checks over the same fixture where valid.
  • For multi-file cases, keep a case directory with explicit source/helper/reference/testbench roles. Discover case roots, not every helper or mutant as a successful standalone design. Declare all helper files as Bazel data.
  • Keep meaningful generated stress shapes, such as deep_fold_chain, at their original depth; use bounded shared generators or checked-in source, not arbitrary commands in metadata.

Shared capabilities — add only where retained coverage needs them

  1. Two explicit LEC profiles. Equiv corpus: require the expected proof or refutation; small fixtures and a reasonable solver budget. Other integration flows: a five-second LEC sanity check may time out and still pass the regression gate, but must report inconclusive rather than proven. Refutation, crash, malformed/missing result and setup error still fail. Preserve proof-bound information; a bounded result is not an unbounded proof. Shrink or split hard equiv fixtures instead of silently reclassifying their claims.
  2. Small optional artifact layer. First retire low-value code-spelling checks. For the remaining meaningful assertions, use optional required/forbidden regexes, counts and selected JSON fields over named emissions; required file/glob existence before negative matches. Keep existing specialized checks for a small number of meaningful residual cases instead of building a general graph-query language. Never embed per-case Python or shell in the metadata.
  3. Small set of fixture profiles. compile/diagnostic, writer round-trip, LEC pair, simulation matrix/oracle, formal verify and synthesis. Reuse existing runners and factor common subprocess/runfiles/report code; do not create a new script per failing design or one giant interpreter of arbitrary shell steps.
  4. Discovery in BUILD macros. Glob fixture roots and associated metadata; default to the ordinary successful profile, declare exceptions beside the case. Keep one Bazel target per case/profile or a measured small batch. A new standard case should need source/data, not edits to a Python CASES list, shell array or central per-file BUILD block. Validate orphan sources/metadata and duplicate IDs.
  5. Bounded matrices and build reuse. Default sim profile plus explicitly selected Slop/LLVM, dirty/fence/live_words, seed and unknown/init variants. Batch compatible independent fixtures without changing their import roots/names; compile once per actual configuration. Do not multiply every corpus file by every option combination. Preserve 20s opt / 60s dbg per target; serialize synthesis-bearing work.

  • prpsim.py already supports fixture :set:/:args: and a runfiles-based host build, but does not offer a corpus-wide declarative tune matrix, generated-artifact checks or cross-vector digest guard.
  • prplib.py already has run_verify with exact proven/refuted totals and replay expectations; reuse it instead of adding a second formal fixture framework.
  • slang_compile.sh already accepts recognized LEC timeouts (currently a 20-second formal.timeout budget). Use --set formal.timeout=5 for ordinary sanity checks and enforce an approximately ten-second external bound.   • v2prp_test.py retains two native-only cases, while most round trips already use v2prp2v_test.py. Consolidate their implementation via modes only if both native-only coverage and the two full-round-trip comparison legs survive.
  • prpvsim.py and sim_rtl_roundtrip.py can skip an absent external simulator. Required oracle cases should declare a tool dependency or an explicit unavailable status, not count as verified comparisons.
