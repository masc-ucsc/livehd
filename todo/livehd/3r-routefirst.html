3r-routefirst Routing with fixed PCRS and movable logic

Can a router close a denser design, or close the same design faster, if it can push combinational cells aside while it connects their pins? Start from a congestion-measured legroute placement, fix the PCRS infrastructure and all flops, and let signal routing move the remaining logic, lower metals first. This is a proposed experiment. Its first deliverable is a decision on whether to build a router. Its second is a list of PCRS problems that only routing shows.

Revised 2026-11-23 after a review against the routed HighTide runs (Evidence) and a question-and-answer session (Decisions). Subtask letters are stable ids. The run order is A, B, F, C, D, E, and G runs with every step. Thresholds, script names and directories are proposals. The design sketch this plan started from is folded into the Design notes, so the page stands alone.

Depends on

  • 2r-route supplies the measured placement before terminal legalization. The existing plan rounds suffice for a first test.
  • 2p-pcrs supplies the installed tree, sink identities and physical power-grid handoff. Use one completed PCRS generation in both arms. Record remaining clock-model uncertainty using the PCRS review. PCRS has priority over this task (RF1): a problem this experiment traces to PCRS is fixed there.

Design notes: route-first legalization

This is the model the experiment tests, folded in from the sketch “Route-First Legalization: Committing Wires Before Cell Positions” (Jose Renau, 2026-11-23). The stretchable stub, the fixed-order row solve and the planted-witness test come from it. Where the plan above departs from it, the note says so.

The idea

The conventional flow fixes cell positions before any wire exists at track level. Legalization minimizes displacement from the global placement, which is only a proxy for routability. The detailed router then cannot move cells, so at high routing density it rips up and reroutes for many iterations, or fails. Route-first legalization commits the lower-metal routing topology first: each wire gets a track and an order on that track, and its length stays free. Legal cell coordinates then come from an exact solve per row, and discrete changes are confined to small windows. Two observations motivate it:

  • Legalization moves are small. A cell typically moves a few sites. That rarely changes the global topology of its nets. It changes the last hop to each pin.
  • A wire on a fixed track has one free dimension. If only its length may change, cell positions and wire lengths can be solved together as a one-dimensional problem per row.

The claim is that this replaces displacement-driven legalization plus rip-up-heavy detailed routing with a solve whose objective is real wire, and which reports infeasibility exactly. The claim is untested. The main risk is routing the lower metals in over-dense regions before the cells have spread.

Model

The lower metals are unidirectional: M1 pins, M2 horizontal, M3 vertical. ASAP7 matches this, with a 36 nm pitch on M1–M3, a 54 nm contacted poly pitch and 270 nm rows.

ElementRule
WireA segment on a fixed track. Only its endpoints move. No track changes during the solve.
TrunkAny segment on M3 or above that is not a pin attachment. Frozen once assigned. In the first rung the trunks are OpenROAD's (RF4), known to LiveHD only as its guide.
M2 stubA horizontal M2 segment from a pin's via to a fixed point of its net, usually an M3 segment. Its pin end moves with the cell.
M3-directA stacked via from the pin through a minimum-length M2 pad to a vertical M3 segment. It needs free M2 above the pin and an M3 track over the pin.
Access pointAn M2 track that a pin's M1 shape can reach. Each cell uses one mutually compatible set, one per pin.
RowEvery cell has a row before routing. M2 power rails separate rows, so stubs do not cross rows.

A cell's freedom follows from how its pins are attached. With every pin on an M2 stub the cell slides in x along its row. With every pin M3-direct it may change rows at a fixed x. The original model fixed a cell that has both kinds, and subtask C replaces that with rigid links. A stub keeps the side of its fixed end on which it was routed. That keeps the order of stubs on each track constant, and the formulation relies on it.

Row formulation

With rows, cell order and stub order fixed, legalizing one row is a linear program over difference constraints. For cells 1..n in left-to-right order, x[i] is the position of cell i:

minimize    sum over attachments p of  lambda[p] * len[p](x)
subject to  x[j] - x[i] >= d[i][j]    for every constraint (i, j)
            L[i] <= x[i] <= U[i]

The length of attachment p is linear in x because each stub keeps its side. A stub of cell i with a fixed end at a[p] has length s[p] * (x[i] + o[p] − a[p]), where o[p] is the pin offset in the cell and s[p] = ±1 is the routed side. A same-row segment between two cells has length (x[j] + o[q]) − (x[i] + o[p]). The weight lambda[p] carries net criticality and the resistance of M2.

Source of a constraint or boundForm
Cell non-overlap and edge spacingx[i+1] − x[i] ≥ w[i] + gap
Two stubs on one track with moving ends facing(x[j] + o[q]) − (x[i] + o[p]) ≥ tip spacing
Row ends, fixed M2 shapes (trunks, pads, blockages), stub side, stretch cap per netL[i] ≤ x[i] ≤ U[i]
  • Exact feasibility. The constraints form a graph. The row is feasible if and only if the graph has no positive cycle, which a longest-path pass decides.
  • Exact optimum. The dual is a min-cost flow. With spacing constants rounded up to the site grid, the optimum is integral.
  • A certificate on failure. A positive cycle names the cells and stubs that cannot coexist. The repair uses it to choose where to act, and subtask G uses it to name a protected object.

With only neighbour constraints this is fixed-order single-row placement, which has near-linear algorithms. Subtask C adds the two endpoints of each pin piece as variables and the equalities of aligned pins. Both keep the same form.

Algorithm

Six phases. Only phase 5 searches, and it is bounded.

  1. Row assignment. Snap each cell to a row, minimizing y displacement subject to the capacity of each row segment. Overlaps in x remain. This is the only step that moves whitespace across rows at long range.
  2. Mobility planning. Choose one attachment mode per cell. The default is M2 stubs. M3-direct is used where M2 demand exceeds the track budget and the cell is not expected to move.
  3. Trunk track assignment. Assign tracks to the global routes on M3 and above, then freeze them. The first rung leaves this phase to OpenROAD (RF4).
  4. Order-committed stub routing. For each pin, pick an access point and connect it to the nearest point of its net's trunk tree. Commit the track and the order of stubs on that track, not coordinates. Leaf Steiner points are chosen here, per pin.
  5. Row solve and bounded repair. Solve every row exactly, in parallel. For each infeasible or over-cost row, try discrete moves inside a small window around the certificate, and solve again only the touched row segments.
  6. Hand-off. Emit coordinates and final stub lengths. The detailed router completes the remaining connections and rule checks with all cells fixed.

The repair moves of phase 5, in increasing cost:

  • Swap two neighbouring cells in a row, allowed when their stubs sit on different tracks.
  • Row change of an M3-direct cell by one or two rows, with a landing check for its M2 pads.
  • Re-attach a cell: rip its stubs and route them again with another access pattern or mode. This is the only move that reroutes.
RFL(GP, global_routes):
  rows  <- AssignRows(GP)                       # capacity-aware; x overlaps remain

          roll back
      if best exists:
          commit best; push touched rows that are still infeasible
      else:
          mark r for fallback                   # local trunk rip-up or spread again
  return x, T, S

Every trial is a transaction on an undo trail: each change logs its old value, and a rollback pops to the checkpoint. Occupancy is stored as sorted intervals per track and per row, owned by nets and cells, so removing a wire never requires a search.

Cost and termination

  • Row solve. A row with n cells has O(n + stubs) constraints. The neighbour-only case is near-linear and the general case is a min-cost flow on a sparse graph. Rows share no variables, so they solve in parallel. The rigid links of subtask C join rows into components, and those solve in parallel instead.
  • Incremental solve. A repair trial solves again only the row segment between the nearest fixed cells on each side of the window.
  • Repair. A window with k movable cells and r choices each has at most rk combinations. With k ≤ 5 and r ≤ 3 this is a constant, so repair is linear in the number of failing windows.
  • Termination. Let Φ be the total weighted wire length plus a large penalty times the total constraint violation. Every committed move strictly lowers Φ and the state space is finite, so the loop stops at a local optimum.

The guarantee is local. The full two-dimensional problem is NP-hard and this does not solve it globally. A row imbalance wider than the repair window cannot be fixed by phase 5, so phase 1 must balance row capacity up front.

Limits and open risks

The exact solve covers one dimension with the order fixed. Everything hard moved into phases 1, 2 and 4, and none of those is proven.

  1. Routing over overlapping cells. In an over-dense spot there are more pins than M2 capacity until the cells spread. Committing order instead of coordinates is the proposed answer. Whether a good order can be found there is the central open question.
  2. M2 budget. A rough estimate gives a mean stub of 3–4 sites before the tracks of a row saturate. Typical displacement fits. Cells that must move tens of sites need the re-attach move.
  3. One axis per cell, chosen early. Mobility is fixed in phase 2, before the solve shows which axis a cell needs. The 3:2 ratio of poly pitch to M3 pitch likely limits M3-direct to about half the sites. This is an inference from the pitches, to check against the LEF.
  4. Short local nets. Most nets have no trunk. They add terms between two moving cells and compete for M2 exactly where pin access is hardest.
  5. Trunk validity. Trunks are assigned against approximate pin positions. A cell that moves more than about a routing tile invalidates them.
  6. Timing. Stretch on M2 is resistive. The weights and stretch caps must come from slack, with a periodic full timing refresh. A worst-slack gate alone lets non-critical paths degrade.
  7. Whitespace across rows. The repair window reaches one or two rows. Larger imbalances must be removed by row assignment or by spreading again in global placement.
  8. “Legal” is partial. The original solve guarantees no overlap and spacing on tracks, and leaves via spacing, minimum area and M1 rules to the detailed router, which can still fail. Subtask C moves line ends and minimum length inside the solve. Cut spacing stays a check after it.

Tests of the sketch and where they are now

  • The oracle study before building is subtask B.
  • The planted one-dimensional test is subtask C, on fixtures first and then at design scale.
  • The end-to-end comparison from one global placement and the utilization sweep are subtask E.
  • Ablations to run with E: a displacement-only cost (isolates the objective), no repair, and no M3-direct.

Added by the review of 2026-11-23:

  • CoRe-ECO solves detailed placement, detailed routing and cell replacement together with SMT in windows of a routed layout. It is the closest work to B and D. Its follow-on SLO-ECO reports 45% fewer violations at 15.6 hours average on 11K–70K instances, so an exact joint search per window is the slow path.
  • Kahng, Kuang, Liu and Xu refine the placement inside routing, driven by pin access, and report fewer initial violations and less routing time afterwards. It is the closest work to F1.
  • Xu, Lin, Livramento and Pan (DAC 2017) treat pin access under unidirectional routing as weighted interval assignment on tracks. That is phase 4 of the algorithm with the cells fixed. Here the cell position is a variable too.
  • Ding, Chu and Mak (ISPD 2017) refine a detailed placement by flipping, swapping and shifting for pin access, with about a third fewer unroutable nets.
  • Making the same algorithm faster gives about 2×: RouterAcc reports 2.1–2.3× over TritonRoute on an FPGA, and offline reinforcement learning of its cost weights 1.56× on average. The search found no GPU detailed router that reports a gain over TritonRoute.
  • What stays new: cell positions and stub intervals solved together and exactly per row, starting from an overlapping placement, as the legalization step.
