2m-magnet Iterative macro magnetization during macro_plan

During macro global placement, pairs of equal-shape macros (or previously magnetized groups, called meta-macros) that sit close together with very few standard cells between them are aligned and magnetized: from then on the pair is one rigid rectangle for the rest of macro_plan. Rounds of magnetization alternate with DREAMPlace relaxation, so the global placer adapts to each clustering decision instead of a separate macro-clustering phase deciding arrays up front. Regularity emerges incrementally wherever the placement already wanted it.

Global scope: magnetization is independent of synthesis color, master identity and hierarchy. A magnetized set owns one physical macro node for placement, density, routing feedback, snap and legalization. Member identities and rigid offsets are used for expansion and diagnostics, not as separately movable placement objects.

Implementation in progress; rulings settled 2026-10-22 The default staged flow (synth.place.macro=none with movable macros: macro GP → fixed macros → final cells) is the target. H2D keeps its own topology groups and is out of scope.

Depends on

  • The staged native placement pipeline in native placement: macro GP with the same-master alignment well force (synth.place.macro.align_*, on by default), end-of-GP macro snap, macro LP legalization, fixed-macro handoff to the final cell stage. See the placement README.
  • DREAMPlace native GP controls already used by pass/place/place.cpp: checkpoint_interval (timing callbacks), macro_pull_* (2w-warpspace anchors with macro_pull_settle_iterations), terminal_interval, the per-iteration same-master pair strip index, and GpSample/ gp_history.json overflow sampling.
  • The H2D macro/abstract.hpp rigid-member machinery (abstract_design, member offsets, pin transforms, transactional expand) is the reference for how a group node is built. It is reused or factored, not re-invented, but the plain flow must not depend on H2D topology, pseudo-nets or seed search.

Rulings (2026-10-22)

  1. Rounds, not single pairs. A magnetization round may merge several pairs at once as long as the pairs are mutually independent (no shared member, no conflicting gap regions). Strictly one pair per relaxation was rejected: Eyeriss has 1040 SRAMs, so one-at-a-time would need about a thousand relaxations. A cap knob keeps one-per-round available for experiments.
  2. Stability gate, not an iteration count. There is no native notion of "stable"; the proxy in macro_plan is movement of each candidate macro or meta-macro over the last iterations, normalized by its own smaller physical dimension. Both candidates must pass; movement elsewhere does not veto them. Every instability-inducing event — timing checkpoint, anchor (macro pull) refresh, terminal pin update, snap, and a magnetization round itself — resets the gate. A magnetization round never coincides with another event, and the macro stage must not stop until macros have settled after the last event.
  3. Start when globally stable, then check each pair. Per the latest CNN experiment request, the first complete motion window with global maximum displacement ≤10% opens a one-shot start gate. Subsequent pairs must each satisfy the 5% local threshold; unrelated movement cannot close the start gate. There is no overflow prerequisite, extra cooldown, or future-event quiet window. Applied feedback and merges reset the local motion history. The separate absolute center-step sum, normalized to its peak in the first 50 GP iterations, is independent of the magnet gate. It opens the configurable macro-warpspace start gate (default 20% after the first 50 reference steps). The current warpspace coefficient stays at a programmable constant (default 0.7), with target refresh every configured GP interval (default 25), independent of subsequent stability. Adaptive strength controllers were removed after the CNN spreading previews. An opt-in before-snap experiment instead finishes ordinary GP and searches frozen geometry immediately before macro snap/LP, without a motion gate or any post-merge GP.
  4. A magnetized group is one macro. Inside macro_plan the group is a single movable node (union rectangle, re-offset pins, rigid member offsets): density, overlap repulsion, RUDY, alignment force, macro pulls, snap and the macro LP legalizer see one rectangle. The final cell stage receives fixed member macros and has no concept of meta-macros.
  5. Internal spacing stays two halos. Members keep the ordinary macro-to-macro clearance (each macro's halo, so 2 × synth.place.halo between facing bodies). Zero-gap abutment on pinless facing edges is a possible later refinement, not part of this plan.
  6. Same shape is the only type rule. Two candidates may magnetize when their outer rectangles have equal width and height (macro or meta-macro, regardless of master or interior). Side-by-side or stacked both yield a full rectangle by construction. Consequence: a single macro never joins an existing 2×1 group (different shape); groups grow by doubling-shaped merges (1×1+1×1, 2×1+2×1, 2×2+2×2, …) or by any coincidentally equal rectangles.
  7. Selection. Candidates come from the existing strip index. A pair is eligible when the gap along the merge axis is at most magnet_max_gap × extent (default 1.0), the orthogonal center offset is below half the shared extent, and the standard-cell density inside the region joining the facing padded edges is at most magnet_density_fraction × global_cell_density (default 0.25, so 0.1 absolute at global density 0.4). Global cell density is movable standard-cell area divided by core area minus the union of physical macro bodies; halos are excluded and overlaps count once. No other macro may intersect the trapezoid. Score: lowest gap density first, then smallest total displacement; greedy, independent pairs only.
  8. Merge pose. Align on the merge axis, keep the pair's area-weighted center where feasible, place members at two-halo spacing. If the ideal pose extends beyond the core but the padded union fits, translate the whole proposal by the minimum amount into the core. This preserves rigid member spacing; unions too large for the core remain ineligible. Cells in the gap are not moved; the next relaxation pushes them out.
  9. Coexists with alignment force and snap. Both stay on by default. A group gets a shape signature as its alignment class so the well force pairs it only with equal rectangles, never a member's original line with an outside macro. End-of-GP snap treats groups as macros of their own size class.

Subtasks — specification and acceptance checklist

  • A — Native rigid group node (DREAMPlace).
    • Add a plain-GP group facility in ../DREAMPlace (no H2D topology dependency): merge_macros(Design&, members, poses) builds one movable node whose physical rectangle is the union of member bodies at the merge pose (interior two-halo channels included in the body; the ordinary halo is padded outside as for any macro). Member pins are re-offset into the group frame, nets rebound, member rectangles recorded as rigid offsets. Factor shared code out of macro/abstract.cpp where practical.
    • Orientation: members keep their orientation; the group's orientation is frozen at merge. Group flipping or LEF-symmetry search on groups is out of scope and must be rejected explicitly, not silently applied.
    • Replacement is atomic, like macro_pull_update: validate (members movable, inside core, no fixed-macro overlap after the pose), then rebuild density/filler state and restart momentum seeded from current positions. Invalid requests leave GP untouched and report a reason.
    • expand back to member coordinates at the macro-stage end, before macro legalization writeback to LiveHD, so the host always sees member macros with their final positions. Members of one group carry a stable group id for diagnostics only.
    • Density model: the group charges its union body (plus interior channels) as macro occupancy exactly as the two separate macros plus their halo channel would; scale_macro_density and filler compensation account for the removed nodes so target density and overflow stay comparable before and after a merge.
  • B — Stability gate and event scheduler.
    • Add a macro-movement metric per iteration: max and RMS displacement of movable macro centers (groups count once) over a window of magnet_settle_window iterations (default 10), normalized by the each macro's own smaller physical extent. Record in GpSample/ gp_history.json as macro_move_max, macro_move_rms.
    • Define a single instability event hook inside native GP that every disturbing action reports: timing checkpoint applied, macro pull replacement, terminal update, magnetization round. Store the last-event iteration.
    • Gate: a magnetization round may run at iteration i only if a complete post-event motion window exists and both candidate macros individually move ≤ magnet_settle_displacement (default 0.05) of their own smaller physical dimension. An unrelated unstable macro cannot block them. The global maximum opens the one-shot 10% start gate; maximum/RMS also remain diagnostics and whole-placement stopping checks. No overflow, extra age, or future-event test applies.
    • Stop criterion: normal convergence (overflow ≤ stop_overflow, HPWL tolerance) and all macro objects settled after the last event. This whole-placement stop check does not gate individual merges. Respect the existing iteration cap; at the cap, report that settling was not reached rather than claiming convergence.
    • Rounds continue opportunistically until no eligible pair exists or magnet_max_rounds (default 0 = unbounded) is reached.
    • A no-pair result is specific to its geometry and cell-density snapshot. Recheck at each stable GP sample, including when only cells move out of a corridor.
  • C — Candidate search and gap density.
    • Reuse the per-iteration same-class strip index. Replace the master-based class with a shape signature (padded width, height) for magnet candidates; keep the same-master class for the alignment force except that groups use the shape signature (ruling 9).
    • For each neighbor pair with equal shape, consider both axes whose gap and orthogonal-offset limits hold; compute the quadrilateral joining corresponding endpoints of the facing padded edges. Per user feedback on 2026-10-22, offset pairs use this slanted gap region, not its bounding rectangle or only the shared projection. Equal-shape pairs form a parallelogram; aligned pairs form a rectangle. Overlapping/touching facing edges have no positive gap area.
    • Standard-cell density in the gap: sum of movable standard-cell area overlap (no macros, no fillers, no halo padding) divided by gap area, from a summed-area table over the auxiliary grid for aligned pairs. Offset regions weight bins by polygon intersection area. Exact per-cell polygon clipping is used if the candidate count and design are small; measure.
    • Eligibility and score per ruling 7. Independence: a chosen pair excludes any other pair sharing a member or whose gap region intersects a chosen pair's merged rectangle. Apply magnet_max_per_round (default 0 = all independent eligible pairs).
    • Reject (and report the reason) when the padded merged rectangle cannot fit the core, its proposed pose overlaps a fixed macro, or either candidate participates in a pending macro pull replacement in the same iteration.
    • Before selecting a pair, verify that its frozen member offsets admit one common routing/manufacturing phase for all original supported pin profiles. Intersect single-axis domains and combine mixed-layer pin coverage across both axes. Cache by master, orientation and relative offsets; an incompatible proposal reports routing_track_phase and leaves GP running.
  • D — Round execution and relaxation.
    • A round computes poses for all chosen pairs (ruling 8), issues one atomic batch of merges (subtask A), marks the instability event, and lets GP continue. Existing anchors (macro pulls) of the members are dropped; the next scheduled pull refresh sees the group as one memory with the union rectangle. Timing checkpoints are unaffected: pins keep physical coordinates through the group transform.
    • Alignment force on the group: re-key its class to the shape signature; its force is normalized by pair degree as today.
    • Groups of groups: a meta-macro is a candidate like any macro; its members' offsets are composed into the new group (flat member list, no nested nodes).

Implementation notes

The implementation includes physical rigid-group contraction and expansion, member-offset preservation, geometry checks, per-object motion tracking, and macro-only playback over measured cell-density maps. Tests cover group composition, orientation, boundaries and fixed-macro handoff.

Benchmark measurements, parameter sweeps, performance profiles, plots and animations belong under repros/ and are shared separately through ChatGPT. Intermediate results are not maintained in versioned documentation.

Design notes

Why a node merge and not a constraint

Keeping members as separate nodes with a projected shared displacement would require overlap repulsion, fillers between members, the alignment well, macro pulls and the macro LP each to learn about groups. Merging into one node makes all of them correct by construction and matches how H2D already represents rigid members. The price is a GP restart per round seeded from current positions, which the round/relax model needs anyway.

Halo arithmetic

Each macro reserves synth.place.halo per side and two macros reserve both halos between them. A group's body therefore spans n·w + (n−1)·2h along the merge axis for n members of width w and halo h, and the group pads one more halo outside. Halo lines of members are aligned because member shapes are equal, so no isolated pocket of standard-cell space is created inside a group.

Interaction with 2w-warpspace anchors

Anchors are optimizer-only targets refreshed on their own cadence; a merge invalidates member anchors and the next refresh issues a single anchor for the group. Both the pull replacement and the merge are instability events, so they never land on the same iteration and each is followed by a settle window.

Deferred

  • Zero-gap abutment on facing edges without signal pins (ruling 5).
  • Allowing a single macro to attach to a longer group edge (would relax the same-shape rule; revisit if Eyeriss leaves many singletons next to rows).
  • Group flipping / orientation search, and using the same facility inside H2D.
  • Any hard constraint attribute in HHDS for groups; JSON is cache/output only.
