Live floorplanning through the agent socket

Design goals, 2026-11-18. The first workflow to ship is “try these placements from here, measure the delta, and keep the winner.” A direct edit takes effect immediately. The same GUI shows the selected objects, active trial and resulting placement throughout.

  1. Make selection usable across views. Give chunks, IO contacts, macros, colors and cells typed references scoped to a design and revision. Resolve “selected” to the exact one-to-many click selection when the request arrives. Return those references from module, hierarchy and connectivity queries, and highlight the results in the same view. Preserve selection across solver frames and report objects lost to a topology edit.
  2. Consolidate the socket and client. Extend the existing selection, edit, exploration and comparison commands. Let one request resolve a selection and apply a batch atomically. Cover move, fix one or both axes, release, align, split, transfer and chunk placement. Provide structured results, progress and completion tied to the request. Move pagination, receipt polling, epoch changes and worker routing behind the client. Keep English interpretation in the agent. A move supplies a new starting pose. An explicit fix survives subsequent iterations.
  3. Run controlled trials on the existing forks. Capture the solver and design state once, including positions, constraints, shared IO, seed, iteration and metric settings. Submit a batch of alternatives from that checkpoint and run them concurrently within worker resource limits. Report each fork’s actual completed iterations and any early stop. Compare with the saved value for a before/after question. To isolate the edit’s effect, advance an unedited control by the same iteration budget. Hold scope, estimator and solver settings constant. An interrupted or short trial stays distinguishable from a completed comparison.
  4. Make the decision reversible. Support keeping a chosen result on main or undoing the entire trial, including incidental cell motion and shared IO changes. Verify placement and metric after replay or adoption. If the user edits main meanwhile, preserve their edit and report that the common baseline has changed. Never publish speculative neighbor contact changes outside a fork.
  5. Keep one live GUI. Stream worker positions, iterations, affected contacts and metrics to the existing canvas. Show the active branch, selection, occupancy, HPWL and best current WNS estimate with its scope, estimator and age. Refresh the estimate during placement and attach slower timing results to the revision they measured. Compare like estimates and keep unavailable timing explicit. Keep options, object details, pause, undo and branch switching accessible. Retire duplicate editing panels only as their socket and selection workflows pass the same interaction tests.

Acceptance run. Click four RAMs. From one checkpoint, try an aligned row on the left, an aligned row on the right and an unedited control. Run at least 100 completed global-placement iterations per candidate, display comparable HPWL and estimated WNS deltas, and keep the winner for the named metric. Exercise the losing and undo paths. Check that an intervening edit cannot be overwritten. Repeat with a CSR-only macro run and verify the parent canvas shows the returned cell and memory positions and that incident chunks agree on shared IO coordinates. Use a small repository fixture in CI and Rocket as the interactive acceptance design.

Track selection-to-highlight, edit-to-visible-frame, estimate age and time for the complete trial. Record these separately from solver time to expose interaction overhead. The agent should complete the workflow through the normal client without generating a script, parsing worker files or opening another GUI.

Implemented and exercised. The workdir client now resolves clicked objects, ranks connected floorplan members, applies chunk edits and runs measured placement alternatives. The chunk viewer shows solver frames and a density overlay. On Rocket, four browser-selected CSR memories ran for 100 iterations on each of three forks. Against the unedited control, the right row saved 8,112.488 µm and the left row added 42,174.872 µm. Both exceeded the original HPWL. Keeping the right row and undoing restored the original revision. A register-counter trial exercised negative estimated WNS. See the commands and estimator scope.

Each chunk fork starts a new optimizer from the same legal placement. Full optimizer continuation and final path timing in the isolated worker are separate from this implementation.

Bugs the attack found, fixed

  • G1 find/highlight/select regex froze the whole GUI. A nested quantifier ((.*)*x) ran in std::regex (backtracking) while the session lock was held: the agent socket, the token page port and the flow all stopped, lhd spun at 100% CPU, only a kill recovered it. Now RE2 (linear time), compiled before the lock: the same request answers in 48 ms. Backreferences and lookaround are refused with a message. New dependency re2 (already in the resolved module graph; credited in docs/acknowledgement.html).
  • G2 restart with a set flag that does not exist, is read-only, or cannot hold the value (iterations=abc, timing_driven=maybe) was answered ok and queued; the re-executed lhd then exited with status 2 and the session was gone with its pins and edits. The flag, its read-only bit and its boolean/integer type are checked before anything is queued.
  • G3 restart with a checkpoint that does not exist (99) restarted from the beginning and dropped every edit. It is a note and no restart now; a string or a number below -1 is refused; absent or -1 still means the start.
  • G4 find limit and critical n ignored a string or a fraction and clamped 0 or a negative number to 1. They are bounded integers now and say what is wrong.
  • G5 {"cmd":"state\u0000x"} ran as state (C-string truncation); strings keep their length.
  • G6 move with scalar x/y (as the help shows) was refused with "equal length"; one number now applies to every node.
  • G7 describe did not take #index (move, select, highlight_names do).
  • G8 A whatif candidate without "cmd" failed as "bad command json"; it is a move now and a bad candidate is named by its position.
  • G9 The screenshot page command was silent when it could not write; it sets the note with the path it wrote (<workdir>/synth/place/gui/<basename>) or why not.
  • G10 Screenshots were stored (uncompressed) PNGs: 2.4 MB at 900x900. They are compressed now by a built-in encoder (PNG Sub filter, then one deflate block with the fixed Huffman code and matches against the previous byte and the same place one row up): 63.7 KB for the 1000x1000 fp-plan picture, against 81.7 KB for the first zlib version; the round trip is exact (a small inflater in the unit test) and the Python smokes inflate it with real zlib. See G21 for why it is not zlib.
  • G11 Dead sessions left their /tmp/lhd-gui-<pid>.sock: 1,089 had piled up. A new session removes the sockets of processes that no longer exist (same user, a socket, kill(pid,0) says ESRCH); 2 were left after the run.
  • G12 highlight color ran a std::regex on caller text; it is a plain character check.
  • G13 A macro pose that passes every geometry check can still end the run: a pinned macro is held exactly through legalization and then rejected as a fixed macro whose pins miss the routing tracks (the live session died with fixed macro pin misses routing tracks: ...u_storage_64w1024d_6:r0_addr_in[0]). The session now carries the macro's track lattice as data (Scene::track_lattices, built from the flow's own profile in macro_tracks.cpp, serialized because the flow and the session are different processes). A pinned or fixed macro off the lattice is a conflict misses_tracks (x axis; nearest aligned origin X,Y): the move is applied but not pinned, and the answer says where to go. A unit test shows the lattice is exactly what legalize_macro_tracks accepts for a fixed macro at every origin of a 12x12 window and four orientations.
  • G14 move of a placed (fixed) macro after the macro stage was skipped but still answered applied, with the old pose and a new frame number. It is refused now, naming macro_move (which was missing from the agent's help and is listed now). See W3: macro_move does not move flow-placed LEF macros either.
  • G15 geometry at the fp gate ended the whole GUI controller with std::bad_alloc (gdb catch throw: floorplan_findings → measure_dead_space → classify → vector::assign). The fp-gate scene builder (place.cpp, the one for chunked plans) never set dead_pitch, so it stayed at 1 DBU and a 3.6 mm core asked for 1.3e13 raster cells. It sets the pitch and the notch width now; floorplan_findings coarsens a pitch that would exceed about four million cells and reports the pitch used (it answered 2,048 on mixed_soc, which is how the unset 1 was recognised); measure_dead_space refuses more than 2^27 cells with the minimum pitch in the message. The same unset pitch applies to any chunked fp gate; liteeth's was never queried.
  • G16 Any exception inside a request handler (POST /agent and /cmd had no try) left a detached thread and ended the process, taking the flow with it. Every request now answers 500 {"ok":false,"error":"internal error: ..."} and the session lives on.
  • G17 The Unix socket's listen backlog was 8 (the TCP port 16): a burst of parallel agents got EAGAIN (28 of 44,000). Both are 128 now, and the server stops spawning a thread per connection past 256 concurrent handlers (idle connections wait up to 10 s each).
  • G19 macro_scan checked each candidate against every node of the design (66 ms at 4M nodes: a 16x16 grid took 16.9 s). The check reads only macros and exclusions, so it runs on a scene reduced to them: 53 ms for the same scan.
  • G20 find, highlight and select scanned the node names with the session lock held, so every other request, the page and the flow's own publish waited behind a 100 ms scan (state p99 314 ms with 16 clients at 4M nodes). They scan an immutable snapshot of the scene and take the lock only to store the selection or the highlight (state p99 4.4 ms).
  • G21 A regression of mine: G10 first added @zlib to the gui library, and a statically linked test (//lhd:lhd_options_test) then failed to link, because LLVM already brings zlib-ng in zlib-compat mode (duplicate zlibVersion, zError, ...). The shipped lhd linked, so the 113-test run that followed missed it; running that test found it. The encoder has no library behind it now.
  • G18 state.since_flow_s: seconds since the flow last published a frame. While state is running and this keeps growing the flow is inside a stage that does not poll; a queued pause, stage switch or timing request waits for it.

Features

  • F1 macro_scan {node, grid:{nx,ny} | positions:[[x,y],...], orientations?, top?, refine?}: ranks poses of one macro by the sum of its pin nets' half-perimeters (each connected pin joined with the box of the cells on its net, so a clock or an enable reaching thousands of cells costs about the same everywhere); only poses the floorplan checks accept (core, halo, channel, exclusions, other macros, routing tracks, positions snapped to the lattice); the current pose is always a candidate; the best is walked downhill; orientation changes are offered only at the gates that accept them (orientations_dropped otherwise). Milliseconds for 576 poses. The net half-perimeter is checked exactly against a hand computation in the unit test.
  • F2 evaluate wait_ms=N returns the measured summary (2 s on liteeth); before, it answered "processed" at once and the numbers showed up later in state.evaluation_seq.
  • F5 synth.place.chunk.seed_cache=off|exact|translate (default off): a persistent store of each chunk's finished local placement in <workdir>/chunk_seed_cache/chunk_seeds.bin (not removed by a GUI restart), keyed by what the chunk contains (partition, implementation, a hash of member names, sizes and net structure) and kept as positions relative to the chunk's own box. Same shape: translate reuses it even when the boundary contacts moved, exact needs the same contacts and otherwise refines; a reshaped chunk refines. Opt-in because a stored placement is a different start than a solved one, so replays that must be byte-identical keep it off. Unit tests: persistence across stores, a moved chunk replaced relative to its box, a chunk with different contents solved alone, damaged and foreign files ignored whole.
  • F6 Poses relative to the chunk: move takes "frame":"chunk" (x and y from the chunk's lower-left corner; "chunk" names it, else each node's home chunk) and the instruction stays recorded that way in export relationships; macro_scan takes the same (the grid is the chunk, the body must stay inside it, every pose is reported in both frames); export macros gives each macro its chunk, chunk_x and chunk_y. Live on the 4,035,632-node scene: all 139 macros carry a chunk, a 16x16 scan of one macro took 53 ms, and a chunk-relative move of the best pose resolved to the right absolute DBU, pinned, and was recorded as "frame":"chunk".
  • F3 tools/lhd_gui.py: screenshot out=FILE, wait state=gate phase=edit, macros (pose, size, orientation, pinned for every macro), --retry SECONDS (the socket is down while a restart re-executes lhd; a restart takes about 18 s here).
  • F4 describe of a macro and macro_scan report track_check: the pins that constrain it and its periods and phases.
  • F5 (2026-11-22) The native clock tree, once the flow has built it (synth.place.pcrs.clock=true): clock (summary, nets, sinks, pair, map), a clock tree layer in the page (stage depth, sink arrival, leaf slew, local skew grid), screenshot layers=...,clock, and clock_edit, which stages leaf drive steps, wanted arrivals and scalar synth.place.pcrs options and applies them by a restart. The tree travels in the scene by node index (Scene::clock_nets); code in pass/place/gui/gui_clock.{hpp,cpp}, test gui_clock_test. Checked live on lfsr; see 2p-pcrs-review for what is not done.

Tests added: gui_session_test (regex time bound over a 4,000-character name, argument checks, NUL, #index, colours, scalar move, restart refusals, placed-macro move, macro_scan ranking/orientation/refinement/tracks, PNG), macro_tracks_test (lattice vs legalizer). README.md of pass/place and the livehd skill describe the new surface.
